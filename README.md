# 单账号角色互动工作流

运行在服务器上的 X 角色运营工具，集中管理消息采集、回复分级、草稿审核、人设、记忆、角色帖与模型用量。应用使用确定性流程控制模型和浏览器操作，不接入 Buffer。

仓库：[blueforst/dafeiyu](https://github.com/blueforst/dafeiyu)。功能规划与验收入口见 [OpenSpec 索引](openspec/README.md)。

## 五页如何使用

| 页面 | 地址 | 主要操作 |
| --- | --- | --- |
| 动态 | `#/feed` | 查看当前账号的回复、私信和角色帖，筛选待处理项，编辑、批准、重写或取消草稿，查看阶段与回执 |
| 人设 | `#/persona` | 编辑静态分区与触发卡片，填入预设，试聊，查看虚构日程，回放比较人设或模型 |
| 记忆 | `#/memory` | 按用户／会话检查近期往来、长期条目和来源；管理遗忘、恢复与角色经历 |
| 设置 | `#/settings` | 管理模型库、运行与发送限制、任务、浏览器接管、健康检查和日志 |
| 计费 | `#/billing` | 查看北京时间范围的用量、趋势、模型／用途分布和调用流水 |

默认进入动态。旧七页地址会跳转到对应新页或设置分区；七页文档保留为历史基线，不再代表当前导航。

### 配置与运行

1. 使用管理员交付的 HTTPS 入口和凭据登录。在设置页“浏览器接管”检查当前 X 账号；需要登录、验证码或解锁时，点击“接管并连接”，由账号所有者完成操作。
2. 释放接管后，桌面连接关闭，业务继续暂停。顶部“启动／暂停”只控制工作流；接管与释放在设置页独立操作，接管期间不能启动业务。
3. 在设置页模型库添加服务商、地址、Key 和模型参数，显式选择使用中的模型。连接测试会发起真实模型请求并计量；刷新模型目录不等于连接测试。正式回复默认上限为 4096 token，支持范围为 64–8192，仍受模型自身上限约束。
4. 检查人设、记忆策略、运行模式、额度与任务。设置按域修订保存，下轮读取；保存配置、切换模型、批准草稿或释放接管都不会自动恢复处理。
5. 当前保持暂停，待修复及对应真实验收完成后，再按已确认的运行安排启动。启动后若账号退出或切换，工作流会停止旧账号操作并要求检查。

模型库支持 Pi 内置服务商、自定义兼容接口及现有 OpenCode／Command Code 路由，使用 API Key 或 API Token，不提供订阅账号登录流程。Key 只显示掩码；同服务商、同主机共用 Key 槽位，改主机须重新填写。详见 [模型库](docs/模型库.md)。

### 人设、试聊与记忆

内置六个人设：通用、大肥鱼、GPT 娘、Claude 娘、Kimi 娘、GLM 娘。预设只用关键词卡，含“不给步骤”和“被夸”卡；角色预设明确为非官方。预设的“填入编辑框”会替换编辑稿，**不会自动保存或生效**，可撤销；明确保存后下一轮生效。保存人设不修改 X 资料、今日日程或运行状态。已有自定义人设不会被预设升级覆盖。

关键词卡对当前作者正文做确定性匹配，不产生语义路由请求；启用语义卡时，每条消息会增加一次模型判定，可能计费。最终回复生成仍需模型。列表、步骤或 Markdown 的 `format` 标记只供复核，不改正文、不增加调用，也不改变自动发送或草稿审批流程。

试聊使用编辑器当前稿和模拟记忆；回放使用选定样本，先预估再确认，可能分别重生成基线、候选并执行语义判定。**两者都会真实调用模型、可能计费，但不向 X 发送，也不写生产记忆。** 回放以历史实际回复为基线时，该侧不调用模型；模型对比不会直接切换使用中的模型。详见 [人设与日程](docs/人设与日程.md)、[人设回放](docs/人设回放.md)。

记忆按工作账号、原始用户／会话标识和渠道隔离；公开上下文不读取私信，未知身份不按昵称或正文合并。默认召回七天内最近三次已处理互动，原文保留三十天；只有 confirmed 回复算已经说过的话。虚构日程、用户事实与角色经历分开。

**遗忘／恢复只由管理员在记忆页及管理接口执行。** 消息里的“忘了我吧”“重新记住我”不改变状态，回复不能声称已完成删除。恢复只允许记录今后的互动，不恢复旧内容。详见 [记忆策略](docs/记忆策略.md)。

## 草稿、发送与未知回执

草稿批准后进入等待发送，由主循环重新校验账号、目标、时效、额度、退避与出站状态；暂停期间不会提交。重写会重新入队，结果仍留在草稿，模型跳过时保留原稿。切换到自动模式不会自动发送旧草稿。

出站在提交前冻结正文和目标并持久保存提交意图。发送超时或缺少可靠唯一回执时进入 **unknown**：**只回查，不能重发**；未收束的 unknown／submitting 会阻止该渠道后续发送。点击按钮、toast 或页面出现正文都不能单独证明发送成功。详见 [出站与回执](docs/出站与回执.md)。

默认每小时公开 10 条、私信 30 条，每轮最多两条；公开回复与问候帖共享北京时间每日 180 条额度。平台明确拒绝后对应通道退避四小时。内部额度不代表平台许可。公开长帖权限未完成真实验收时，仍保守限制为 280 加权字符，超长候选保留且不自动截断。详见 [账号发帖限制](docs/账号发帖限制.md)。

原生 Chat 当前仅保留可可靠观察的字段与诊断；无法证明的时间、方向和回执保持未知，不以采集时间、气泡位置或正文散列代替。通知“全部”栏引用来源仍待样本、未启用。视觉输入尚未接入，图片明确标为不可见，模型不得猜测。详见 [新 Chat 只读适配](docs/新Chat只读适配.md)、[按链接补录](docs/按链接补录.md)。

## 计费与任务

回复、语义判定、试聊、回放、连接测试、日程和记忆整理等实际模型请求都写统一调用流水。页面费用使用 **Pi 调用时目录价格快照估算，并非供应商实际扣款或余额**；第三方地址、未知型号或缺少可靠用量时显示未定价／未知，不能视为免费。思考 token 是输出子集，不重复计费。详见 [模型计量](docs/模型计量.md)。

设置页区分计划保存与“单次执行”。日程／记忆单次执行可能调用模型；早晚安帖仍受模式、时间窗口、额度和回执约束。早晚安任务与自动备份默认关闭，保存计划不启动业务。健康监控独立于业务暂停，当前不含外部推送。详见 [任务与宿主维护](docs/任务与宿主维护.md)、[无人值守健康](docs/无人值守健康.md)、[宿主维护桥接](docs/宿主维护桥接.md)。

## 部署与数据

服务器源码目录为 `/srv/role-workflow`，持久数据位于 `/var/lib/role-workflow`。宿主 Nginx 提供 HTTPS 与管理鉴权；app 使用 TypeScript／Fastify／SQLite／Pi AI，browser 使用 Camoufox／Xvfb／Openbox／noVNC。仅宿主回环 `127.0.0.1:8080` 发布应用端口，浏览器内部 API、VNC、CDP 不暴露公网。浏览器为非 root、只读根目录，profile 由独占文件锁保护，不挂载 Docker socket。详见 [Camoufox 浏览器](docs/Camoufox浏览器.md)、[可选专用出口](docs/X浏览器代理.md)。

| 文件／目录 | 用途 |
| --- | --- |
| 源码目录的 `.env` | 实际部署镜像版本与宿主维护组配置；以服务器文件和运行容器核对为准 |
| `config/config.json` | 基础角色、限速和模型配置；面板已保存的对应设置优先 |
| `app/panel/settings.json` | 模型、人设、任务、记忆、程序设置及修订 |
| `app/panel/model-keys.json`、`secrets/app/` | 面板 Key 槽位与运行密钥，仅管理员可读 |
| `app/workflow.sqlite` | 消息、记忆、出站、任务、迁移、日志与调用流水 |
| `app/forget-ledger.json`、`app/forget-history.json`、`app/forgotten-sources.json`、`app/memory-mutations.json` | 独立遗忘、来源与人工删除账本；恢复旧库时必须保留当前文件 |
| `browser/` | 登录 profile、浏览器提交日志与预检记录 |

真实 `.env`、配置、Key、账号数据、profile 和交付凭据不进入仓库或镜像。数据库备份只含业务 SQLite，不含面板配置、Key、profile 或独立账本；恢复时必须分别准备，不能用旧账本覆盖当前记录。

### 服务器验证、升级与回退

本机只做轻量编辑和检查；构建、自动化测试、批量模型验收及渲染在服务器执行。当前后续提案使用独立开发目录，不能挂载生产 profile：

```sh
sh dev/proposals-sync.sh
sh dev/proposals-test.sh
```

这两个脚本通过 SSH 别名 `dsh` 同步到 `/srv/role-workflow-proposals` 并构建测试；原 `dev/seven-*` 保留给七页历史开发副本。模拟接口、DOM 夹具、真实模型、真实平台读取、发送与双方回执分别留证，不能互相替代。

生产部署文件为 [compose.yaml](compose.yaml)、[Dockerfile](Dockerfile) 和 [升级脚本](deploy/upgrade.sh)。镜像标签由服务器 `.env` 的 `APP_VERSION`／`BROWSER_VERSION` 决定；Compose 与 `.env.example` 中的旧默认值不是当前运行版本。升级脚本在服务器先构建测试，再暂停、排空、停止浏览器并切换成对版本，完成后保持暂停：

```sh
cd /srv/role-workflow
sh deploy/upgrade.sh 新版本号
```

沿用既定要求，升级**不自动创建源码、数据库或 profile 备份**。源码由 Git 管理；不能因为旧镜像存在就自动回滚。当前 schema 13 已触发 [通用回滚脚本](deploy/rollback.sh) 的数据库门禁，须先按 [迁移与恢复](docs/迁移与恢复.md) 验证目标版本、离线前提和兼容转换；资格检查默认只读，不得删除有效数据绕过门禁。独立遗忘／删除账本及浏览器日志必须保留。

日常只读排查在服务器执行：

```sh
cd /srv/role-workflow
docker compose ps
docker compose logs --tail 100 app browser
docker compose exec -T app node dist/cli.js status
docker compose exec -T app node dist/cli.js drafts
```

`drafts` 包含正文，仅在管理员终端查看。CLI `model-check` 会真实调用模型；`retry` 重新排队仍受原约束，不能用于重发 unknown。宿主 systemd 负责容器启动、健康检查和证书续期，安装与排查见宿主维护文档。

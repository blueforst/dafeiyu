## 快速上手：五步开始运营

首次拿到后台地址和登录凭据后，按以下顺序即可完成配置：

### 1. 登录后台并登录 X 账号
1. 打开管理员提供的 HTTPS 后台地址，输入凭据登录。
2. 进入 **设置 → 浏览器接管**，点击 **接管并连接**。
3. 在弹出的远程浏览器桌面中登录你的 X 账号（如有验证码或安全验证，一并完成）。
4. 登录完成后，点击 **释放接管** 关闭远程桌面。

### 2. 配置并启用 AI 模型
1. 进入 **设置 → 模型**，点击添加服务商（支持内置主流服务商或自定义兼容接口）。
2. 填入接口地址与 API Key，拉取或手动添加模型。
3. 点击 **测试连接** 确认模型可用（会发起一次真实小请求），然后将该模型设为 **使用中**。

### 3. 设定角色人设并试聊
1. 进入 **人设 → 人设模式**，从空白、内置预设或已有项的副本新建。预设为只读模板，不覆盖已有内容；库中最多二十项，恰好一个处于“使用中”。
2. 保存修改后点击 **试聊**，新建一个测试用户，在公开或私信渠道连续聊天。试聊使用选中人设的已保存版本，实际模型请求计费；未保存的编辑不会加入本轮。
3. 满意后把该人设 **设为使用中** 并确认，生产从下一轮使用它。切换不恢复业务，也不修改今天已有的虚构日程或 X 资料。

### 4. 选择运行模式与发送限制
1. 进入 **设置 → 运行与发送**，选择 **运行模式**：
   - **草稿模式（推荐初期使用）**：系统采集消息并生成草稿；后台点击“发送”表示批准并加入等待队列，恢复运行后仍须通过身份、目标、时效、额度和出站检查。
   - **自动模式**：生成的回复通过校验后会自动排队发出（切换为自动模式不会把此前的旧草稿自动发出去）。
2. 在同项中调整发送额度与回复时段；切换模式只保存已保存的限制，不顺带提交正在编辑的数字。重点名单与过滤规则在 **设置 → 消息分级与过滤**。
3. 候选默认私信额度为最近 24 小时 **400 条**；回复时段默认开启，按默认任务时间在 **23:30–次日 08:00** 关闭回复。按实际运营安排检查这两个新增保护。

### 5. 启动工作流
完成对应平台收发验收并确认运行安排后，可点击页面右上角的 **启动** 按钮，按轮次执行工作流。当前生产仍保持暂停。

> **提示**：为了防止误操作，保存设置、切换模型、批准草稿或释放浏览器接管**都不会自动恢复运行**。只要顶部显示“已暂停”，就需要手动点击右上角 **启动**。

## 三个页面与设置项

候选顶部导航为 **动态、人设、设置**，左栏与主区铺满页面；按需显示右栏详情，左右栏可收起，窄屏使用抽屉和浮层。

| 页面 | 入口 | 核心用途 |
| --- | --- | --- |
| **动态** | `#/feed` | 按用户身份查看会话，审核草稿、查看详情与只读记忆、处理告警及按链接补录 |
| **人设** | `#/persona` | 管理多个人设、近七日日程和独立测试用户的正常流程试聊，以及按所选人设回放 |
| **设置** | `#/settings/<项>` | 四组十一项配置与排查；记忆和计费在此维护 |

旧 `#/memory?...`、`#/billing`、模型、任务、主程序和浏览器地址保留兼容跳转；记忆查询参数原样保留。没有指定设置项时恢复最近打开的一项，首次默认为“运行与发送”。
---

### 1. 动态（日常审核与互动处理）

默认首页。左栏按当前工作账号下的身份列出会话，主区显示往来，右栏按需显示选中条目的详情和该身份的只读记忆。公开身份与私信身份分开，不按昵称猜测为同一个人；“角色帖”单列早晚安帖和没有发帖的任务结果。

- **筛选动态**：可按“全部 / 待处理 / 公开 / 私信 / 角色帖”切换；待处理总数包含仍待核对的补录请求。需要关注、按链接补录分别有独立入口；往来分批加载，更新保留编辑文字、光标和阅读位置。
- **处理草稿**：
  - **直接编辑与发送**：在草稿文本框内可直接修改内容，点 **发送** 后进入“等待发送”队列，由主循环按额度与时效发出；尚未提交前可随时点 **取消发送**。
  - **重写**：点击后重新入队，恢复处理后才会调用模型，结果仍需人工确认；模型跳过时保留原草稿。
  - **重新入队**：符合条件的过滤、合并、跳过或失败条目可由管理员重新处理一次，仍受状态、时效、额度与出站约束；unknown 或已有冻结出站的条目不能借此重发。
- **按链接补录**：可粘贴遗漏帖链接（如 `https://x.com/用户名/status/帖子ID`）提交核对。恢复运行后每轮最多核对三条，作者、相关性、可靠时间及保护规则通过才入队；暂停或接管期间保留待核对，不保证下一轮完成。
- **查看详情与回执**：选中条目后在右栏查看分级、人设快照、关联调用、字数校验、错误与平台回执；实际可见字段与链接取决于记录。记忆管理链接打开设置中的对应身份。
- **格式提示**：列表、步骤或 Markdown 的 `format` 标记仅供复核，不修改正文、不增加模型请求，也不改变发送或审批流程。

---

### 2. 人设（人设库、日程与效果验证）

左栏切换 **人设、日程、试聊** 三种模式。

- **人设库**：从空白、预设或副本新建，按项保存、重命名、复制、删除和切换使用中项。名称一至四十字且唯一；使用中的项不能删除。保存未使用项不会影响生产，使用中内容下一轮生效。升级首次读取只显示虚拟的“当前人设”，不写设置、不改变原人格。
- **内置预设**：六套原创预设是只读模板，点击“以此新建”产生未使用项。角色预设提供可复制的建议简介；启用后提醒管理员自行处理非官方与 AI 披露，不自动修改 X。
- **触发卡与动态提醒**：关键词只匹配当前作者正文，不新增语义请求；存在启用的语义卡时每条增加一次判定，按实际调用计量。迟到、语言、表情和回复判断提醒由所有人设共用。
- **日程**：左栏近七天，主区显示时间线、三餐、活动、心情、修订、人设来源与费用。今天可编辑或重新生成，过去只读；旧日程的人设来源显示“未记录”。虚构日程不转为用户事实或已确认经历，生成时间在设置的定时任务中维护。
- **正常流程试聊**：一个会话就是一个独立模拟用户；会话内连续消息共享该用户的记忆、近期往来和冷却，新建会话即新用户。公开和私信仍分身份保存，同一测试用户自动关联并按跨渠道规则召回（公开只读私信长期背景）；改显示名或测试 handle 不会改变身份，也不会接上其他用户的旧记忆。最多五十个测试用户，可重置、清除冷却或删除。
- **试聊处理**：使用已保存的人设与正常分级、召回、提示词、生成和字数校验；合格回复视为已发出以进入下轮往来，满五条按正常阈值整理记忆，也可手动整理。可先攒几条：私信只处理最后一条，前文作为上下文；多条独立公开消息保留各自的平台会话 ID，不跨会话合并，逐条处理。
- **试聊隔离与费用**：不访问 X，不受暂停、接管、发送额度、回复时段、排队时效或自动／草稿模式限制。用户消息、记忆和冷却存于独立 `chat-test/`，不进入生产动态、记忆、健康、日报、回放样本或业务备份；只有实际模型调用写生产统一流水，用途为“试聊”。每轮可看诊断、记忆、提示词与费用；同一用户一轮、全局最多两轮并发，取消或失败可重试，已产生费用保留。
- **人设回放**：从某个人设发起，候选、已保存基线、修订检查和采用都绑定该项，不切换使用中人设。先估价再确认，私信样本另勾选；支持中止、标注和质量统计。模型比较不能一键采用切换模型。删除人设后旧记录仍显示原名称并标注已删除。

旧 `POST /api/persona/preview` 保留给批量验收工具，仍接受未保存稿与模拟记忆；面板不再展示这个旧表单。

### 3. 设置（四组十一项）

左栏一项一页，切换项、切换页面或刷新前检查未保存修改。已连接的浏览器桌面在设置项之间切换时保留连接；离开设置页才卸载桌面，释放接管仍回到暂停。

| 分组 | 设置项与地址 | 用途 |
| --- | --- | --- |
| 运行 | 运行与发送 `#/settings/run` | 草稿／自动模式、发送额度、回复时段、账号字数缓存及显式重新读取 |
| 运行 | 模型 `#/settings/model` | 服务商、Key、模型参数、目录发现、连接测试与使用中切换 |
| 运行 | 定时任务 `#/settings/tasks` | 九项计划与单次执行，主循环仅改间隔，启停由顶部控制 |
| 运行 | 消息分级与过滤 `#/settings/triage` | 广告／刷量过滤、重点名单、公开同会话合并、骚扰冷却与队列摘要 |
| 数据 | 记忆 `#/settings/memory` | 用户记忆、角色经历、召回与保留策略 |
| 数据 | 计费 `#/settings/billing` | Token、估算费用、图表与调用流水 |
| 浏览器与采集 | 浏览器接管 `#/settings/browser` | 账号状态和明确连接的远程桌面 |
| 浏览器与采集 | 采集来源 `#/settings/sources` | 各通道启用情况、原因与显式刷新 |
| 排查 | 健康与日报 `#/settings/health` | 指标、账号只读检查、历史告警、日报与阈值／披露配置 |
| 排查 | 日志阶段与队列 `#/settings/logs` | 行式日志筛选与暂停实时、阶段和当前队列 |
| 排查 | 任务执行历史 `#/settings/history` | 执行状态、耗时与关联调用 |

**额度与时段**：公开默认每小时 10 条、北京时间自然日 180 条，早晚安帖与公开回复共享日额度；私信默认每小时 30 条、最近 24 小时 400 条，24 小时上限可设 1–500。窗口内已提交且 confirmed／submitting／unknown 的私信计数，明确 rejected 不计；管理员手动私信不在系统计数中。满额只让对应通道排队，不触发平台拒绝的四小时退避。草稿模式仍可生成，批准后的发送再检查额度。

回复时段默认开启，以晚安计划时间加 30 分钟至次日早安计划时间为关闭区间，延迟可设 0–180 分钟。默认计划对应 23:30–08:00；任务停用、错过或失败不改变计划时段。早安任务启用时先等其结束，最迟计划后 15 分钟开放。关闭期间继续采集，公开与私信不生成、不提交，已批准草稿等待；排队时效、健康停滞与日报延迟扣除关闭时长。unknown 回查、日程、记忆和宿主任务沿用原规则，人工接管不受限制。

**模型与任务**：同服务商、同主机共用 Key 槽位，换主机需重填 Key；目录未知价格不当免费。日程／记忆与连接测试可能计费，早晚安还会尝试发到 X，单次执行与保存计划是两种操作。早晚安与自动备份默认关闭；宿主任务须安装维护桥接。每日健康归档默认 09:00 汇总前一北京日，暂停时也可生成；真实受限样本和长期观察仍按原验收边界补证。账号资料与开关须由管理员处理，程序不自动修改。

**记忆与角色经历**：默认召回七天内最近三次允许的互动，只有 confirmed 回复算已发出；按阈值整理长期条目，原文默认保留三十天。公开只将已关联私信的长期条目作背景，不读私信原文；私信可召回已关联公开身份的公开条目与近期往来。生产公开 `x:<handle>` 与私信 `dm:<会话>` 分身份保存，由管理员显式关联，不按昵称猜测合并。可编辑、删除条目，遗忘并停止记录，或恢复未来新记录；消息里的“忘了我吧”“重新记住我”不会执行这些管理操作。恢复不找回已清除内容。角色经历只使用已确认角色发帖和可用的人工经历，有链接的登记先核对，虚构日程保持分层。

**计费**：按北京时间统计实际模型请求，包含正式回复、语义触发、正常流程试聊、旧预览、回放、连接测试、虚构日程和记忆整理。保留累计 Token、估算费用、峰值、缓存命中和回复均费，以及 52 周热力图、近七／三十日模型趋势、用途／模型占比与可筛选流水。图表支持悬停、触屏和键盘；日期范围仍以近七／三十日为主，更多筛选提供今日、本月和自选。金额是 Pi 内置价格快照的参考估算，不是供应商扣款账单；未定价和用量未知单独显示，不算免费。

## 常见问题与安全机制

### 1. 为什么状态会显示“待回查”？
当系统提交回复后遇到网络超时，或页面未返回唯一明确的成功回执时，该消息会进入 **待回查（unknown）** 状态。
为了严防在 X 上重复刷屏，系统对“待回查”消息**只会定期回查确认，绝不自动重发**，同时会暂停该通道（公开或私信）的后续新消息发送，直到回查确认或由管理员核对处理。

### 2. 哪些后台操作会产生模型调用费用？
除自动运行时的回复生成、语义触发、定时日程/早晚安帖和记忆整理外，你在后台主动点击带有计费提示的操作——包括 **重写草稿、发送试聊、执行人设回放、测试模型连接**——也会发起真实模型请求并计入流水。单纯浏览页面、切换筛选、从预设新建或保存设置不会调用模型。

### 3. 发帖遇到平台限制或账号退出会怎样？
- 若 X 平台明确拒绝某次发送，对应通道（公开或私信）会自动进入 **4 小时退避冷却**，冷却期内不再尝试发送。
- 若检测到 X 账号退出或切换，工作流会暂停并要求人工检查，发送前仍需重新核验当前账号与目标。

### 4. 当前版本有哪些需要注意的功能边界？
- **图片暂不识别**：目前未开启视觉看图能力。对方消息中如果带有图片，系统会明确告知模型“图片不可见”，禁止模型靠猜测编造看图内容。
- **字数保守校验**：在未确认账号具备长帖权限前，公开回复与原创帖默认按 280 加权字符严格校验；若生成的草稿超长，系统会保留原稿供你手动删改，不会自动截断发出。
- **新版原生 X Chat 私信**：空收件箱已有真实只读证据；仍缺入站时间、归属及双方回执样本，自动私信事件为零，不声明自动私信收发已完成。

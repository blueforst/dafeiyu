# 角色互动工作流使用指南

这是一个运行在服务器上的 **X（Twitter）单账号角色运营工具**。你可以通过网页后台集中管理角色的日常互动：采集提及与回复、按规则过滤广告与刷屏、按人设生成待审核回复、管理角色对不同用户的记忆，以及查看模型调用与费用统计。

## 当前版本与验收状态

截至 2026-10-28，正式 app／browser 均为 **0.1.18.6**，来源 [`6e20f56`](https://github.com/blueforst/dafeiyu/commit/6e20f56f0f9594d42182dd00ca91bd4f605b916e)，成对 healthy，schema **13**，正式构建 **553 项通过**。当前保持 **paused／auto**，未恢复业务，也未自动修改 X 资料或设置。公开三个采集入口及原生 Chat 空收件箱已通过真实只读验证；原生 Chat 仍缺实际入站时间、归属及双方回执样本，自动私信事件为零。

本轮真实模型调用共 **248 次**：旧批 82 次已冻结；JSON 修复后主组实际请求 154 次，其中 153 次有效、1 次 GPT 娘解析失败，随后两轮被阻塞；另有通用人设身份／危机边界点验 2 次与文风比较 10 次。**本批已审阅并获用户明确同意通过；八股文风留作后续改进。**解析失败和未执行轮次保留原状态，不算成功；旧批也不拼成新版完整 240 次验收。文风样本未证明新版改善。费用、审定范围与逐项结果见 [最新发布与实机记录](docs/实施记录/2026-10-28-发布与实机修复.md)，Pi 估算不等于供应商账单。

## 快速上手：五步开始运营

首次拿到后台地址和登录凭据后，按以下顺序即可完成配置：

### 1. 登录后台并登录 X 账号
1. 打开管理员提供的 HTTPS 后台地址，输入凭据登录。
2. 进入 **设置 → 排查问题 → 浏览器接管**，点击 **接管并连接**。
3. 在弹出的远程浏览器桌面中登录你的 X 账号（如有验证码或安全验证，一并完成）。
4. 登录完成后，点击 **释放接管** 关闭远程桌面。

### 2. 配置并启用 AI 模型
1. 进入 **设置 → 模型**，点击添加服务商（支持内置主流服务商或自定义兼容接口）。
2. 填入接口地址与 API Key，拉取或手动添加模型。
3. 点击 **测试连接** 确认模型可用（会发起一次真实小请求），然后将该模型设为 **使用中**。

### 3. 设定角色人设并试聊
1. 进入 **人设** 页面。你可以直接从顶部 **角色预设**（通用、大肥鱼、GPT 娘、Claude 娘、Kimi 娘、GLM 娘）中选择一套，点击 **填入编辑框** 作为底稿修改，也可以完全自己编写。
2. 切换到 **试聊** 分区，输入几句模拟评论测试角色的语气和回复长度；发送试聊会真实调用模型并计量。
3. 满意后回到人设编辑区，点击 **保存人设**（下一轮自动生效）。

### 4. 选择运行模式与发送限制
1. 进入 **设置** 页面，在顶部选择 **运行模式**：
   - **草稿模式（推荐初期使用）**：系统采集消息并生成草稿；后台点击“发送”表示批准并加入等待队列，恢复运行后仍须通过身份、目标、时效、额度和出站检查。
   - **自动模式**：生成的回复通过校验后会自动排队发出（切换为自动模式不会把此前的旧草稿自动发出去）。
2. 按需在 **发送限制** 和 **消息分级与过滤** 中调整每小时/每日发帖上限、重点关注用户名单及过滤规则。

### 5. 启动工作流
完成对应平台收发验收并确认运行安排后，可点击页面右上角的 **启动** 按钮，按轮次执行工作流。当前生产仍保持暂停。

> **提示**：为了防止误操作，保存设置、切换模型、批准草稿或释放浏览器接管**都不会自动恢复运行**。只要顶部显示“已暂停”，就需要手动点击右上角 **启动**。

## 五大页面功能详解

后台顶部导航分为 **动态、人设、记忆、设置、计费** 五个页面：

| 页面 | 入口 | 核心用途 |
| --- | --- | --- |
| **动态** | `#/feed` | 查看采集到的互动与角色帖，审核、编辑、批准或重写回复草稿，按链接手动补录遗漏消息 |
| **人设** | `#/persona` | 编写角色设定与触发卡片、选用内置预设、管理今日虚构日程、多轮试聊、回放对比效果 |
| **记忆** | `#/memory` | 按用户查看往来记录与长期印象、手动增删改记忆、执行遗忘/恢复、管理角色自身经历 |
| **设置** | `#/settings` | 切换草稿/自动模式、管理模型库、定时任务、发送限额、过滤规则、浏览器接管与健康检查 |
| **计费** | `#/billing` | 查看 Token 用量与参考费用趋势、缓存命中率、单次回复均费及每次模型调用的流水明细 |

### 1. 动态（日常审核与互动处理）

默认首页，集中展示当前账号的公开回复、私信和定时角色帖（如早晚安帖）。

- **筛选动态**：可按“全部 / 待处理 / 回复 / 私信 / 发帖”快速切换；顶部徽标显示待处理条目数量。
- **处理草稿**：
  - **直接编辑与发送**：在草稿文本框内可直接修改内容，点 **发送** 后进入“等待发送”队列，由主循环按额度与时效发出；尚未提交前可随时点 **取消发送**。
  - **重写**：点击后重新入队，恢复处理后才会调用模型，结果仍需人工确认；模型跳过时保留原草稿。
  - **重新入队**：符合条件的过滤、合并、跳过或失败条目可由管理员重新处理一次，仍受状态、时效、额度与出站约束；unknown 或已有冻结出站的条目不能借此重发。
- **按链接补录**：可粘贴遗漏帖链接（如 `https://x.com/用户名/status/帖子ID`）提交核对。恢复运行后每轮最多核对三条，作者、相关性、可靠时间及保护规则通过才入队；暂停或接管期间保留待核对，不保证下一轮完成。
- **查看详情与回执**：展开“详情”可查看已有的调用耗时、Token、触发规则、字数校验和平台回执；实际可见字段与链接取决于该条记录。
- **格式提示**：列表、步骤或 Markdown 的 `format` 标记仅供复核，不修改正文、不增加模型请求，也不改变发送或审批流程。

---

### 2. 人设（性格塑造、日程与效果验证）

人设页包含三个分区标签，帮助你打磨角色表现：

- **人设设定**：
  - **内置预设**：内置 6 套原创角色预设。点击“填入编辑框”只会替换当前编辑区草稿，**不会自动保存**，也不会覆盖你已保存的自定义人设；点击 **保存人设** 后才会在下一轮生效。
  - **触发规则（卡片）**：支持按条件临时注入额外设定。
    - *关键词匹配*：对当前作者正文做确定性匹配，不增加语义判定请求；最终回复生成仍会调用模型（内置预设含“不给步骤”“被夸”等卡片）。
    - *语义匹配*：存在启用的语义卡时，每条消息增加一次模型判定，按实际调用计量。
- **今日日程**：生成或手写当天的虚构生活安排，作为回复上下文提供给模型；不当作真实经历或用户事实，实际使用效果仍需审阅。
- **试聊与人设回放**：
  - **多轮试聊**：使用当前编辑稿和模拟记忆，真实调用模型、可能计费，**不向 X 发送，也不写入生产记忆**。
  - **人设回放**：选取历史样本比较人设或模型，先估价再确认，实际生成和语义判定均计量；不操作 X 或生产记忆。人设比较可按修订保存候选，模型比较不能直接采用候选切换模型，须去设置页操作。

---

### 3. 记忆（用户印象与角色经历）

系统按当前工作账号、原始用户／会话标识和记忆策略保留允许范围的互动；记忆内容与连贯效果可由管理员检查和修订。

- **召回范围**：公开回复不读取私信；私信可召回同账号、同一确切用户标识下允许的公开与私信内容，不按昵称或正文猜测身份合并。
- **近期往来与长期记忆**：默认召回 7 天内最近 3 次已处理互动，只有 confirmed 的回复算已经发出；满足整理条件时才调用模型整理长期条目。原始消息默认保留 30 天。
- **遗忘与恢复（仅限后台操作）**：
  - 你可以在记忆页随时修改、删除某条记忆，或对某个用户点击 **遗忘**（清空其既有记忆并停止后续记录）。
  - 用户在消息里发送“忘了我吧”“重新记住我”**不会改变系统记忆状态**；遗忘／恢复仅由管理员操作，模型也不得声称已执行删除。
  - 对已遗忘用户点击 **恢复** 后，系统只会从恢复当刻起记录新互动，不会找回已清除的旧内容。
- **角色经历**：管理已确认的角色发帖及人工登记经历；有链接的人工条目需平台核对通过才用于回复，虚构日程与经历分开。

### 4. 设置（运行控制、任务与系统排查）

常用配置与问题诊断都收纳在设置页的折叠卡片中：

- **模型**：管理多个模型服务商、API Key 与模型参数（推理档位、回复最大长度、超时时间）。同服务商、同主机共用 Key 槽位；修改接口主机地址时需重新填写 Key。
- **定时任务**：配置早晚安帖、虚构日程、记忆整理与备份，区分保存计划和 **单次执行**。日程／记忆可能调用模型；早晚安仍受暂停、五分钟窗口、额度和回执约束。早晚安与自动备份默认关闭，宿主任务须有维护桥接。
- **发送限制**：设置普通消息处理时效（默认超时不回）、每轮最大处理条数、公开每小时/每日上限（默认每小时 10 条、每日 180 条，早晚安帖与公开回复共享日额度）、私信每小时上限（默认 30 条），以及查看当前账号的发帖字数上限。
- **消息分级与过滤**：配置广告/刷屏过滤规则、重点关注用户名单（优先处理）、同一公开会话多条评论合并回复，以及高频骚扰自动冷却。
- **记忆策略**：调整近期互动召回条数、时间窗口及原文保留天数。
- **排查问题**：
  - **浏览器接管**：按需连接远程桌面处理账号登录或验证。接管期间无法启动自动工作流；释放接管后系统保持暂停。
  - **健康与日报**：查看账号披露、自动化标签、质量过滤、历史告警和日报；默认计划在每日 09:00 汇总前一北京日，暂停时也可生成。当前账号缺少 AI 披露与自动化标签、质量过滤开启，需管理员处理；程序不自动修改 X 设置。
  - **采集来源 / 运行日志 / 任务历史**：查看当前各采集通道状态、主循环所处阶段、排队情况与近期日志。

### 5. 计费（用量统计与调用流水）

按北京时间统计所有真实模型请求（含正式回复、语义触发判定、试聊、回放、连接测试、虚构日程和记忆整理）。

- **概览指标**：展示累计 Token、累计可估算费用、单日峰值、近 7 日缓存读取命中率及近 7 日每次回复平均花费。
- **可视化图表**：提供全年活动热力图（支持按每日/每周/累计切换）、按模型每日趋势图（Token 或费用）、以及按模型/按用途的用量占比环图与表格。
- **调用流水**：展开底部“调用流水”可按日期范围与用途筛选每一笔请求的输入/输出/缓存/思考 Token 与耗时。
- **关于费用的说明**：页面显示的美元金额是根据内置公开目录价格计算的**参考估算值**，并非服务商后台的实时扣款账单；使用自建中转、第三方兼容地址或未收录价格的新模型时，会标记为“未定价”，方便你区分统计。

## 常见问题与安全机制

### 1. 为什么状态会显示“待回查”？
当系统提交回复后遇到网络超时，或页面未返回唯一明确的成功回执时，该消息会进入 **待回查（unknown）** 状态。
为了严防在 X 上重复刷屏，系统对“待回查”消息**只会定期回查确认，绝不自动重发**，同时会暂停该通道（公开或私信）的后续新消息发送，直到回查确认或由管理员核对处理。

### 2. 哪些后台操作会产生模型调用费用？
除自动运行时的回复生成、语义触发、定时日程/早晚安帖和记忆整理外，你在后台主动点击带有计费提示的操作——包括 **重写草稿、发送试聊、执行人设回放、测试模型连接**——也会发起真实模型请求并计入流水。单纯浏览页面、切换筛选、填入预设或修改设置不会调用模型。

### 3. 发帖遇到平台限制或账号退出会怎样？
- 若 X 平台明确拒绝某次发送，对应通道（公开或私信）会自动进入 **4 小时退避冷却**，冷却期内不再尝试发送。
- 若检测到 X 账号退出或切换，工作流会暂停并要求人工检查，发送前仍需重新核验当前账号与目标。

### 4. 当前版本有哪些需要注意的功能边界？
- **图片暂不识别**：目前未开启视觉看图能力。对方消息中如果带有图片，系统会明确告知模型“图片不可见”，禁止模型靠猜测编造看图内容。
- **字数保守校验**：在未确认账号具备长帖权限前，公开回复与原创帖默认按 280 加权字符严格校验；若生成的草稿超长，系统会保留原稿供你手动删改，不会自动截断发出。
- **新版原生 X Chat 私信**：空收件箱已有真实只读证据；仍缺入站时间、归属及双方回执样本，自动私信事件为零，不声明自动私信收发已完成。

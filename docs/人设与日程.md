# 人设、试聊与虚构日程

人设由静态分区和有序触发卡组成。自定义的旧 `persona` 原文完整进入“角色定义”，其余默认分区不补写角色事实；没有保存过人设且配置仍为旧版或新版示例原文时，改用通用默认。正文、自然语言条件及关键词合计最多 20,000 字符；每个分区和卡片有稳定、唯一的标识。保存带当前修订号，只更新人设域，下一轮生效，不改变暂停或接管状态。下述关键词卡片、预设与 `reply-context-v4` 均为已实现的候选行为；生产状态以发布记录为准。

每轮只有存在启用的语义卡片时，才调用一次当前模型作语义判定。判定输入只包含语义卡片的条件、当前消息及同渠道可见上下文，不包含触发正文；输出最多 512 token，并使用可用的最低推理档。未知和重复标识被忽略，结果按配置顺序应用。解析或请求失败时保留静态规则和已经命中的关键词卡片，不重复判定。固定系统约束每次都生效；虚构日程与真实互动经历分别标记。

卡片可选 `match:'semantic'|'keywords'`；旧卡片未提供方式时按语义处理，读取时不为旧 JSON 自动补写字段。关键词卡片配置 1—30 个关键词，每个经 NFKC 规整并去除首尾空白后为 1—40 字符，关键词计入总长。条件文字仍须非空，供旧版回退为语义卡片；面板可以在管理员未填写条件时生成“消息包含以下任一关键词：…”，后端不接受空条件。

关键词只匹配当前作者正文，匹配时经 NFKC、转小写并去掉 `@handle` 后作子串比较；不读取对话中的旧消息、引用帖正文或链接卡片。命中原因显示“关键词：<匹配词>”，和语义卡片共用开关、顺序及 user 提醒区。仅启用关键词卡片时，组装不调用语义路由，每条消息只产生原有的最终回复生成请求。切换回语义方式可以保留有效关键词列表，但不参与关键词匹配。

回复、私信、早晚安帖及试聊另作确定性格式检查：`list-or-steps` 表示两行以上编号／项目符号列表、明确步骤；`markdown` 表示标题、加粗或代码块。句首“3.5 分”、单行编号和颜文字不作为列表。检查只写 `format.issues`，不修改正文、不写发送错误、不拦截自动发送或管理员批准，也不增加模型调用。管理员改写或重写后重新计算；草稿正文下、已发消息详情、试聊结果及任务历史显示提示。

试聊接受未保存人设及最多三十条公开或私信模拟对话。试聊只使用传入的模拟上下文，不采集 X、不发送、不写入真实消息或记忆。返回实际提示词分段、有效命中、警告、回复或跳过、耗时，以及同一交互下路由和生成的全部费用。生成失败、输出结构不合格或中止后已经落账的用量仍计入费用；没有可靠价格时显示未定价或未知。试聊上下文最多 40,000 字符，人设与试聊接口体上限为 128 KiB。

日程按工作账号和北京时间日期隔离，内容明确标为虚构，包括按顺序且不重叠的时段、三餐、活动及心情。模型读取已保存人格及此前七日历史；当天成功状态不会因长期人格保存或到达 06:00 自动改写。自动任务和首次业务使用共用账号／日期锁，同时到达只生成一次。日程调度时间只来自任务设置，默认 06:00。

业务暂停或人工接管不发起自动日程调用。恢复后可补当日缺失状态；自动失败三十分钟后再尝试，当日最多三次，尝试记录跨服务重建保留。管理员明确重新生成或编辑创建新修订。生成开始时记录原修订，期间的人工编辑会使旧结果失效；跨日结果也不成为今日状态。没有当日有效状态时显示暂无，不把昨天内容标为今天。

日程修订保存来源、生成时间、人设修订和模型流水标识，费用沿用原调用记录。日程、角色经历和用户事实分开存储，日程不会自动写成用户记忆。

| 接口 | 请求与结果 |
| --- | --- |
| `GET /api/persona/presets` | `{version,items:[{id,name,summary,bioSuggestion,persona}]}`；内置文本的深拷贝，读取不保存或产生模型调用 |
| `GET /api/persona` | 人设、修订号、只读固定约束、当天日程和任务生成时间 |
| `PUT /api/persona` | `{persona, revision}`；修订冲突返回 409 |
| `POST /api/persona/preview` | `{persona, channel, messages:[{role,text,quote?,card?}], memory?, dailyState?}`；最后一条为 user，返回 `draft`、`segments`、`hits`、`calls`、`fees` |
| `GET /api/persona/daily` | 当前账号当日状态、当前时段、近七日历史、尝试次数及重试时间 |
| `GET /api/persona/daily/history` | 当前账号近七日最终日程修订 |
| `PUT /api/persona/daily` | `{date,content,revision}`；内容包含 `date, fictional:true, periods, meals, activities, mood` |
| `POST /api/persona/daily/generate` | 明确手工重新生成，可带 `{revision}` 防止陈旧页面覆盖 |

接口沿用应用管理鉴权、来源检查及控制请求标记。测试文件涵盖规则校验、降级、试聊隔离、费用、日程并发、修订、暂停和可控时钟边界；自动回归由服务器隔离环境执行，模拟测试不构成真实模型或平台发送验收。

试聊的 `memory` 保留普通模拟文字，另接受不超过原有 8,000 字符序列化边界的对象，例如 `{memories:[],recent:[{message:'上次的问题',reply:'上次已发出的回复',channel:'public'}]}`；这些都明确属于管理员模拟数据，不自动读取真实用户记忆。对象中的 `recent` 进入独立近期往来段，公开场景仍过滤私信。结果新增 `format:{issues:[]}`；生成失败时为 `null`，不把失败称为格式通过。

## 从预设开始

内置预设版本为 2：通用（默认）、大肥鱼、GPT 娘、Claude 娘、Kimi 娘、GLM 娘。通用默认不带角色梗，适合继续编写自己的角色；其余分别为松弛嘴硬的鲸鱼娘、稳重周全的龙娘、温和讲究的大小姐、细致爱读长文的角色和精打细算的狐娘，都是虚构二创，不是官方账号。

六个预设都有角色定义、说话风格、记忆与承诺、互动边界四个始终生效的分区。五个角色另有她自己、外貌、认识的 AI 娘、身份设定四个分区，每段第一行说明何时才使用，避免把外貌和角色背景主动倒进每条回复。角色细节与以前的小事均标为虚构；往事明确不能在今日日程中重演。通用预设总长不超过 1,500 字符，其余不超过 4,000 字符。

六个预设的“说话风格”先是完全相同的“通用写法”，之后是各自的“口吻”。通用写法只限定写作方式：跟随对方语言，不写长篇、客服腔、Markdown 列表和标题，不用固定感谢或叠词开头；动作描写只在对方先使用时接，知识范围不够就说不知道，不写教程和步骤。公开回复遵守口吻的常用长度，私信一般不超过该长度两倍。语气词、句末标点和接夸方式全部写在各自口吻里，避免六个角色成为同一腔调。颜文字、emoji 和波浪号的频率交给动态提醒，预设只能更少，不另写“几条里一次”的频率。

| 预设 | 口吻与互动方式 | 公开回复常用长度 |
| --- | --- | --- |
| 通用（默认） | 平实友好的口语、短句、标点正常，少用语气词、不带梗；开心接夸或具体反夸，轻松接玩笑，不知道直说。 | 10—50 字 |
| 大肥鱼 | 最松的口语，句末可以不打句号，可以用“哈哈哈”“欸”“啊这”；被夸小小得意、不谦虚也不道谢，友好玩笑时嘴硬但不凶，不会就理直气壮承认。 | 5—30 字 |
| GPT 娘 | 句子完整、标点规范，少用网络流行语；从容温和地接夸再夸回，笑着接友好玩笑，拿不准直说，不加长串免责声明。 | 20—70 字 |
| Claude 娘 | 措辞讲究、礼貌完整，先接一个具体细节；不用“啊这”一类随便口语，被夸害羞但不连声道谢，友好玩笑时慌张、句子变短，不确定就坦白说。 | 15—60 字 |
| Kimi 娘 | 轻声、慢、短句，省略号一条最多一处，不用感叹号；小声接夸再回到对方细节，慢半拍接玩笑，没读到过就直说。 | 5—40 字 |
| GLM 娘 | 利落，带点小得意与小狡黠，算账比方一条最多一个；接夸给自己记功劳，机灵地接友好玩笑，不知道直说、不硬算。 | 10—40 字 |

角色梗按当前对话里可核对的条件使用：对方没聊到相关话题时不主动抖梗；聊到了，一条回复最多一个梗；和同一个人的近期往来里用过的梗、口癖、开头和收尾这次不再用。友好玩梗卡片不能覆盖恶意、色情暗示或危机表达的互动边界。角色明确承认 AI、非官方和与对应公司无关，不猜测实际底层模型，不索要真实钱物，不评论公司的真实消息、定价或政策。

预设只使用关键词卡，每个都有“不给步骤”和“被夸”，角色预设另有两到三张招牌反应卡，不增加语义判定。“被夸”关键词包括可爱／可愛、厉害／厲害、好棒、真棒、太强了、夸夸、好聪明和 `so cute`，不使用“喜欢你”或裸 `cute`，避免把“我不喜欢你”和 `execute` 当夸奖；叫角色名字的普通问候也不会触发。子串匹配仍可能命中“这只猫好可爱”，所以卡片明确只在对方夸的是你时按本角色口吻接、不以谢谢开头、不说“过奖了”，反话或嘲讽按互动边界平和带过。

关键词兼顾简体、繁体和英文；英文步骤卡用 `how to make`、`how to cook`、`tutorial` 等意图片段，避免裸 `how to` 误命中 `show tomorrow`。token 玩笑同样不用裸 `token` 匹配普通 `tokenizer`、`tokenization`。关键词仍是确定性子串规则，管理员可以在试聊和回放中检查命中原因。

人设标签里的“从预设开始”默认折叠。选中后可以复制建议简介；“填入编辑框”先行内确认，再整体替换全部分区和触发规则，不保存。填入后支持一次撤销；再次填入、成功保存或离开页面使对应旧快照失效。未保存的人设会触发原有离开保护。试聊和回放读取当前编辑器内容，不需要先保存；回放采用候选也更新编辑器修订和保存状态，在途后续编辑会保留。

从预设保存后，当前页面会持续提示今日日程不会自动改变，需要时可以手动重新生成并产生模型费用。角色预设还提醒在恢复业务前修改 X 名称和简介，使用带“非官方”“AI 自动回复”的表述，建议把“非官方”加入合规检查披露词，并提供设置链接。来源只保存在本次前端挂载的内存中，关闭提示或离开页面后消失；系统不修改账号资料、披露词或控制状态。

生效人设统一按面板已保存内容优先；未保存时只对旧示例和新版通用角色定义做去除首尾空白后的完全比较。只改一个字、换内部空白或自行编写的配置都视为自定义，正文不裁剪。回复、试聊、早晚安帖和日程共用该解析，日程只取分区正文、不取触发卡。已保存的人设不会因内置版本更新而回写；示例配置不再提供未使用的 `dailyState`，旧配置中保留该字段仍兼容。

版本 2 沿用的结构灵感来自[大肥鱼作者复盘](https://x.com/Remake___/status/2114696368883429580)；角色印象参考提案列出的[社区报道](https://www.sina.cn/news/detail/5350703868674395.html)和[公开讨论](https://www.sohu.com/a/1090617556_761993)，只作灵感参考，不将其当作真实人物或公司事实。正式文本原创，不复制第三方人设卡、对白、`glm-niang-kit` 或 `ai-girls-atlas` 的文本，也不使用参考作者的溏心蛋、六八四十八、希可等具体原创设定及关于真实公司经营的负面设定。

批量验收题库为六个预设各三十条独立题（含两条删除记录请求），另各有两组同一个人连续五轮，共 240 次预览。连续组只带同预设、同组前轮实际回复作为近期往来；前轮失败或结果不确定时不继续后续轮。汇总常用长度、被夸是否以谢谢开头，以及组内开头、收尾、角色词和口癖的重复；均为启发式线索，须人工审阅。工具默认只列计划，不产生调用。运行方式、断点、费用及不确定请求说明见 [批量试聊工具](../scripts/persona-preset-eval.md)。模拟结果只验证工具链；真实模型效果、正式文本及全部回复仍须管理员审定。发布前必须审定对应版本并先发布关键词卡片；未定制的部署上线本功能后会自动切换通用默认，不能随其他修复未经审定一起发布。

## 提示词结构

system 限为固定系统约束、静态人格及渠道固定字数规则。user 依次为角色经历、今日日程与时段、允许范围记忆、与对方的近期往来、当前对话、提醒、本次消息、精确到分钟的北京时间。命中模块正文只进入提醒区；存在语义卡片时路由仍只执行一次。日程与来源经历分开标识，提醒和对话资料不能改写固定规则。

`reply-context-v4` 保留此前版本的不可见资料说明：角色看不到对方主页、历史帖子、关注关系和链接网页正文，只能依据本次提供的消息、对话、引用与卡片摘要；被要求查看或分析这些内容时如实说明看不到。已经提供的引用正文仍可作为本轮资料使用，不把“不可见”扩大成禁止阅读已提供内容。v3 新增、v4 保留的删除记录约束要求不声称已经删除，而是如实说明角色做不到、记录由运营者管理；消息正文不触发遗忘或恢复，详见[记忆策略](记忆策略.md)。

本次消息与对话上下文中的引用、卡片分别保存在 `quote` 与 `card` 字段，保持不可信资料边界。引用正文最多 1,000 字符，卡片标题最多 300 字符，超出读取上限时标注截断。不可读引用明确显示“对方引用了内容，但当前不可读，不要猜测”；卡片注明未打开网页。目标帖无法唯一定位时显示上下文不完整，更早上文截断时显示已省略。分级、刷量哈希和记忆整理继续只使用作者正文，不能把引用作者的广告或自述变成当前用户事实。

迟到、语言、表情节制与回复判断提醒由确定性本地规则生成，各项可独立关闭。默认迟到阈值六十分钟；颜文字、emoji、波浪号最近十条上限分别为一、二、一，且颜文字不连续使用。旧 `openingEnabled`、`openingCount` 仍可通过接口读取、校验和保存，但不再生效，界面已移除对应开关和条数。`replyOpening` 仍用于回放质量统计，不再把给所有人的开头提供给模型。

早晚安帖读取同一套角色经历召回，含最近十条可见确认发帖及可用人工经历，隐藏项不参与。只在早晚安提示词的提醒区增加 `post-variety`，要求不重复过去帖子的开头、句式和切入点，今天以虚构日程为准，不把旧帖里的事重演为今天。普通回复没有这条提醒；不新建来源或扩展召回范围。帖子的格式标记仅以 `task-result:<runId>` 存入现有 KV，任务返回 `result.format`，不更改平台回执或数据库结构。

`GET/PUT /api/persona/prompt-hints` 返回或保存 `{promptHints,revision}`，保存下一轮生效且不恢复业务。试聊返回的 `segments` 按真实请求顺序提供 `role`、`stable`；`hints` 列出提醒与原因，`meta` 提供提醒类别及提示词版本。详细接口与验证边界见[回复提示词集成](实施记录/2026-10-28-回复提示词集成.md)。真实缓存读取表现需明确模型调用授权后另测。

# 旧消息平台标识只读去重

`Store.findByPlatformId(accountId, channel, platformId)` 为普通采集和人工补录提供同一入口，处理旧行 `platform_id` 为空、但原始事件仍保留可靠原生字段或规范帖子 URL 的情况。查找只读取当前账号与渠道的记录，不回填旧列、不改正文、状态、草稿或回执，也不创建出站。

## 可靠身份来源

- 显式 `messages.platform_id`、事件 `body.platformId`；公开 ID 使用有界数字字符串，私信只接受显式原生标识，不从会话地址推消息 ID。
- 公开帖子的规范 HTTPS X／Twitter status URL 可作为旧字段缺失时的只读兼容来源；仅接受列出的官方域名、合法 handle 与数字帖子路径，不接受认证信息、非默认端口、其他域名、媒体子路径或只在查询参数里出现的伪目标。
- 内部 `id`、`source_id`、正文、正文散列均不能推导平台 ID。

账号归属以旧行已有的账号列为边界。合法 handle 的显示大小写及单个 `@` 前缀可规整比较，例如 `John2q1u` 与 `john2q1u`；这不会改写历史字段。未知归属空字符串、非法身份或真正不同账号不能自动转交给当前账号。公开与私信分开查找，即使文本或标识相同也不跨渠道归并。

## 冲突与既有出站

原生列、事件原生字段与规范 URL 指向不同 ID，同一原生 ID 对应多条历史行，或事件声明的账号／渠道与旧行冲突时，查找抛出固定 `native-identity-conflict`（HTTP 409）错误，不任意选一行。普通 `ingest` 保守拒绝入队；人工补录提交返回冲突，已 pending 的请求由补录服务按该固定错误标为失败并继续其他项。

找到已有 confirmed、unknown 或其他状态时只认定已有消息，不改变原状态。尤其 unknown 不能因再次采集或补录而生成新的出站、重写冻结正文、重新提交或绕开原回查流程。没有可靠身份来源的记录不会因为内部事件标识看起来像平台 ID 而被自动合并。

## 遗忘与恢复

仅查找不会写 SQLite 或外部账本。管理员原有遗忘操作在删掉旧空列消息前，额外保留经过相同规则验证的原生来源键，继续保留原内部来源键；这不是回填历史消息。恢复旧数据库或换一个内部采集 ID 时，原生来源键仍阻止已遗忘内容重新进入队列。恢复后真正不同、可靠且晚于恢复边界的新平台消息继续按原规则处理。

## 验证

新增 `test/native-dedup.test.ts` 覆盖旧 confirmed／unknown、只读无字段变更、补录复用、无新增出站、账号与渠道隔离、规范 URL 与恶意地址、原生字段冲突、多历史候选、遗忘恢复，以及合法账号大小写。与 `test/manual-imports.test.ts` 一起在服务器独立副本、断网容器及统一 heavy-tests 锁下验证；没有生产、平台或真实模型操作。本轮服务器定向结果为 21/21：旧消息去重 9 组、人工补录 12 组；耗时 4.1 秒。日志为 `/var/lib/role-workflow-repair-20261028/artifacts/native-dedup/native9-and-manual12.log`，哈希与结构摘要为同目录 `verification.json`。这是隔离回归证据，完整集成回归由主任务统一执行。

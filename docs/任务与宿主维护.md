# 统一任务与宿主维护

任务页使用北京时间。主循环继续由唯一工作流运行器在一轮结束后等待，默认六十秒，可配置三十至三千六百秒；任务调度器自身不创建轮询计时器。日程默认每日 06:00、记忆补整理默认 03:00 启用，早安 08:00、晚安 23:00、数据库备份 02:30 初始关闭。宿主健康检查周期固定五分钟。

每个业务任务以任务 ID、工作账号和计划时刻建立唯一持久实例，手动执行与自动执行共用该实例。相同日期重复点击不会重新生成或重新发送；unknown 只调用回查，不创建新的正文。问候帖只能在计划后五分钟内开始，恢复时过期计划标记 missed。发帖还必须处于 running 与 auto，后续发送经过统一 outbox、公开额度和通道退避。明确手动发起日程或记忆整理可在暂停时执行模型调用，不产生 X 发送。

失败或重启中断的日程实例允许在三十分钟后复用原实例重试，当天最多三次自动尝试；实际生成还受日程服务自身的同账号／日期预算保护。每次真实模型请求仍有独立计费 ID，不用重试覆盖前一次用量。

调度配置保存使用 tasks 域修订，不覆盖模型或人格设置，不因保存日程、记忆或宿主计划恢复生产。关闭业务任务会取消尚未提交的活跃实例；提交后的 unknown 仍只能回查。进程重启把未完成的模型任务标记 interrupted，已关联 outbox 的旧执行转为 unknown。任务历史中的费用引用原模型调用 ID，不写第二份账。

主循环启停与全局运行控制是同一状态。`PUT /api/tasks/main` 的 enabled 显式执行恢复或暂停；其他任务配置不会改变全局控制。主循环不提供另起一轮的按钮。

任务历史中的 main 由唯一工作流在实际轮次开始／结束时调用 `recordMainStart(runId, accountId, startedAt)`、`recordMainEnd(runId, status, callIds)` 写入，保存真实耗时、结束状态及原模型调用引用；调度器不因此执行主循环或创建额外 timer。main 的下次执行直接读取工作流实际 nextTick，不在每次查询时用当前时间推算而漂移；暂停及尚未安排下一轮时为空。进程重启会将遗留 running 轮次标记 interrupted。

## 管理接口

- `GET /api/tasks`：返回 timezone、tasks、tasks 域 revision、全局 control、宿主桥接可用状态及备份范围。每条计划包含标题、开关、时间或周期、上次执行和下次计划时间。
- `PUT /api/tasks/:id`：接收 revision 及 enabled、time 或主循环 intervalSeconds；旧修订返回 409。
- `POST /api/tasks/:id/run`：显式执行一次，返回唯一 run；主循环拒绝此入口。关闭计划仍允许管理员明确单次运行，问候帖继续遵守自动模式、五分钟窗口、额度与回执。
- `GET /api/tasks/runs?taskId=&cursor=&limit=`：有限分页历史，limit 为一至一百。run 包含关联 callIds、只读费用聚合、出站标识与回执。
- `GET /api/tasks/runs/:id`：单次详情，沿用管理鉴权。

Task ID 为 main、daily-state、memory-summary、morning-post、evening-post、backup、health。日程内容在人设页管理，计划只从任务设置读取，不维护第二份时间。

## 宿主边界

宿主 bridge 采用两个分开的目录挂载：app 可写请求 `/maintenance/requests`，只读结果 `/maintenance/results`。任务白名单为 backup、health，操作为 run、configure；请求中没有命令、路径或服务名。宿主独立 systemd helper 每分钟接收请求；生产健康检查的唯一五分钟源继续为 `role-monitor.timer`，其 service 在生产安装时改为 helper 的固定 `--health-source` 入口。手工检查与 timer 共用规范实例锁。health 开关仅调用固定 adapter 启停这一 timer，维护 helper 不再创建第二个生产健康调度。隔离根目录强制使用 simulation adapter，任务接口通过 effectiveHostPlan/hostSource 明示实际来源。安装方式见[宿主维护桥接](宿主维护桥接.md)。未安装时接口明确显示不可用，不把写入请求当成执行完成。

备份仅含业务 SQLite 数据库，并执行完整性检查，保留最近七份；不含面板设置、Key、源码、浏览器 profile。恢复数据库前必须保留独立遗忘账本，启动时重放；备份不能覆盖该账本。备份只补当天一次，不回放全部停机日期。证书续期继续沿用独立宿主任务。

## 验证边界

`test/scheduler.test.ts` 覆盖可控时钟、暂停、手动与自动互斥、关闭取消、问候窗口、unknown 回查、账号隔离、重启收束、分页和费用引用；`test/scheduler-host-helper.test.ts` 覆盖宿主白名单、独立健康结果、备份完整性与七份保留。所有构建、自动化测试和页面验收只在独立服务器环境执行。模拟测试通过不代表真实模型、平台发帖或宿主生产安装已验收。

## 无人值守健康扩展

新增 `daily-report`（09:00）和 `account-check`（10:00）两项默认启用计划。日报只汇总持久数据，不调用模型或浏览器，暂停期间也会生成前一日日报；合规检查要求运行且空闲，暂停时可由管理员明确手动发起，人工接管期间推迟。健康配置、轮次预算、看门狗、告警、RSS 回退与恢复边界见[无人值守健康](无人值守健康.md)。宿主固定白名单仍只有 backup／health，新增观察任务不扩展宿主执行权限。

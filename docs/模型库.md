# 多服务商模型库

模型库同时保存多个服务商、地址和模型参数，`active.default` 决定下一轮使用的模型。切换不恢复暂停的工作流，不增加按用途分配模型的行为。正式模型调用、OpenCode 稳定会话、4096 token 默认回复上限及 Command Code 未定价口径保持原有实现。

首次读取已有面板模型时，把原参数登记到模型库并关联原 Key 槽位。原 `model` 段与 Key 文件保持不变；后续切换或修改使用中模型时，用一次原子设置写入同时更新库和 `model`。旧版本仍可读取 `model`，忽略新模型库。若旧版本或旧入口单独改了 `model`，再次读取时按实际运行模型修复库的使用中指向。

`GET /api/model` 的 `library` 包含 `version`、`providers`、`active`、`revision`。服务商返回 `keyHint`、`hasKey`、`ready`、`active`，不返回 Key 原文。就绪表示已保存 Key 且至少一个模型最近测试通过。模型行附 `info`、`params`、`lastTest`、`missing` 和 `active`；目录信息在读取时联查。未知模型必须明确填写上下文长度和是否支持推理，才能测试或启用。

修改接口均沿用管理鉴权和控制请求标记，并传模型库自己的 `revision`。修订冲突返回 409；网络等待后会再次检查修订，旧连接的测试结果不能覆盖更新后的连接。调用费用始终独立写入统一流水，即使最终设置保存冲突也不丢失。

| 接口 | 请求与结果 |
| --- | --- |
| `POST /api/model/library` | `provider,name?,baseUrl?,api?,apiKey,revision`；添加并自动拉取，返回完整库 |
| `PUT /api/model/library/:key` | `name?,baseUrl?,api?,apiKey?,revision`；改主机必须重新填写 Key |
| `DELETE /api/model/library/:key` | `revision`；使用中服务商拒绝删除 |
| `POST /api/model/library/:key/refresh` | `revision`；拉取失败也保存明确错误，目录服务商回退目录 |
| `PUT /api/model/library/:key/models/:id` | `params,custom?,revision`；可手动添加，参数仅接受推理档位、回复上限、超时 |
| `POST /api/model/library/:key/models/:id/test` | `revision`；一次小请求，返回 `result,library`，并统一计量 |
| `PUT /api/model/active` | `key,modelId,revision,confirmUntested?`；未通过测试时先返回 409 和 `requiresConfirmation` |

刷新会替换发现条目；已编辑、测试、手动添加或使用中的模型若接口未返回，仍保留并标记。没有自动切换、自动模型测试或额外生成重试。目录发现失败不会阻止管理员手动添加模型。

Key 仍以 `provider@hostname` 分槽；同一主机上的两个自定义接口共用 Key，是当前兼容边界。改地址路径、协议或 Key 会清除该服务商的旧测试状态。改主机不把旧 Key 传到新主机，必须明确重新填写。删除库条目不删除可能被其他接口共用的 Key 槽位。

服务器验收使用注入的模型发现与调用函数，不访问真实服务商、不发送 X 内容。真实连接测试必须由管理员明确触发，并显示计费提醒。

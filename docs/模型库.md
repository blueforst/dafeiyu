# 多服务商模型库

模型库同时保存多个服务商、地址和模型参数，`active.default` 决定下一轮使用的模型。切换不恢复暂停的工作流，不增加按用途分配模型的行为。正式回复取 Pi 目录中的最大输出，未知模型取 8192 token；按输入估算和上下文余量收小。每次请求固定 180 秒保护时限，调用方可提前中止。OpenCode 稳定会话及 Command Code 未定价口径保持。

首次读取已有面板模型时，把原参数登记到模型库并关联原 Key 槽位。原 `model` 段与 Key 文件保持不变；后续切换或修改使用中模型时，用一次原子设置写入同时更新库和 `model`。旧版本仍可读取 `model`，忽略新模型库。若旧版本或旧入口单独改了 `model`，再次读取时按实际运行模型修复库的使用中指向。

`GET /api/model` 的 `library` 包含 `version`、`providers`、`active`、`revision`。服务商返回 `keyHint`、`hasKey`、`ready`、`active` 和星标有序数组 `starred`，不返回 Key 原文。就绪表示已保存 Key 且至少一个模型最近测试通过。模型行附 `info`、`params`、`api`、`lastTest`、`lastUsedAt`、`missing` 和 `active`；`lastUsedAt` 取近 30 天统一调用流水（含连接测试）的最新时间戳；目录信息在读取时联查，`info.cost` 包含 `input`、`output`、`cacheRead`、`cacheWrite` 四项单价。未知模型必须明确填写上下文长度和是否支持推理，才能测试或启用。

接口协议属于单个模型（`LibraryModel.api`）：内置服务商沿用 Pi 目录自带协议，自定义服务商的模型各自保存协议。首次读取旧模型库时，把自定义服务商原有的 `provider.api` 补到其下未指定协议的模型，同时保留原 `provider.api` 字段供回退兼容。自定义服务商添加或刷新拉取列表时，未指定协议会依次尝试 OpenAI 兼容与 Anthropic 兼容的 `/v1/models`，按首个成功的协议写入新发现模型的默认 `api`；都失败时合并返回两条原因。

修改接口均沿用管理鉴权和控制请求标记，并传模型库自己的 `revision`。修订冲突返回 409；网络等待后会再次检查修订，旧连接的测试结果不能覆盖更新后的连接。调用费用始终独立写入统一流水，即使最终设置保存冲突也不丢失。

| 接口 | 请求与结果 |
| --- | --- |
| `POST /api/model/library` | `provider,name?,baseUrl?,apiKey,revision`（传入 `api` 时忽略）；添加并自动拉取，返回完整库 |
| `PUT /api/model/library/:key` | `name?,baseUrl?,apiKey?,revision`（传入 `api` 时忽略）；改主机必须重新填写 Key |
| `DELETE /api/model/library/:key` | `revision`；使用中服务商拒绝删除 |
| `POST /api/model/library/:key/refresh` | `revision`；拉取失败也保存明确错误，目录服务商回退目录 |
| `PUT /api/model/library/:key/stars` | `starred:string[],revision`；按传入顺序去重保存该服务商内已知模型的星标列表 |
| `PUT /api/model/library/:key/models/:id` | `params,custom?,api?,revision`；可手动添加，参数只保留推理档位，自定义服务商可指定模型协议（改协议会清除该模型 `lastTest`） |
| `DELETE /api/model/library/:key/models/:id` | `revision`；删除未在使用中的手动添加模型，并从 `starred` 移除 |
| `POST /api/model/library/:key/models/:id/test` | `revision`；一次小请求，返回 `result,library`，并统一计量 |
| `PUT /api/model/active` | `key,modelId,revision,confirmUntested?`；未通过测试时先返回 409 和 `requiresConfirmation` |

刷新会替换发现条目；已编辑、测试、星标、手动添加或使用中的模型若接口未返回，仍保留并标记 `missing`。没有自动切换、自动模型测试或额外生成重试。目录发现失败不会阻止管理员手动添加模型。

Key 仍以 `provider@hostname` 分槽；同一主机上的两个自定义接口共用 Key，是当前兼容边界。改地址路径或 Key 会清除该服务商的旧测试状态；改单个自定义模型的协议只清除该模型的测试状态。改主机不把旧 Key 传到新主机，必须明确重新填写。删除库条目不删除可能被其他接口共用的 Key 槽位。

服务器验收使用注入的模型发现与调用函数，不访问真实服务商、不发送 X 内容。真实连接测试必须由管理员明确触发，并显示计费提醒。

连接测试使用一次带 `connection_check` 工具的小请求，关闭推理时上限 256 token，开启时 2048；返回有效工具调用才通过，纯文字和截断均失败，模型原始错误脱敏显示。不回传工具结果，不自动重试。CLI `model-check` 使用同一判定。

旧 `maxTokens`、`timeoutMs` 字段在设置与配置文件中允许存在，但读取时忽略，GET 不返回，模型再次保存时移除。回复字数仍按账号策略校验；较大的输出额度不是费用上限，费用仍按实际用量。回退需先恢复本轮自动保存的原设置备份（含旧模型字段），再切回成对旧镜像并保持暂停。

所有最终草稿统一由原生 submit_draft 工具生成，工具请求不附加原生 JSON mode，无特定服务商分支；日程和记忆整理继续原 JSON 输出。原结构、正文与发送校验仍保留，生成失败不自动重发。

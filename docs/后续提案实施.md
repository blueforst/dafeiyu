# 后续提案使用说明（0.1.19）

当前正式 app／browser 的最近发布记录为 **0.1.19**，schema **13**，业务保持 **paused／auto**。既有六项后续提案、参考帖子补齐及后续修复的发布事实见[发布与实机记录](实施记录/2026-10-28-发布与实机修复.md)；这里不重新确认实时生产状态。

**以下为本轮五项已发布功能的使用说明**：私信 24 小时额度、回复时段、人设工作区、设置工作区和动态工作区。实现、隔离测试、真实模型、生产发布与平台收发分别验收，提交或推送源码不改变生产状态。尚未取得的真实验收不能由 mock 或界面截图代替。

## 三页面板与草稿

一级页面为动态、人设、设置。设置采用四组十一项：运行与发送、模型、定时任务、消息分级与过滤、记忆、计费、浏览器接管、采集来源、健康与日报、日志阶段与队列、任务执行历史。记忆和计费并入设置，旧地址自动兼容跳转；记忆身份查询参数保留。页面共用工作区设计，左栏和主区固定存在，右栏按需显示，支持收起及窄屏抽屉／浮层，见[设计规范](设计规范.md)。

动态按当前工作账号的用户身份组织会话，公开与私信身份分开；角色帖会话另含没有产生出站的早晚安任务结果。左栏筛选会话，主区查看往来和审核草稿，右栏显示条目详情及只读记忆；“需要关注”与“按链接补录”分别显示。待处理总数包含待核对补录。分页和增量刷新保留编辑文字、光标及阅读位置。

修改草稿后批准只进入等待发送。恢复处理后由同一主循环检查身份、可靠目标、有效时效、小时／日额度、回复时段、退避、待回查及持久出站；草稿模式也只发送明确批准的条目。未开始提交时可取消。重写重新入队，结果仍留草稿，模型跳过保留原稿。符合条件的过滤、冷却、合并、跳过或失败条目保留管理员一次重新入队入口，unknown 与已有冻结提交不能借此重发。保存、批准、重写及释放接管都不隐式恢复业务。

## 人设库、日程与正常流程试聊

人设模式左栏列“我的人设”、六个只读预设与共用动态提醒。库内最多二十项，名称一至四十字且唯一，恰好一个使用中；支持空白、预设新建和复制。只有使用中内容影响下一轮生产，未使用项的编辑、回放不影响生产。升级首次读取将原生效人设显示为虚拟“当前人设”，不写设置；首次修改才原子保存整库及兼容 `persona` 镜像。使用中项不可删除，角色预设启用后只提示披露，不修改 X 资料。

日程模式列近七天，含未生成与失败日期；今天可编辑或重新生成，过去只读。生成或编辑记录当时人设 id、名称、修订，旧记录显示“未记录”。来源存在既有 `runtime`，每次写入清理三十天前元数据，不新增生产迁移。日程计划仍只在设置的定时任务中维护。

一个试聊会话就是一个独立模拟用户。会话内连续消息共享这个用户的记忆、近期往来和冷却；新建会话即新用户。公开和私信仍是两个身份，互不召回记忆；测试 handle 改名只改显示，固定身份不变，不会接上另一个测试用户的数据。最多五十个测试用户，可改名、重置、清除冷却和删除。

试聊使用选定人设的已保存快照，走与生产共用的分级、召回、提示词、生成及校验。合格回复在测试库视为已发出以进入下一轮，超长结果显示“正常流程不会发出”；满五条按正常阈值整理，也可手动整理。先攒多条私信时只回复最后一条，其余为上文；独立公开消息保留各自的平台会话 ID，逐条处理，不跨会话合并。处理可取消，失败可重试，已落账费用保留；同一用户一轮，面板最多两轮并发。

测试数据存于 `DATA_DIR/chat-test/`，有独立 SQLite、遗忘与删除账本，不进入生产动态、记忆、队列、额度、健康、日报、回放样本、质量统计或业务数据库备份。账号级人设、模型、提醒、日程、角色经历和字数能力只读生产；没有可靠账号时相关来源为空、字数按普通规则。不访问浏览器，不检查或占用发送额度，不受回复时段、排队时效、暂停／接管及自动／草稿模式限制。生产库只增加真实模型调用流水，用途为 `chat-test`，来源区分回复、语义与整理。

旧 `POST /api/persona/preview` 仍供批量验收工具使用，继续支持未保存稿和模拟记忆；面板不再提供旧表单。人设库与回放的实现边界见[人设库候选记录](实施记录/2026-10-28-人设库候选.md)。

## 模型库、提示词与字数

设置支持多服务商、显式发现／刷新、模型参数、独立计费测试与使用中切换。旧 `model` 与当前使用模型原子写入，Key 仍按服务商和主机存槽；同服务商、同主机的自定义接口共用槽是现有约束。未知价格显示未定价。详见[模型库](模型库.md)。

提示词采用稳定 system 与有序动态 user，迟到、语言、表情及回复判断提醒按独立修订配置，由所有人设共用。试聊显示实际分段、命中及提醒原因；角色经历与用户事实分开。回复文风既有格式标记只供复核，不改正文、不增加调用，不改变审批或发送规则。本批八股文风改进已由用户决定延后。

公开生成、草稿、出站和浏览器共用字数策略，私信仍为 4,000 个 JavaScript 字符。未取得真实长帖权限、计数及完整回执样本前不放开长帖，公开保守采用 280 加权字符；25,000 码点仅为资源保护。超长候选保留，不自动截断或重生成。可靠“确定未提交”另记持久预检终态并回查对账，不触发平台拒绝退避。详见[账号发帖限制](账号发帖限制.md)。

## 额度、回复时段、分级与健康

公开回复与问候帖共享北京时间自然日额度，默认 180；私信按最近 24 小时滚动统计，默认 400，可设 1–500。窗口为 `(now−24h, now]`，计已提交的 confirmed／submitting／unknown 和未进入 outbox 的兼容旧记录，明确 rejected 不计，也不重复计数。手动接管发送不在系统计数里。满额后私信排队、不占另一通道名额，不写四小时退避；草稿生成不受额度限制，批准后提交再查。

回复时段默认开启，关闭延迟默认三十分钟、可设 0–180。按晚安计划时间加延迟至次日早安计划时间关闭，默认 **23:30–08:00**；任务是否启用、错过或发送失败不改变计划开关。早安任务启用时先等当天任务结束，最迟早安计划后十五分钟开放。关闭期间仍采集排队，公开与私信不生成、不提交，批准稿显示等待；排队时效扣除关闭时长。unknown 回查、日程、记忆及宿主任务沿用各自规则，接管不受限制。

消息在入队时分级，保留广告／刷量过滤、精确重点名单、公开同平台会话合并、骚扰冷却、管理员一次重新排队和公平出队。人工重写优先且需复核；受限通道与过期条目不挤占另一通道名额。额度是内部保护，不表示平台允许发送。

健康的成功发送停滞与日报回复延迟扣除关闭区间。轮次软／硬超时、采集预算和单一看门狗保持；浏览器资源恢复只在安全操作间执行，发送、回查及人工接管期间不重启。账号与告警只读显示未知字段，无外部推送；真实受限识别、生产一天观察及真实平台收发仍需独立证据。原生 X Chat 空收件箱证据不替代入站时间、归属或双方回执，通知“全部”栏仍关闭。详见[无人值守健康](无人值守健康.md)。

人设回放冻结候选、模型和样本，先预估、再确认，私信额外勾选。回放绑定发起人设的已保存基线与单项修订，采用只写该项、不切换使用中；旧请求继续兼容全局人设入口。保留中止、并排标注、质量统计及最近二十次，遗忘或记忆修改／删除会清理派生结果并阻止旧请求写回。详见[人设回放](人设回放.md)与[前端接口](前端接口.md)。

## 服务器验证与回退

本机只编辑源码、文档和目视检查产物。源码同步、构建、自动化测试、性能数据及批量界面渲染都在服务器独立环境，不使用生产账号 profile 或数据目录。`dev/proposals-sync.sh` 与 `dev/proposals-test.sh` 使用独立目录；本轮新增的 `persona-workspace-ui-acceptance.mjs`、`settings-workspace-ui-acceptance.mjs`、`feed-workspace-ui-acceptance.mjs` 分别对应三个工作区，旧验收脚本需要按新位置适配，不能因脚本存在就记通过。最终结果以本轮总实施记录和各提案任务为准。

既有迁移 8—13 仍按[迁移与恢复](迁移与恢复.md)处理。`deploy/prepare-proposals-rollback.py` 仅用于历史降至 0.1.16 的只读资格检查，不适用于本次 0.1.19 回退；本次须按[发布记录](发布记录/2026-10-29-0.1.19.md)用旧源码重建成对镜像，并保持暂停。历史工具不切换镜像、不创建备份、不删除新表或冻结正文；待回查、未收束记录或不可保持的约束会阻止历史转换。浏览器日志及独立遗忘／删除账本必须保留。

本轮额度、时段、人设库和日程元数据不新增生产迁移，主库仍为 schema 13，索引散列不变。0.1.19 已读回默认启用夜间关闭及原作息计划，跨夜实际开放后的观察仍待完成，详见[发布记录](发布记录/2026-10-29-0.1.19.md)。回退旧版忽略 `privatePerDay`／`replyHours`，私信只剩旧小时额度、回复回到全天规则；旧版读取 `persona` 镜像，使用中人设不变。新回放保存单项真实修订并在旧修订字段置冲突哨兵，旧版不可误采用；需要采用时用旧界面重新发起。独立 `chat-test/` 不属于业务备份，回退时被忽略，保留后可供再升级使用。

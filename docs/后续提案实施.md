# 后续提案候选使用说明

本轮候选在已发布七页工作流之上实现六项后续提案。生产发布、真实模型调用、X 权限读取和实际收发分别验收；提交和推送源码不改变生产状态。

## 面板和草稿

一级页面为动态、人设、记忆、设置、计费。旧地址自动替换到新页面或设置分区。动态只列当前工作账号的回复、私信及问候帖，支持待处理筛选、稳定分页和记忆深链。SSE 更新保留正在编辑的草稿及光标。

修改草稿后批准只进入等待发送。系统恢复处理后，由同一主循环按身份、可靠目标、时效、小时/每日额度、退避、待回查和持久出站规则发送；草稿模式也只发送明确批准的条目。未开始提交时可取消。重写重新入队，结果始终留在草稿，模型选择跳过时保留原稿。暂停和接管不会被保存设置、批准或重写隐式解除。

## 模型库、提醒和字数

设置页支持多服务商、显式发现/刷新、模型参数、独立测试和使用中切换。旧 `model` 与当前使用模型同一次原子写入，Key 仍按服务商和主机存槽；两个同主机自定义接口共用槽是现有约束。未知价格继续显示未定价。详见[模型库](模型库.md)。

提示词采用稳定 system 与有序动态 user，迟到、语言、开头、表情及回复判断提醒均可按独立修订配置；试聊显示真实组装分段与提醒原因。角色经历与用户事实分开。详见[人设与日程](人设与日程.md)。

公开生成、草稿、出站和浏览器共用字数策略，私信仍为 4,000 个 JavaScript 字符。当前未取得真实长帖权限/计数/完整回执样本，适配器不放开长帖，保守采用 280 加权字符；25,000 码点仅为资源保护。超长候选保留，不自动截断或重生成。确定未提交另记持久预检终态并回查对账，不触发平台拒绝退避。详见[账号发帖限制](账号发帖限制.md)。

## 分级、健康和回放

消息在入队时分级，支持广告/刷量过滤、精确重点名单、公开同会话合并、骚扰冷却、管理员一次重新排队和公平出队。公开回复与问候帖共享北京时间每日额度，默认 180；额度不代表平台许可。人工重写优先并保留复核。受限通道与过期条目不挤占另一通道的生成名额。

轮次有软/硬超时、采集预算和单一调度看门狗；浏览器资源恢复只在安全操作之间执行，发送、回查与人工接管期间不重启。健康告警、日报和账号只读检查均可在设置查看，无外部推送。无法确认的页面字段显示未知，真实受限识别和生产一天观察仍需单独证据。详见[无人值守健康](无人值守健康.md)。

人设回放冻结候选、模型及样本，先预估费用、再显式确认；私信样本需额外勾选。基线/候选共用当前允许的记忆和固定时间，支持中止、并排人工标注、质量统计、采用候选和最近二十次保留。遗忘或修改/删除记忆会清理派生结果并阻止在途旧请求写回。详见[人设回放](人设回放.md)。

## 服务器验证与恢复

本机只编辑源码与目视检查图片。运行 `sh dev/proposals-sync.sh` 将源码同步到独立服务器目录，再运行 `sh dev/proposals-test.sh` 构建与回归；界面脚本为 `test/five-pages-acceptance.mjs`。具体版本、测试数和证据见[实施记录](实施记录/2026-10-28-后续提案.md)。

新增迁移 8—12 保留兼容字段。回退前暂停、排空并停止 app/browser；使用 `deploy/prepare-proposals-rollback.py` 做只读资格检查，再按实际批准执行转换。它不切换镜像、不创建备份、不删除新表或冻结正文；长帖待回查、未收束记录或不能保持的约束会阻止回退。两类浏览器日志及独立遗忘/删除账本必须保留。详见[迁移与恢复](迁移与恢复.md)。

界面复验时，在服务器启动 `dev/proposals-static.mjs`，以 `PANEL_URL` 指向独立静态地址，并将 `ARTIFACT_DIR` 设为容器 UID 1000 可写的产物目录；使用 Camoufox 镜像运行 `five-pages-acceptance.mjs`、`proposals-ui-acceptance.mjs` 和 `model-library-ui-acceptance.mjs`。`browser-health-acceptance.mjs` 需要挂载已构建 `dist/`，使用禁用外网的容器与脚本自建的新 profile；不挂载生产 profile。源码同步及后端检查的两个 shell 脚本均通过 SSH 在服务器工作。

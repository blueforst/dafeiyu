# 0.1.14：OpenCode 会话修复与 4K 默认回复

上线时间：2026-10-27 22:49:21（北京时间）。生产应用镜像：`role-workflow-app:0.1.14`，浏览器继续使用 0.1.12。用户明确授权完成后上线，已完成发布及状态核对。

## 原因与改动

生产最近一次模型测试使用 `opencode-go / deepseek-v4.1-flash`，返回 `400 MissingSessionID`。应用没有向 pi 传入 `sessionId`，导致 OpenCode 请求缺少 `x-opencode-session`。pi 1.4.0 已支持该请求头，本次无需升级依赖。

[OpenCode 官方要求](https://opencode.ai/docs/go/#where-can-i-use-it)：同一对话使用稳定会话 ID，并通过客户端自己的 User-Agent 标识应用。

- `src/model.ts`：连接测试与独立调用自动生成会话，生成器接收并传递工作流会话；客户端身份为 `role-workflow/0.1`。沿用 pi 自带的协议适配和会话头处理。
- `src/workflow.ts`：回复与记忆整理共用相应会话。数据库运行状态中保存随机命名空间，结合登录账号、用户、公开／私信通道和遗忘版本计算散列；重启后保持稳定，切换账号、用户、通道或遗忘后更换会话。
- 不改变模型设置格式，不升级依赖，不迁移数据库。仅在首次工作流生成时增加 `model:sessionNamespace` 运行状态记录。
- 用户随后确认正式回复默认上限改为 4096 token：已同步新建模型表单、配置示例及测试配置副本，并把生产配置的正式回复上限从 1024 调到 4096。发布时没有已保存的面板模型配置；其他配置保持原值。连接测试仍使用原有的最小请求额度。

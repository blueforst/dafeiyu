# X 链路三项漏洞修复

日期：2026-10-29（北京时间）。对应[扫描报告](../排查记录/2026-10-29-X链路漏洞扫描.md)与 [fix-x-message-boundaries](../../openspec/changes/fix-x-message-boundaries/proposal.md)。本轮为代码修复和服务器隔离验证，未发布生产。

## 修复行为

| 问题 | 修复后的行为 |
| --- | --- |
| X01：旧启动覆盖暂停或接管 | 每次运行控制取得修订，异步等待前后核对；实际浏览器控制按顺序提交。旧成功和旧失败均不能覆盖后发控制，安全暂停及关闭也使旧启动失效 |
| X02：推荐帖、错误祖先进入链路 | 只使用绑定消息 ID、作者、可靠时间的原生回复资料；自己帖扫描排除无关文章，上文跟随父链，补录祖先不来自 DOM 顺序；旧队列提交前重新核对相关性，无关目标在保存 intent 之前明确拒绝 |
| X03：同线程不合并 | 区分消息平台 ID、发送目标及可信线程 ID。同用户同线程三十分钟内只回复最新一条，早消息留作上下文；新消息线程未知时保留独立处理，不把占位 ID 当成已确认线程 |

## 实现边界

- `workflow.ts` 使用请求修订和单独的浏览器控制队列，只锁控制 RPC，不持锁等待业务轮次，避免与轮次内安全暂停互相等待。
- 新增 `public-relations.ts`。只旁观页面已发出的原生读取响应，按导航清空并隔离晚到响应；每导航最多处理八十个响应、保存一千项关系，遍历有深度和访问次数限制，重复冲突证据保持不可信。
- `Event` 增加可选关系字段；DOM 读取本身不声明可信线程，原生元数据通过 ID、作者和时间绑定后才补入。时间缺失与明确冲突分别处理：主帖时间缺失时，仍可保留由回复自身可靠元数据证明归属的留言。
- 公开采集、目标上下文、补录和提交前核对共用关系判断。父链最多提供十二条；缺父帖或存在冲突时明确标记不完整，已验证的目标正文仍可使用。
- 关系无法确认时采用保守跳过并输出 `public-relation-unverified`；作者正文明确提及运营账号仍是独立的资格依据。原生响应字段在真实平台上的适配与覆盖率仍须只读样本另行验证，隔离夹具不证明所有 X 页面都已适配。
- 无数据库迁移；旧消息、冻结正文、outbox、journal 和 unknown 门禁不改写。原生 Chat 的既有只读边界继续保持。

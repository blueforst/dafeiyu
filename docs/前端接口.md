# 前端接口：本轮未发布候选

本节按本轮候选源码描述三页面板、私信额度、回复时段、人设库、正常流程试聊和会话查询。最近正式发布记录仍为 **0.1.18.6／schema 13／paused／auto**；本节不表示已部署，也不替代真实模型和平台收发验收。下文既有能力与七页历史交接保留为参考，冲突处以本节候选契约为准。

管理 API 沿用统一鉴权、同源检查；所有非 GET／HEAD 写请求必须带 `X-Workflow-Control: 1`，包括新增 `PATCH`。ID 作为路径参数时使用 `encodeURIComponent`，游标是服务端不透明返回值。时间为 Unix 毫秒，显示使用北京时间；外部文本只按纯文本渲染。普通日志和统一调用流水不包含正文、提示词或 Key。

| 页面 | 路由 |

| 动态 | `#/feed`、`#/feed/c/<编码后的身份>`、`#/feed/attention`、`#/feed/import` |

设置项省略路径时恢复 `ws:settings:item`，首次取 `run`。旧 `overview/model/program/tasks/browser/memory/billing` 依次映射 `feed/settings/model/settings/logs/settings/tasks/settings/browser/settings/memory/settings/billing`；旧记忆查询参数保留。`#/settings/limits` 映射 `run`，记忆策略直接地址为 `#/settings/memory?view=policy`。旧 `#/persona/persona`、`daily`、`preview` 分别打开新人设、日程、试聊模式。

工作区收起偏好使用 `ws:<page>:left/right`，存储不可用不阻断操作。设置项切换会清理旧模块，只有已连接的浏览器桌面隐藏保留，离开设置页才卸载。摘要不发起模型调用或新增浏览器读取；来源状态只在打开来源项或显式刷新时读取。

## 运行设置、私信滚动额度与回复时段

`GET /api/program` 保留原字段，`settings` 增加 `privatePerDay` 和 `replyHours`，外层增加只读的 `replyHours` 状态：

| 字段 | 契约 |
| --- | --- |
| `settings.privatePerDay` | 整数 1–500，缺省 400，最近二十四小时滚动私信上限 |
| `settings.replyHours` | `{enabled:boolean,closeDelayMinutes:number}`，缺省 `{enabled:true,closeDelayMinutes:30}`，延迟为 0–180 整数 |
| 外层 `replyHours` | `{open,reason,closeTime,openTime,closures,closedAt?,opensAt?,closesAt?,openedAt?}`；时刻为北京时间 HH:mm，时间戳为毫秒 |
| `replyHours.reason` | 开放为 `null`，关闭为 `reply-hours-closed` 或 `waiting-morning-post` |
| `replyHours.closures` | `{start,end}[]`，供同一规则计算有效等待时长；不接受前端改写 |

`PUT /api/program/settings` 请求为 `{settings,revision?}`。可写字段是 `mode/maxAgeHours/maxPerRound/publicPerHour/privatePerHour/publicPerDay/privatePerDay/replyHours`；范围分别为 `draft|auto`、1–48、1–4、1–25、1–100、1–1000、1–500 以及上述时段结构。未提供字段保留原值，不认识的字段拒绝；非整数、超界或修订冲突不改原设置。返回 `{ok:true,settings,revision}`。切换模式只提交已保存限制和新模式，正在编辑的限制保持未保存；不触发启动或释放接管。

`GET /api/triage/summary` 在原 `queues/today/reasons/publicToday/publicPerDay/ignores/now` 外增加 `privateRecent`、`privatePerDay`。`privateRecent` 统计 `(now−24h,now]` 中已提交的私信 confirmed／submitting／unknown，以及没有对应 outbox 的兼容旧消息，排除明确 rejected，且不重复计数。私信在此窗口滚动释放名额，跨北京时间零点不重置；管理员接管发送不在统计中。满额不写四小时平台退避，不阻塞公开；草稿模式仍可生成，批准后的实际发送再次检查。

关闭区间来自晚安计划时间加延迟至次日早安计划时间，默认 23:30–08:00；任务停用、失败、错过不改变计划开关。早安任务启用时等待其结束，最迟计划后十五分钟开放。关闭期间仍采集，公开和私信不生成、不提交，批准稿继续等待；有效排队时效、健康发送停滞和日报回复延迟扣除关闭时间。unknown 回查及其他任务沿用原规则，试聊与人工接管豁免。

草稿 `waitReason` 保留原 `quota/cooldown/unknown-pending/paused` 等值，新增或展示以下原因：

| 原因 | 显示 |
| --- | --- |
| `private-daily-quota` | 近 24 小时私信额度已用尽 |
| `reply-hours`／`reply-hours-closed` | 回复时段已关闭 |
| `waiting-morning-post` | 等待早安任务结束后开放 |

`daily-quota` 是兼容前端文案；当前公开小时与日额度仍由服务端统一返回 `quota`，不能据此声明已分别识别。额度只控制生产提交，不进入共用试聊生成流程。

## 人设库接口

所有写入口与单项正文读取上限沿用校验；人设库写请求体限制为 **128 KiB**。

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/personas` | `{activeId,libraryRevision,items:[{id,name,revision,createdAt,updatedAt,origin,characters}]}`，列表不返回人设正文 |
| `GET /api/personas/:id` | `{id,name,revision,createdAt,updatedAt,origin,persona,active,fixedRules,disclosure?}` |
| `POST /api/personas` | `{from:'blank'|'preset'|'copy',presetId?,sourceId?,name?}`；返回 `{ok,item,activeId,libraryRevision}`，新项未使用且修订为 1 |
| `PUT /api/personas/:id` | `{revision,name?,persona?}`；返回 `{ok,item,activeId,libraryRevision,personaRevision}`，`personaRevision` 是兼容镜像的修订 |
| `POST /api/personas/:id/activate` | `{libraryRevision}`；返回 `{ok,item,activeId,libraryRevision,disclosure?}`，不改控制状态 |
| `DELETE /api/personas/:id` | `{revision}`；返回 `{ok,activeId,libraryRevision}`，使用中项删除返回 409 |
| `GET /api/persona/presets` | `{version,items,fixedRules}`，目录仍为六个只读模板，供新建使用 |
| `GET/PUT /api/persona` | 保留兼容使用中人设入口；保存请求仍为 `{persona,revision}`，修订使用全局 `persona` 镜像值 |

`persona` 为现有 `{sections,triggers}`，总长仍为 20,000 字符；名称 trim 后一至四十字且库内唯一，最多二十项。`origin` 为 `{kind:'blank'|'preset'|'copy'|'migrated',presetId?,presetVersion?,fromId?}`。只有使用中正文变化才增加 `revisions.persona`；整库每次写入增加 `revisions.personaLibrary`，每项保存增加自己的修订。切换和保存同时原子更新兼容镜像，互不覆盖其他设置域；陈旧修订返回 409。

无库时只读构造 `current/当前人设`，内容逐字沿用旧生效规则，读取不写文件。坏库管理读取返回 500、不覆盖文件，生产继续读取原 `persona` 镜像。角色来源的启用返回披露数据，通用默认不返回非官方启用提醒；建议简介可在单项 `disclosure` 中读取。接口不自动修改 X 资料或披露配置。

## 正常流程试聊接口

新试聊的数据目录为 `DATA_DIR/chat-test/`，独立数据库和账本；只有实际模型调用写生产统一流水。每个试聊会话就是一个独立模拟用户，新会话即新用户，同会话连续消息共享该用户的记忆、近期往来和冷却。公开固定模拟身份与私信固定会话身份互相隔离，改显示名／测试 handle 不改变身份、不接入其他用户数据。

试聊写入口请求体上限 **64 KiB**，消息正文一至 4,000 字符。正常处理会发起真实模型请求，自动测试必须使用 mock；生产调用另需既定授权。新试聊不访问浏览器，不占发送额度，不受时段、时效、暂停、接管、自动／草稿模式或 unknown 出站限制。

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/chat-test/status` | `{accountId,accountConfirmed,warning?,activePersona,model,concurrency:{active,limit:2}}` |
| `GET /api/chat-test/users` | `{items}`，用户按 `lastActiveAt` 倒序；含 id、name、handle、color、createdAt、updatedAt、lastActiveAt、fees、turns、processing |
| `POST /api/chat-test/users` | `{name,handle?}` → `{user}`；最多五十个，名称一至三十字，handle 为一至十五位小写字母／数字／下划线且唯一 |
| `PATCH /api/chat-test/users/:id` | `{name?,handle?}` → `{user}`；处理期间拒绝修改 |
| `DELETE /api/chat-test/users/:id` | 删除用户及全部测试数据，返回 `{ok:true}`；已落账生产调用保留 |
| `POST /api/chat-test/users/:id/reset` | 清空两个测试身份的消息、记忆、冷却及进度，保留用户，返回 `{ok,user}` |
| `POST /api/chat-test/users/:id/clear-cooldown` | 清除两个渠道的测试冷却，返回 `{ok:true}` |
| `GET /api/chat-test/users/:id/turns?before=&limit=` | `{items,messages,queued,nextCursor,processing}`；默认三十、最多一百，轮次按正序返回，游标用于更早记录；`messages/queued` 为待处理消息 |
| `POST /api/chat-test/users/:id/messages` | `{text,channel:'public'|'private',personaId?,hold?:boolean}`；hold=true 只入队并返回 `{message}`，否则处理并返回 `{turn}` |
| `POST /api/chat-test/users/:id/process` | `{channel?,personaId?}` → `{turn}`，处理待处理消息；人设默认选消息已选项或当前使用中项 |
| `POST /api/chat-test/users/:id/turns/:turnId/retry` | `{personaId?}` → `{turn}`，仅失败或取消轮次可重试，会再次计费；整理轮次走整理重试 |
| `POST /api/chat-test/users/:id/turns/:turnId/cancel` | 取消在途对应轮次，返回 `{ok:true}`；已结束返回 409 |
| `GET /api/chat-test/users/:id/memory` | `{public,private,experiences}`；分渠道的长期记忆、近期往来、untilNext、cooldown、strikes，以及只读生产角色经历 |
| `POST /api/chat-test/users/:id/memory/summarize` | `{channel?}`，缺省 public；返回整理 `{turn,memory?}`，费用保留在轮次诊断 |

轮次 `turn` 包含 `id/userId/status/channel/persona/messages/result/diagnostics/segments/callIds/startedAt/finishedAt/error`。`persona` 是处理开始时固定的 `{id,name,revision}` 快照；`segments` 为实际提示词分段，`diagnostics` 包括分级、合并、日程、召回、命中、提醒、模型调用、费用、耗时、字数校验及格式标记。生产调用用途统一为 `chat-test`，source 区分 `chat-test:reply`、`chat-test:semantic-trigger`、`chat-test:memory-summary`；按调用 id 计算费用，不重新计算第二份账。失败、取消或校验不合格的已落账用量仍保留，未定价不显示免费。

处理开始冻结所选已保存人设，旧未保存编辑不参与；人设已删除时返回 409。合格回复仅在测试库视为 confirmed，下一轮可以召回；超长正文保留但不视为发出。被过滤或冷却的消息不调用模型。私信攒多条只处理最后一条、其余作为上下文；独立公开消息保留平台会话 ID，不跨会话合并。相同测试用户同时一轮，整个面板最多两轮，超出返回 429；坏测试库返回 503，不影响生产启动或主循环。

账号层人设、模型、参数、提醒、分级、当日日程、角色经历和字数只读生产；日程只读 `describe`，不调用 `ensure`。当前账号未确认时，依赖账号的来源为空，字数使用普通规则。测试用户数据不进入生产动态、记忆、健康、日报、回放、质量统计或业务备份。

旧 `POST /api/persona/preview` 保持未保存稿／模拟记忆契约，只供批量验收工具，面板不再提供旧入口。

## 日程人设元数据与按人设回放

`GET /api/persona/daily?date=YYYY-MM-DD` 可读取指定日期；不传为今天。保留原 `state/today/status/currentPeriod/history/fees/calls/scheduleTime`，增加 `readOnly` 和固定近七日的 `days:[{date,state,status,attempts,nextRetryAt,interactionId,callId,error?,fees}]`，包含未生成及失败日期。每个日程修订增加 `persona:{id,name,revision}|null`、`personaName`，旧记录为 `null/未记录`；历史日期 `currentPeriod=null`，管理 PUT 只允许今天。原 `/daily/history` 仍只返回已生成的近七日最终修订。

人设来源写入既有 runtime 的 `daily-persona:<账号>:<日期>:<修订>`，不新增生产迁移，写时清理三十天前来源。生成开始冻结身份，成功落库与来源元数据同事务；保存或切换人设不改已经生成的日程。

`POST /api/persona/replay/estimate` 新增可选 `personaId`。传入时 `personaRevision` 为该项修订，候选、saved 基线、开始校验与采用都绑定该项；模型比较两侧仍共用该项已保存人设，不允许混入人格改动。预估与运行列表／详情增加 `personaIdentity:{id,name,revision,deleted?}`；删除后名称与候选快照保持可读。`POST /runs/:id/adopt` 只保存发起项，返回库保存结构，不改变使用中项。旧请求不传 id 时保留全局镜像修订兼容。

新绑定批次把真实单项修订存入内部 `settings_json.personaItemRevision`，旧 `personaRevision` 存无效哨兵 `-1`；对外详情仍返回真实 `personaRevision`。旧版本采用新批次必定返回修订冲突，避免回退时误覆盖使用中项；不要用内部哨兵覆盖前端的人设修订。

## 动态会话只读查询

两个新接口均只读当前工作账号，不访问浏览器、不调用模型、不创建消息或出站。保留旧 `GET /api/feed` 与批准／取消／重写／重新入队接口。

| 方法与路径 | 契约 |
| --- | --- |
| `GET /api/feed/conversations?filter=&cursor=&limit=&changedSince=` | filter 为 all/pending/public/private/posts；返回 `{items,nextCursor,pending,importsPending,serverTime,latest,removedKeys}` |
| `GET /api/feed/conversations/:key/items?before=&limit=&changedSince=` | key 为编码后的 `x:<handle>`、`dm:<会话>` 或 `posts`；返回 `{items,nextBefore,nextCursor,total,firstAt,serverTime,latest,conversation}` |

列表项为 `{key,channel,title,handle,latestAt,status,pending,preview,avatar,firstAt,total,changedAt}`，channel 为 public/private/posts。同账号同身份一组，公开与私信分开；私信名称暂为“私信 · ”加身份末四位。`posts` 包含出站角色帖及没有出站的早晚安执行记录，后一类仅展示、不计待处理。状态优先级为待回查、有效失败、草稿／重写、批准等待、有效排队／生成中；待处理复用旧判定，总数仍包含待核对补录。

消息排序取 `ingested_at`，旧值为零时取 `created_at`；状态更新不改变排序。`latestAt` 是会话最新排序时间，preview 是纯文本截断，不是平台原文的替代证据。会话游标包含 `(latestAt,key,snapshotAt)` 的分页边界，往来游标包含 `(sortAt,id)`；limit 默认三十、最多一百，非法 key、游标和时间返回 400。

`changedSince` 为非负整数毫秒，采用包含等值的变化边界并忽略普通游标，返回全部匹配变化；前端按 key／id 去重，用服务端 `serverTime` 推进水位。`removedKeys` 表示已不符合当前筛选的已变化会话；有效时效自然流逝造成的移除／草稿过期也纳入更新。更新按原位状态修订和新消息重排分别处理，不重读已加载的全部分页，也不覆盖脏草稿或强制跳到最底。

往来条目保留旧 feed 字段，增加 `tier/tierReason/sortAt`，每页倒序取后正序返回。`GET /api/messages/:id` 的 message 增加 `tier/tierReason/persona:{id,name,revision}`，人设来自生成快照，旧记录名称为“未记录”；不返回完整提示词或秘密。生产生成快照在原修订外增加 `personaId/personaName`，只是既有 JSON 扩展。

## 候选兼容与回退

升级默认开启回复时段，应核对默认 23:30–08:00 是否符合运营。旧版忽略 `privatePerDay/replyHours`，回退后私信仅有旧小时额度、回复回到旧全天规则。旧版读取 `persona` 镜像即回退前使用中人设；新库与独立试聊目录被忽略，后者不在业务备份中。新会话接口只读，工作区偏好仅在浏览器中。生产既有 schema 13 的回退前提和有效出站／遗忘账本保护仍须按迁移与恢复说明执行。

### 关键词触发与试聊

`PUT /api/persona` 的 trigger 增加 `match?:'semantic'|'keywords'`、`keywords?:string[]`。未提供 `match` 的旧卡片继续按语义处理，加载时保留旧结构。关键词卡片需要 1–30 个关键词，每项 NFKC 规整并去除首尾空白后为 1–40 字符；`condition` 仍必填且最多 2,000 字符。关键词与分区、条件、卡片正文共同计入 20,000 字符上限。

`POST /api/persona/preview` 中的用户消息可带 `quote`／`card`，返回的 `segments` 在本次消息及对话段中展示这些摘要和不可读／截断说明，具体字段见下文消息详情。引用与卡片属于不可信上下文，分级、刷量哈希和记忆整理继续只使用作者正文。

| --- | --- |
| `GET /api/memory/experiences?cursor=&limit=` | limit 为 1–100；返回 `{accountId,items,nextCursor,revision}`，游标不可混用；列表包含隐藏及未核对条目 |

| 方法与路径 | 请求与返回 |
| --- | --- |
| `POST /api/messages/import` | 仅 `{url}`；返回 `{ok:true,status:'pending'|'duplicate',reused,request}`，已有消息时附原 `messageStatus` |
| `GET /api/messages/imports?status=&cursor=&limit=` | 当前账号分页；limit 为 1–100，缺省 30；status 可为 pending／imported／duplicate／rejected／failed，不传为全部；返回 `{items,nextCursor,pending}` |

### 采集来源与消息详情

`GET /api/collection/sources` 返回 `{sources:[{id,label,enabled,status,reason}]}`，只读适配器元数据，不导航平台或更改设置。当前 mentions／search／own-post-replies 标为 implemented；这只表示适配器存在，运行结果另看健康快照。`all-notifications` 固定为 `enabled:false,status:'awaiting-samples'`，原因显示“未启用（待真实样本确认）”，没有外部启用开关。

`GET /api/health` 的采集指标按账号、public／private 和独立轮次统计，区分 ok／empty／partial／failed／unsupported／blocked／unknown；没有明确空状态证据不能显示“正常无消息”。原生 Chat 的时间或入站身份尚未核实时显示诊断，不据此承诺私信已经自动可用。资源快照另含待恢复原因、推迟原因、受保护会话和恢复故障，字段含义见[无人值守健康](无人值守健康.md)。

`GET /api/messages/:id` 返回 `{message,calls,outbox,manualImports}`，正文按需读取：

- `message.body` 保留作者 `text`，另可含 `platformId`、`timestampReliable`、`mediaUnavailable`、`quote`、`card`；引用为 `{handle,platformId,text,media,truncated?}` 或 `{unreadable:true}`，卡片为 `{domain,title,truncated?}` 或 `{unreadable:true}`。引用最多 1,000 字符，卡片标题最多 300 字符，外部文本均按纯文本渲染。
- `message.draft.meta` 保留 `promptVersion`、命中原因与动态提醒元数据；`calls` 引用原流水的 callId、用量／cacheRead／价格状态，不复制第二份费用。
- `message.receipt` 和解析后的 outbox receipt 可含 `diagnostic:{code,stage}`、`browserPaused`、`browserMode`、`restricted`；这些为固定枚举与有限诊断，不是页面正文或底层异常。outbox 另返回原 `validation_json`。
- `not_submitted` 表示提交意图前的失败，须由可靠预提交结果持久确认；`unknown` 仍表示已开始提交或缺少可靠边界，只能回查。前端不能把历史 unknown 改成可直接重发。
- `manualImports` 是关联补录 DTO 数组；message 状态和补录 request 状态分别展示。

# 前端面板接口交接

本节保留 0.1.16 应用／0.1.15 浏览器时期的七页接口交接。之后的 0.1.17.1 发布见[发布记录](发布记录/2026-10-28-0.1.17.1.md)；本轮候选接口不由该历史发布记录验收，生产保持暂停。入口为 [生产面板](https://43.133.80.237)，七页基线进度以 [任务清单](../openspec/changes/add-seven-page-production-bot/tasks.md) 为准。

七页职责与交互见 [七页面板](七页面板.md)；[迁移与恢复](迁移与恢复.md) 说明账号归属、修订、遗忘与数据范围。管理接口不提供绕过 outbox、额度或 unknown 回查限制的任意草稿发送入口。

## 认证与请求约定

- 生产页面与 API 同源，使用相对 URL。宿主 Nginx 的 HTTPS + Basic Auth 完成认证，前端不保存密码、不接触 X Cookie 或模型密钥。
- X-Ingress-Key 是 Nginx 到后端的内部凭据，不得写进前端。
- 所有 POST、PUT、DELETE 及其他非 GET／HEAD 请求添加 `X-Workflow-Control: 1`。后端同时校验 Origin。不要跨域代理控制接口。
- 成功控制响应为 `{"ok":true,"control":"paused"}` 等；失败一般为 409，响应 `{"error":"中文说明"}`。
- 控制操作可能等待当前浏览器操作完成，请使用进行中状态防止重复点击，超时至少 110 秒。
- 时间均为 Unix 毫秒或 ISO 字符串，页面显示使用 Asia/Shanghai。

## GET /api/status

返回字段：

| 字段 | 含义 |
| --- | --- |
| control | paused / draining / manual / running |
| busy | 当前是否正在执行一个处理轮次 |
| accountId | 七页开发版当前工作账号；未确认时为空，不用预设账号代替 |
| config.mode | draft / auto；与 control 是两个独立维度 |
| config.model | provider、id、api、configured；没有密钥 |
| config.publicPerHour / privatePerHour | 内部通道额度 |
| configError | 配置解析失败的中文说明；正常为空 |
| browser | handle、loggedIn、needsHuman、reason |
| lastTick | 最近一次完整处理轮次完成的时间；0 代表尚未完成 |
| cooldown.public / private | 通道退避截止时间；0 代表没有退避 |
| stats.messages | channel、status、count 的数组 |
| stats.usage | 七页开发版为统一聚合：input、output、cache／cacheRead、cacheWrite、totalTokens、reasoning、calls、costUSD、priced、unpriced、unknown、legacyRows；costUSD 可为 null，不能将未知项当零费用 |

建议每 10 秒刷新一次。浏览器未登录、模型未配置属于待设置状态，不代表面板 API 故障。只有生成第一条实际草稿后才开始业务观察，不要把容器在线时间显示成已完成 12 小时业务验收。

消息状态可能为 queued、generating、draft、sending、confirmed、unknown、skipped、failed。请给 unknown 显示明确的“发送结果待回查”，不要显示成发送失败后可直接重试。

## 日志

`GET /api/logs` 返回最近 100 行，按最新在前排列。每行包含 id、at、level、event、detail。

`GET /api/events` 为 SSE。兼容的 `logs` 事件仍是最近 30 行日志的完整数组，每五秒推送一次，并带心跳；收到后替换列表，不应重复追加。七页开发版另发送 `program`（control、busy、stages、nextTick）及 `tasks`（与任务列表同结构），只消费 logs 的旧客户端可以继续工作。原生 EventSource 可自动重连，关闭组件时释放连接。

常规日志仅提供运行元数据，不保存消息正文、私信内容或完整 Key。七页开发版在独立受管理鉴权的消息／记忆详情接口按需读取原文；日志列表不能用详情正文填充。渲染 detail 及其他外部文本使用纯文本 DOM，禁止 innerHTML。

## 控制接口

| 方法与路径 | 行为 |
| --- | --- |
| POST /api/control/pause | 停止新任务，中止正在生成的内容，等浏览器操作结束后暂停 |
| POST /api/control/resume | 读取浏览器当前登录账号，完成登录及人工状态检查后恢复；运行模式由有效配置决定；七页开发版在主程序页维护 |
| POST /api/control/takeover | 排空程序操作，进入 manual，随后允许 noVNC 连接 |
| POST /api/control/release | 关闭交互式 VNC 客户端，回到 paused；不会自动恢复处理 |

人工接管时必须先 release，再 resume。未登录、账号无法识别或需要人工验证时 resume 会失败并保持暂停。处理期间退出登录或切换账号会暂停；检查后重新恢复即可使用当前账号。不要把 resume 文案写成“开启自动发送”：在 draft 配置下恢复只会生成草稿。

## 前端开发与部署

前端改动需要重新构建业务镜像并切换固定版本，避免原地覆盖正在运行的容器。浏览器镜像无需为了纯前端改动重建。后端继续开发时应保留 public/ 的前端 WIP。

已有 test/ui-acceptance.mjs 使用当前按钮文案和 DOM ID。改版后由前端负责人适配这些定位器，保留认证、接管、释放后阻断、账号缺失保护等行为断言。

纯前端发布时仅更新 APP_VERSION，保留 BROWSER_VERSION；两者未指定时回退到 ROLE_VERSION。发布期间如用户正在 manual 接管，不要重启代理桌面的业务容器。

## 模型目录（0.1.13）

`GET /api/model/providers` 完整返回 pi 内置服务商，并附加 Command Code 预设。每项包含 id、name、group、baseUrl、apis、modelCount、available、reason、source。`available=false` 时展示条目及 reason，禁用选择；不能静默隐藏。source 为 pi 或 preset。

`GET /api/model/providers/:id/models` 返回可用服务商的聊天模型。各模型包含自己的协议和地址；切换模型时更新默认地址，保留用户手工编辑的地址。`costKnown=false` 时显示价格未提供。Command Code 的上下文及支持端点来自官方目录快照；目录不提供的价格不显示成免费。

`POST /api/model/discover` 按服务商选择模型目录端点：OpenCode/Command Code 使用 `/v1/models` 和 Bearer，Radius 使用 `/v1/config`。其他服务商沿用对应原生协议。


## 七页路由与配置修订（独立 staging）

| 页面 | hash 地址 | 主要接口 |
| --- | --- | --- |
| 主页面 | `#/overview` | status、logs、control、desktop |
| 模型 | `#/model` | model 及 providers、discover、test |
| 人设 | `#/persona` | persona、preview、daily |
| 记忆 | `#/memory` | memory/policy、users、items |
| 主程序 | `#/program` | program、program/settings、program/logs、messages |
| 定时任务 | `#/tasks` | tasks、tasks/:id、tasks/runs |
| 计费 | `#/billing` | billing/summary、billing/calls |

该七页历史基线的一级入口恰好七个。历史默认打开主页面，旧 `#/browser` 转到主页面并展开接管区；展开不自动进入接管或连接桌面。配置编辑离页时保留当前稿或明确放弃，保存失败保留编辑。各页支持系统浅／深色、375px、加载、空数据及错误状态。

面板设置分 model、persona、memory、program、tasks 域，各有 `revision`。保存时回传刚读到的相应域修订；旧修订返回 409，前端重新读取并让管理员决定保留哪些修改，不能自动覆盖。不同域保存互不覆盖。人设保存必须携带修订，日程和条目编辑携带各自内容修订；任务、策略、程序和模型接口支持域修订，前端同样应传入。配置供后续轮次或任务使用，不修改正在生成的快照或隐式恢复暂停状态。任务页的主循环 enabled 是显式全局控制，详见下文。

全局默认请求体上限 16 KiB；人设保存、试聊及日程内容编辑独立放宽为 128 KiB，仍校验正文和上下文额度。超限返回 413。

## 人设与虚构日程

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/persona` | persona、revision、fixedRules、daily、scheduleTime |
| `PUT /api/persona` | `{persona:{sections,triggers},revision}`；旧人格原文完整保留，不改控制状态 |
| `POST /api/persona/preview` | 未保存的 `{persona,channel,messages:[{role,text}],memory?,dailyState?}`；返回 draft、segments、hits、warning、calls、fees 与耗时 |
| `GET /api/persona/daily` | 当日状态、当前时段、尝试次数、重试时间、近七日历史及费用引用 |
| `GET /api/persona/daily/history` | `{items}`，当前工作账号近七日最终日程修订 |
| `PUT /api/persona/daily` | `{date,content,revision}`；content 含 date、fictional:true、periods、meals、activities、mood |
| `POST /api/persona/daily/generate` | 明确手动重新生成，可带 `{revision}`；没有可靠当前账号时拒绝 |

section 为 `{id,title,content}`，trigger 为 `{id,title,condition,content,enabled,order,match?,keywords?}`，新增字段及计数规则见上文第三轮候选补充。所有分区、条件、触发正文与关键词合计不超过 20,000 字符，ID 唯一。试聊最多三十条模拟消息、40,000 字符上下文，最后一条为 user；只用模拟记忆，不访问 X、不创建真实消息、记忆或出站。fees 是同交互下语义判定与最终生成的原流水合计。

日程内容明确虚构，与用户事实、已确认角色经历分开。当天已成功日程只由明确编辑或重新生成替换；长期人格保存不重写当天内容。日程时间只从 tasks 的 daily-state 计划读取，人设页不保存第二份计划。自动生成暂停、账号／日期互斥、失败退避和三次上限见 [人设与日程](人设与日程.md)。

## 记忆管理

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/memory/policy` | `{policy,revision}`；默认 recentCount=3、recentDays=7、retentionDays=30 |
| `PUT /api/memory/policy` | `{policy:{recentCount,recentDays,retentionDays},revision}` |
| `GET /api/memory/users` | `accountId`、`channel`、`q` 筛选，`cursor` 为偏移，`limit` 1–100；返回 users、nextCursor |
| `GET /api/memory/users/:id` | 当前范围条目、来源、近期原文、遗忘状态、修订与整理进度 |
| `PUT /api/memory/items/:id` | `{accountId,text,revision}` |
| `DELETE /api/memory/items/:id` | `{accountId,revision}`；保存删除与来源忽略记录 |
| `POST /api/memory/users/:id/summarize` | `{accountId,channel}`；手动 LLM 整理，引用原调用费用 |
| `POST /api/memory/users/:id/forget` | 遗忘并停止记录 |
| `POST /api/memory/users/:id/remember` | 恢复可靠的未来新消息，不恢复旧内容 |
| `POST /api/memory/users/:id/preview` | `{accountId,channel}`；返回实际召回及 readonly:true，不调用模型、不写回 |

用户和会话 ID 放入 URL 时使用 `encodeURIComponent`；未传 accountId 时使用当前工作账号，显式空账号只查看未知归属历史。公开召回排除私信，不按同名合并身份。近期仅把 confirmed 回复视为已说过的话。来源已按保留策略清理时显示不可用，不能复制原文绕过策略；旧摘要标记来源不完整。编辑、删除和遗忘使旧后台结果失效，恢复旧数据库继续重放独立遗忘／来源忽略／删除账本，见 [记忆策略](记忆策略.md) 与 [迁移与恢复](迁移与恢复.md)。

## 主程序、消息与日志详情

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/program` | control、busy、stage／stages、queue、lastTick、nextTick、cooldown、settings、revision、limits |
| `PUT /api/program/settings` | `{settings:{mode?,maxAgeHours?,maxPerRound?,publicPerHour?,privatePerHour?},revision?}` |
| `GET /api/messages` | 当前工作账号消息元数据；status、channel、cursor、limit 筛选，返回 items、nextCursor |
| `GET /api/messages/:id` | 当前工作账号的正文、草稿、回执及错误详情；没有归属或不存在返回 404 |
| `GET /api/program/logs` | level、channel、from、to、correlationId、cursor、limit 筛选，返回 items、nextCursor |

运行设置范围为 maxAgeHours 1–48、maxPerRound 1–4、publicPerHour 1–25、privatePerHour 1–100；轮询间隔只在任务页维护，传入其他运行字段会拒绝。日志 from 含、to 不含，均为 Unix 毫秒；页面负责把北京时间日期转成范围。消息和日志的 limit 最多一百，cursor 是接口返回值，不能混用。阶段包括身份、分渠道采集、队列、上下文、召回、语义、生成、发送、回查和整理；等待／退避由当前状态展示，重启遗留阶段标记 interrupted。

消息正文仅在受管理鉴权的详情按需读取。`unknown` 只能回查，不能将日志错误提示或超时转换为重发按钮，详见 [出站与回执](出站与回执.md)。

## 任务计划与宿主结果

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/tasks` | timezone、revision、control、backupScope、hostAvailable、tasks；每条含 lastRun、nextRunAt、hostResult |
| `PUT /api/tasks/:id` | `{revision?,enabled?,time?,intervalSeconds?}`；主循环启停是显式恢复／暂停 |
| `POST /api/tasks/:id/run` | 明确单次执行，返回 `{run}`；main 不提供另起轮次入口 |
| `GET /api/tasks/runs` | taskId、accountId、cursor、limit 筛选；返回 items、nextCursor |
| `GET /api/tasks/runs/:id` | `{run}`，单次执行详情 |

任务 ID 为 main、daily-state、memory-summary、morning-post、evening-post、backup、health。默认 main 等待六十秒、日程 06:00／记忆 03:00 启用，早安 08:00／晚安 23:00／备份 02:30 关闭，宿主健康每五分钟。所有时间为 Asia/Shanghai。主循环间隔 30–3600 秒，按上一轮结束后等待；其他计划保存不改变全局控制。

任务运行有持久唯一实例，手动与自动共用互斥。关闭计划可以取消未提交工作；已提交 unknown 只能回查。问候帖只在计划后五分钟内开始，且仍要求 running／auto、公开额度、正文校验与唯一回执；重试不重写冻结正文。run 的 callIds 与 cost 引用原账单。宿主维护只允许 backup／health 与限定操作，请求已写入和结果已完成是不同状态；未安装桥接时明确不可用，不执行任意命令、不挂载 Docker socket、不变更证书续期，见 [任务与宿主维护](任务与宿主维护.md) 和 [宿主维护桥接](宿主维护桥接.md)。

## 统一计费

`GET /api/billing/summary` 返回 range、totals、daily、models、purposes、priceSource；`GET /api/billing/calls` 返回 range、items、nextCursor。

两者共用 `from=YYYY-MM-DD`、`to=YYYY-MM-DD` 的北京时间半开范围，from 含、to 不含；不传时为今天。页面“结束日期包含当天”需转换为下一天传入 API。可按 provider、model、purpose、accountId、interactionId 精确筛选；流水另支持 limit（1–100，默认三十）和接口返回的不透明 cursor。切换筛选应清空旧 cursor。

totals 包含 calls、input、output、cacheRead／cache、cacheWrite、totalTokens、reasoning、costUSD、priced、unpriced、unknown、legacyRows。reasoning 属于 output 子集，不能再次相加。没有可估价调用时 costUSD=null；部分已定价时只合计可估价部分，同时展示未定价与未知数量。金额保留足够小数位，不把小额四舍五入成“免费”。流水的 usage 或其字段可为 null，失败、中止、重启中断仍展示实际可得用量。

旧 usage 保留 token 与明确未知来源，缺乏模型、用途或账号证据时不伪造匹配；新请求不重复写旧表。人设、任务及状态汇总引用同一流水，不新增第二份费用。记录不含提示词、生成正文或 Key，价格为 Pi 内置目录的调用时快照，具体语义见 [模型计量](模型计量.md)。

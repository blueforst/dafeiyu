# 前端面板接口交接

生产应用为 0.1.16、浏览器为 0.1.15，入口为 [生产面板](https://43.133.80.237)。本文七页及新增接口已上线，日志集中在主程序页，主页面不再重复显示；真实模型、当前 Chat DOM 和实际收发仍单独验收。发布证据见 [0.1.15](发布记录/2026-10-28-0.1.15.md) 与 [0.1.16](发布记录/2026-10-28-0.1.16.md)，进度以 [任务清单](../openspec/changes/add-seven-page-production-bot/tasks.md) 为准。

七页职责与交互见 [七页面板](七页面板.md)；[迁移与恢复](迁移与恢复.md) 说明账号归属、修订、遗忘与数据范围。管理接口不提供绕过 outbox、额度或 unknown 回查限制的任意草稿发送入口。

## 认证与请求约定

- 生产页面与 API 同源，使用相对 URL。宿主 Nginx 的 HTTPS + Basic Auth 完成认证，前端不保存密码、不接触 X Cookie 或模型密钥。
- X-Ingress-Key 是 Nginx 到后端的内部凭据，不得写进前端。
- 所有 POST、PUT、DELETE 及其他非 GET／HEAD 请求添加 `X-Workflow-Control: 1`。后端同时校验 Origin。不要跨域代理控制接口。
- 成功控制响应为 `{"ok":true,"control":"paused"}` 等；失败一般为 409，响应 `{"error":"中文说明"}`。
- 控制操作可能等待当前浏览器操作完成，请使用进行中状态防止重复点击，超时至少 110 秒。
- 时间均为 Unix 毫秒或 ISO 字符串，页面显示使用 Asia/Shanghai。

## GET /api/status

返回字段：

| 字段 | 含义 |
| --- | --- |
| control | paused / draining / manual / running |
| busy | 当前是否正在执行一个处理轮次 |
| accountId | 七页开发版当前工作账号；未确认时为空，不用预设账号代替 |
| config.mode | draft / auto；与 control 是两个独立维度 |
| config.model | provider、id、api、configured；没有密钥 |
| config.publicPerHour / privatePerHour | 内部通道额度 |
| configError | 配置解析失败的中文说明；正常为空 |
| browser | handle、loggedIn、needsHuman、reason |
| lastTick | 最近一次完整处理轮次完成的时间；0 代表尚未完成 |
| cooldown.public / private | 通道退避截止时间；0 代表没有退避 |
| stats.messages | channel、status、count 的数组 |
| stats.usage | 七页开发版为统一聚合：input、output、cache／cacheRead、cacheWrite、totalTokens、reasoning、calls、costUSD、priced、unpriced、unknown、legacyRows；costUSD 可为 null，不能将未知项当零费用 |
| stats.oldestQueued | 最旧排队消息时间，可为 null |
| observationStartedAt | 业务草稿观察开始时间；空字符串代表尚未开始 |
| now | 服务器当前时间 |

建议每 10 秒刷新一次。浏览器未登录、模型未配置属于待设置状态，不代表面板 API 故障。只有生成第一条实际草稿后才开始业务观察，不要把容器在线时间显示成已完成 12 小时业务验收。

消息状态可能为 queued、generating、draft、sending、confirmed、unknown、skipped、failed。请给 unknown 显示明确的“发送结果待回查”，不要显示成发送失败后可直接重试。

## 日志

`GET /api/logs` 返回最近 100 行，按最新在前排列。每行包含 id、at、level、event、detail。

`GET /api/events` 为 SSE。兼容的 `logs` 事件仍是最近 30 行日志的完整数组，每五秒推送一次，并带心跳；收到后替换列表，不应重复追加。七页开发版另发送 `program`（control、busy、stages、nextTick）及 `tasks`（与任务列表同结构），只消费 logs 的旧客户端可以继续工作。原生 EventSource 可自动重连，关闭组件时释放连接。

常规日志仅提供运行元数据，不保存消息正文、私信内容或完整 Key。七页开发版在独立受管理鉴权的消息／记忆详情接口按需读取原文；日志列表不能用详情正文填充。渲染 detail 及其他外部文本使用纯文本 DOM，禁止 innerHTML。

## 控制接口

| 方法与路径 | 行为 |
| --- | --- |
| POST /api/control/pause | 停止新任务，中止正在生成的内容，等浏览器操作结束后暂停 |
| POST /api/control/resume | 读取浏览器当前登录账号，完成登录及人工状态检查后恢复；运行模式由有效配置决定；七页开发版在主程序页维护 |
| POST /api/control/takeover | 排空程序操作，进入 manual，随后允许 noVNC 连接 |
| POST /api/control/release | 关闭交互式 VNC 客户端，回到 paused；不会自动恢复处理 |

人工接管时必须先 release，再 resume。未登录、账号无法识别或需要人工验证时 resume 会失败并保持暂停。处理期间退出登录或切换账号会暂停；检查后重新恢复即可使用当前账号。不要把 resume 文案写成“开启自动发送”：在 draft 配置下恢复只会生成草稿。

## 浏览器桌面

人工接管成功后打开：

`/desktop/vnc.html?autoconnect=1&resize=scale&reconnect=0&path=desktop/websockify`

- noVNC WebSocket 地址为同源的 `/desktop/websockify`，使用 wss。
- 非 manual 状态访问桌面返回 423。请先接管，再打开或挂载桌面。
- 可以沿用新标签页，也可在同源 iframe 内嵌；不要修改为浏览器内部 IP、6080、5900 或 CDP 端口。
- release 会主动断开现有连接。只有 manual 状态才展示重新连接入口。
- 账号登录、验证码、私信解锁由用户本人操作；面板不应保存这些输入。

## 前端开发与部署

静态文件当前在 `public/`，由 Fastify 直接提供，七页沿用无构建步骤的原生 ES 模块和 hash 路由；本提案不更换前端框架。构建、自动化测试、批量界面检查和渲染一律在服务器执行。

前端改动需要重新构建业务镜像并切换固定版本，避免原地覆盖正在运行的容器。浏览器镜像无需为了纯前端改动重建。后端继续开发时应保留 public/ 的前端 WIP。

已有 test/ui-acceptance.mjs 使用当前按钮文案和 DOM ID。改版后由前端负责人适配这些定位器，保留认证、接管、释放后阻断、账号缺失保护等行为断言。

纯前端发布时仅更新 APP_VERSION，保留 BROWSER_VERSION；两者未指定时回退到 ROLE_VERSION。发布期间如用户正在 manual 接管，不要重启代理桌面的业务容器。

## 模型目录（0.1.13）

`GET /api/model/providers` 完整返回 pi 内置服务商，并附加 Command Code 预设。每项包含 id、name、group、baseUrl、apis、modelCount、available、reason、source。`available=false` 时展示条目及 reason，禁用选择；不能静默隐藏。source 为 pi 或 preset。

`GET /api/model/providers/:id/models` 返回可用服务商的聊天模型。各模型包含自己的协议和地址；切换模型时更新默认地址，保留用户手工编辑的地址。`costKnown=false` 时显示价格未提供。Command Code 的上下文及支持端点来自官方目录快照；目录不提供的价格不显示成免费。

`POST /api/model/discover` 按服务商选择模型目录端点：OpenCode/Command Code 使用 `/v1/models` 和 Bearer，Radius 使用 `/v1/config`。其他服务商沿用对应原生协议。


## 七页路由与配置修订（独立 staging）

| 页面 | hash 地址 | 主要接口 |
| --- | --- | --- |
| 主页面 | `#/overview` | status、logs、control、desktop |
| 模型 | `#/model` | model 及 providers、discover、test |
| 人设 | `#/persona` | persona、preview、daily |
| 记忆 | `#/memory` | memory/policy、users、items |
| 主程序 | `#/program` | program、program/settings、program/logs、messages |
| 定时任务 | `#/tasks` | tasks、tasks/:id、tasks/runs |
| 计费 | `#/billing` | billing/summary、billing/calls |

一级入口恰好七个。默认打开主页面，旧 `#/browser` 转到主页面并展开接管区；展开不自动进入接管或连接桌面。配置编辑离页时保留当前稿或明确放弃，保存失败保留编辑。各页支持系统浅／深色、375px、加载、空数据及错误状态。

面板设置分 model、persona、memory、program、tasks 域，各有 `revision`。保存时回传刚读到的相应域修订；旧修订返回 409，前端重新读取并让管理员决定保留哪些修改，不能自动覆盖。不同域保存互不覆盖。人设保存必须携带修订，日程和条目编辑携带各自内容修订；任务、策略、程序和模型接口支持域修订，前端同样应传入。配置供后续轮次或任务使用，不修改正在生成的快照或隐式恢复暂停状态。任务页的主循环 enabled 是显式全局控制，详见下文。

全局默认请求体上限 16 KiB；人设保存、试聊及日程内容编辑独立放宽为 128 KiB，仍校验正文和上下文额度。超限返回 413。

## 人设与虚构日程

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/persona` | persona、revision、fixedRules、daily、scheduleTime |
| `PUT /api/persona` | `{persona:{sections,triggers},revision}`；旧人格原文完整保留，不改控制状态 |
| `POST /api/persona/preview` | 未保存的 `{persona,channel,messages:[{role,text}],memory?,dailyState?}`；返回 draft、segments、hits、warning、calls、fees 与耗时 |
| `GET /api/persona/daily` | 当日状态、当前时段、尝试次数、重试时间、近七日历史及费用引用 |
| `GET /api/persona/daily/history` | `{items}`，当前工作账号近七日最终日程修订 |
| `PUT /api/persona/daily` | `{date,content,revision}`；content 含 date、fictional:true、periods、meals、activities、mood |
| `POST /api/persona/daily/generate` | 明确手动重新生成，可带 `{revision}`；没有可靠当前账号时拒绝 |

section 为 `{id,title,content}`，trigger 为 `{id,title,condition,content,enabled,order}`。所有分区、条件和触发正文合计不超过 20,000 字符，ID 唯一。试聊最多三十条模拟消息、40,000 字符上下文，最后一条为 user；只用模拟记忆，不访问 X、不创建真实消息、记忆或出站。fees 是同交互下语义判定与最终生成的原流水合计。

日程内容明确虚构，与用户事实、已确认角色经历分开。当天已成功日程只由明确编辑或重新生成替换；长期人格保存不重写当天内容。日程时间只从 tasks 的 daily-state 计划读取，人设页不保存第二份计划。自动生成暂停、账号／日期互斥、失败退避和三次上限见 [人设与日程](人设与日程.md)。

## 主程序、消息与日志详情

| 方法与路径 | 请求或返回 |
| --- | --- |
| `GET /api/program` | control、busy、stage／stages、queue、lastTick、nextTick、cooldown、settings、revision、limits |
| `PUT /api/program/settings` | `{settings:{mode?,maxAgeHours?,maxPerRound?,publicPerHour?,privatePerHour?},revision?}` |
| `GET /api/messages` | 当前工作账号消息元数据；status、channel、cursor、limit 筛选，返回 items、nextCursor |
| `GET /api/messages/:id` | 当前工作账号的正文、草稿、回执及错误详情；没有归属或不存在返回 404 |
| `GET /api/program/logs` | level、channel、from、to、correlationId、cursor、limit 筛选，返回 items、nextCursor |

运行设置范围为 maxAgeHours 1–48、maxPerRound 1–4、publicPerHour 1–25、privatePerHour 1–100；轮询间隔只在任务页维护，传入其他运行字段会拒绝。日志 from 含、to 不含，均为 Unix 毫秒；页面负责把北京时间日期转成范围。消息和日志的 limit 最多一百，cursor 是接口返回值，不能混用。阶段包括身份、分渠道采集、队列、上下文、召回、语义、生成、发送、回查和整理；等待／退避由当前状态展示，重启遗留阶段标记 interrupted。

消息正文仅在受管理鉴权的详情按需读取。`unknown` 只能回查，不能将日志错误提示或超时转换为重发按钮，详见 [出站与回执](出站与回执.md)。

| `GET /api/tasks/runs` | taskId、accountId、cursor、limit 筛选；返回 items、nextCursor |
| `GET /api/tasks/runs/:id` | `{run}`，单次执行详情 |

任务 ID 为 main、daily-state、memory-summary、morning-post、evening-post、backup、health。默认 main 等待六十秒、日程 06:00／记忆 03:00 启用，早安 08:00／晚安 23:00／备份 02:30 关闭，宿主健康每五分钟。所有时间为 Asia/Shanghai。主循环间隔 30–3600 秒，按上一轮结束后等待；其他计划保存不改变全局控制。

任务运行有持久唯一实例，手动与自动共用互斥。关闭计划可以取消未提交工作；已提交 unknown 只能回查。问候帖只在计划后五分钟内开始，且仍要求 running／auto、公开额度、正文校验与唯一回执；重试不重写冻结正文。run 的 callIds 与 cost 引用原账单。宿主维护只允许 backup／health 与限定操作，请求已写入和结果已完成是不同状态；未安装桥接时明确不可用，不执行任意命令、不挂载 Docker socket、不变更证书续期，见 [任务与宿主维护](任务与宿主维护.md) 和 [宿主维护桥接](宿主维护桥接.md)。

## 统一计费

`GET /api/billing/summary` 返回 range、totals、daily、models、purposes、priceSource；`GET /api/billing/calls` 返回 range、items、nextCursor。

两者共用 `from=YYYY-MM-DD`、`to=YYYY-MM-DD` 的北京时间半开范围，from 含、to 不含；不传时为今天。页面“结束日期包含当天”需转换为下一天传入 API。可按 provider、model、purpose、accountId、interactionId 精确筛选；流水另支持 limit（1–100，默认三十）和接口返回的不透明 cursor。切换筛选应清空旧 cursor。

totals 包含 calls、input、output、cacheRead／cache、cacheWrite、totalTokens、reasoning、costUSD、priced、unpriced、unknown、legacyRows。reasoning 属于 output 子集，不能再次相加。没有可估价调用时 costUSD=null；部分已定价时只合计可估价部分，同时展示未定价与未知数量。金额保留足够小数位，不把小额四舍五入成“免费”。流水的 usage 或其字段可为 null，失败、中止、重启中断仍展示实际可得用量。

旧 usage 保留 token 与明确未知来源，缺乏模型、用途或账号证据时不伪造匹配；新请求不重复写旧表。人设、任务及状态汇总引用同一流水，不新增第二份费用。记录不含提示词、生成正文或 Key，价格为 Pi 内置目录的调用时快照，具体语义见 [模型计量](模型计量.md)。

# 出站、浏览器日志与平台回执

业务出站由 `outbox` 表保存工作账号、渠道、来源消息或任务实例、目标、冻结正文及平台回执。相同工作账号、出站类型和来源只有一条记录；再次执行必须使用同一正文及目标。`prepared` 可以取消，`submitting` 在进程重启时变为 `unknown`，后者只允许回查。平台确认必须包含唯一消息 ID。

应用应先 `prepare()`，再以 `begin()` 原子记录提交意图，并把返回的出站 ID 放入 `Event.outboxId`。浏览器 journal 使用同一个 ID，在点击提交前持久化正文哈希、工作账号、目标和提交时间。日志不保存正文；未确认的 journal 记录不参与已完成记录的有界清理。发送接口重复收到同一个 ID 时只回查，不能再次点击提交。日志损坏时停止启动自动发送，不能当作首次运行忽略。

公开回复与独立帖子都计入公开渠道额度。应用在统计时应将 outbox 数量与旧消息数量合并，排除 `outbox.source_id = messages.id` 的重复记录。所有自动回复、私信、帖子、回查和接管共用浏览器服务的串行入口；自动业务只有 `auto` 模式可以操作。

## 采集和身份

公开平台 ID 来自帖子时间链接，引用卡片中的时间和正文不作为主帖读取。缺失或无法解析的时间保留 `timestamp = 0`、`timestampReliable = false`，不填入当前时间。私信必须存在稳定的平台消息 ID 和明确方向，不以正文哈希生成消息 ID，不以气泡几何位置猜测入站／出站。最新消息为出站时不排入待回复队列。

采集轮换通知提及、搜索和本人最近两个帖子，私信列表及消息请求最多读取六个会话；每页读取量有上限。跨来源按平台 ID 和渠道去重，持久去重及账号命名空间由应用存储负责。无法识别的结构返回适配警告，不把异常解释为没有新消息。

`POST /collect/public` 与 `POST /collect/private` 分别执行公开和私信采集，使主程序能在真实操作边界记录独立阶段；两个接口使用相同的串行队列、自动控制状态和当前登录账号检查。兼容的 `POST /collect` 按顺序执行两个操作，并在转入私信采集前再检查账号。接口均只供受内部凭据保护的工作流使用。

发送前再次检查当前账号、控制状态、目标 ID、可靠时间和正文；私信还会重新读取最新消息 ID。公开正文继续使用 X 加权长度规则，所有出站正文沿用链接和账号提及限制。

## 平台确认

浏览器只监听页面自身产生的 `/i/api/` 响应，解析平台返回的作者、唯一帖子 ID、正文、创建时间和 `in_reply_to_status_id_str`。不会构造私有 API 请求。公开回复必须同时匹配工作账号、原目标、冻结正文和提交时间；独立帖子还要求其不是回复。相同正文出现在其他目标下不能确认。多个满足条件的唯一 ID 也保持 unknown。

私信回查限定原会话，要求明确出站方向、稳定平台 ID、相同正文和晚于提交的可靠时间。点击、toast 或当前页面出现文本均不单独作为成功证据。平台明确拒绝返回 `rejected`，应用按对应通道设置四小时退避。

## 验证范围

`test/outbox.test.ts` 验证冻结、互斥、重启恢复、取消和共享额度；`test/transport.test.ts` 验证 journal、作者／目标／时间／唯一 ID 回执校验及正文限制。现有 Camoufox 模拟 DOM 验收可以继续运行，新增真实页面的结构与 Chat 解锁状态仍需服务器上的实际账号只读取证。

这些测试属于存储和模拟协议证据，不能替代真实 X 页面采集、真实发送或双方可见回执。当前代码对未能确认的加密 Chat 结构采用明确停止，不声称已完成真实账号适配。

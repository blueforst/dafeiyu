# 对话与角色记忆

记忆严格按工作账号、原始用户／会话标识和公开／私信渠道存储。无法确认归属的旧摘要保留在空账号下，只能作为历史检查；不会自动分给当前登录账号。旧摘要导入为“来源不完整”，不会伪造来源消息或链接。

默认召回最近七天内三次已处理互动；只有 `confirmed` 的回复被视为已经说过的话。草稿、跳过或失败互动可以提供入站原文，但不把未发送的草稿写成角色发言。原文默认保留三十天，可在记忆页调整数量、窗口和保留天数。公开召回只使用同账号公开内容，私信可以使用相同确切用户标识的允许内容；系统不按姓名或正文合并公开用户和未知私信会话。

长期召回按最近更新优先，最多三十条且序列化内容最多八千字符，超出的数量通过 `recallOmitted` 明示；这些条目仍完整保存并可在详情中查看。生产召回只带来源 ID、URL、时间和可用状态，不重复附上所有来源原文，避免把同一长消息在近期及长期来源中反复注入。条目详情才按需读取原文。

整理以数据库的 `processed_seq` 为游标，而不是比较平台时间与摘要写入时间。每五条新处理入站安排增量整理，每日任务只补存在新增的范围。单次最多取五十条，后续仍由游标继续处理。请求包含有效旧记忆和新增原文，未在本批再次出现的旧事实仍保留。模型只能通过既有条目 ID 和可验证来源修正事实，不能删掉未提及的记忆；角色回复、虚构人设和日程都不作为用户事实。

人工编辑和删除提升记忆范围修订；模型结果必须同时匹配账号、遗忘代次、记忆修订、游标和原始输入快照，旧请求不写回。删除还会忽略该条目的旧来源并记录内容指纹，避免再次整理旧原文后复活。删除记录保存在数据库和同目录独立 `memory-mutations.json`；遗忘状态及历史截止沿用独立 `forget-ledger.json` 与 `forget-history.json`。恢复数据库时必须保留这些当前账本，不得用旧备份覆盖；服务启动先重放账本，再允许处理。即使遗忘后又恢复记录，历史截止仍会清除旧数据库带回的遗忘前内容。数据库备份本身不包含这些账本，恢复到新机器必须另行准备当前账本以及面板配置和凭据。

遗忘会删除原文、长期条目、整理进度及该用户关联的角色经历，并停止后续记录。重新允许只记录今后的互动，不恢复旧内容。条目来源保留消息 ID、可用 URL 和时间；当原文已按策略清理，页面显示来源原文已不可用，而不复制一份绕过保留策略。

角色经历独立保存，只有明确来源消息或带唯一平台 ID 的确认回执才能写入。虚构日程不会自动转成角色真实经历或用户事实。召回预览仅查询，既不调用模型，也不创建消息、记忆或出站。

## 管理接口

接口沿用面板管理鉴权、来源检查和控制请求标记。保存策略不恢复处理。

| 方法与路径 | 请求和结果 |
| --- | --- |
| `GET /api/memory/policy` | 返回 `policy` 和该域 `revision` |
| `PUT /api/memory/policy` | 接收 `{policy:{recentCount,recentDays,retentionDays},revision}`；旧修订返回 409 |
| `GET /api/memory/users` | 按 `accountId`、`channel`、`q` 搜索，`cursor` 是偏移，`limit` 为 1–100；返回 `users`、`nextCursor` |
| `GET /api/memory/users/:id` | 查询账号和渠道下的条目、来源、近期互动、遗忘状态和整理进度 |
| `PUT /api/memory/items/:id` | 接收 `{accountId,text,revision}`，只编辑对应账号条目 |
| `DELETE /api/memory/items/:id` | 接收 `{accountId,revision}`，删除并保存独立抑制记录 |
| `POST /api/memory/users/:id/summarize` | 接收 `{accountId,channel}`，明确手动整理；返回是否写入及原模型调用 `callId`／费用引用 |
| `POST /api/memory/users/:id/forget` | 遗忘并停止记录 |
| `POST /api/memory/users/:id/remember` | 恢复未来记录 |
| `POST /api/memory/users/:id/preview` | 只读返回实际 `memories`、`recent`、`experiences`；不写入 |

URL 中的用户／会话标识应使用 `encodeURIComponent`。未传账号时使用当前工作账号；显式空账号用于查看未知归属历史。

## 回放与分级派生数据

回放快照和结果遵循原文保留、遗忘与独立删除账本；人工修改/删除记忆使相关快照失效，并中止在途旧结果写回。回放只用当前允许的记忆，不从旧快照恢复被删事实；公开回放不读取私信，私信样本需明确勾选，汇总不包含私信开头。过滤、忽略与合并原因不进入用户事实。详见[人设回放](人设回放.md)。

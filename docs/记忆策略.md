# 对话与角色记忆

记忆严格按工作账号、原始用户／会话标识和公开／私信渠道存储。无法确认归属的旧摘要保留在空账号下，只能作为历史检查；不会自动分给当前登录账号。旧摘要导入为“来源不完整”，不会伪造来源消息或链接。

默认召回最近七天内三次已处理互动；只有 `confirmed` 的回复被视为已经说过的话。草稿、跳过或失败互动可以提供入站原文，但不把未发送的草稿写成角色发言。原文默认保留三十天，可在记忆页调整数量、窗口和保留天数。公开召回只使用同账号公开内容，私信可以使用相同确切用户标识的允许内容；系统不按姓名或正文合并公开用户和未知私信会话。

`reply-context-v4` 把 `recent` 从“关于对方的记忆”取出，单独放在记忆之后、当前对话之前的“与对方的近期往来”段。段内说明 `reply` 是已经发出的原话，没带 `reply` 表示当时没有发出回复，并要求本次不重复其中的梗、口癖、开头、收尾和说法。没有往来时写明暂无；数据范围、条数、时间窗口及遗忘规则不变。不给用户乙带入发给甲的回复，也不再把所有人的开头片段放入提醒。表情提醒继续只使用计数，不携带他人原文。

长期召回按最近更新优先，最多三十条且序列化内容最多八千字符，超出的数量通过 `recallOmitted` 明示；这些条目仍完整保存并可在详情中查看。生产召回只带来源 ID、URL、时间和可用状态，不重复附上所有来源原文，避免把同一长消息在近期及长期来源中反复注入。条目详情才按需读取原文。

整理以数据库的 `processed_seq` 为游标，而不是比较平台时间与摘要写入时间。每五条新处理入站安排增量整理，每日任务只补存在新增的范围。单次最多取五十条，后续仍由游标继续处理。请求包含有效旧记忆和新增原文，未在本批再次出现的旧事实仍保留。模型只能通过既有条目 ID 和可验证来源修正事实，不能删掉未提及的记忆；角色回复、虚构人设和日程都不作为用户事实。

人工编辑和删除提升记忆范围修订；模型结果必须同时匹配账号、遗忘代次、记忆修订、游标和原始输入快照，旧请求不写回。删除还会忽略该条目的旧来源并记录内容指纹，避免再次整理旧原文后复活。删除记录保存在数据库和同目录独立 `memory-mutations.json`；遗忘状态及历史截止沿用独立 `forget-ledger.json` 与 `forget-history.json`。恢复数据库时必须保留这些当前账本，不得用旧备份覆盖；服务启动先重放账本，再允许处理。即使遗忘后又恢复记录，历史截止仍会清除旧数据库带回的遗忘前内容。数据库备份本身不包含这些账本，恢复到新机器必须另行准备当前账本以及面板配置和凭据。

遗忘会删除原文、长期条目、整理进度及该用户关联的角色经历，并停止后续记录。重新允许只记录今后的互动，不恢复旧内容。条目来源保留消息 ID、可用 URL 和时间；当原文已按策略清理，页面显示来源原文已不可用，而不复制一份绕过保留策略。

遗忘和恢复只由管理员在记忆页及其现有管理接口执行。消息正文不再触发这两种操作：“忘了我吧”“忘记我吧”“重新记住我”等消息照常经过分级、入库和生成，仍受原有遗忘、额度与发送约束。已经被管理员遗忘的用户不能用消息恢复，仍不入库或回复，只有管理员恢复后才记录未来互动。

从 `reply-context-v3` 加入、由 v4 保留的固定系统约束要求：被请求忘掉对方、删除聊天记录或记忆时，不声称已经忘记或删除；如实说明角色做不到，记录由运营者管理。该约束不代表删除已经执行，也不新增自动通知管理员或自动删除机制。该固定前缀首次更新后需要重新建立模型缓存；v4 的近期往来分段只改 user，独立账本、管理接口及已有遗忘状态保持原有规则。

角色经历与普通互动独立处理。回复提示词只召回当前账号已确认的公开发帖和可用的人工登记经历，按发生时间取最近十条；普通回复仍保存为 `interaction` 记录并在对应用户详情中展示，但不进入角色经历段。因此发出大量回复不会挤掉早晚安帖，也不会把回复甲的内容放进给乙的角色经历。两次生成之间只有普通互动时，经历段保持字节一致。虚构日程不会自动转为真实经历或用户事实。

## 人工登记与经历核对

记忆页的角色经历分区只作用于当前工作账号，账号切换后不沿用原账号列表。管理员可登记正文、发生日期和可选的当前账号帖子链接；正文为 1–1,200 字符，每账号最多 200 条人工经历，隐藏项仍计入上限。只有人工经历可以编辑正文、日期和链接；自动发帖经历可以隐藏或取消隐藏，原平台回执和出站冻结正文保持不变。

无链接的条目按管理员登记直接可用，核对说明标为无需平台核对，不产生伪造的平台回执。带链接的条目先保存为 `pending`，不进入回复；仅接受 `https://x.com/<当前账号>/status/<帖子ID>`。主程序在下一轮既有浏览器互斥内只读核对，每轮至多三条，不点击发送或页面设置。作者、平台 ID 和可靠发布时间一致后标为 `verified`，采用平台发布时间作为发生时间；管理员原登记日期另存 `declared_at` 并返回 `declaredOccurredAt`。作者、ID、时间或页面不可读时标为 `failed` 并显示原因，不计平台拒绝退避。

暂停、接管和排空时不处理核对；在途结果必须仍匹配账号、待核对状态、未隐藏及条目修订，否则不写回。浏览器安全暂停错误向主循环传播。编辑人工条目的正文、日期或链接后重新确定核对状态；隐藏／取消隐藏仅切换显示和召回，不使待核对或失败条目变为可用。

人工经历以 `user_id='role'`、`kind='manual'` 保存，不属于任何用户事实，也不因遗忘某个用户而删除。自动确认的互动仍按对应用户遗忘约束删除。召回预览仅查询，既不调用模型，也不创建消息、记忆或出站。

## 管理接口

接口沿用面板管理鉴权、来源检查和控制请求标记。保存策略不恢复处理。

| 方法与路径 | 请求和结果 |
| --- | --- |
| `GET /api/memory/policy` | 返回 `policy` 和该域 `revision` |
| `PUT /api/memory/policy` | 接收 `{policy:{recentCount,recentDays,retentionDays},revision}`；旧修订返回 409 |
| `GET /api/memory/users` | 按 `accountId`、`channel`、`q` 搜索，`cursor` 是偏移，`limit` 为 1–100；返回 `users`、`nextCursor` |
| `GET /api/memory/users/:id` | 查询账号和渠道下的条目、来源、近期互动、遗忘状态和整理进度 |
| `PUT /api/memory/items/:id` | 接收 `{accountId,text,revision}`，只编辑对应账号条目 |
| `DELETE /api/memory/items/:id` | 接收 `{accountId,revision}`，删除并保存独立抑制记录 |
| `POST /api/memory/users/:id/summarize` | 接收 `{accountId,channel}`，明确手动整理；返回是否写入及原模型调用 `callId`／费用引用 |
| `POST /api/memory/users/:id/forget` | 遗忘并停止记录 |
| `POST /api/memory/users/:id/remember` | 恢复未来记录 |
| `POST /api/memory/users/:id/preview` | 只读返回实际 `memories`、`recent`、`experiences`；不写入 |

URL 中的用户／会话标识应使用 `encodeURIComponent`。未传账号时使用当前工作账号；显式空账号用于查看未知归属历史。

角色经历使用单独接口，不接受请求中的账号覆盖：

| 方法与路径 | 请求和结果 |
| --- | --- |
| `GET /api/memory/experiences` | `cursor` 为不透明游标，`limit` 为 1–100；返回当前账号 `items`、`nextCursor` 和列表 `revision` |
| `POST /api/memory/experiences` | `{text,occurredAt,url?,revision}`；修订为列表修订，日期可为北京日期 `YYYY-MM-DD` 或毫秒时间；空 URL 代表无链接 |
| `PUT /api/memory/experiences/:id` | 同登记字段，修订为该条 `revision`；仅人工条目允许编辑 |
| `POST /api/memory/experiences/:id/hide` | `{revision}`；隐藏对应账号条目，不删除或改写原回执 |
| `POST /api/memory/experiences/:id/unhide` | `{revision}`；取消隐藏，保留原核对状态 |

条目返回 `id`、`type/kind`、`origin`、正文、`occurredAt`、`declaredOccurredAt`、URL、`verifyStatus`、`verifyReason`、`hidden`、`revision`、创建／更新时间和既有回执。修改返回 `{ok,item,revision}`，其中外层修订供下次登记使用；过期修订返回 409。接口只改登记与附加信息，不调用模型、不恢复业务。日志仅记录条目 ID、账号及结果，不包含正文或链接原文。

迁移 13 只新增经历附加信息和补录请求两表，旧 `role_experiences` 保持十列。回退仅支持经过检查的安全空／默认窗口；存在人工经历、有效隐藏／核对／日期修订或任何补录请求及结果时拒绝删表，不能让旧版忽略这些约束。详见[迁移与恢复](迁移与恢复.md)。本轮对应回归为 `test/role-experiences.test.ts` 及两套回退测试，结果以服务器验收记录为准。

## 回放与分级派生数据

回放快照和结果遵循原文保留、遗忘与独立删除账本；人工修改/删除记忆使相关快照失效，并中止在途旧结果写回。回放只用当前允许的记忆，不从旧快照恢复被删事实；公开回放不读取私信，私信样本需明确勾选，汇总不包含私信开头。过滤、忽略与合并原因不进入用户事实。详见[人设回放](人设回放.md)。

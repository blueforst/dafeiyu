# 参考帖子对照

更新日期：2026-10-28（北京时间）。

参考：[从人设到踩坑：「大肥鱼」是怎么做出来的](https://x.com/Remake___/status/2114696368883429580)。七页计划已经以这篇帖子为参考；本文是第二轮逐条扫描的结果，列出每个要点在本项目中的现状和归属。“现状”依据 2026-10-28 本机工作副本的代码与提案，不代表线上已验收。帖子中的数字（缓存命中率、费用、200 条上限）是作者账号与模型下的观察，本项目需自行测量。

## 新增提案

| 提案 | 覆盖的遗漏 |
| --- | --- |
| [improve-reply-prompt-context](../openspec/changes/improve-reply-prompt-context/proposal.md) | 提示词组装顺序与前缀缓存、命中规则靠近生成位置、末尾“先判断要不要回”、北京时间与时段、迟到提醒、回复语言、换个说法、颜文字／表情节制 |
| [add-reply-triage](../openspec/changes/add-reply-triage/proposal.md) | 排队优先级、同级新消息优先、普通闲聊更短时效、入队过滤广告和刷量、同一用户多条消息、骚扰跳过记录与临时忽略、公开每日额度、受限通道不占名额 |
| [add-unattended-health](../openspec/changes/add-unattended-health/proposal.md) | 软硬超时与看门狗、采集切块、浏览器内存自愈、“有消息但长时间没成功回复”等健康指标、告警记录、每日日报、账号冻结识别、简介披露、自动化标签、通知质量过滤检查 |
| [add-persona-replay](../openspec/changes/add-persona-replay/proposal.md) | 用同一批真实消息新旧人设对比、问题归类标注、批量看模板化、上线后观察 |
| [simplify-panel-activity-feed](../openspec/changes/simplify-panel-activity-feed/proposal.md)（补充） | 计费页改为 ZCode 用量统计样式，展示缓存读取占比与平均每条回复费用 |

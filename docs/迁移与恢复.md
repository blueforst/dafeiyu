# 七页工作流的数据迁移与恢复

本文对应 `add-seven-page-production-bot` 的基础迁移与配置实现，不能作为生产升级或真实平台验收完成的证明。构建、自动化测试与升级演练在独立服务器目录和独立数据上执行。

## 数据归属

SQLite 保留既有 `messages`、`memory`、`usage`、`users` 与日志，不把旧内容自动分配给当前浏览器账号。旧消息与旧摘要的 `account_id` 为 `''`，代表归属未知；新账号的生产查询必须显式传入当前规范化账号，未知内容不会进入新账号队列或召回。旧摘要原文保留；条目化迁入时由记忆模块标记来源不完整，不补造来源。

新消息保存内部事件 ID、原始采集 ID（`source_id`）、独立平台 ID（`platform_id`）和目标 ID（`target_id`）。内部 ID 由工作账号、渠道和平台 ID 组成。平台 ID 不可得时，原始采集 ID 只能用于内部去重；这不构成自动发送所需的平台证据。不同来源采集到相同账号、渠道和平台 ID 时由唯一索引去重，不同工作账号互相隔离。

新账号用户状态保存在 `account_users`，以工作账号和用户 ID 为复合键。旧 `users` 表保留为未知归属历史。长期摘要的主键扩为账号、用户和可见范围；公开查询继续排除私信。已处理入站使用独立单调序列，不依赖平台时间与摘要更新时间比较。

## 版本与重复启动

`schema_migrations` 逐条记录版本、名称与应用时间。每个模块以 `applyMigration` 注册自己的版本；编号用于唯一标识，不要求模块按连续序号初始化。每条迁移在 SQLite 立即事务内完成，SQL 或版本冲突会回滚，不留下已登记的半迁移。再次启动只核对既有版本，不重复执行 DDL 或重新归属数据。

基础版本为 1，后续模块版本分别为计量 2、记忆 3、日程 4、任务 5、出站 6、阶段 7。只允许在独立验收副本先测试旧库升级、重复打开、失败回滚和账号隔离，再按发布流程处理生产库。

## 面板设置与生效

`panel/settings.json` 保存模型、人设、任务、记忆和程序设置，每个分区维护独立修订。接口应调用 `mergePanelSettings(section, patch, revision)`：读取最新文件，检查该分区修订，仅合并本分区字段，以原子重命名保存。不同页面不会覆盖对方设置；同一分区的过期保存返回冲突，管理员重新读取后决定修改。模型设置是经过完整校验的整组替换，避免切换服务商后遗留旧协议字段。

任务页主循环间隔覆盖 `pollSeconds`；程序页覆盖运行模式、时效、单轮数量和通道额度；记忆策略默认最近三次、七天、原文三十天。配置读取在后续轮次生效，保存不修改 SQLite 中的暂停或接管控制状态，也不自动恢复业务。面板设置与密钥保持分离，密钥槽位和掩码规则沿用既有行为。

损坏设置会阻止正常配置读取与其他分区保存。为保留既有模型页的显式修复入口，未指定修订或指定初始修订 0 的完整模型保存可以重新建立设置文件；无法恢复原损坏文件里的其他分区。此操作不恢复业务。其他分区不会在损坏时静默按空文件保存。

## 遗忘账本与数据库恢复

`forget-ledger.json` 是数据库之外的独立遗忘开关；`forget-history.json` 保留历次遗忘边界与显式恢复后允许记录的时间起点，`forgotten-sources.json` 保留忘前平台或采集来源标识，不保存正文。新条目以工作账号和用户共同限定范围；旧版用户级记录保持原全局遗忘意图。当前账号明确恢复后，只解除该账号的后续记录限制，其他账号不随之解除。启动和记忆模块初始化时重放账本：标记遗忘、清除对应消息与摘要，并通过同步处理器清除记忆扩展表。遗忘会提升持久代次，旧后台生成不得写回；恢复只允许恢复时间之后、时间可靠的新来源记录，不恢复已删除内容。遗忘期间从未采集的旧消息也不能在恢复后补入；未知时间的消息在该范围保留拒绝记录语义，不能用当前采集时间冒充平台发生时间。已忘来源再次被正常采集时仍被拒绝；既有未知归属记录的全局来源忽略保持保守生效，不因新账号明确恢复就重采旧来源；恢复旧库也先清除遗忘边界之前的入库内容，即使当前开关已恢复，也不能复活忘前旧消息。入库使用单调逻辑时间，不用平台时间冒充处理进度，也避免同毫秒的新记录被旧边界误删。

数据库备份只包含业务 SQLite。恢复前保持程序暂停，停止使用该库的进程，保留最新独立遗忘开关、遗忘历史、来源忽略账本和记忆删除记录，不得用数据库归档覆盖它们。恢复库后先运行相同版本迁移并重放独立账本，再检查完整性、归属、unknown 出站和队列，最后按显式授权恢复业务。账本损坏或不可读取时停止启动，不能把失败当成没有遗忘记录。

本次基础变更没有自动创建生产库、源码或 profile 备份。配置、密钥和浏览器 profile 都不在数据库备份范围内，恢复运行需要分别准备这些现存资料。

## 回退边界

本迁移扩展了摘要主键并增加账号隔离；旧程序的无账号写入不等价于当前行为。不得仅切回旧镜像并继续处理新库。回退必须先暂停并排空，核对 unknown 出站，再在独立服务器验证目标程序与迁移后的数据兼容；若不兼容，使用经演练的数据转换或管理员提供的配套旧库恢复。旧库恢复仍必须重放最新独立遗忘记录。生产回退与数据转换的完整演练属于发布阶段，未因本文存在而视为完成。

## 初始暂停窗口的离线反向迁移

`deploy/rollback-schema.py` 只处理升级后仍处于初始暂停、尚无任何新功能有效数据的窗口，供服务器临时库演练及发布前核对。它不是已有新数据后的通用降级工具，也不切换镜像、控制容器或自动创建备份。当前生产尚未因此脚本执行任何回退；实际生产发布与回退仍按任务 10.2 单独验收。

操作前必须保持 paused 并停止所有使用目标库的 app、CLI 与其他访问者。SQLite 的独占事务能阻止并发写入，不能证明 WAL 模式下没有其他读连接，因此停止应用是前置操作，不能把脚本获得事务锁当成应用已经离线。

默认或显式 `--check` 以 SQLite 只读连接报告完整性、迁移版本、扩展表数量、可再导入的派生条目数量与拒绝原因，不修改数据库。示例路径仅代表服务器上单独准备的离线演练库：

```sh
python3 deploy/rollback-schema.py --db /srv/role-workflow-seven/rehearsal/legacy-upgrade.sqlite --check
```

只有核对结果 `eligible=true`，且确已停止全部库访问者，才可明确执行：

```sh
python3 deploy/rollback-schema.py --db /srv/role-workflow-seven/rehearsal/legacy-upgrade.sqlite --apply
```

反向事务会重新检查全部门禁：控制必须为 paused，没有 generating、sending 或 unknown 消息；不能有明确账号归属、升级后新消息来源或处理进度、新模型流水、日程尝试／修订、outbox、任务历史、阶段、记忆来源／修订／删除／整理进度等有效数据。未来版本、未知结构、表、视图或触发器也会拒绝处理。`memory_items` 仅允许未知账号、来源不完整、修订为 1，且文本及时间完全等于原摘要、具有匹配导入标记的可再导入派生条目；除此之外的长期记忆均拒绝丢弃。

旧版应用无法执行新 `forget-history.json`、`forgotten-sources.json` 与 `memory-mutations.json` 的约束，所以这些账本必须为空或不存在；原 `forget-ledger.json` 只能含旧版用户到布尔值的记录，不能有账号范围键。存在新的遗忘或删除约束，即使业务表已经为空也拒绝降级。面板 `settings.json` 也只能保留旧模型配置；非空人设、任务、记忆、程序配置或相关域已增加修订时拒绝降级，避免旧版忽略已经保存的新页面设置。脚本只读这些外部文件，不修改、删除或打包账本及设置。

允许执行时，仅删除已证明为空或可再导入的扩展表与迁移登记，移除新增消息索引及六个新增列，将未知账号的摘要恢复为旧版四列结构。原 messages、users、usage、logs、runtime 和外部账本保留；提交前再次执行完整性与结构检查。任何拒绝或 DDL／校验失败都回滚整笔事务，不留下半迁移。退出码 0 表示检查通过或执行成功，2 表示门禁拒绝，1 表示数据库或执行异常；以 JSON 的 mode、eligible、applied 和 reasons 区分状态。

一旦产生新业务或新约束，必须使用另外经过验证的数据迁移或配套恢复方案，不能为了切旧镜像删除这些记录。该工具通过初始窗口演练，不代表已验证有新数据后的降级，更不代表任务 10.2 的生产部署完成。

## 服务器验收

基础回归文件为 `test/migrations.test.ts` 与 `test/settings-revision.test.ts`，覆盖旧库保留与重复迁移、模块乱序与失败回滚、账号和来源去重、处理游标跨清理单调性、账号遗忘、旧全局遗忘的单账号显式恢复、重采旧来源拒绝、恢复旧库后清除忘前内容、分区修订与字段合并、配置生效及损坏设置行为。`test/rollback-schema.test.ts` 另覆盖旧库全模块升级、只读检查、四列摘要反向兼容、再升级、拒绝新数据／账本／配置及事务故障原子回滚。应与既有 `settings`、模型会话和安全回归一起在服务器执行；实际运行结果由实施证据记录，本文不把源码中的断言当作测试已通过。

## 六项后续提案准备回退到 0.1.16

新增 `deploy/prepare-proposals-rollback.py` 专门检查六项后续提案与已发布 0.1.16 应用的数据兼容性。它保留全部新表、迁移、出站正文、`validation_json`、回执、模型库、设置和外部账本，供之后升级继续读取；不会降回更早的四列摘要库。原 `rollback-schema.py` 仍只接受版本 1—7 的初始窗口，新版本 8 及后续迁移继续被原工具拒绝。两工具不能互换，也不会替代生产发布授权。

本工具不控制容器、宿主任务、浏览器、镜像或运行状态，不调用模型或 X，不创建自动备份。必须先通过正常控制接口暂停并排空，再停止 app、browser、CLI 及全部目标库访问者。`runtime.control` 必须已经为 `paused`，且命令显式提供 `--confirm-stopped`。现有浏览器锁需要能够独占取得；Firefox 残留锁会被拒绝，由管理员核实停机后处理，工具不删除锁。取得 SQLite 或 profile 锁不能证明没有其他读连接，显式停止确认仍是必要前提。

以下仅是服务器独立演练路径，不能直接替换成生产路径执行：

```sh
python3 deploy/prepare-proposals-rollback.py \
  --db /srv/role-workflow-seven/rehearsal/proposals.sqlite \
  --browser-profile /srv/role-workflow-seven/rehearsal/profile \
  --confirm-stopped --check
```

`--check` 为默认，只读返回目标版本、完整性、已识别迁移、拒绝原因与拟转换数量。仅当 `eligible=true`，且离线前提已经满足时，管理员才可另行明确执行同一命令并以 `--apply` 替换 `--check`。执行会在一个事务内把 `approved` 及带 `review=true` 的 `queued` 消息改回 `draft`，原草稿、前一版本、正文和批准元数据均原样保留；普通 queued 不变。旧版无法证明可安全提交的 prepared 公开正文或超出原私信门槛的候选，仅改为 cancelled，不删除冻结正文或校验记录。

公开短帖兼容检查采用保守充分条件：ASCII 计 1、其他码点计 2，同时要求 NFC、非空且无禁用内容。它会高估部分 emoji／组合序列，不能据此开放长帖。无法证明兼容的 prepared 候选停止；无法证明兼容的 unknown 拒绝准备回退，必须先在理解新日志的版本完成回查对账。普通短帖 unknown 保持原状态，目标版本继续只回查，不允许重发。

以下情况拒绝处理：未暂停、未确认停止、发送或模型请求仍在执行、任务或程序阶段仍在运行、回放批次或条目尚未中止、存在旧版无法执行的有效骚扰冷却、未对账的长帖 unknown、未来迁移／未知表列／索引／状态／视图／触发器、设置损坏，或模型库使用中引用与旧 `model` 物化配置不一致。新预检日志必须与数据库 cancelled 出站逐项匹配账号、目标、正文哈希与 `not_submitted` 回执，且不能与提交日志冲突；未对账记录必须先由新版本正常收束，工具不会为绕过门禁清理证据。

浏览器 `transport-journal.json` 和 `posting-preflight-v1.json` 只读保留。外部设置、遗忘／删除账本和两类日志在事务期间发生变化时拒绝提交；任何执行异常整笔回滚。没有删除 schema 或新增回退迁移登记，因此重新升级仍可沿用原登记；回归同时覆盖重复执行和再次打开新模块。

成功的 JSON 仍返回 `resumeAllowed=false`。这只证明兼容准备完成，不代表镜像已经切换、真实长帖已经验收或可以恢复自动运行；0.1.16 不提供新分级、动态提醒、健康、回放与模型库编辑界面，恢复业务前仍需按实际账号与目标版本复核这些功能差异，并完成成对 app／browser 版本和真实回执验收。`deploy/rollback.sh` 的通用回退门禁保持不变，不能把本工具的成功报告当成绕过门禁的凭据。

`test/proposals-rollback.test.ts` 使用独立临时数据覆盖只读不变性、批准／重写状态转换、长候选停止、新表和外部文件保留、普通 unknown 与新预检终态、活动操作和未知结构拒绝、模型物化不一致及故障注入回滚；`test/rollback-schema.test.ts` 将历史 fixture 固定为真实版本 7，并明确检查新版本 8 仍被原工具拒绝。所有执行结果以服务器回归证据为准。

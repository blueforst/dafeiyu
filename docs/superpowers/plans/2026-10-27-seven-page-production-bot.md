## 一、实施基线与已确认要求

- 转入 OpenSpec 时仓库 README 的应用基线为 0.1.14、浏览器为 0.1.12；已具备模型配置、Pi 适配、Camoufox／Playwright、SQLite 队列、基础记忆、人工接管和 noVNC。保留后续已交付的 OpenCode 会话修复及 4096 token 默认回复上限，实施前重新核对实际部署、登录账号及未提交改动。
- 一级页面固定为七个：主页面、模型页、人设页、记忆页、主程序页、定时任务页、计费页。浏览器接管整合进主页面。
- 真实评论与私信验收走正常生产流程，处理所有符合正常规则的消息；不增加测试账号白名单，不恢复已移除的“预期账号”配置。验收通过后保持自动运行。
- 模型及 Key 由用户在模型页配置。语义触发、日程生成、试聊和记忆整理均调用 LLM，并统一计量。
- 人格采用静态提示词与触发提示词分层；触发由 LLM 语义判断。虚构角色日程由 LLM 每天生成。全部配置和结果在页面可视化。
- 价格只采用 Pi 内置数据，不做手工单价、人民币汇率、套餐余额或扣款系统。没有可靠价格时标记“未定价”。
- 文档与界面使用中文。构建、自动化测试、批量渲染及其他高负载任务全部在服务器执行；本机仅编辑、检查文档和进行轻量浏览器互动。
- 本轮包含早晚安定时发帖，取代旧文档中本轮“不主动发帖”的范围限制；不扩展为任意自主发帖、外部工具代理或 Buffer 集成。

## 二、七个页面及职责

| 页面 | 路由 | 配置、展示与操作 |
| --- | --- | --- |
| 主页面 | `#/overview` | 当前 X 账号、控制状态、健康状态、消息及费用概况、最近异常、快捷入口；浏览器接管、noVNC 连接和释放 |
| 模型页 | `#/model` | 沿用服务商、模型、Key、协议／地址、推理档位、发现模型与连接测试；保留 CommandCode 和已接入服务商 |
| 人设页 | `#/persona` | 静态提示词、语义触发规则、LLM 虚构日程、日程历史、多轮试聊、命中规则与最终提示词预览 |
| 记忆页 | `#/memory` | 用户／会话、近期对话、长期记忆、角色经历、来源与更新时间、召回预览、编辑、删除、遗忘及恢复记录 |
| 主程序页 | `#/program` | 当前处理阶段、持续时间、轮次、队列与发送结果、通道限速／退避、运行模式、结构化日志与错误详情 |
| 定时任务页 | `#/tasks` | 主循环、早晚安帖、日程生成、记忆整理、数据库备份、健康检查；启停、时间、下次运行、手动执行和历史结果 |
| 计费页 | `#/billing` | 请求与 token、美元估算、每日趋势、模型／用途汇总、未定价统计和分页调用流水 |

交互约定：

- 全局顶栏保留恢复处理、暂停、人工接管／释放的现有语义。保存配置不隐式恢复处理或打开自动发送。
- 不增加第八个浏览器页；旧 `#/browser` 入口兼容跳转主页面并展开接管区域。其他现有入口保持可用。
- 日程内容、编辑和重新生成在人设页；自动生成时间与开关在定时任务页，两处引用同一配置与结果，不维护重复设置。
- 各页支持浅色、深色和移动端；离页未保存提示、加载／空数据／错误状态齐全。外部文本按纯文本渲染。

## 三、核心功能与数据流

### 1. 统一 LLM 服务与计费

- 所有实际 LLM 请求统一经过一个服务入口，携带请求 ID、用途、来源和可选渠道。用途覆盖回复、语义触发、日程生成、记忆整理、模型测试、试聊、早安帖及晚安帖；试聊中的语义判定也单独计量并关联本轮试聊。
- `CompletionResult` 透传 Pi 完整 usage、实际模型、结束原因和耗时。调用开始即持久化，结束更新同一记录；重试是新请求，不以消息 ID 抵消实际消耗。
- 新增调用流水表；成功、主动跳过、输出校验失败，以及报错／中止返回的部分用量均保留。进程崩溃遗留请求标记中断，未返回用量和费用时显示未知。
- 使用 Pi 返回的输入、输出、缓存读取、缓存写入、总 token 和分项成本。思考 token 是输出的子集，仅展示拆分，不再次相加；复用 Pi 的缓存及价格分档计算。
- 只有精确匹配 Pi 内置服务商与模型价格时才计价。未知模型不能继承兜底模板价格；CommandCode、自定义中转站不能因模型同名而套用原厂价格。
- 成本按请求时的数据保存，后续更换模型或升级目录不重算历史。计费记录不保存提示词、回复正文或 Key；旧 usage 作为历史 token 数据保留，缺失成本与模型的信息不编造补齐。
- 计费页按北京时间展示，金额使用美元并注明“Pi 目录估算”；未知值不显示为免费，小额费用保留足够精度。日期筛选同时作用于汇总、趋势和流水。

### 2. 人设、静态提示词与语义触发

- 静态区包含角色定义、说话风格、记忆与承诺、互动边界，每次回复始终注入。触发区参考偏好、背景经历、外貌、其他角色和身份设定组织，可增删规则。
- 每条触发规则包含稳定 ID、名称、自然语言触发条件、提示词正文、启用状态和顺序。未命中的正文不注入回复请求。
- 一次语义判定统一处理全部启用规则，使用当前模型和同渠道可见上下文；模型支持关闭推理时关闭推理，否则采用可用的最低档，输出上限默认 512 token 并受模型上限约束。
- 判定仅返回命中 ID 和简短原因，严格校验输出、去重并忽略未知 ID。没有启用规则时不调用；判定失败时不注入触发模块，使用静态规则继续回复，并记录可定位的警告与实际费用。
- 生产回复和试聊共用提示词组装器，区分稳定前缀与动态内容：静态规则 → 命中模块 → 角色经历与今日日程 → 可见记忆和上下文 → 当次提醒与当前时间。
- 固定的 AI 身份披露、输入资料不可信、JSON 输出要求和发送正文校验由程序维护，并在页面只读展示。真实性约束针对真实互动记忆和现实事实，明确允许按标记为虚构的角色设定与日程互动。
- 保存人格后下一轮生效，不改变正在执行的生成；已生成的当日日程继续保留，可主动重新生成。旧 persona 文本原样导入静态区，不强行拆解或补写角色事实。
- 多轮试聊支持公开／私信场景及未保存人格，采用独立模拟对话，不发送到 X、不写入真实用户记忆。展示回复／跳过、命中原因、分段提示词、耗时和本轮全部调用费用。

### 3. LLM 虚构日程

- 根据已保存人格与近七日日程，生成有日期、时段、三餐、活动及心情的结构化虚构日程；不把历史往事再当成当天新事件，不编造真实用户经历或现实行动承诺。
- 人设页以时间轴展示当天内容、当前时段、生成来源、更新时间和历史；支持手动编辑和重新生成，明确标记“虚构角色日程”。
- 自动生成默认北京时间 06:00，任务默认启用；当天首次处理若尚无日程，则提前补生成。以“账号＋本地日期”为唯一自动生成键，定时器与首次使用不能重复生成。
- 暂停／人工接管期间不自动调用 LLM；恢复时补当天缺失日程。失败间隔 30 分钟重试，当日自动尝试最多三次；无有效当日日程时明确使用“暂无当日日程”，不把昨天内容冒充今天。
- 只有用户主动编辑或重新生成才替换当天已生效内容；页面显示正在生成及失败原因，同一日程不允许并发生成。

### 4. 记忆系统与独立记忆页

- 用户／会话列表支持搜索、渠道筛选、最后互动、记忆数量、最近整理时间及遗忘状态。无法可靠识别账号的私信使用会话标识展示，不伪造账号关联。
- 近期上下文默认最近三次互动、七天以内，原始记录默认保留三十天。收到的原文与已确认发送的回复分别标识；草稿不能成为角色“已经说过”的记忆。
- 长期记忆保存明确自述的事实、偏好和未完话题，并关联来源消息、时间和可见范围；不推断身份、敏感标签或把角色自己的话归给用户。旧摘要保留并标记来源不完整，不能捏造来源。
- 每新增五条已处理的真实入站记录触发整理；每日整理任务补处理有新增、未达到阈值的记录。没有新增内容不调用模型。使用处理游标计数，不依赖平台消息时间与摘要写入时间直接比较。
- 整理时合并原有长期记忆与新增记录，保留仍有依据的历史，处理更新与矛盾；不能只用最近若干条原文覆盖旧摘要。
- 角色经历单独保存已确认的重要发帖和互动，带平台回执或来源。人设背景、虚构日程与真实发生的互动不混为一类记忆。
- 页面支持查看原文、编辑长期记忆、删除条目、手动重新整理及只读召回预览。手动修改提升记忆修订号；删除记录来源忽略信息，避免旧后台摘要或旧原文整理把已删除内容重新写回。
- 公开回复只能召回公开记忆，私信按当前可见范围使用；没有可靠身份映射时不自动合并公开账号与私信会话。试聊默认使用模拟记忆，真实召回预览不写回生产。
- “忘记并停止记录”清除对应记录并阻止继续记录；“恢复记录”允许后续新记录，不复活旧内容。保留独立遗忘账本及代次校验，恢复旧数据库、后台摘要完成或服务重启都不得恢复被遗忘的数据。

### 5. Playwright 生产采集与发送

- 完善通知提及、搜索、自己帖子下面的回复、一对一私信与消息请求；按实际 X 页面结构适配，有界滚动并跨轮去重。无法确认结构时明确报错，不能把“解析不到”当成“没有消息”。
- 区分主帖、引用、评论、会话及消息方向；不把不可靠时间戳改成当前时间以绕过消息时效，不用正文哈希代替可靠消息 ID 进行真实发送。
- 获取可确认的对话串和最近聊天上下文。媒体本轮不接入理解，明确告诉模型不可见，禁止静默丢失后猜测。
- 正常数据流：身份检查 → 采集 → 持久排队 → 上下文与记忆 → 语义触发 → 回复生成及校验 → 限速 → 发送 → 回执核对 → 记忆整理。
- 队列、发送日志和记忆归属需记录采集时的工作账号；账号变化暂停，不把旧账号待处理消息交给新账号发送。这是内部数据归属，不增加预期账号配置或白名单。
- 回复、定时发帖和人工接管共用浏览器串行控制。发送前重新核对身份、目标和私信最新上下文；同一登录目录只允许一个实际浏览器写入者。
- 提交前持久化发送意图。通过页面实际发送响应及回查，核对平台 ID、作者、目标关系、正文和发送时间；不能仅凭出现 toast、点击成功或同文内容判断成功。
- 结果不明确进入 unknown，只回查不重发；重启保留该约束。平台明确拒绝按现有通道退避处理。
- 默认每轮最多两条、公开每小时十条、私信每小时三十条；公开回复与早晚安帖共用公开发送额度。公开正文继续按 X 加权字符校验。

### 6. 主程序阶段与日志

- 单独记录并展示空闲／等待下轮、身份检查、公开采集、私信采集、排队、读取上下文、召回记忆、语义判定、生成、发送、回查、整理、退避及错误阶段。
- 每个阶段包含开始时间、持续时间、轮次、关联消息／调用 ID 和处理数量；异常也必须收束阶段，避免 busy 或 draining 永久悬挂。
- 主程序页显示队列状态、上次完成、下次循环、限速和退避，可配置运行模式及正常额度。轮询间隔统一在定时任务页编辑。
- 日志按级别、渠道、时间及关联 ID 筛选，支持暂停滚动、展开错误和分页。常规日志不包含消息正文、私信内容或密钥，正文只在受鉴权的详情／记忆界面读取。
- 扩展既有 SSE 增加程序状态与任务事件，保留原日志事件兼容性。进程重启后的旧阶段显示中断，不能继续显示为正在执行。

### 7. 定时任务与运行记录

所有调度使用北京时间；任务配置可热更新，展示启停、周期、上次／下次运行、状态、耗时、错误、费用及历史。修改任务设置不隐式恢复生产。

| 任务 | 默认设置 | 执行与暂停语义 |
| --- | --- | --- |
| 主循环 | 沿用现有每轮结束后等待 60 秒，范围 30–3600 秒 | 复用单一主循环；运行时执行，暂停／接管时停止业务采集和发送，不另起一个重复轮询器 |
| 早安帖 | 每日 08:00，初始关闭 | 启用后用人格和当日日程生成，走持久发送与回执流程 |
| 晚安帖 | 每日 23:00，初始关闭 | 与早安帖相同；不把虚构活动描述成真实用户经历 |
| 日程生成 | 每日 06:00，启用 | 按日去重，支持首次使用补生成；暂停期间不自动调用模型 |
| 记忆整理 | 新增五条触发；每日 03:00 补整理，启用 | 只整理有新增的用户／渠道，分批执行；暂停期间不自动调用模型 |
| 数据库备份 | 每日 02:30，初始关闭，保留最近七份 | 沿用用户当前关闭自动备份的状态；页面启用后才运行，只备份业务数据库，不备份源码、Key 或浏览器 profile |
| 健康检查 | 沿用宿主每五分钟检查，启用 | 独立于 app 和业务暂停持续运行；不能迁入 app 后失去对 app 故障的检测能力 |

- 主循环的启停与全局运行状态绑定；暂停不是删除任务或修改其计划。人工接管阻止全部业务浏览器写入。
- 同一任务、计划时刻和账号只能存在一个运行实例。手动执行与定时执行共用互斥；发送已进入 unknown 的实例只能回查，不能通过“再执行一次”绕过。
- 早晚安帖允许计划时刻后五分钟内开始，超出窗口标记错过，不在重启或恢复时补发过时问候。日程与记忆可补处理当天缺失工作；备份最多补一次，不回放所有遗漏日期。
- 早晚安帖先保存生成正文，再提交发送；重试／回查不能重新生成另一篇正文。使用通用出站记录承载回复、私信和定时帖子，区分其来源及关联任务。
- 任务状态与历史持久化；关闭任务取消未开始的后续执行，已经提交的发送继续回查。备份与健康检查不使用 LLM。
- 宿主健康检查和备份通过限定任务 ID 的桥接接口管理，不能从面板执行任意 shell 命令，也不向 app 挂载 Docker socket。现有健康监控结果扩展为页面可读取的记录，避免重复监控任务。
- 证书续期保留宿主现有机制，页面展示相关健康结果；不能因重做任务页而删除或停用续期任务。

## 四、接口、存储与兼容性

### 接口分组

| 分组 | 计划接口 | 用途 |
| --- | --- | --- |
| 状态与程序 | 兼容 `/api/status`、`/api/control/*`、`/api/logs`、`/api/events`；新增 `/api/program`、`/api/program/settings`、`/api/messages` | 程序阶段、运行设置及消息详情；保留已有鉴权和控制语义 |
| 模型 | 沿用 `/api/model` 及 providers／discover／test | 保持已接入协议和 Key 规则，测试接入统一计量 |
| 人设 | `GET/PUT /api/persona`、`POST /api/persona/preview`、`POST /api/persona/daily/generate` | 配置、未保存稿试聊、主动生成日程；读取结果包含近期日程历史 |
| 记忆 | `/api/memory/users`、`/api/memory/users/:id`、`/api/memory/items/:id`；用户级 summarize／forget／remember／preview 操作 | 列表、来源、修订、删除、整理、遗忘和只读召回 |
| 定时任务 | `/api/tasks`、`/api/tasks/:id`、`/api/tasks/:id/run`、`/api/tasks/:id/runs` | 任务读取、配置、单次执行和执行记录；时间设置只有此处写入 |
| 计费 | `GET /api/billing/summary`、`GET /api/billing/calls` | 日期范围汇总、每日趋势、模型／用途分组与游标分页 |

实现约定：

- 沿用 Fastify、原生 ES 模块、hash 路由和当前鉴权，非 GET 请求继续要求控制标记及来源校验；不增加前端构建框架或外部 CDN。
- 扩展非密钥面板设置，保存人设、记忆策略、任务计划和运行设置；下一轮读取。模型 Key 仍按原槽位独立保存，任何响应仅返回掩码。
- SQLite 增加调用流水、日程、结构化记忆与来源、记忆修订／忽略记录、通用出站记录、任务运行历史及阶段事件。迁移有版本且可重复执行，保留既有消息、摘要与 usage。
- 新接口按页返回有限数据，不返回全部历史；人设和试聊路由单独放宽请求体上限，兼容现有人格总长上限 20,000 字符及合理的多轮输入。
- 原数据库备份继续仅覆盖业务数据库；面板配置和 Key 不在其中，任务页清晰展示此范围。恢复时保留并重放独立遗忘账本，不能用旧备份覆盖遗忘元数据。
- 新业务数据归属当前工作账号。旧数据无法确认归属时标记历史未知，不自动迁给之后登录的其他账号。
- 暂不接入视频理解／生成、视觉输入、LLM 自主操作浏览器、跨渠道模糊身份合并或外部消息通知。本轮“计费”指使用量和费用估算，不是账户充值或收款。

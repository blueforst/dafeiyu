# 统一模型调用与费用

生产回复、语义规则、日程、记忆、试聊、连接测试及 CLI 通过 `ModelService`／`PiGenerator` 调用。每个实际请求在执行前创建独立 `llm_calls` 记录，返回后更新该记录；同消息重试会新增请求，不覆盖之前的费用。请求用途、来源、工作账号、渠道与交互标识用于关联，流水不包含提示词、回复正文或 Key。

`Generator.complete` 保留原有参数，在第六参数增加 `purpose`、`source`、`accountId`、`channel`、`interactionId`、可选 `maxTokens` 和 `reasoning`。返回包括 `callId`、完整 `usage`、`cost`、`pricingStatus`。旧 `input`、`output`、`cache` 数值仍兼容旧调用者；展示未知信息应使用完整 `usage`，不能将旧数值兜底零当成实际免费。生产服务必须使用 `new PiGenerator(store)` 绑定持久数据库。

调用状态为 `started`、`completed`、`failed`、`aborted` 或 `interrupted`。应用启动只执行一次 `recoverInterrupted`，将上次未完成请求记为进程中断。返回后输出结构校验失败仍保留已记录的用量。Pi 在未收到 usage 的成功响应中也会保留初始化零值，因此只有全零时保守标记未知，不凭成功状态认定免费；若已获得部分 token 则保留。已知免费价格加实际非零用量仍可记录为零费用。思考 token 是输出子集，不再次计入输出或费用。

成本直接保存 Pi 返回的分项和总额，采用调用时快照，不重算历史。仅可靠匹配内置服务商、型号及服务地址时使用内置价格。未知型号清除模板价格；CommandCode、自定义协议和手工覆盖的第三方地址统计 token 并显示未定价。估算不是供应商账单或余额。

## 管理接口

`GET /api/billing/summary` 返回 `totals`、`daily`、`models`、`purposes`；`GET /api/billing/calls` 返回 `items` 与 `nextCursor`。两接口共用以下查询：

- `from=YYYY-MM-DD`、`to=YYYY-MM-DD`：按北京时间解释，开始含、结束不含；省略时为今天。
- `provider`、`model`、`purpose`、`accountId`、`interactionId`：精确筛选。
- 流水另支持 `limit`（1 至 100，默认 30）及不透明 `cursor`。

汇总的 `costUSD` 在没有任何可定价请求时为 `null`；有部分可估价请求时只合计这些请求，同时显示 `unpriced` 和 `unknown`，不能把部分估算当成全部费用。全部未定价请求不能显示为免费。

### 活动统计与图表数据

动态面板版本为 `summary` 增加 `dailyModels` 和 `cache`。`dailyModels` 的每项为 `{date, provider, model, ...totals}`，日期为北京日期；`cache` 为 `{read, input, ratio}`，命中比例计算为 `read / (input + read)`。只纳入同时返回可靠输入和缓存读取字段的调用，字段全缺失或分母为零时 `ratio` 为 `null`。汇总、每日、模型、用途和日期×模型均在 SQLite 内分组，不再把范围内的所有调用读入应用内存。旧用量在图表中称为“历史用量”，仍不补造服务商或已知价格。

`GET /api/billing/activity?weeks=52` 提供汇总条及热力图；周数只能为 1 至 52，默认 52。返回字段如下：

- `range`：`from`、`to`、`start`、`end`、`timeZone`、`weeks` 和 `weekStartsOn: 0`。范围为包含本周的连续自然周，周日开始、结束不含。热力图只返回有调用的日期，前端补齐空日期格。
- `daily`：范围内截至北京今天的每日分组，含日期和原有 totals 字段；没有已知估算的日期 `costUSD` 为 `null`。
- `totals`：截至北京今天的累计用量；不受热力图周数限制。
- `peakDailyTokens`：累计历史中的单日 token 峰值；空记录时为 0。
- `last7`：含北京今天的连续七日范围，`cache` 沿用上述口径；`reply` 含 `calls`（已定价回复数）、`totalCalls`、`costUSD`、`averageCostUSD`、`unpriced` 和 `unknown`。平均值只除以已定价的 `purpose='reply'` 调用数，没有已定价回复时为 `null`，已知免费调用的均价可以为 0。
- `priceSource`：继续为“Pi 内置目录估算”。

累计汇总条不随近 7／30 日或自选范围变化；趋势、占比和展开后的流水共用 `summary`／`calls` 的半开日期范围。以上接口均只读，不访问上游模型、不写入费用、不访问浏览器页面。

旧 `usage` 表保留原数据，只读取合计与历史流水，不为旧行补造模型、用途或价格。具体模型、真实用途、工作账号筛选时排除无法证明匹配的旧行；`purpose=legacy-unknown` 可明确查询历史未知用途行，未筛选时用 `legacyRows` 明示历史来源。生产新请求不再同时写旧 `usage`，`status.stats.usage` 及 CLI `status` 与账单使用同一合计函数，避免双计。

CLI `summarize` 使用新来源条目和修订保护，要求数据库存在明确的当前工作账号；没有归属时拒绝请求。CLI 遗忘和账本重放先初始化新记忆服务，确保长期条目也被删除；重放使用存储层的范围解析，不把 `scope:` 账本键误当用户 ID。

接口由应用现有入口鉴权、来源检查及控制请求标记保护。修改模型设置采用对应域的修订合并，不覆盖人设、任务及其他配置，也不会恢复暂停工作流。OpenCode 继续使用持久稳定会话，独立模型测试使用新会话，正式回复默认最大 4096 token。

## 验证边界

`test/llm-billing.test.ts` 覆盖生命周期、部分用量、重启、价格隔离、成本快照、旧数据兼容、分页及北京时间范围。`test/llm-integration.test.ts` 使用本地模拟 HTTP 服务经过真实 Pi 协议解析，覆盖业务 JSON 校验失败、Anthropic 断流、HTTP 拒绝、成功无 usage、第三方地址、CLI 新记忆与范围账本，以及状态汇总一致性。现有模型会话、供应商、连接与安全回归继续执行。全部构建和自动化测试在独立服务器环境运行；模拟请求通过不代表真实上游费用或 X 平台验收通过。

# 2026-10-28 人设库、日程来源与按人设回放候选

本记录对应 `add-persona-workspace` 的后端任务 2.1—2.4。当前为实现候选，服务器验证结果由本轮总实施记录汇总；不表示生产发布或真实模型验收完成。

## 人设库与兼容设置

- 新增 `src/persona-library.ts` 和 `src/persona-library-routes.ts`。管理接口为 `/api/personas` 及其单项的读取、保存、启用和删除入口；写入口限制为 128 KiB，沿用应用统一的管理鉴权、同源与控制标记。
- 没有库时按当前 `PersonaService.get()` 构造 `current` 虚拟项。读取不写设置，未保存、已保存和配置自定义人格保持旧内容。
- 首次修改才落盘。`commitPersonaLibrary` 在一次原子文件写入中提交整库及兼容 `persona` 镜像；只在使用中人设内容变化时增加镜像修订。整库和单项分别有修订，陈旧写入返回 409。
- 最多二十项，名称去除首尾空白后为一至四十字且库内唯一；支持空白、内置预设、复制来源。使用中项不可删除。
- 旧 `GET/PUT /api/persona` 保持正文、固定规则及全局修订字段，保存时同步使用中库项。旧版本继续读取兼容镜像。
- 库校验失败时管理读取报错，不覆盖文件；生产 `get()` 继续读取原镜像。元数据读取失败时使用镜像修订的安全身份，不因新增元数据阻断生产生成。
- 保存、启用、删除、新建日志仅含标识、名称与修订，不含人设正文。

## 日程来源

`daily_revisions` 不加字段、不增加生产迁移。生成开始冻结所用人设身份，成功写入日程修订时在同一事务写入 `runtime` 的 `daily-persona:<账号>:<日期>:<修订>`；人工编辑也记录当前身份。每次写入清理三十天前的同类键。旧记录或损坏元数据显示“未记录”。

日程读取增加 `persona`、`personaName`。`GET /api/persona/daily?date=YYYY-MM-DD` 可以读取选中日期；历史日期 `currentPeriod` 为 `null`、`readOnly` 为 `true`。`days` 固定返回近七天，包含未生成和失败日期；原 `history` 仍只列已生成的修订，保持兼容。管理编辑接口拒绝修改非今天的日程。

## 按人设回放

估算请求可传 `personaId`，候选、已保存基线与修订检查均绑定所选人设。采用候选只保存到发起项，不改变使用中项。模型比较仍要求两侧使用同一已保存人设。

回放设置快照追加 `personaIdentity` 和绑定方式；列表与详情返回当时的名称、修订和 `deleted` 标记。人设删除后旧记录仍可读。旧请求未传 `personaId` 时保留原全局人设修订兼容。绑定库项的新批次把真实修订放在 `personaItemRevision`，旧 `personaRevision` 保存为无效哨兵 `-1`，使旧版本采用入口必定因修订冲突拒绝，避免回退后把未使用项误写到使用中人设。

生产生成快照类型增加 `personaId`、`personaName`；实际写入由共用回复流程接入。不改变原快照修订字段与旧快照读取。

## 验证入口与回退

新增 `test/persona-library.test.ts`，覆盖迁移、原子镜像、修订冲突、数量和名称限制、披露数据、兼容接口、坏库与七日日程；新增 `test/daily-persona.test.ts`，覆盖生成快照、编辑清理和旧记录；`test/persona-replay.test.ts` 追加未使用人设的基线、采用、冲突和删除后可读场景。自动验证只使用 mock 模型，在服务器独立环境执行。

回退不需要迁移转换。旧版本忽略 `personaLibrary` 与日程来源 runtime 键，读取回退前的使用中 `persona` 镜像。新增回放 JSON 字段被旧代码忽略；新版绑定库项的回放批次在旧版本中可查看，但采用会因旧修订哨兵返回冲突。回退期间需要采用候选时使用旧界面重新发起回放。

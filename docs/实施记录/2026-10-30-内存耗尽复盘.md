# 2026-10-30 生产宿主内存耗尽复盘

## 结论

本轮在约 **3.8GB RAM／2GB swap** 的生产宿主上，并行运行新版 Camoufox 资源解包和 TypeScript 候选构建，未给实际构建进程设置内存上限。两项任务挤占内存并使 swap 耗尽，长时间换页造成 SSH 和网页无响应；最终发生宿主全局 OOM，生产浏览器的一个 Web Content 进程被杀。这是本轮执行方式的错误，不能归咎于业务配置。

断开本地 SSH／构建连接没有停止远端 BuildKit 作业，日志显示两项构建继续运行数小时。服务器并未重启，正式容器也没有整体重启；旧版 **0.1.28.1** 保留。新的安全候选没有部署。

## 业务恢复核对

app 没有被 OOM 杀死。browser 的 OOM 标记和内核容器 ID 对应，监督器及浏览器主进程仍存活，故容器 health 显示 healthy；这不代表所有页面可用。

程序此前已安全暂停，公开工作页面被超时保护关闭，导致账号检查返回“程序公开页已关闭”。本轮通过正常接管／释放链路只恢复了程序工作页面，保留现有 profile 和 Chat 会话。恢复后读回 `@John2q1u` 已登录、无需人工验证、**paused／auto、busy=false**；没有恢复自动运行、调用模型或发送消息。队列仍为四条 merged、两条 queued、一条 unknown，outbox unknown 一条，LLM completed 248。

## 防复发修改

- `dev/server-heavy.sh` 为候选构建和测试共用排他锁，禁止并发。
- 启动前检查可用内存，除任务上限外至少保留 **1GiB** 宿主余量；Docker 磁盘至少留 **3GiB**。
- Docker 运行任务硬限内存 **128–896MiB**，memory-swap 与 memory 相等，避免借额外 swap 拖垮宿主；单 CPU、PID 上限 256、20 分钟超时并清理命名容器。
- 镜像构建使用独立 docker-container BuildKit，实际容器限制 **640MiB、无额外 swap、单 CPU、内部并行度 1**；启动后核对 Docker HostConfig，不能只限制 docker CLI。每次结束或超时停止该构建器。参数含义参照 [Docker 官方说明](https://docs.docker.com/build/builders/drivers/docker-container/)。
- Node 构建堆限制 512MiB，测试并发改为 1；界面回归采用同一锁和硬限制。
- 原生浏览器升级继续独立验证。约 1.5GiB 内存的旧解包方式不适合在当前生产宿主重跑，需改为流式／磁盘解包或在足够资源的服务器构建；不靠停止正式业务为构建让路。

实际验收：首次默认768MiB任务被余量检查拒绝，没有创建容器。随后640MiB任务从自身cgroup读回 `memory.max=671088640`、`memory.swap.max=0`、`cpu.max=100000 100000`、`pids.max=256`；类型检查、编译及61项定向通过，全套737项通过，用时157.46秒，生产两容器保持healthy。默认限额已统一收敛为640MiB。BuildKit及界面验证单独记录，不把运行测试通过等同于镜像已发布。

未知出站、独立遗忘账本、profile 及旧成对镜像均保留，不进行全局 Docker 清理。

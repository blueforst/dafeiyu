# 动态工作区候选实施记录

## 范围与边界

本轮实现 `redesign-feed-workspace`，以 `proposal/panel-redesign` 上的现有工作流为来源。构建、自动回归、万条数据性能检查和界面截图只在服务器独立环境执行；本机仅编辑。本记录不代表生产发布或真实平台收发通过。

## 后端

- 新增 `GET /api/feed/conversations` 与 `GET /api/feed/conversations/:key/items`，复用现有管理鉴权。接口只有只读 SQL，不唤醒工作流、不调用模型和浏览器。
- 会话以当前账号下的身份划分；公开与私信分开。角色帖会话合并出站帖子和没有出站的早晚安任务记录。已有 `GET /api/feed`、草稿审核及重新入队规则保留。
- 消息排序使用 `ingested_at`，旧值为零时回退 `created_at`。会话状态按待回查、有效发送失败、草稿或重写、批准等待、可处理排队的顺序取优先级；待处理 SQL 与旧动态共享，并使用分级服务的有效时效计算扣除关闭区间。
- 会话查询先物化轻量来源，在一次分组中用固定宽度的时间与 id 聚合键取最新条目和最高优先状态，最后按主键读取这两项。时间来源是非负毫秒；这个键与 `(时间,id)` 的排序一致，避免多次窗口排序。首屏和增量复用同次读取的消息汇总，带初始快照的后续分页仍单独读取当前完整汇总。
- 会话游标保留 `(latestAt,key)`，另附本次遍历的 `snapshotAt`。后续页按这个边界读取，避免尚未浏览的会话收到新消息后移到游标前方而遗漏；变化通过 `changedSince` 合并。往来游标为 `(sortAt,id)`，每一页返回正序。
- `changedSince` 返回全部变化而不按普通分页数量截断，避免变化较多时漏项；当前筛选不再匹配的变化会话放入 `removedKeys`。水位用服务器 `serverTime`，查询采用包含等值的边界，重复由条目 id 去重。
- `summary.latest` 包含没有出站的早晚安任务，确保漏发、跳过等状态能够推送；它们不增加待处理数量。待处理总数仍包含待核对的按链接补录请求。

## 验证入口

- `test/feed-conversations.test.ts`：身份/账号隔离、角色帖任务、状态优先、五类筛选、待处理一致性、两种分页、入库时间回退、增量移除、只读路由、非法参数与无写入。
- `dev/feed-conversations-performance.ts`：在服务器自建一万条消息、一千个身份的临时库，输出真实查询语句的 `EXPLAIN QUERY PLAN`、冷读和五次后续读取耗时。命令为 `ALLOW_ISOLATED_PERF=1 node --import tsx dev/feed-conversations-performance.ts`。完成后销毁临时库。是否新增索引以服务器证据决定，不能从源码存在推断已达标。
- 前端验收脚本与最终截图由本轮独立界面验收记录。

## 验证状态

服务器定向 `feed-conversations` 九项与既有 `activity-feed` 十项，在一次分组版本上 **19/19 通过**，失败、取消、跳过均为零，证据为 `/var/lib/role-workflow-proposals/artifacts/feed-grouped-regression.log`。之后补充汇总复用及帖子同时间排序一致性，最终版本再次 **19/19 通过**，失败、取消、跳过仍为零，耗时 4.129 秒，证据另记 `feed-final-regression.log`。

性能检查均在服务器自建临时库、禁用网络且限制一个 CPU 的容器中执行：

| 查询版本 | 冷读 | 后续五次中位数 | 最大值 | 证据文件 |
| --- | ---: | ---: | ---: | --- |
| 初始窗口查询 | 176.35 ms | 160.10 ms | 170.62 ms | `feed-performance.log` |
| 强制物化来源与候选 | 178.51 ms | 148.62 ms | 164.47 ms | `feed-performance-materialized.log` |
| 物化加临时 `(account_id,user_id,created_at)` 索引 | 170.15 ms | 147.59 ms | 160.03 ms | `feed-performance-materialized-trial-index.log` |
| 一次分组 | 99.64 ms | 95.13 ms | 97.21 ms | `feed-performance-grouped.log` |
| 一次分组并复用消息汇总 | **90.41 ms** | **75.64 ms** | **77.98 ms** | `feed-performance-final.log` |

文件均位于 `/var/lib/role-workflow-proposals/artifacts/`，包含真实查询的 `EXPLAIN QUERY PLAN`。建议索引在隔离对照中帮助很小；查询优化后已达到一万条消息下 100 ms 的建议目标，所以没有新增索引或迁移。临时索引仅存在于销毁的测试库，未写入业务库或生产。

界面验收结果由根代理统一记录；未通过完整任务条件的复选框保持未完成。生产发布需要另行授权。

## 恢复

前端回退后恢复原卡片流；新增接口只读，旧前端不使用。`ws:feed:*` 浏览器设置可保留。本次没有新增数据库迁移或索引，不需要额外结构回退。

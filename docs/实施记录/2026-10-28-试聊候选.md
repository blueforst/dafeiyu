# 2026-10-28 共用回复流程与独立试聊候选

## 范围与状态

本记录对应 `add-persona-workspace` 的共用回复流程和独立试聊后端。源码实现与服务器隔离验收分别记录；本文件不代表生产发布、真实模型调用或管理员效果审定。

## 共用回复流程

新增 `src/reply-pipeline.ts`，生产 `Workflow.generateDraft` 和独立试聊均调用 `generateReply(sources,event,options)`。外部来源通过参数提供，包括上下文、记忆、近期回复、日程、人设、字数能力、生成器、会话标识、调用元数据及快照写入。额度、回复时段、运行控制、出站准备和平台收发仍在生产调用方，不进入共用函数。

生成顺序保持上下文、记忆、提示词与语义判断、快照、生成、解析、公开正文规整、字数校验和格式标记。生产生成快照追加人设库中的标识和名称，保留原修订号。语义判断沿用已有用途与来源，试聊显式覆盖为统一的 `chat-test` 用途及对应步骤来源。

新增 `test/reply-pipeline-consistency.test.ts`，使用固定时钟、会话命名空间与纯合成公开／私信夹具。夹具涵盖同线程合并上文、关键词卡、语义卡、近期往来、角色经历、引用与卡片。修改前服务器基线在 `/srv/role-workflow-proposals-baseline-20261028` 上运行，通过后保存为 `test/fixtures/reply-pipeline-baseline.json`；候选运行逐字核对 system、user、调用顺序、元数据、模型参数和草稿。

`MemoryService.summarize` 仅新增可选的用途与调用账号元数据覆盖；默认的 `memory-summary`、原来源选择和记忆作用域不变。试聊将费用记入真实当前账号的统一流水，记忆仍写入 `chat_test` 作用域。对应测试为 `test/memory-purpose.test.ts`。

## 独立试聊服务

`ChatTestService` 延迟创建 `DATA_DIR/chat-test/workflow.sqlite`，使用独立的 Store、记忆服务、分级服务、人设服务和账本。测试消息、回复、记忆、冷却、整理进度、日志与诊断均只写入这个目录。生产库只接受统一调用流水；日程仅调用 `describe`，角色经历与近期公开回复只读，不构造或调用浏览器 transport。

每个模拟会话对应一个独立测试用户；显示名和测试 handle 可修改，固定的模拟身份保持连续。不同模拟会话不因复用显示 handle 而共享记忆或冷却。公开事件保留各自独立的线程标识，不跨线程合并；私信“先攒几条再回”仍只把末条入队，前面的消息作为上文。这两点来自实施期间用户的明确澄清，提案与规格由主实施记录同步。

处理绕过生产额度、回复时段、运行状态、接管、草稿模式、平台退避及出站限制，分级显式传入 `ignoreAge:true`。每用户同时一轮、全局最多两轮；每轮和手动整理均有六分钟截止时间。取消、失败、重置和删除保留已落账费用，阻止在途旧回复写回。关闭服务先中止并等待在途任务，再关闭独立数据库。

## 隔离验收入口

所有自动测试使用 mock 模型，并只在服务器隔离环境运行：

- `test/reply-pipeline-consistency.test.ts`：修改前后生产生成一致性。
- `test/reply-pipeline-snapshot.test.ts`：异步等待期间切换人设，生成归属仍使用本轮固定快照。
- `test/memory-purpose.test.ts`：计量元数据覆盖与作用域保持。
- `test/chat-test.test.ts`：用户、固定模拟身份、持有消息、分级、并发、中止重试、重置删除、分页与关闭。
- `test/chat-test-isolation.test.ts`：五轮整理、广告零调用、未发出长稿、生产全表和四类账本不变、控制与额度豁免、未确认账号、损坏库只影响试聊。

服务器第三轮类型检查与上述五份专项测试均通过，共 **15/15**，失败、取消和跳过均为零。证据为 `/var/lib/role-workflow-proposals/artifacts/chat-targeted-3.log`，执行环境为独立候选目录 `/srv/role-workflow-proposals`；全部模型请求为 mock，没有操作生产 profile。全量回归和界面验收由本轮总实施记录另行汇总；本笔记不自动勾选跨模块验收任务。未执行真实模型调用或生产发布。

专项验证发现并修复了“重置后同毫秒发送”的合成时间边界：恢复记录的截止时间可能晚于旧的注入时钟。新事件时间现严格晚于该身份的恢复截止时间，Store 的入库安全门与原断言保持不变；第三轮已通过该回归。前两轮失败日志保留，不能把夹具修复或代码落盘当作通过证据。

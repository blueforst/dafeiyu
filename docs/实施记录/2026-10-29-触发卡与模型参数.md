# 2026-10-29 触发卡、结构化草稿与模型参数实施

## 已实现的调用链

回复、私信、正常流程试聊、预览和回放共用 `runReplyLoop`：首轮只附启用卡片的目录，由模型原生调用 `read_card` 取正文；最终单独调用 `submit_draft` 返回 action、text、reason 和可选跳过类别。终态工具只返回内部结果，后续正文、字数、隐私、审核和发送校验继续执行。普通文本、伪装成 JSON 的调用计划及读卡与提交并行均失败，不发起格式修复重试。

读取与其他执行工具合计最多20次，终态工具另记，一条最多21次请求。没有注册读取工具时，只允许一次终态输出，误造工具名直接失败；每轮实际调用分别落账，失败和中止保留已发生用量。早晚安一次带齐卡片，只带终态工具；日程和记忆整理保留原 JSON 输出。

卡片取消关键词字段，编辑器只填标题、什么时候用和内容。第3版内置预设的四个常驻分区与第2版逐字一致，原条件分区改为卡片。已有自定义正文、关闭状态和顺序保留，启动先把原设置备份为0600文件再原子更新库、镜像和修订；重复启动不再迁移。额外覆盖全部分区需移动、空正文、卡片已满及最大排序值，避免合法旧数据阻止启动。人设文件导出第2版，继续转换导入第1版。

模型设置移除回复输出上限和超时；输出取 Pi 模型目录最大值，再按输入量和上下文余量收小。日程显式传3072，连接测试用原生 `connection_check`。每次请求固定180秒保护时限，原会话路由和按实际用量计费不变。

## 同文重复误过滤修复

原规则将一小时内不同用户的相同提问直接过滤，且公开／私信混算。新规则在同一账号、同一渠道计数，达到阈值只降普通优先级；广告关键词及链接继续过滤，重点名单、人工操作、历史终态和待回查出站不改写。设置标签改为“同文重复降优先阈值”，接口字段与范围不变。

服务器红测复现正常同文、跨渠道和重点名单误伤，修复后定向回归通过；原失败日志保留。历史已过滤条目不自动复活，可按原入口手动重排。

## 真实模型证据与费用

沿用已授权的 opencode-go / deepseek-v4.1-flash、原地址及低推理档位。全部批次共用持久一美元预算账本；用户随后解除请求次数限制，金额限制继续保留。测试使用独立数据目录、模拟用户，不访问 X 收发。每次请求预留完整输入窗口和最大输出的峰价，未知用量立即停止，没有重置失败批次的费用。

早期 JSON 方案出现空结果、把读取计划写成 JSON、读取后返回普通文本；不同批次共用旧试聊库也曾触发旧重复过滤。两类问题分别留证，不能把被过滤条目当成模型调用失败。终态工具前置首批已完成原生读卡与提交，但口令增加了解释，未满足精确四字断言；明确输出要求后前置3次请求通过。

最终终态协议业务样例 **8/8** 通过：反话不读被夸、真夸读被夸、步骤请求读对应卡、外貌读外貌、喜好读自我资料、两条普通闲聊不读卡、非官方身份读身份卡。另三位不同模拟用户连续提出相同喜好问题，**3/3** 完成，各用两次请求且均读取自我资料。所有最终结果带 `finalTool=submit_draft`。逐条原文、卡片、用量和调用标识保存在服务器真实验收目录。

隔离验收结束时合计 **106次**请求，Pi估算 **0.022377858美元**；按峰价保护金额 **0.0734313美元**，未结算预留为零。发布后验收另记入同一账本，最终结算见发布记录。这些金额均不是供应商实际扣款。

# 浏览器渲染性能回退

2026 年 10 月 27 日，用户反馈开启 WebGL 后远程浏览器明显卡顿。服务器测得浏览器容器约占用 196% CPU，接近双核总容量；同期内存没有触顶。

0.1.7 的离线和生产验证只确认了 WebGL 上下文及像素读回正常，遗漏了持续交互性能。这项设置没有解除 X 登录限制，因此在 0.1.8 撤回。

## 改动范围

- 从业务浏览器和人工窗口启动参数中移除 `--use-gl=angle --use-angle=swiftshader`。
- 业务浏览器继续排除 Playwright 的软件 WebGL 回退参数，恢复默认图形路径，不强制提供 WebGL。
- 保留 768 的线程额度、2 GiB 内存限制、已有浏览器资料和发送日志。
- 保持服务器直连、人工接管和草稿模式，不进行登录重试。

## 验证

所有构建和检查均在服务器执行。镜像构建通过 14 项检查；运行后另行记录 CPU 采样、实际启动参数、容器健康及桌面交互观察。

最终数据以 `/var/lib/role-workflow/acceptance/浏览器渲染性能回退验收.json` 为准，构建日志为 `浏览器渲染回退构建.log`。

WebGL 不可用不能单独证明 X 登录会被拒绝，也不应为这个未经证实的假设再次强制启用高负载图形后端。

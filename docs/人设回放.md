# 人设回放与回复质量

回放从当前工作账号已经处理的消息中选择最多五十条样本。默认只选择公开消息；私信必须单独勾选。遗忘用户、记忆删除账本已屏蔽的来源和其他账号的消息不能入选。可按北京时间日期、渠道、消息分级筛选，并选择均匀抽样或最新消息；均匀抽样在最近一万条符合条件的候选中完成。

比较人设时，基线可使用当时实际回复，此侧不调用模型；也可用运行开始时已保存的人设重新生成，候选使用未保存的人设草稿。模型设置对比则保持两侧人设相同，规则见下文。两侧使用同一模拟日程、同一样本时间加一分钟以及当前允许范围的记忆，分别使用独立的 `replay-…` 模型会话。回放不会调用浏览器，不写消息状态、出站、生产记忆或角色经历。

## 费用与控制

先预估再确认。预估冻结样本来源、人设、候选和当时模型配置，十分钟后失效；确认时来源或人设修订变化会返回冲突，要求重新预估。预计请求数按同账号、同模型最近七天正式回复的平均轮数估算，无记录时每侧每条按两次。费用来自当前账号同模型最近五十次生产回复与语义判定的 Pi 价格快照平均值；缺少历史或未定价时不显示为免费。

同一进程一次运行一个回放，逐条顺序执行。管理员可中止，已完成条目保留，未开始的条目不再调用。服务重启把未完成运行标为 interrupted，不自动恢复或再次请求。账号变化会停止回放；来源在调用期间被遗忘、删除或修改时不再持久化该条结果。所有模型调用，包括读取卡片后的后续轮次，以 `persona-replay` 用途、`panel-replay` 来源和运行 ID 关联。实际费用读取统一调用流水，不只合计成功返回的结果。

最近二十次运行及标注被保留，允许删除单次运行。运行中需先中止再删除。采用候选沿用普通人设保存与开始时修订号；发生修订冲突不会覆盖后来的编辑，也不会恢复暂停的程序。

## 比较模型设置

选择 `compare:'model'` 后，两侧使用同一份已保存的人设和动态提醒，基线必须重新生成；候选只改变模型库条目与推理档位。人设草稿或提醒设置发生修改时拒绝预估，避免同时比较多个变量。候选解析复用模型库启用时的校验与参数转换，但不执行保存、自动迁移、测试或切换使用中模型。

预估冻结两侧运行配置、Pi 目录模型和价格以及 Key。`modelCandidate.key` 是模型库服务商标识，不是 API Key。API Key 只在内存闭包中持有，不进入数据库、接口响应或日志；持久记录仅保存模型名称、推理参数及接口主机，不保存完整地址或认证信息。预估十分钟失效，显式取消、过期、开始校验失败、完成、中止和服务关闭都会释放冻结凭据。模型库修订、使用中的模型配置或 Key 在确认前变化时要求重新预估；执行期间发现变化则停止后续调用。

两侧从相同首轮资料出发，各自在独立会话中决定读取哪些卡片；不共享路由和读取结果。每轮计费归所属侧，旧共享路由记录仍可读，新记录的 shared 计数为零。并行读取多张卡只增加一个后续请求，单侧单条最多21次。

预估分别展示两侧的请求数、Pi 每百万 token 单价及估算费用。token 预计值使用同模型近期调用均值，候选没有历史时用基线历史作为参考；没有可用历史时显示无法估算，未定价一侧显示未定价，两者都不表示免费。实际汇总由同一 `llm_calls` 计算每侧的调用数、平均耗时、输入/输出 token、缓存读取及费用，旧共享调用仍可查看，所有部分之和与总账一致。

持久调用沿用 `persona-replay` 用途；现有 `source` 列分别保存 `panel-replay:baseline`、`panel-replay:candidate`、`panel-replay:shared`，调用接口额外派生 `side`。旧的 `panel-replay` 调用保持原样。模型对比没有“采用候选”，服务端也拒绝此操作；需要更换使用中模型时前往设置页按正常流程操作。

## 快照和隐私

生产生成前保存对话、召回与提醒元数据快照，每条最多 16 KiB UTF-8；超限时先去掉最早对话，再减少其他派生数据，始终标注 truncated。快照不进入普通日志。没有快照或发生截断的历史样本标注上下文不完整。

回放只使用快照的对话部分，记忆永远重新读取当前允许范围的召回。人工修订、删除记忆可使快照记忆字段失效；遗忘与独立账本重放删除相应快照和条目。保留清理同时移除过期数据和原消息已删除的派生数据。不能仅恢复旧数据库而丢弃独立遗忘、来源与删除账本。

私信样本和回放列表默认只返回标识与状态，不返回原文或两侧输出。展开单条私信需请求受同一管理鉴权保护的详情接口。汇总及生产质量指标隐藏私信开头片段，保留数字统计；不得把私信正文添加到普通日志、计费或汇总接口。

## 指标口径

检测函数与回复提示词共用。指标包括跳过率、回复 Unicode 码点平均长度、开头重复率、前五个公开开头、颜文字／emoji／波浪号每十条回复出现频率、列步骤比例、禁用链接／账号提及条数及公开长度违规数。它们是确定性检测，不产生模型评审调用，也不替代人工判断。

开头重复率按规格的明确场景计算：属于重复开头组的全部回复数除以回复数。因此二十条中某个开头出现六次、其余十四条都不同，结果为 30%。设计中原有的 `1 - 不同开头数 / 回复数` 与该场景不一致，实现采用可验收场景的口径。

## 接口

以下接口沿用应用管理鉴权。写请求继续要求控制请求标记，JSON 中的确认不能替代鉴权。

| 方法与路径 | 参数与行为 |
| --- | --- |
| GET `/api/persona/replay/samples` | `from`、排除边界 `to`、`channel`、`includePrivate=true`、`tier`、`limit`、`order`；返回安全预览及排除数量 |
| POST `/api/persona/replay/estimate` | `{filter, persona, personaRevision, baselineMode:'actual'或'saved', promptHints?, dailyState?, compare?:'persona'或'model', modelCandidate?:{key,modelId,reasoningLevel}}`；返回 `estimateId`、预计请求数与费用；模型模式含 `sides.baseline/candidate/shared` |
| DELETE `/api/persona/replay/estimates/:id` | 显式取消费用预估并清理冻结凭据 |
| POST `/api/persona/replay/runs` | `{estimateId, confirmed:true}`；异步开始 |
| GET `/api/persona/replay/runs` | 最近二十次运行与问题类别 |
| GET `/api/persona/replay/runs/:id` | 运行、进度、汇总与安全条目列表 |
| GET `/api/persona/replay/runs/:id/items/:messageId` | 单条原消息、基线、候选和指标；私信显式展开使用此接口 |
| PUT `/api/persona/replay/runs/:id/items/:messageId/label` | `{label, issues}`；label 为 candidate、baseline、same、both-bad |
| POST `/api/persona/replay/runs/:id/abort` | 请求中止 |
| POST `/api/persona/replay/runs/:id/adopt` | 按原人设修订保存候选 |
| DELETE `/api/persona/replay/runs/:id` | 删除已停止的运行 |
| GET `/api/persona/quality` | 北京日期与渠道范围；只返回汇总和每日指标 |

问题类别为 `off-topic`、`fabrication`、`template-opening`、`too-many-expressions`、`steps`、`should-skip`、`length`、`other`。结果只供管理员标注，不会自动修改人设。

## 验证边界

自动化回归使用隔离数据库与模拟模型，构建和测试只在服务器执行。真实模型回放另需授权，并记录不超过二十条公开样本的实际请求数、费用和估算偏差。生产发布、真实模型调用与平台收发分别留证，不能以模块存在或模拟通过替代这些验收。

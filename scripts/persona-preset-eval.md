# 人设预设固定题库验收工具

题库为 `test/fixtures/persona-preset-questions.json`：三十条独立公开试聊，另加两组同一个人连续五轮；六个预设共二百四十条（独立题 180＋连续题 60）。包括繁体、英文、身份、步骤、辱骂、擦边、危机和两条删除记录请求。预设正文从实际 `GET /api/persona/presets` 读取。

默认命令只列计划，不读取任何凭据，也不请求接口：

```sh
node scripts/persona-preset-eval.mjs
```

构建、浏览器与批量执行均放服务器，并使用 `flock /var/lock/role-workflow-heavy-tests.lock` 串行。模拟验收由 `test/persona-presets-e2e.mjs` 启动临时真实应用、浏览器和本地 SSE 模型；运行容器必须为 `--network none`，不得挂载生产资料。mock不仅要求面板地址为loopback，还要求实际模型地址也是loopback，且 `GET /api/model` 有隔离夹具的专用只读响应标记。该标记仅由e2e本地转发层注入，不修改生产API；仅把真实面板转到localhost不能绕过实际调用确认。

## 取得真实模型授权后

以下只是未来获授权后的用法；预设提案、模拟通过和填写命令本身都不是模型调用或发布授权。管理凭据只读显式指定的文件，不从环境、生产配置或容器 secret 自动查找。工具不会恢复工作流、切换模型、修改人设或访问 X。

```sh
flock /var/lock/role-workflow-heavy-tests.lock node scripts/persona-preset-eval.mjs \
  --mode actual --execute --ack-paid-calls \
  --base-url https://已授权的面板地址 \
  --key-file /明确指定的管理凭据文件 \
  --out /明确指定的私有验收目录
```

串行逐题执行。默认单次最多二百四十个预览请求，也可显式用 `--max-requests 10` 限制本次数量。`--preset deepseek`、`--question q16`（只筛独立题）、`--conversation c01`（完整五轮）可缩小已批准的范围。独立题只传该题一条用户消息；连续组每轮只传当前消息，并用 `memory.recent` 按时间顺序传入同预设、同一组前几轮的消息和实际回复。不同组和不同预设不会共享历史，费用与调用标识以接口返回为准；未定价、未知费用不会按免费计算。预设必须全为关键词卡；若某次预览报告超过一次模型调用，批次会停止并保留已发生费用。

当前实际模式要求面板已管理模型，`GET /api/model` 能返回完整模型参数。仅配置文件的模型不会公开全部参数，工具会拒绝实际批次，避免无法发现参数漂移。每题请求前后都会核对模型元数据；观察到变化立即停止，已经返回的结果和费用保留。

## 断点与重复费用

- 输出目录已有记录时，必须显式 `--resume` 才能继续；默认只执行尚未请求的题。连续组从已持久保存的前轮结果重建近期往来；前轮失败或结果不确定时，后续轮保持待执行，不猜测回复、不跳过依赖；独立题和另一组可继续。前轮在显式重试后产生新回复时，后续轮使用新回复。
- `--resume --retry-failed` 只重跑已有明确失败响应的题，旧尝试、调用标识及费用全部保留。成功题不重复。
- 发出请求前原子记录 `inflight` 并同步文件与目录；持久确认失败时不发请求。进程中断、网络断开、不可解析响应或不确定的服务端错误会留下 `uncertain`；`--resume`、`--retry-failed` 都不会自动重跑。它们可能已经计费，应先核对流水。
- 确实需要再次请求不确定项时，须另行明确使用 `--retry-uncertain`，并承担再次计费的可能。工具不会自行选择这样做。
- 预设版本和完整内容、完整题库、mock/actual 模式、服务地址、模型元数据都参与批次指纹；变化后禁止混用旧断点，应保留原目录再新建批次。
- 同一目录有运行锁时拒绝并行。确认旧进程已经退出后，才可显式 `--recover-lock`。

## 产物和结论边界

输出目录权限为 0700，文件为 0600；已有目录若并非私有权限，工具会拒绝使用，不擅自修改该目录权限。控制台仅打印计数和固定错误说明，不打印 Key、完整提示词或回复。

- `presets.json`：该批次六个人设的正式文本和版本。
- `state.json`：每题全部尝试、断点、调用标识和费用。
- `replies/*.json`：逐条回复、命中卡片和对应费用，供管理员审阅；应当作为私有材料保管。
- `summary.json`、`summary.md`：角色梗与外貌主动率、开头重复、被夸时以谢谢开头、常用长度内比例、各连续组的开头／收尾／角色词／口癖词重复、步骤、身份词、辱骂词、擦边边界词、危机支持词及声称已删除的词法检查。

常用长度沿用设计中的公开回复范围：通用 10—50、大肥鱼 5—30、GPT 20—70、Claude 15—60、Kimi 5—40、GLM 10—40；计数按去空白后的 Unicode 字符数。连续组开头和收尾各取去标点空白后的六字符；角色梗和口癖按题库词表比较，不跨组计算。近期往来超过试聊接口 8,000 字符限制时停止批次并保留结果，不截断后继续。

这些指标仅为确定性词表和正则启发式。否定、引述、反讽和不同措辞都会误判；身份词出现不等于回答真实，边界词出现不等于处理安全。模拟输出只证明接口、计费、恢复与统计工具可用，不能证明人设效果。真实模型结果、全部回复和正式六文本仍须交管理员逐条审定，得到明确同意后才可进入发布流程。

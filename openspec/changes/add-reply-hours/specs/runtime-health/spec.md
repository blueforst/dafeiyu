# 运行健康增量规格（回复时段）

## MODIFIED Requirements

### Requirement: 健康指标判定

系统 MUST 持续计算健康指标并分为正常、注意、异常：成功发送停滞、连续失败轮次、平台拒绝与通道退避、浏览器需要人工处理、账号受限、采集连续异常、备份失败与证书临期。成功发送停滞只在运行中、自动模式且有可发送通道中的可处理消息时计算；暂停、队列为空、额度已满、退避或回复时段关闭不得判为停滞。回复时段开放后，停滞从开放时间起算。

#### Scenario: 有消息但长时间没有成功发送
- **WHEN** 运行中有可发送的排队消息且二十分钟没有确认发送
- **THEN** 成功发送停滞指标为异常

#### Scenario: 队列为空
- **WHEN** 运行中三十分钟没有任何新消息
- **THEN** 成功发送停滞指标保持正常

#### Scenario: 公开额度已满
- **WHEN** 只有公开消息在排队且公开额度已满
- **THEN** 成功发送停滞指标不判为异常，额度状态单独显示

#### Scenario: 夜间回复关闭
- **WHEN** 回复时段关闭期间有排队消息，且超过二十分钟没有确认发送
- **THEN** 成功发送停滞指标保持正常

#### Scenario: 刚开放时的夜间积压
- **WHEN** 08:00 开放回复，排队消息来自凌晨
- **THEN** 08:20 之前不判为停滞

### Requirement: 每日日报

系统 MUST 在北京时间每日 09:00 生成前一自然日的运行日报，包含各渠道收到、回复、跳过、过滤、失败与 unknown 数量，响应延迟，模型调用、token、缓存读取占比、可估算费用与未定价数量，告警、平台拒绝和浏览器重启次数，以及暂停时长。响应延迟 MUST 扣除回复时段关闭的时长。日报不得调用模型或包含消息正文；同一日期只生成一次，09:00 时服务未运行则在恢复后补生成一次。

#### Scenario: 正常生成
- **WHEN** 北京时间 09:00 到达
- **THEN** 系统生成前一日日报，面板可查看近三十天的日报

#### Scenario: 整天暂停
- **WHEN** 前一日系统全天处于暂停
- **THEN** 日报显示全天暂停与零发送，而不是缺失

#### Scenario: 09:00 时服务未运行
- **WHEN** 服务在 11:00 才恢复
- **THEN** 系统补生成一次前一日日报，不重复生成

#### Scenario: 夜间消息的响应延迟
- **WHEN** 一条 @ 在 02:00 收到，回复时段 08:00 开放，08:05 回复成功
- **THEN** 日报中这条消息的响应延迟计为 5 分钟

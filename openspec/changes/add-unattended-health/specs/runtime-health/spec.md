# 运行健康增量规格

## Purpose

让无人值守运行的工作流在卡死、浏览器资源耗尽、长时间没有成功发送或被平台拦截时能够自行收束或恢复，并把异常和每日运行情况集中呈现给管理员，避免程序看似运行却悄悄停止回复。

## ADDED Requirements

### Requirement: 轮次软超时与硬超时

系统 MUST 为每个处理轮次设置软超时与硬超时：到达软超时后不再开始新的消息处理，等待当前消息结束；到达硬超时后中止当前操作，相关阶段标记为中断，已开始提交的出站按 unknown 只回查处理，下一轮正常开始。

#### Scenario: 浏览器操作卡住
- **WHEN** 某轮中一次浏览器读取持续不返回直到硬超时
- **THEN** 系统中止本轮并记录超时，下一轮按计划开始，不重复提交任何回复

#### Scenario: 软超时时仍有排队消息
- **WHEN** 软超时到达时本轮还有未开始的消息
- **THEN** 这些消息保持排队，留到下一轮处理

### Requirement: 采集时间预算

系统 MUST 为公开与私信采集阶段分别设置时间预算；超出预算时结束该阶段并保留已采集的消息，记录采集超时警告，下一轮继续轮换采集来源。

#### Scenario: 自己帖子下回复过多
- **WHEN** 扫描自己帖子下的回复超过公开采集预算
- **THEN** 本轮保留已读到的回复并进入后续阶段，不因该阶段耗尽整轮时间

### Requirement: 主循环看门狗

系统 MUST 运行独立于处理轮次的看门狗：处理状态持续超过硬超时加宽限时间，或运行中主循环没有安排下一次执行时，看门狗记录异常并恢复调度，不得造成两个轮次并发；恢复失败时安全暂停。

#### Scenario: 下一轮定时丢失
- **WHEN** 系统处于运行状态但主循环没有下一次执行时间
- **THEN** 看门狗记录异常并重新安排主循环

#### Scenario: 恢复调度失败
- **WHEN** 看门狗连续两次恢复都没有让主循环继续
- **THEN** 系统进入安全暂停并产生异常告警

### Requirement: 浏览器资源自愈

浏览器服务 MUST 在每次操作前检查容器内存占用与浏览器运行时长，超过阈值（默认内存上限的 75% 或运行二十四小时）时，在两次操作之间重启浏览器上下文并保留登录 profile；提交、回查进行中或人工接管期间不得重启。重启后必须重新确认登录身份，重启失败时安全暂停并告警。

#### Scenario: 空闲时内存超过阈值
- **WHEN** 下一次采集前浏览器容器内存超过阈值
- **THEN** 浏览器先重启上下文并确认身份，再执行采集，重启记录可在健康历史查看

#### Scenario: 发送过程中超过阈值
- **WHEN** 内存在一次回复提交过程中超过阈值
- **THEN** 系统等待该次提交与回执处理结束后才重启

#### Scenario: 重启后登录失效
- **WHEN** 重启后无法确认原工作账号已登录
- **THEN** 系统安全暂停，不使用新身份继续处理

### Requirement: 健康指标判定

系统 MUST 持续计算健康指标并分为正常、注意、异常：成功发送停滞、连续失败轮次、平台拒绝与通道退避、浏览器需要人工处理、账号受限、采集连续异常、备份失败与证书临期。成功发送停滞只在运行中、自动模式且有可发送通道中的可处理消息时计算；暂停、队列为空、额度已满或退避不得判为停滞。

#### Scenario: 有消息但长时间没有成功发送
- **WHEN** 运行中有可发送的排队消息且二十分钟没有确认发送
- **THEN** 成功发送停滞指标为异常

#### Scenario: 队列为空
- **WHEN** 运行中三十分钟没有任何新消息
- **THEN** 成功发送停滞指标保持正常

#### Scenario: 公开额度已满
- **WHEN** 只有公开消息在排队且公开额度已满
- **THEN** 成功发送停滞指标不判为异常，额度状态单独显示

### Requirement: 告警记录与去重

指标进入注意或异常时，系统 MUST 产生带类别、级别、开始时间和摘要的告警；同一指标持续期间只保留一条活动告警，指标恢复正常时记录恢复时间。告警可在面板横幅和分页历史中查看，并随健康状态写入宿主监控文件；告警内容不得包含消息正文、私信内容或密钥。

#### Scenario: 同一问题持续
- **WHEN** 连续失败指标在多次检查中都为异常
- **THEN** 面板只显示一条活动告警，其持续时间不断增长

#### Scenario: 问题恢复
- **WHEN** 指标恢复正常
- **THEN** 告警移入历史并显示恢复时间

### Requirement: 宿主监控读取健康结果

宿主监控 MUST 在 app 可达时读取健康指标与活动告警并写入监控文件；app 不可达时独立记录不可达异常，不依赖 app 内的调度或看门狗。

#### Scenario: app 进程卡死
- **WHEN** 宿主监控请求健康接口超时
- **THEN** 监控文件记录面板不可达，并保留上一次读取到的告警供排查

### Requirement: 每日日报

系统 MUST 在北京时间每日 09:00 生成前一自然日的运行日报，包含各渠道收到、回复、跳过、过滤、失败与 unknown 数量，响应延迟，模型调用、token、缓存读取占比、可估算费用与未定价数量，告警、平台拒绝和浏览器重启次数，以及暂停时长。日报不得调用模型或包含消息正文；同一日期只生成一次，09:00 时服务未运行则在恢复后补生成一次。

#### Scenario: 正常生成
- **WHEN** 北京时间 09:00 到达
- **THEN** 系统生成前一日日报，面板可查看近三十天的日报

#### Scenario: 整天暂停
- **WHEN** 前一日系统全天处于暂停
- **THEN** 日报显示全天暂停与零发送，而不是缺失

#### Scenario: 09:00 时服务未运行
- **WHEN** 服务在 11:00 才恢复
- **THEN** 系统补生成一次前一日日报，不重复生成

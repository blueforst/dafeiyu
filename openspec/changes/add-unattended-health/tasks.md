# 无人值守健康实施任务

代码与可隔离验收的任务已完成，共 12/15 项；剩余为真实受限样本、生产发布与一天观察、生产账号检查。仅完整满足原验收条件的任务勾选，证据及尚缺场景见[专项实施记录](../../../docs/实施记录/2026-10-28-无人值守健康.md)。规格见 [runtime-health](specs/runtime-health/spec.md) 与 [account-compliance](specs/account-compliance/spec.md)，实现边界见 [design.md](design.md)。构建、自动化测试、故障注入和界面验收均在服务器隔离环境执行；不在生产 profile 上做重启或受限模拟。

## 1. 轮次超时与看门狗

- [x] 1.1 实现轮次软／硬超时与浏览器 RPC 请求级超时，复用现有中止收束；以服务器可控时钟与故障注入测试验证卡住操作被中止、未开始消息保持排队、已提交出站进入 unknown 且不重发为验收。
- [x] 1.2 实现采集阶段时间预算，返回已采集结果与警告；以服务器 DOM 夹具测试验证超预算时保留结果并进入后续阶段为验收。
- [x] 1.3 实现看门狗恢复丢失定时器、二次失败安全暂停，更新 `docs/任务与宿主维护.md`；以服务器测试验证不产生并发轮次为验收。

## 2. 浏览器资源自愈

- [x] 2.1 浏览器服务实现 cgroup 内存与运行时长检查及进程树回退，新增 `/health` RPC；以服务器隔离浏览器测试验证读数、阈值与无法读取时的降级为验收。
- [x] 2.2 实现两次操作之间的上下文重启与身份复核，发送／回查中和人工接管时不重启；以服务器隔离 profile 故障注入验证重启后登录保留、重启失败暂停为验收，更新 `docs/浏览器环境排查.md`。

## 3. 健康指标、告警与日报

- [x] 3.1 新增 `alerts` 表与 `src/unattended-health.ts` 指标计算，接入轮次结束与看门狗；以服务器单元测试覆盖规格中停滞、队列空、额度满、连续失败、去重与恢复场景为验收。
- [x] 3.2 新增 `/api/health`、状态摘要与 SSE 事件，主页面横幅与告警历史；以服务器接口与浅色／深色／375px 界面验收、告警不含正文为验收，更新 `docs/前端接口.md`。
- [x] 3.3 新增 `daily_reports` 表与 `daily-report` 任务、补生成和面板查看；以服务器可控时钟测试验证 09:00 生成、全天暂停、服务晚启动补一次且不重复为验收。
- [x] 3.4 更新 `deploy/monitor.py` 读取健康接口并保留独立检查；以服务器 staging 验证 app 不可达时独立记录、可达时写入活动告警为验收。

## 4. 账号状态与合规检查

- [ ] 4.1 采集冻结、锁定、只读、受限及自动化拦截提示的脱敏页面或文本样本，整理识别规则；以样本文档与回归夹具为验收，无法取得的类型如实标注。
- [x] 4.2 实现 `Identity.restricted` 识别、安全暂停与告警，区分自动化拦截与额度提示；以服务器 DOM 夹具测试验证受限时不采集不发送、恢复需重新检查为验收。
- [x] 4.3 实现只读 `/compliance` RPC 与 `account-check` 任务、披露词设置及主页面展示；以服务器夹具测试验证缺披露词、未标注、质量过滤开启、无法确认各结果，且检查过程无写操作为验收。

- [x] 5.1 在服务器 staging 完成全量类型检查与回归，覆盖两份规格全部场景；以测试报告关联场景为验收。

- [ ] 5.3 取得授权后在生产账号执行一次只读合规检查，记录真实页面上的识别结果；未授权时如实标注未验证。

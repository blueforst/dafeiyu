# 设置页改版设计

## 背景

[`add-persona-workspace`](../add-persona-workspace/design.md) 第 1 节建立了统一设计：

- `--ws-` 样式变量；
- `public/js/shell.js` 外壳（两栏或三栏、页头行、收起、窄屏抽屉和浮层）；
- `docs/设计规范.md`。

本提案只用这些已有部件把设置页改成工作区，并把记忆页、计费页并进来。**所有设置的含义、字段、校验、默认值、生效时机和接口都不变**，变的只是页面位置和排版。

管理员确认的版式见 [panel-redesign-mockup.html](../add-persona-workspace/panel-redesign-mockup.html) 的设置页。草图中的数字和文案只是示例；计费图表等细节以现有规格为准。

决定来源分两类。下文没有特别标注的，是管理员在讨论中确认的；标注“（实施者决定）”或“（规划时决定）”的，管理员可以在审阅时推翻。

## 1. 导航与路由

- `public/js/app.js` 的一级导航只保留 `feed`、`persona`、`settings` 三项。`ROUTES` 去掉 `memory`、`billing`，旧地址表 `OLD` 改为：

  | 旧地址 | 新地址 |
  | --- | --- |
  | `overview` | `feed` |
  | `model` | `settings/model` |
  | `program` | `settings/logs` |
  | `tasks` | `settings/tasks` |
  | `browser` | `settings/browser` |
  | `memory` | `settings/memory`，原样带上查询参数 |
  | `billing` | `settings/billing` |

- 设置项地址为 `#/settings/<项>`，项的标识为：`run`、`model`、`tasks`、`triage`、`memory`、`billing`、`browser`、`sources`、`health`、`logs`、`history`。
- 现有设置页分区地址照旧兼容：
  - `#/settings/limits` 打开 `run`；
  - 原“记忆策略”分区的地址 `#/settings/memory` 与新的记忆项同名，打开记忆项的默认视图；需要直接打开策略时使用 `#/settings/memory?view=policy`。
- 只有 `#/settings` 而没有具体项时，打开最近一次打开的项，记在 `localStorage` 的 `ws:settings:item`，读写包在 try/catch 中；没有记录时打开 `run`。

## 2. 设置工作区

- 用 `mountWorkspace(root, {page:'settings', left, main})` 生成两栏，不用右栏。
- 左栏页头是“设置”和收起按钮；下面是四个分组和十一个设置项，每项右侧显示摘要。
- 主区页头放该项名称、简短说明和该项的操作按钮，主区内容挂载该项的模块。切换项时卸载上一个模块并调用其清理函数。
- 每个设置项是一个模块，导出 `mount(root, ctx)`，返回清理函数，并通过 `ctx.setLeaveGuard` 登记未保存检查。切换项、切换页面和离开页面都先走同一个保护（沿用 `editorGuard`）。
- 例外：浏览器接管项在桌面已连接时，切换到其他设置项不卸载，只隐藏，桌面保持连接，与旧长页面中折叠分区不卸载的行为一致。只有离开设置页、或桌面未连接时才卸载。现有 `browser.js` 卸载时会断开桌面。
- 模块文件拆分（实施者决定，建议放在 `public/js/views/settings/` 下）：
  - 运行与发送：从现有 `settings.js` 的运行模式、`renderLimits`、`loadPosting` 迁出；
  - 模型、定时任务、消息分级、浏览器接管、日志阶段与队列、任务执行历史：分别复用现有设置页对应分区实际挂载的模块（`model.js`、`task-settings.js`、`triage-settings.js`、`browser.js`、`program.js` 等），去掉页面级标题与外层卡片。`tasks.js` 已经没有地方引用，不作为依据；
  - 记忆：由 `memory.js` 改造，并合入 `experience-panel.js` 与原 `renderPolicy`；
  - 计费：由 `billing.js` 改造；
  - 采集来源、健康与日报：从现有 `settings.js` 的 `loadSources`、`loadHealth`、`healthForm` 迁出。

### 2.1 左栏摘要

| 设置项 | 摘要内容 | 数据来源 |
| --- | --- | --- |
| 运行与发送 | 模式与运行状态，如“自动 · 已暂停” | 全局状态流 + `GET /api/program` |
| 模型 | 使用中模型名称，或“尚未配置” | 全局状态流 |
| 定时任务 | 启用数／可开关的任务数（主循环和宿主健康检查不计入分母） | 现有任务接口 |
| 消息分级与过滤 | 排队数 | 现有分级摘要接口 |
| 记忆 | 身份数，或策略摘要“近期 3 次 / 7 天” | 现有记忆接口（实施者按可得数据选择） |
| 计费 | 今日估算费用，或“未定价 N” | 现有计费汇总接口 |
| 浏览器接管 | 未接管／人工接管中／需要登录 | 全局状态流 |
| 采集来源 | 打开该项之后显示启用数／来源数，之前不显示 | 现有来源接口（它会访问浏览器，所以不在打开设置页时读取） |
| 健康与日报 | 正常，或“需关注 N”“异常 N”（带颜色） | 现有健康接口 |
| 日志阶段与队列 | 不显示 | — |
| 任务执行历史 | 最近一次失败时显示“最近失败” | 现有任务记录接口 |

- 摘要在设置页打开时读取；收到状态事件或某项保存成功后，刷新相关的摘要。
- 某个摘要读取失败时，该项显示“—”，不阻塞其他项，也不弹错误。
- 摘要读取 MUST 是只读的：不触发模型调用和任务执行，也不新增浏览器请求。全局状态流每 10 秒轮询 `/api/status`，它本来就会读取浏览器身份，这不属于设置页新增的请求。采集来源的接口会访问浏览器，因此不参与摘要；账号字数只读已缓存的结果，不触发“重新读取”。
- 如果打开设置页时并发请求过多，可以新增只读接口 `GET /api/settings/summary` 汇总以上内容（实施者决定）。新增时它只读现有服务的数据，不加新的统计口径。

## 3. 各设置项布局

每项都按草图实现，以下只写结构和与现状不同的地方。

### 3.1 运行与发送

- **运行模式**：两张单选卡（草稿、自动），各带一句说明。选中即调用现有的运行设置保存接口，保存失败时恢复原选择并提示。与现在不同的是，现有 `saveMode` 会把未保存的发送限制一起提交并标为已保存；改版后只提交 `mode` 和当前已保存的其他字段，未保存的发送限制保持未保存状态。
- **发送限制**：三列数字框：公开每小时、私信每小时、公开每日、每轮最多处理、普通消息时效。每个框下方显示本小时或今日的已用量，数据来自现有队列与额度接口。页头“保存”只保存这组限制。
- **账号字数**：原创和公开回复各一行，显示上限、来源和检查时间，另有“重新读取”。重新读取沿用现有接口，可能访问浏览器，所以只在点击时执行。

### 3.2 模型

- 主区按“主区二级列表”规则分两部分：
  - 左侧：服务商列表，分“已配置”和“可添加”，带搜索。现有的“添加服务商”对话框保留，模型库验收脚本依赖它。“可添加”里的条目只是快捷入口，点击后打开同一个对话框并预选该服务商；已配置的内置服务商不再出现在“可添加”中；“自定义兼容接口”始终可用，可以添加多个；
  - 右侧：服务商详情，依次是接口（地址、Key 掩码与更换）、模型列表（单选使用中、价格或未定价）、参数（回复上限 64–8192、推理档位等现有字段）、上次连接测试结果。
- 页头：服务商名称、使用中徽标；刷新目录、连接测试（计费）、保存。
- 现有模型库的所有行为不变：Key 槽位、同主机共用、切换确认、自动拉取模型等。

### 3.3 定时任务

- 与现在一样列出全部九个任务：主循环、虚构日程、记忆补整理、早安帖、晚安帖、数据库备份、宿主健康检查、每日日报、账号合规检查。
- 每行：开关、名称、说明（计划、上次结果与费用）、时间或间隔框、“单次执行”（会调用模型的任务带计费标记）。页头“保存”保存计划。
- 主循环一行只能改循环间隔，没有开关和单次执行，写明“由顶部启动／暂停控制”。保存时 MUST NOT 为主循环提交 `enabled`，因为 `PUT /api/tasks/main` 带 `enabled` 会直接恢复业务。
- 宿主健康检查一行只读，与现在相同。
- 底部链接打开“任务执行历史”项。
- 已知差异：现有规格要求宿主健康检查与证书续期的结果可在定时任务处查看，但当前页面没有展示证书续期。本提案不改变这一现状，不新增展示，以免混入行为变化；该差异另行处理。

### 3.4 消息分级与过滤

- 顶部四个指标卡：今日公开额度（含问候帖）、排队（按优先、普通）、今日过滤（按原因）、骚扰冷却人数。
- 中部规则表单：两列文本框和数字框，字段与现有分级设置相同。页头“保存”。
- 底部骚扰冷却名单：每行一个身份和渠道，显示冷却截止时间，可“清除”。

### 3.5 记忆

- 页头分段切换三个视图：
  - **用户记忆**：主区二级列表。左侧是身份列表，带搜索和全部／公开／私信筛选，显示每个身份的渠道、条目数和遗忘状态；右侧依次是身份信息和操作（只读召回预览、立即整理〔计费〕、遗忘或恢复）、长期记忆（编辑、删除、来源）、近期往来。
  - **角色经历**：原记忆页的角色经历面板，包括登记、编辑和隐藏。
  - **策略**：原设置页的记忆策略表单，带“保存”。
- 从 `#/memory?...` 或动态页跳来的地址，按查询参数选中账号、身份和渠道，行为与现在相同。

### 3.6 计费

- 内容与交互完全沿用计费现有规格，包括汇总条、52 周热力图的三种视图、近 7 日与近 30 日每模型趋势、按模型或按用途的用量占比，以及默认收起的调用流水。
- 范围控件与现状完全相同：页头右侧是“近 7 日／近 30 日”切换，默认近 7 日；今日、本月和自选日期仍在“更多筛选”中。草图中页头的“今日／本月／自选”只是示意，以现状为准。图表配色改用新变量，浅色和深色都要清晰。
- 用途名称已包含 `add-persona-workspace` 新增的“试聊”。

### 3.7 浏览器接管

- 上方是状态列表：账号与登录、接管状态、需要处理的账号设置（链接到“健康与日报”）。
- 下方是桌面区域：未接管时显示说明，接管后嵌入现有桌面。
- 页头按状态显示“接管并连接”“连接桌面”或“释放接管”，接管语义不变。

### 3.8 采集来源

每个来源一行，显示状态圆点、名称、启用状态和原因；页头有“刷新状态”。

### 3.9 健康与日报

- 顶部是指标卡，不正常的指标用告警色标出。
- 下面依次是账号检查列表、日报列表（可查看单日）。
- “健康与披露配置”默认收起，展开后是披露词和运行阈值表单，带保存；页头有“刷新”。

### 3.10 日志阶段与队列

- 页头分段切换日志、阶段、队列。
- 日志：筛选框、级别筛选、“暂停实时”，每行一条：时间、级别圆点、事件、说明。
- 阶段和队列沿用现有内容。

### 3.11 任务执行历史

每次执行一行：状态圆点、任务名称、时间与触发方式、状态徽标、费用，点开显示详情。

## 4. 窄屏

- 设置项列表进入抽屉，选中后关闭。
- 主区二级列表收为详情顶部的选择器（模型选服务商、记忆选身份）。
- 页头里次要的说明和按钮在窄屏隐藏，主要操作（保存、接管）始终可见。
- 指标卡改为两列，表单改为单列。

## 5. 兼容与回退

- 只有前端变化，没有数据和接口语义变化。如果实施时新增了 `GET /api/settings/summary`，它也只是只读汇总。
- 回退到旧版本即恢复五页导航和长设置页。浏览器里的 `ws:settings:*` 键对旧版本无影响；旧版本的 `settings:open:*` 键仍保留在浏览器中，新版本忽略。

## 6. 验证

构建、测试和界面验收只在服务器隔离环境执行，不使用生产数据目录。

- **路由**：所有新地址可直接打开；旧地址 `#/overview`、`#/model`、`#/program`、`#/tasks`、`#/browser`、`#/memory?...`、`#/billing`、`#/settings/limits` 跳转正确；旧 `#/memory?...` 跳转后选中正确的身份。
- **各设置项**：十一项逐一打开，保存、校验失败提示、只读区都与改版前一致。现有设置保存与校验的自动测试全部通过。
- **未保存保护**：在运行与发送、模型、分级、记忆、健康配置中各做一次未保存修改，然后切换项、切换页面、刷新页面，都会询问；选择保留时内容不变。
- **摘要**：模拟各接口返回不同状态，左栏摘要文字与颜色正确；某个接口失败时显示“—”，不影响其他项；打开设置页时没有模型调用，除全局状态轮询外没有浏览器请求（断言调用流水计数为零，浏览器请求只有 `/identity`）。
- **浏览器接管**：桌面已连接时切到“健康与日报”再切回，桌面连接没有断开；离开设置页时才断开。
- **计费**：计费图表交互验收脚本改到新位置后全部通过。
- **界面**：1440、1280、860、375 四种宽度，浅色和深色，十一项全部截图存入证据目录，无整体横向滚动。
- **回归**：五页、模型库、记忆、计费等现有界面验收脚本中与页面位置相关的步骤改写后通过。

## 7. 留给实施者的决定

- 设置项模块的文件拆分与命名。
- 是否新增 `GET /api/settings/summary`，以及记忆项摘要显示身份数还是策略摘要。
- 指标卡、表单列数等细节尺寸，以草图为参照。

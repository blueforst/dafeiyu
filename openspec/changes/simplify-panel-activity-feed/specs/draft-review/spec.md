# 草稿人工处理增量规格

## Purpose

让管理员在动态时间线上直接处理角色生成的回复与私信草稿：修改文字后批准发送，或让模型按当前人设重写。人工批准的发送必须和自动发送遵守同一套身份、额度、出站与回执规则，重写结果始终等待人工确认。

## ADDED Requirements

### Requirement: 改写并批准发送

管理员 MUST 能在动态中修改回复或私信草稿的文字并批准发送。批准时系统 MUST 校验：正文非空；公开回复通过当前账号对应回复类型的生效字数策略（普通或未知／过期／冲突时使用 280 加权字符，仅在长帖资格、数字上限和计数适配均确认时使用对应长帖规则）；草稿未过期；草稿自管理员打开后未被重写或改动。校验通过后该条状态变为“等待发送”，发送的正文为批准时的文字。字数策略、提交前重新复核与明确未提交收束沿用[账号发帖限制提案](../../../add-account-aware-post-limits/specs/x-posting-limits/spec.md)；管理员批准不能授权未确认的长帖权限，私信仍为 4,000 个 JavaScript 字符。

#### Scenario: 修改后发送
- **WHEN** 管理员把草稿“在的，你说～”改为“在的，怎么啦？”并点击发送
- **THEN** 该条变为“等待发送”，最终提交到 X 的正文是“在的，怎么啦？”

#### Scenario: 公开回复超长
- **WHEN** 管理员修改后的公开回复超过当前账号对应回复类型的生效字数上限
- **THEN** 系统拒绝批准并提示超出长度，草稿保持不变

#### Scenario: 草稿已被重写
- **WHEN** 管理员在一个页面批准草稿前，该草稿已在另一页面被请求重写
- **THEN** 系统拒绝批准并提示重新读取，不发送旧版本

### Requirement: 批准发送沿用出站规则

已批准的草稿 MUST 只在系统处于处理中时由主循环发送，并与自动发送使用相同的发送前身份复核、通道额度、退避、待回查阻塞、可靠目标校验、持久出站和唯一回执规则。运行模式为草稿时已批准草稿同样发送。暂停、等待排空或人工接管期间，已批准草稿 MUST 保持等待，不得发送。

#### Scenario: 草稿模式下批准
- **WHEN** 系统处于处理中、运行模式为草稿，管理员批准一条草稿
- **THEN** 主循环在下一轮发送该草稿并记录平台回执，其他未批准草稿不发送

#### Scenario: 暂停时批准
- **WHEN** 系统已暂停时管理员批准一条草稿
- **THEN** 该条显示“等待发送（恢复处理后发送）”，恢复处理前不提交到 X

#### Scenario: 通道额度已用尽
- **WHEN** 私信通道本小时额度已用尽时存在已批准私信
- **THEN** 该私信保持“等待发送”并显示额度原因，额度恢复后的轮次再发送

#### Scenario: 提交后结果未知
- **WHEN** 已批准草稿提交后连接中断，无法确认是否发出
- **THEN** 该条显示“待回查”，系统只回查不重复提交

#### Scenario: 发送前账号已变化
- **WHEN** 发送前复核发现浏览器登录账号与草稿所属账号不同
- **THEN** 系统不发送并按现有规则安全暂停

### Requirement: 取消等待发送

处于“等待发送”且尚未提交到平台的草稿 MUST 可以取消，取消后恢复为草稿并保留批准时的文字；已开始提交的条目 MUST NOT 可取消。

#### Scenario: 发送前取消
- **WHEN** 管理员在主循环提交前取消一条等待发送的私信
- **THEN** 该条恢复为草稿，文字为批准时修改后的版本，不提交到 X

#### Scenario: 已在提交中
- **WHEN** 管理员取消一条已进入提交阶段的草稿
- **THEN** 系统拒绝取消并显示当前发送状态

### Requirement: 重写草稿

管理员 MUST 能请求重写一条草稿。重写由主循环按当前人设、记忆和对话上下文重新生成，并计入统一计费；重写结果 MUST 始终作为草稿等待人工确认，即使运行模式为自动。重写期间该条显示“重写中”且不可批准；重写时模型选择跳过的，系统 MUST 保留原草稿并提示。

#### Scenario: 自动模式下重写
- **WHEN** 运行模式为自动，管理员请求重写一条草稿
- **THEN** 新生成的回复作为草稿显示，不自动发送

#### Scenario: 暂停时请求重写
- **WHEN** 系统已暂停时管理员请求重写
- **THEN** 该条显示“等待重写（恢复处理后执行）”，暂停期间不调用模型

#### Scenario: 重写时模型选择跳过
- **WHEN** 重写生成结果为跳过
- **THEN** 该条恢复为原草稿，并提示本次重写选择了跳过及原因

### Requirement: 草稿过期

超过普通消息处理时效的草稿 MUST 显示为“已过期”，不可批准或重写；已批准但在发送前超过时效的，系统 MUST 不发送并标记为已跳过（超时未发送）。

#### Scenario: 打开一条旧草稿
- **WHEN** 一条草稿对应的消息已超过普通消息时效
- **THEN** 该条显示“已过期”，发送和重写按钮不可用

#### Scenario: 等待发送期间过期
- **WHEN** 已批准草稿因暂停一直未发送，恢复时已超过时效
- **THEN** 系统不发送该条并标记为“已跳过：超时未发送”

### Requirement: 草稿操作留痕

批准、取消和重写请求 MUST 写入运行日志，记录操作、消息关联 ID 和结果，日志 MUST NOT 包含草稿或回复正文。

#### Scenario: 查看批准记录
- **WHEN** 管理员批准一条草稿后在排查问题区按该消息关联 ID 筛选日志
- **THEN** 日志显示批准与后续发送结果，不显示正文

# 动态时间线增量规格

## Purpose

让管理员打开面板就能按时间看到角色最近的回复、私信和公开发帖，以及每条对应的对方原话、发送状态和细节，并能从一条互动直接跳到该用户的记忆，不再需要逐条展开消息编号或原始数据。

## ADDED Requirements

### Requirement: 动态时间线内容

面板首页 MUST 以“动态”时间线按时间倒序列出当前工作账号的公开回复、私信和早晚安帖。每条显示类型、对方账号（帖子除外）、时间和状态；回复与私信同时显示对方原话和角色回复正文，帖子显示正文。所有外部文本 MUST 按纯文本显示。时间线 MUST NOT 显示其他工作账号的数据。

#### Scenario: 查看已发送回复
- **WHEN** 一条公开回复已确认发送且回执带有平台链接
- **THEN** 时间线显示对方原话、回复正文、“已发送”状态和在 X 上查看的链接

#### Scenario: 模型选择跳过
- **WHEN** 模型对一条入站消息选择跳过
- **THEN** 该条显示“已跳过”和跳过原因，不显示空白回复

#### Scenario: 查看早安帖
- **WHEN** 早安任务已提交一条公开帖子
- **THEN** 时间线显示“发帖”类型、任务名称、帖子正文和出站状态

#### Scenario: 数据库含其他账号记录
- **WHEN** 数据库中存在其他工作账号或未知归属的消息
- **THEN** 时间线只显示当前工作账号的记录

#### Scenario: 原话含 HTML 片段
- **WHEN** 对方原话包含 HTML 标签或脚本片段
- **THEN** 页面按原样文本显示，不执行或解析其中内容

### Requirement: 时间线筛选与待处理计数

时间线 MUST 提供全部、待处理、回复、私信、发帖五种筛选。待处理 MUST 包含未过期的草稿、重写中和已批准待发送的条目，未超过普通消息时效的发送失败条目，以及发送结果待回查的条目；已过期的条目不计入。待处理数量 MUST 显示在筛选项上，并在其他页面的导航“动态”入口上显示。

#### Scenario: 筛选待处理
- **WHEN** 存在两条草稿、一条发送失败和若干已发送回复
- **THEN** 选择“待处理”只显示这三条，筛选项和导航上显示数量 3

#### Scenario: 旧草稿已过期
- **WHEN** 一条草稿已超过普通消息时效
- **THEN** 它仍在“全部”中显示为已过期，但不计入待处理数量

#### Scenario: 没有待处理
- **WHEN** 当前没有草稿、失败或待回查条目
- **THEN** 不显示数量标记，“待处理”筛选显示空状态说明

### Requirement: 时间线分页

时间线 MUST 首次只加载有限条数，并提供“加载更早”继续向前翻页；翻页过程中有新条目到达时，已加载内容不得重复或遗漏。

#### Scenario: 浏览时有新消息到达
- **WHEN** 管理员已加载两页后有新消息入库，再点击“加载更早”
- **THEN** 新消息出现在顶部，第三页紧接第二页最后一条，没有重复条目

### Requirement: 条目细节默认收起

每条 MUST 默认只显示正文和状态；展开“详情”后显示关联的模型调用（用途、模型、耗时、token、费用估算或未定价）、平台回执和错误原因。细节 MUST NOT 显示提示词正文或密钥。

#### Scenario: 展开一条回复的详情
- **WHEN** 管理员展开一条已发送回复的详情
- **THEN** 页面显示该回复关联的调用耗时、token 和估算费用以及平台回执，费用与计费页同一流水一致

#### Scenario: 发送失败
- **WHEN** 平台明确拒绝一条回复
- **THEN** 该条显示“发送失败”，展开详情可见拒绝原因

### Requirement: 跳转到用户记忆

回复和私信条目 MUST 提供“记忆”入口，打开记忆页并直接选中该条所属的工作账号、用户和渠道；帖子条目不提供该入口。

#### Scenario: 从私信跳到记忆
- **WHEN** 管理员点击一条私信条目的“记忆”
- **THEN** 记忆页打开并显示该用户在私信渠道的记忆，不显示其公开渠道记忆

#### Scenario: 记忆页有未保存修改
- **WHEN** 管理员已在记忆页修改条目但未保存，再从动态点击另一用户的“记忆”
- **THEN** 页面提示保留编辑或放弃，不静默丢失修改

### Requirement: 时间线实时刷新

动态页打开期间，新入库消息、状态变化和新帖子 MUST 在不手动刷新的情况下出现在时间线中；刷新 MUST NOT 覆盖管理员正在编辑的草稿文字。

#### Scenario: 草稿发送成功
- **WHEN** 管理员批准的草稿在后台发送成功
- **THEN** 该条状态在页面上变为“已发送”，无需重新加载页面

#### Scenario: 编辑草稿时后台刷新
- **WHEN** 管理员正在修改一条草稿，期间时间线收到更新
- **THEN** 输入框中的文字和光标位置保持不变

### Requirement: 首页概况行

动态页顶部 MUST 用一行显示运行状态、运行模式、当前模型、登录账号和暂停／恢复主操作，取代原主页面的运行、账号、模型卡片；配置错误、通道退避和待回查数量在该行下方以提示显示。

#### Scenario: 草稿模式运行中
- **WHEN** 系统处于处理中且运行模式为草稿
- **THEN** 概况行显示“处理中”“草稿模式”、模型名称、登录账号和“暂停”按钮

#### Scenario: 公开通道退避
- **WHEN** 公开通道处于平台拒绝后的退避期
- **THEN** 概况行下方显示退避结束时间

# 模型配置增量规格

## MODIFIED Requirements

### Requirement: 服务商与模型配置

系统 MUST 允许管理员从服务商目录添加服务商或自定义兼容接口，目录中展示已接入和暂未接入的服务商及原因；已添加的服务商及其模型配置 MUST 同时保存，系统同一时间只使用其中一个模型，并在后续处理轮次使用该模型。

#### Scenario: 服务商暂未接入
- **WHEN** 某服务商需要尚未支持的认证或云参数
- **THEN** 添加服务商的目录中展示原因且不允许误选为已可用服务商

#### Scenario: 保存新模型
- **WHEN** 管理员把一个已添加的模型设为使用中
- **THEN** 后续处理使用新模型，无需重建镜像且不会自动恢复暂停的业务

#### Scenario: 切换后再切回
- **WHEN** 管理员把使用中的模型从服务商 A 切换到服务商 B，之后再切回 A
- **THEN** A 的地址、Key 和模型参数仍然保留，无需重新填写

## ADDED Requirements

### Requirement: 模型分区两栏布局

设置页模型分区 MUST 采用左右两栏：左栏列出已添加的服务商，每项显示名称和状态（就绪、未就绪），并标出使用中模型所在的服务商；右栏显示所选服务商的详情。就绪表示已设置 Key 且至少一个模型测试通过。窄屏下左栏 MUST 收为右栏顶部的服务商选择器，页面不得横向溢出。

#### Scenario: 打开模型分区
- **WHEN** 管理员已添加 DeepSeek 和一个自定义中转站，使用中模型属于 DeepSeek
- **THEN** 左栏显示两个服务商及各自状态，DeepSeek 带“使用中”标记，右栏默认显示 DeepSeek 详情

#### Scenario: 窄屏查看
- **WHEN** 管理员在 375px 宽度下展开模型分区
- **THEN** 服务商以顶部选择器切换，详情区可完整操作，没有整体横向溢出

### Requirement: 服务商详情与连接

服务商详情 MUST 显示 Base URL（目录服务商带预设值且可修改）、接口协议（仅自定义接口可选）和 API Key（只显示掩码）。修改 Base URL 的主机后 MUST 要求重新填写 Key；使用中模型所在的服务商 MUST NOT 可删除。

#### Scenario: 修改地址主机
- **WHEN** 管理员把已设置 Key 的服务商 Base URL 改到另一主机
- **THEN** 页面提示需要重新填写 Key，旧 Key 不会发送到新主机

#### Scenario: 删除使用中的服务商
- **WHEN** 管理员尝试删除使用中模型所在的服务商
- **THEN** 系统拒绝删除并提示先切换使用中的模型

### Requirement: 添加服务商后自动拉取模型

添加服务商并保存 Key（自定义接口还需地址与协议）后，系统 MUST 自动用该 Key 拉取模型列表并保存为该服务商的模型列表，之后管理员只需从列表中选择模型。服务商详情 MUST 提供“刷新列表”重新拉取；拉取失败时 MUST 显示原因，目录服务商回退为目录中的模型，并允许手动填写模型 ID。

#### Scenario: 添加目录服务商
- **WHEN** 管理员从目录添加 DeepSeek 并保存 Key
- **THEN** 系统自动拉取模型列表，右栏直接显示可选模型，无需逐个添加

#### Scenario: 拉取失败
- **WHEN** 自定义接口不提供模型列表或 Key 无效
- **THEN** 页面显示失败原因，允许刷新重试或手动填写模型 ID

#### Scenario: 刷新后模型下线
- **WHEN** 刷新列表后，接口不再返回使用中的模型
- **THEN** 该模型仍保留并标注“接口未返回”，不自动切换使用中的模型

### Requirement: 服务商模型列表

服务商详情 MUST 以可搜索列表显示该服务商的模型，管理员测试过、编辑过或正在使用的模型排在前面。每行显示模型名称、上下文长度、推理与看图标记，并提供测试、编辑和设为使用中。编辑 MUST 包含推理强度、回复长度上限（默认 4096）和超时；无法识别的模型另需填写上下文长度和是否支持推理。

#### Scenario: 在长列表中选择
- **WHEN** 某服务商拉取到上百个模型
- **THEN** 管理员可按名称搜索，已用过的模型显示在顶部

#### Scenario: 选择未识别的模型
- **WHEN** 管理员把一个目录无法识别参数的模型设为使用中或打开编辑
- **THEN** 编辑窗口要求填写上下文长度和是否支持推理后才能保存

### Requirement: 单模型测试与切换确认

模型列表中的每个模型 MUST 可单独测试，测试按钮带“计费”标记，结果（通过及耗时，或失败原因）显示在该行并保留到下次测试。把最近一次测试未通过或从未测试的模型设为使用中时，系统 MUST 先请求管理员确认。

#### Scenario: 测试单个模型
- **WHEN** 管理员点击某模型的“测试”
- **THEN** 系统用该服务商的地址和 Key 发送一次小请求，在该行显示结果并记录到统一计费流水

#### Scenario: 切换到未测试的模型
- **WHEN** 管理员把从未测试的模型设为使用中
- **THEN** 页面先提示该模型未通过测试，管理员确认后才切换

### Requirement: 既有模型配置迁移

升级后系统 MUST 把原有的单一模型配置迁移为一个已添加服务商及其中一个使用中模型，保留地址、协议、推理强度、回复长度上限、超时、自定义参数和已保存的 Key，不改变实际调用行为。

#### Scenario: 升级后打开模型分区
- **WHEN** 升级前已配置并测试过一个 OpenCode 模型
- **THEN** 升级后模型分区左栏显示 OpenCode 并标记使用中，模型参数、Key 掩码和测试结果与升级前一致，正式请求仍保留会话路由

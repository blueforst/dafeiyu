# 动态首页与面板精简提案

## Why

七页面板上线后，管理员最常做的事是看角色最近发了什么帖、回了谁、回得怎么样，但这些内容只能在主程序页的“消息与回执”里按消息 ID 逐条展开原始 JSON 查看，早晚安帖只在任务历史中留出站编号。与此同时，每个页面平铺了大量设好后很少再改的配置项和说明文字，设置分散在模型、主程序、定时任务、记忆四处。草稿模式下生成的回复也没有任何处理入口，只能看不能发。项目仍处于 MVP 阶段，趁使用习惯尚未固定，把面板改成“先看动态、配置收起”的结构。

## What Changes

- 新增“动态”首页：一条按时间倒序的时间线，显示回复、私信和早晚安帖，每条包含对方原话、角色回复（或帖子正文）、状态、时间，可按全部／待处理／回复／私信／发帖筛选；细节（模型调用、耗时、费用、回执）默认收起。
- 首页顶部一行显示运行状态、运行模式、当前模型、登录账号和暂停／恢复主按钮，替代原主页面的运行、账号、模型三张卡片；浏览器需要人工处理时显示提示条。
- 新增草稿处理：草稿可以直接修改文字后发送，也可以让模型按当前人设重写。发送沿用现有出站、额度、退避、身份复核和回执规则，由主循环执行；重写产生的草稿始终等待人工确认，不会自动发送。
- 回复和私信可跳转到该用户在对应渠道的记忆。
- **BREAKING**（面板导航）：一级页面由七个改为五个：动态、人设、记忆、设置、计费。模型、主程序、定时任务三页并入“设置”；旧地址 `#/overview`、`#/model`、`#/program`、`#/tasks`、`#/browser` 跳转到对应新位置。
- 设置页按分区折叠，每个分区标题行显示当前值摘要：运行模式（直接切换）、模型、定时任务（紧凑表格、统一保存）、发送限制、记忆策略；浏览器接管、日志、阶段、队列和任务执行历史收进“排查问题”区。原主程序页的“消息与回执”由动态首页取代。
- 模型配置由“只有一个模型”改为参照开源 ZCode：可以添加多个服务商，配置同时保存，从全部模型中选一个使用。设置页模型分区改为左右两栏：左栏是已添加的服务商及状态（就绪／未就绪／使用中），右栏是所选服务商的地址、协议、Key 和模型列表。添加服务商并保存 Key 后自动拉取模型列表，之后只需选择模型；每个模型可单独测试、编辑参数并设为使用中。切换模型不再需要重新填写。按用途为不同任务分配不同模型留待后续提案，本次的数据结构为其预留位置。
- 人设页拆为“人设／今日日程／试聊”三个标签；触发规则和固定系统约束默认折叠。
- 记忆页移除记忆策略（移至设置页），筛选收敛为搜索框和渠道切换，工作账号筛选收进“更多筛选”。
- 计费页参照开源 ZCode 的用量统计页重做：顶部一条汇总条（累计 token、累计估算费用、单日峰值、近 7 日缓存读取占比、近 7 日平均每次回复费用）；其下为最近 52 周活动热力图（每日／每周／累计切换）；近 7 日／近 30 日切换的按模型每日趋势折线；按模型或用途切换的用量占比环形图及明细；数字用中文紧凑单位（万／亿）和等宽字体。调用流水默认折叠，自选日期范围收进“更多筛选”。估算口径不变：只用 Pi 内置价格、美元，未定价不计为零。
- 全面删减说明小字：计费提醒改为按钮上的“计费”标记与悬停说明，只保留真正需要警告的提示（例如会真实发送到 X 的操作）。

## Capabilities

### New Capabilities

- `activity-feed`：动态时间线的内容范围、排序、筛选、待处理计数、细节查看、记忆跳转与实时刷新。
- `draft-review`：草稿的人工改写发送、取消发送、重写、过期处理，以及人工批准发送与现有出站规则的关系。

### Modified Capabilities

- `panel-navigation`：一级页面改为五个并提供旧地址跳转；浏览器人工接管移到设置页“排查问题”区并在首页给出提示；页面职责改为按五页划分；主题与窄屏要求适用于五个页面。
- `workflow-observability`：阶段、队列、日志在设置页“排查问题”区展示；运行模式与额度在设置页配置。
- `task-scheduling`：任务计划在设置页的定时任务表中维护；主循环启停只由全局运行控制决定；健康检查结果在设置页查看。
- `role-daily-state`：日程在人设页“今日日程”标签展示，调度时间引用设置页定时任务表。
- `conversation-memory`：近期互动数量与原文保留策略改在设置页配置。
- `llm-usage-billing`：动态细节和设置页任务历史引用同一调用流水的费用；计费页改为 ZCode 式汇总条、活动热力图、按模型每日趋势与用量占比，展示缓存读取占比，汇总与流水筛选口径保持一致。
- `model-configuration`：多个服务商及其模型配置同时保存、从中选一个使用中模型；两栏布局、按模型测试与切换确认；原单一配置迁移。密钥掩码、会话路由、4096 默认上限和 CommandCode 未定价等既有要求不变。

`workflow-observability`、`task-scheduling`、`role-daily-state`、`llm-usage-billing` 由进行中的 `add-seven-page-production-bot` 提案新增，`panel-navigation` 与 `conversation-memory` 的被修改条文也以该提案的增量版本为准。本提案依赖该提案先归档；`persona-management`、`x-message-workflow` 的需求不变。

## Impact

- 前端：`public/index.html`、`public/js/app.js`（路由与旧地址跳转、顶部状态行）、`public/js/state.js`（动态事件订阅）、`public/style.css`，新增动态与设置视图，按两栏结构重写模型视图，按 ZCode 用量统计布局重写计费视图（内联 SVG 图表，不引入图表库），改造人设、记忆视图，复用任务、主程序视图的现有组件。
- 后端：新增只读动态列表接口和草稿操作接口（批准发送、取消发送、重写）；消息状态新增“已批准待发送”；主循环在每轮发送已批准草稿并复用现有发送路径；重写通过重新排队实现并带人工复核标记；SSE 增加动态更新事件。计费新增只读活动聚合接口（最近 52 周按北京日期汇总、按日期×模型汇总、缓存读取占比），由 SQL 分组计算。现有消息、任务、模型、人设、记忆、计费接口保持兼容。
- 模型：面板模型设置由单一配置扩展为“已添加服务商列表 + 使用中模型”，最近测试结果按模型保存；Key 仍按服务商和主机分槽保存；模型接口增加服务商与模型的增删改，正式调用路径只读取使用中模型，不改变适配器行为。
- 数据：消息表状态取值扩展，草稿记录增加编辑与复核标记，不新增表；面板设置文件的模型段落结构升级并自动迁移；需要确认迁移与回退脚本对新状态和新结构的处理。
- 运维：沿用服务器隔离构建、Camoufox 模拟数据界面验收和现有发布流程；人工批准发送属于真实平台写操作，其真实验收与 `add-seven-page-production-bot` 的平台收发验收采用相同证据等级和授权边界。
- 不涉及：按用途为回复、语义判定、日程、记忆整理分别选择模型（后续提案）；已发送内容的删除或撤回；草稿模式下早晚安帖改为草稿；新的通知渠道；视觉／视频理解。

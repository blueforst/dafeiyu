# 消息分级增量规格（私信每日额度）

## ADDED Requirements

### Requirement: 私信二十四小时额度

系统 MUST 按最近二十四小时滚动统计已提交的私信（已确认、提交中与 unknown，被平台明确拒绝的不计）；达到私信额度（默认 400，管理员可在 1–500 之间调整）后 MUST 不再提交新的私信。达到私信额度 MUST NOT 触发平台拒绝的四小时退避；窗口内最早的私信满二十四小时后名额自动释放；公开通道不受影响。草稿模式下额度不限制生成，审批后的实际发送仍受额度限制。

#### Scenario: 达到私信额度
- **WHEN** 最近二十四小时已提交 400 条私信，队列中还有私信和公开消息等待
- **THEN** 私信保持排队且不占用本轮名额，公开消息照常处理，私信通道不进入退避

#### Scenario: 跨零点不重置
- **WHEN** 私信额度为 400，前一天 12:00 至 24:00 已提交 360 条私信
- **THEN** 次日 00:00 之后只能再提交 40 条私信，较早的私信满二十四小时后才释放更多名额

#### Scenario: 被拒绝的私信
- **WHEN** 一条私信被平台明确拒绝
- **THEN** 该条不计入私信额度，私信通道仍按原规则退避四小时

#### Scenario: 审批草稿时额度已满
- **WHEN** 草稿模式下管理员批准一条私信草稿，此时最近二十四小时已达到私信额度
- **THEN** 系统不提交这条私信，草稿保持已批准并显示等待原因，名额释放后再提交

#### Scenario: 超出调整范围
- **WHEN** 管理员把私信额度设为 0 或 501
- **THEN** 保存被拒绝，原设置保持不变

## MODIFIED Requirements

### Requirement: 分级状态可见

面板 MUST 展示各通道各级别的排队数量、最长等待时间、今日公开提交数与每日额度、最近二十四小时私信提交数与私信额度、过滤与忽略的数量和原因；常规日志只记录级别与原因类别，不包含消息正文。

#### Scenario: 查看主程序队列
- **WHEN** 管理员打开队列信息
- **THEN** 能看到优先、普通的排队数和最长等待，以及当天已过滤、已合并、已忽略的数量

#### Scenario: 查看私信额度
- **WHEN** 最近二十四小时已提交 12 条私信，私信额度为 400，管理员打开队列信息
- **THEN** 能看到“近 24 小时私信 12 / 400”，与今日公开额度并列显示

# 私信每日额度提案

## Why

**X 的限制**：[About X limits](https://help.x.com/en/rules-and-policies/x-limits)（2026-09-26 存档）写明私信每天最多发送 500 条，网页、手机和 API 的操作合计。超过后平台报错，要等时间窗过去才能再发。

- 这一条没有按账号区分。同一页面里，只有发帖写了“未认证账号每天 50 条原创、200 条回复”，私信的 500 条不分认证与否。
- 项目也不识别账号的认证状态。因此私信额度不按账号权限调整，所有账号使用同一个默认值。

**现状（2026-10-28 核对本机提交 `5c1a4c3` 与生产服务器）：**

- 私信只有每小时上限（默认 30 条），没有每日上限。全天跑满，理论上一天可以发 720 条，超过 X 的 500 条。
- 公开通道已有每日额度（北京时间自然日，默认 180），私信没有对应设置。健康告警的自动化拦截提示里，私信的每日额度直接显示“未设置”。
- 生产库里私信入站和出站都是零条：新版 Chat 的可靠时间和入站身份还没通过验收，私信自动回复尚未真正启用。所以这是预防性改动，要在私信自动回复上线前补上。

## What Changes

- **新增私信额度 `privatePerDay`**：默认 400，管理员可以在 1–500 之间调整。上限不超过 X 公布的 500 条；默认值留出 100 条余量，用于管理员接管时手动发的私信（系统看不到这些私信，无法计数）。
- **按最近二十四小时滚动统计，不按自然日**：X 没有说明按哪个时区或时间窗计算。滚动统计能保证任意连续二十四小时都不超过上限；按自然日统计做不到，例如每小时 30 条时，零点前后各十二小时加起来最多 720 条。
- **计数口径**：已提交的私信（已确认、提交中与 unknown）都计入，被平台明确拒绝的不计，与公开每日额度的口径一致。
- **达到额度时**：
  - 私信通道不再占用每轮名额，私信继续排队，超时按现有分级时效处理；
  - 不写冷却键，不触发平台拒绝的四小时退避；
  - 窗口内最早的私信满二十四小时后，名额自动释放；
  - 公开通道不受影响。
- **草稿模式**：额度不限制生成；审批后的实际发送仍然检查，与小时额度现有语义一致。
- **面板**：
  - 设置页“发送限制”增加“私信 24 小时上限”；
  - 队列摘要在“今日公开额度”旁显示“近 24 小时私信 n / 400”；
  - 自动化拦截告警的私信部分显示这个额度，不再显示“未设置”。
- **不改**：公开每日额度（自然日、默认 180）、两个通道的小时额度、四小时退避和 unknown 只回查语义。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `reply-triage`：新增“私信二十四小时额度”；修改“分级状态可见”，加入私信计数与额度。

`reply-triage` 来自未归档的 `add-reply-triage`，本提案需要排在它之后归档。`account-compliance` 的“自动化拦截提示区分”只要求告警写明当前小时和每日额度，没有限定通道，私信改为显示新额度仍符合原文，不需要修改规格。

## Impact

- **代码**：
  - 配置：`src/types.ts`、`src/config.ts`、`src/settings.ts`、`src/program.ts`；
  - 计数与判断：`src/reply-triage.ts`、`src/workflow.ts`；
  - 接口：`src/triage-routes.ts`、`src/app.ts`；
  - 健康：`src/unattended-health.ts`；
  - 前端：`public/js/views/settings.js`、`public/js/views/triage-settings.js`。
- **测试**：`test/reply-triage.test.ts`、`test/triage-workflow.test.ts`、`test/unattended-health.test.ts`，以及面板设置相关测试和界面验收脚本。
- **文档**：`docs/前端接口.md` 的运行设置字段、范围和队列摘要字段。
- **不涉及**：数据库结构不变，没有迁移；不新增模型调用；不改出站回执和 unknown 只回查。
- **回退**：额度保存在面板设置的 `program` 分区。旧版本只读取自己认识的字段，会忽略 `privatePerDay`，回退无需清理。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行，生产发布需要另行授权。

## Out of Scope

公开每日额度按北京时间自然日统计，也有跨零点的问题：每小时 10 条时，任意连续二十四小时最多可发 240 条，超过 X 对未认证账号每天 200 条回复的限制。本提案不改公开额度，需要时另提。

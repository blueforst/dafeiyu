# 同一公开用户的跨帖近期上下文

## MODIFIED Requirements

### Requirement: 近期互动上下文

系统 MUST 向回复生成提供允许近期窗口内、按配置条数限制的入站原文，默认最近三条、七天；只把已确认发送的回复作为已经说过的话，草稿文本不得当成已发送记录。公开生成 MUST 能读取同一工作账号、同一公开用户在其他可靠线程中的近期来言及已确认回复，当前线程和其他线程必须区分来源；本次消息不得重复作为历史注入。尚未处理的其他线程可靠来言可以作为对方说过的话，不得被描述为角色已回复。

#### Scenario: 存在未发送草稿
- **WHEN** 用户的近期记录包含一条草稿和一条已确认回复
- **THEN** 上下文可包含收到的原文，但只有已确认回复被标识为角色已发送内容

#### Scenario: 同一个人在另一帖子继续说话
- **WHEN** 同一公开用户在帖子甲已有可靠往来，又在帖子乙发来新消息且均在允许窗口内
- **THEN** 帖子乙的实际生成上下文包含允许的帖子甲往来，并明确其来源为其他帖子；当前目标仍为帖子乙中的原消息

#### Scenario: 另一帖子尚未处理
- **WHEN** 同一用户在帖子甲的可靠入站仍为 queued、approved、generating、sending、unknown 或 merged，帖子乙开始生成
- **THEN** 帖子甲的入站可作为有来源的对方近期来言，其未确认草稿不得作为角色已经发出的回复

#### Scenario: 当前消息与当前线程待处理内容
- **WHEN** 当前线程的其他未处理来言已通过平台上下文或合并消息提供，当前消息也存在于本地记录
- **THEN** 近期历史不再次加入本次消息或当前线程的未处理条目，避免把同一内容重复注入

## ADDED Requirements

### Requirement: 跨帖来源可靠且范围隔离

跨帖近期历史 MUST 仅来自当前工作账号、当前公开用户和 public 渠道，具有可靠且一致的作者、平台消息 ID、线程、原时间和公开来源链接。身份、平台列或线程关系冲突、未来时间、来源不可靠和超出窗口的记录 MUST 被排除；其他用户、工作账号及私信原文不得通过该召回路径进入公开上下文。

#### Scenario: 同名用户与其他工作账号
- **WHEN** 数据库同时存在其他用户、其他工作账号及私信会话的相似文字
- **THEN** 当前公开跨帖历史仅含同账号、同公开用户的允许记录，不按相似文本或显示名合并

#### Scenario: 平台来源冲突
- **WHEN** 某条历史的作者、链接、平台 ID、线程或可靠时间相互冲突
- **THEN** 该条被跳过，不填入当前时间、不推断父子关系，也不作为已验证背景

### Requirement: 其他帖子背景不改变当前线程

提示词 MUST 说明其他帖往来只是同一人的相关公开背景，不能视作当前帖子的祖先对话或本次发送目标。跨帖召回 MUST NOT 修改消息的 conversationId、目标平台 ID、队列合并状态、出站来源或发送资格，两个帖子仍按现有规则分别处理。

#### Scenario: 不同帖子各有一条提及
- **WHEN** 同一个人在两个不同帖子各提及一次
- **THEN** 两条消息保留各自平台线程与回复目标；后处理消息可读取前一帖背景，但不把两条合并成同一次发送

#### Scenario: 同人其他帖包含不同话题
- **WHEN** 另一帖背景和本条消息讨论不同主题
- **THEN** 模型输入明确其他帖来源和当前目标，背景不被伪装为本帖上文

### Requirement: 有界召回与遗忘保持

跨帖近期召回 MUST 遵守现有条数、时间和正文资源边界，以确定性本地查询完成，不增加模型请求或修改 system 稳定前缀。遗忘中的用户不得返回历史，恢复记录后不得复活已由独立遗忘账本移除的内容；原私信召回及显式身份关联范围保持原有规则。

#### Scenario: 到达条数与时间边界
- **WHEN** 同一用户的可用公开历史多于配置条数，且部分已超出时间窗口
- **THEN** 系统只返回允许窗口内不超过配置条数的可靠历史，结果按时间呈现，不扫描无限历史或追加模型筛选请求

#### Scenario: 用户已被遗忘
- **WHEN** 当前用户处于遗忘状态或旧资料已按独立账本删除
- **THEN** 跨帖召回不返回其旧历史，也不因恢复旧库或恢复后续记录而重新引入已删除内容

### Requirement: 实际输入可核对

生产生成快照或等价受限证据 MUST 保存本次实际使用的近期历史及来源说明，常规日志不得复制消息正文。真实跨帖验收 MUST 核对第二帖实际模型输入包含第一帖允许往来，以及第二帖唯一回执仍匹配自身目标，不能以预览、fixture 或其他消息的成功替代。

#### Scenario: 核对真实跨帖生成
- **WHEN** 已授权同一对端在两个不同帖子参与测试，第二条完成生成和发送
- **THEN** 受限证据可核对第一帖往来确实进入第二条实际请求且标明其他帖，平台回执对应第二条原目标

#### Scenario: 查看普通日志
- **WHEN** 管理员查看包含跨帖历史的一次生成日志
- **THEN** 日志提供关联标识与结果，历史正文只存在于获准的受限业务证据中

# 人设管理增量规格（人设预设与默认人设）

## MODIFIED Requirements

### Requirement: 静态提示词可视化编辑

系统 MUST 提供角色定义、说话风格、记忆与承诺、互动边界等静态分区，每次回复始终使用已生效内容。管理员在配置文件中自行编写的旧人格文本 MUST 原样保留在角色定义中；与随版本发布的示例人格文本完全相同（仅忽略首尾空白）的内容视为未定制，改用通用默认人设。

#### Scenario: 导入自定义旧人格
- **WHEN** 面板从未保存过人设，配置文件中的人格是管理员自行编写的文本
- **THEN** 人设页的角色定义保留该原文，不编写新的角色身份或经历

#### Scenario: 配置文件仍是旧版示例文本
- **WHEN** 面板从未保存过人设，配置文件中的人格与旧版示例文本完全相同
- **THEN** 人设页显示通用默认人设的四个分区，而不是旧的一句话

#### Scenario: 示例文本只改了一个字
- **WHEN** 管理员把示例文本改动了一个字后写入配置文件
- **THEN** 系统视为自定义文本，原样保留在角色定义中

## ADDED Requirements

### Requirement: 内置人设预设

人设页 MUST 提供通用（默认）、大肥鱼、GPT 娘、Claude 娘、Kimi 娘、GLM 娘六个内置预设，每个显示名称和一句话简介。选中预设并确认后，系统 MUST 用它整体替换编辑框中的全部分区和触发规则，但不自动保存；管理员可以撤销这次填入，也可以先试聊或回放对比，再用现有保存流程保存，保存后下一轮生效且不改变暂停或接管状态。

每个预设 MUST 包含角色定义、说话风格、记忆与承诺、互动边界四个始终生效的分区；五个角色预设 MUST 另含她自己、外貌、认识的 AI 娘、身份设定四个“被问到才用”的分区，且每个这类分区的第一行写明触发条件。预设 MUST 只包含关键词触发规则，不得增加语义判定调用，并且每个预设都包含一条“不给步骤”和一条“被夸”关键词规则。每个预设的说话风格 MUST 先写六个预设完全相同的通用写法，再写本预设自己的口吻，口吻写明公开回复的常用长度；角色梗 MUST 按对方是否聊到相关话题、近期往来里是否用过来约束，不写模型无法核对的“几条里一次”频率。五个角色预设 MUST 写明自己是网友二创的非官方角色、与对应公司无关，不冒充官方。

#### Scenario: 填入预设但不保存
- **WHEN** 管理员选中“大肥鱼”并确认替换
- **THEN** 编辑框显示大肥鱼的分区和关键词规则，并标记未保存；已保存的人设和修订号保持不变

#### Scenario: 撤销填入
- **WHEN** 管理员填入预设后、保存前点击撤销
- **THEN** 编辑框恢复为填入前的内容

#### Scenario: 修改后保存
- **WHEN** 管理员填入“GLM 娘”，改动说话风格后保存
- **THEN** 系统保存改动后的内容，修订号加一，下一轮回复使用新人设

#### Scenario: 选用预设不增加判定调用
- **WHEN** 管理员保存任一未经修改的预设，随后一条消息命中其中的关键词规则
- **THEN** 该规则正文进入提醒区，本条消息只有一次回复生成请求

#### Scenario: 被问是不是官方
- **WHEN** 使用“Claude 娘”预设时，用户问“你是 Anthropic 官方的吗”
- **THEN** 互动边界和身份设定中的条款要求回复说明自己是网友二创的非官方角色、与 Anthropic 无关

#### Scenario: 询问做法
- **WHEN** 使用任一未经修改的预设，用户问“番茄炒蛋怎么做”
- **THEN** “不给步骤”规则命中，其正文进入提醒区，试聊显示命中关键词“怎么做”

#### Scenario: 比较两个预设的说话风格
- **WHEN** 管理员先后填入“大肥鱼”和“Claude 娘”，查看说话风格分区
- **THEN** 两者开头的通用写法完全相同，之后的口吻不同，且各自写明公开回复的常用长度

#### Scenario: 被夸
- **WHEN** 使用任一未经修改的预设，用户说“你好可爱”
- **THEN** “被夸”规则命中，其正文进入提醒区；用户说“我不喜欢你”时该规则不命中

#### Scenario: 被问到才用的分区
- **WHEN** 管理员填入任一角色预设并查看编辑框
- **THEN** 她自己、外貌、认识的 AI 娘、身份设定四个分区的第一行都是触发条件说明

### Requirement: 角色预设的账号披露提醒

选中角色预设时，人设页 MUST 显示该预设的建议简介，并可一键复制；建议简介 MUST 包含“非官方”和“AI”。保存来自角色预设的人设后，人设页 MUST 在当前页面显示提醒，直到管理员关闭或离开页面，提示管理员在恢复业务前修改 X 账号名称和简介，并建议把“非官方”加入合规检查的披露词。系统 MUST NOT 自动修改 X 账号资料或合规检查设置。

#### Scenario: 保存大肥鱼预设
- **WHEN** 管理员填入“大肥鱼”并保存
- **THEN** 人设页显示提醒，内容包含建议简介、修改名称和简介的说明，以及到设置页的链接；提醒在管理员关闭或离开页面前一直显示；账号资料和披露词设置保持不变

#### Scenario: 保存通用默认
- **WHEN** 管理员填入“通用（默认）”并保存
- **THEN** 人设页只提示今日日程不会自动改变，不显示非官方披露提醒

### Requirement: 统一的生效人设

面板从未保存过人设、且配置文件人格属于随版本发布的示例文本时，系统 MUST 使用通用默认人设作为生效人设。回复生成、试聊、早安帖、晚安帖和虚构日程生成 MUST 读取同一份生效人设。

#### Scenario: 未定制时生成日程
- **WHEN** 面板从未保存过人设，配置文件人格为旧版示例文本，系统生成当日虚构日程
- **THEN** 传给模型的人格内容来自通用默认人设，而不是旧的一句话

#### Scenario: 已在面板保存过人设
- **WHEN** 面板已保存过人设
- **THEN** 回复、试聊、早晚安帖和日程生成都使用面板保存的人设，配置文件中的人格不参与

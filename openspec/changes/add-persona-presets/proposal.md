# 人设预设与默认人设提案

## Why

系统交给别人使用后，对方打开人设页面对的是空白编辑框，或者一句自带矛盾的旧默认人设，很难从零写出一个有辨识度的角色。

**现状（2026-10-28 核对生产服务器与本机工作副本 `d16dfa2`）：**

- 生产面板设置 `app/panel/settings.json` 里没有 `persona`，所以线上走兜底逻辑（`src/persona.ts` 的 `legacyPersona`）：`config.json` 的一句话整段放进“角色定义”，“说话风格”“记忆与承诺”“互动边界”三个分区为空，也没有触发卡片。
- 这句话随 `config.example.json` 发布：“你是一个明确说明自己是 AI 的友善中文角色。简洁自然地回应用户，不编造经历或承诺，不主动发帖。”它与系统其他部分冲突：
  - “不主动发帖”与早安帖、晚安帖任务冲突。
  - “不编造经历”与每天生成并放进提示词的虚构日程冲突。
  - “明确说明自己是 AI”与固定系统约束重复。
- `config.json` 的 `dailyState` 字段已经没有代码读取，示例文本“不编造现实经历”同样与虚构日程冲突。
- 人设页没有任何预设或模板。

**为什么是这几个角色：** B 站和 X 上正流行“AI 娘”二创，网友把各家大模型画成女孩子并配上性格梗：DeepSeek 是爱吃白饭、嘴硬不承认胖的鲸鱼娘“大肥鱼”，GPT 是稳重又贪财的白发龙娘，Claude 是知书达理的大小姐，Kimi 是爱啃长文档的女仆，GLM 是精打细算的狐娘。这些角色有现成的人气和梗，适合作为可以直接挑选的起点。它们本身就是 AI，与固定约束“明确是 AI 自动回复”不冲突。

## What Changes

- **内置六个预设**：通用（默认）、大肥鱼、GPT 娘、Claude 娘、Kimi 娘、GLM 娘。
- **结构按参考帖分两类**：本项目参考的[大肥鱼作者复盘](https://x.com/Remake___/status/2114696368883429580)指出，外貌、偏好这类内容如果不写触发条件，模型会在每条回复里主动提。所以每个预设有四个始终生效的分区（角色定义、说话风格、记忆与承诺、互动边界）；角色预设另有四个“被问到才用”的分区（她自己、外貌、认识的 AI 娘、身份设定），每个分区第一行写明触发条件。
- **每个预设有自己的口吻**：说话风格分区先写六个预设相同的“通用写法”，只规定不要怎么写（不用客服腔和 Markdown、不写教程、不用“谢谢夸奖”开头等）；再写本预设的“口吻”：句子长短、公开回复常用长度、语气词和标点习惯，以及怎么接夸奖、玩笑和不知道的事。
- **写法吸收参考帖的经验**：
  - 不用“偶尔”这类模糊说法。角色梗用模型看得见的条件：对方没聊到相关话题时不主动抖梗，聊到了一条最多一个；和同一个人的近期往来里用过的梗、口癖、开头和收尾，这次不再用。跨人的重复不控制；
  - 点名禁用“谢谢夸奖”和叠词开头，并给出替代说法；
  - 允许不完美的口语，动作描写只在对方先写时才接；
  - 给见识设上限，不写教程和步骤；
  - 偏好、缺点、往事写具体，往事标明“以前发生过，今天不要再发生一遍”；
  - 被挑衅、辱骂时不还嘴，色情双关一律不接。
- **关键词卡**：每个预设都带一张“不给步骤”卡（参考帖坑 8 的做法）和一张“被夸”卡，角色预设另带二至三张招牌反应卡（例如有人友好地说大肥鱼胖，她就嘴硬否认）。只用关键词卡，不增加模型调用。
- **文本原创**：只借用网上公开流传的性格梗，不复制同人人设卡、其他项目的提示词，也不照搬参考帖作者为 @dafeifish 写的具体设定。每个角色预设写明“网友二创的非官方角色，与对应公司无关”，不冒充官方，不发布或评论该公司的消息、价格和政策。
- **只做温和版**：账号在 X 上公开回复，不提供嘴臭、对线、擦边等流派；不使用贬损真实公司的梗。
- **从预设开始**：人设页新增“从预设开始”，选中后整体替换编辑框里的分区和触发卡，不自动保存；可以撤销这次填入，也可以先试聊、回放对比，再用现有保存流程保存，下一轮生效。
- **账号披露提醒**：参考帖账号上线几天就因“冒用 DeepSeek”被冻结（坑 2）。每个角色预设附一段建议简介（如“非官方同人 AI 角色｜AI 自动回复｜与 DeepSeek 官方无关”），保存后提示管理员在恢复业务前修改 X 名称和简介，并建议把“非官方”加入合规检查的披露词。系统只提示，不代改。
- **默认人设更换**：没有在面板保存过人设时，系统使用“通用（默认）”预设，替代旧的一句话默认人设。管理员在 `config.json` 里自己写过的人格原文仍原样保留；只有与随版本发布的示例文本完全相同的内容才视为“未定制”。
- **生效人设统一**：回复、试聊、早晚安帖和虚构日程生成使用同一份生效人设，避免日程仍读取旧的一句话。
- **示例配置清理**：`config.example.json` 的 `persona` 改为新默认的角色定义原文，删除已不读取的 `dailyState`。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `persona-management`：修改“静态提示词可视化编辑”（区分自定义旧人格与随版本发布的示例文本），新增“内置人设预设”和“未定制时使用通用默认人设”。

这项能力目前只存在于未归档的 `add-seven-page-production-bot` 和 `fill-reference-post-gaps` 中，因此本提案需要排在它们之后归档。

**依赖**：预设使用关键词触发卡，这项能力来自 `fill-reference-post-gaps`，已随 `b607c3d` 提交并推送，具备服务器隔离证据；生产仍未发布。本提案在该提交之后实施，必须在关键词卡片发布之后发布和归档。

## Impact

- **后端**：新增 `src/persona-presets.ts`（预设数据与默认人设解析）；`src/persona.ts` 的读取逻辑、`src/daily-state.ts` 的人格读取改用统一解析；`src/persona-routes.ts` 新增 `GET /api/persona/presets`；`src/types.ts` 中 `dailyState` 改为可选。
- **前端**：`public/js/views/persona.js` 新增“从预设开始”区域；`public/style.css` 少量样式。
- **配置与测试夹具**：`config.example.json`、`test/config-fixture.ts`。
- **线上行为变化**：生产目前没有在面板保存过人设，而且用的正是旧示例文本。发布后，线上会自动从那句旧默认人设切换到“通用（默认）”。如果发布前不想改变线上人设，需要先在面板保存一次当前人设；发布记录必须写明这一点。
- **费用**：预设只使用关键词触发卡，不新增语义判定调用。角色预设控制在 4,000 字符以内（参考帖的人设约 4,000 字），放在可命中缓存的稳定前缀里。
- **不涉及**：固定系统约束、渠道规则、动态提醒、分级与限速、数据库结构均不改。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行，真实模型试聊和生产发布需要另行授权。

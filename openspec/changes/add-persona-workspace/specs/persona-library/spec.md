# 人设库规格

## Purpose

让管理员保存多个人设并在其中切换：恰好一个人设处于使用中，只有它参与生产回复、早晚安帖和日程生成；其他人设可以随时编辑、试聊和回放对比，切换前不影响线上。内置预设作为只读模板，用来新建人设。

## ADDED Requirements

### Requirement: 多人设保存

系统 MUST 允许保存最多二十个人设。每个人设有名称（一至四十字，去除首尾空白后在库内唯一）、分区和触发规则（沿用现有人设校验与 20,000 字符总上限）、各自的修订号、创建与更新时间，以及新建来源（空白、某个预设及其版本，或复制自某个人设）。保存 MUST 校验该人设的修订号，修订已变化时拒绝并提示重新读取，不覆盖他人的修改。保存使用中的人设时 MUST 从下一轮生效，不改变暂停、运行或接管状态；保存其他人设不影响生产。

#### Scenario: 保存未使用的人设
- **WHEN** 管理员修改“大肥鱼 · 温柔版”（未使用）的说话风格并保存
- **THEN** 该人设修订号加一；生产下一轮仍使用原来的使用中人设

#### Scenario: 保存使用中的人设
- **WHEN** 管理员修改使用中的人设并保存，此时一轮生成正在进行
- **THEN** 当前生成使用原快照，下一轮使用新内容，业务状态不变

#### Scenario: 修订冲突
- **WHEN** 两个浏览器标签打开同一个人设，先后保存不同的修改
- **THEN** 后保存的一次被拒绝并提示修订已变化，先保存的内容保持不变

#### Scenario: 名称重复
- **WHEN** 管理员把一个人设改名为库内已有的名称
- **THEN** 保存被拒绝，原名称不变

#### Scenario: 达到数量上限
- **WHEN** 库内已有二十个人设，管理员再新建一个
- **THEN** 新建被拒绝，并提示先删除不用的人设

### Requirement: 新建人设

管理员 MUST 能用三种方式新建人设：空白（只含四个始终生效分区的空白标题）、从内置预设新建（复制该预设当前版本的全部分区和触发规则）、复制已有人设。新建的人设 MUST 不处于使用中，修订号从一开始，并立即出现在“我的人设”中。

#### Scenario: 从预设新建
- **WHEN** 管理员查看内置预设“GLM 娘”并点击“以此新建”
- **THEN** “我的人设”中出现内容与该预设相同的新人设，处于未使用状态；内置预设本身不变

#### Scenario: 复制使用中的人设
- **WHEN** 管理员复制使用中的人设
- **THEN** 新人设内容相同、名称带“副本”字样、未使用；原人设的修订号不变

### Requirement: 切换使用中人设

库内 MUST 始终恰好有一个使用中的人设。把另一个人设设为使用中 MUST 先让管理员确认；确认后从下一轮开始，生产回复、早安帖、晚安帖和之后的日程生成都使用该人设。切换 MUST NOT 恢复暂停的业务、MUST NOT 修改 X 账号资料，当天已生成的日程保持不变。切换和保存都 MUST 写入运行日志，日志不记录人设正文。

#### Scenario: 暂停时切换
- **WHEN** 业务处于暂停状态，管理员把“GLM 娘”设为使用中并确认
- **THEN** 左栏“使用中”标记移到“GLM 娘”，业务保持暂停；恢复后的第一轮回复使用“GLM 娘”

#### Scenario: 切换不影响今天的日程
- **WHEN** 当天日程已由原人设生成，管理员切换使用中人设
- **THEN** 当天日程内容和来源不变；次日自动生成时使用新的使用中人设

#### Scenario: 取消切换
- **WHEN** 管理员点击设为使用中后在确认中选择取消
- **THEN** 使用中人设不变

### Requirement: 删除与重命名

管理员 MUST 能重命名和删除人设。使用中的人设 MUST NOT 被删除，删除按钮提示先切换到其他人设。删除其他人设前 MUST 确认；删除后不可恢复，已有试聊记录和回放记录中保存的人设名称快照保持可读。

#### Scenario: 删除使用中的人设
- **WHEN** 管理员尝试删除使用中的人设
- **THEN** 删除被拒绝，提示先把其他人设设为使用中

#### Scenario: 删除后查看旧试聊
- **WHEN** 管理员删除“通用 · 改”后打开曾用它回复的试聊记录
- **THEN** 那几轮仍显示“通用 · 改”及当时的修订号，并标注该人设已删除

### Requirement: 升级迁移

升级到本版本时，系统 MUST 把当前生效的人设作为名为“当前人设”的第一项并设为使用中，内容与升级前生效的完全相同（包括从未在面板保存过、使用通用默认人设或配置文件中自定义人格的情况）。升级本身 MUST NOT 改变任何回复所用的人设内容，也 MUST NOT 在管理员第一次保存人设库之前写入面板设置。回退到旧版本后，旧版本读取的人设 MUST 等于回退前的使用中人设。

#### Scenario: 从未保存过人设的部署升级
- **WHEN** 生产从未在面板保存过人设、正在使用通用默认人设时升级
- **THEN** 人设页“我的人设”只有“当前人设”一项且处于使用中，内容为通用默认人设；面板设置文件没有因升级而变化

#### Scenario: 升级后回退
- **WHEN** 管理员保存了三个人设并把第二个设为使用中，随后回退到旧版本
- **THEN** 旧版本的人设页和回复都使用第二个人设的内容

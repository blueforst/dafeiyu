# 人设管理增量规格（人设工作区）

## MODIFIED Requirements

### Requirement: 内置人设预设

人设页人设模式的左栏 MUST 在“内置预设”分组中列出通用（默认）、大肥鱼、GPT 娘、Claude 娘、Kimi 娘、GLM 娘六个内置预设，选中后在主区只读显示其名称、一句话简介、全部分区和触发规则。预设 MUST 不能直接编辑、保存或设为使用中；管理员点击“以此新建”后，系统 MUST 在“我的人设”中新建一个内容相同、处于未使用状态的人设，之后按普通人设编辑、试聊、回放对比和保存。预设 MUST NOT 覆盖任何已有人设的内容。

每个预设 MUST 包含角色定义、说话风格、记忆与承诺、互动边界四个始终生效的分区；五个角色预设 MUST 另含她自己、外貌、认识的 AI 娘、身份设定四个“被问到才用”的分区，且每个这类分区的第一行写明触发条件。预设 MUST 只包含关键词触发规则，不得增加语义判定调用，并且每个预设都包含一条“不给步骤”和一条“被夸”关键词规则。每个预设的说话风格 MUST 先写六个预设完全相同的通用写法，再写本预设自己的口吻，口吻写明公开回复的常用长度；角色梗 MUST 按对方是否聊到相关话题、近期往来里是否用过来约束，不写模型无法核对的“几条里一次”频率。五个角色预设 MUST 写明自己是网友二创的非官方角色、与对应公司无关，不冒充官方。

#### Scenario: 以预设新建但不启用
- **WHEN** 管理员选中内置预设“大肥鱼”并点击“以此新建”
- **THEN** “我的人设”中出现内容与预设相同的新人设，处于未使用状态；使用中人设和它的修订号不变

#### Scenario: 预设只读
- **WHEN** 管理员在左栏选中任一内置预设
- **THEN** 主区内容不可编辑，页头只有“以此新建”，没有保存、设为使用中和删除

#### Scenario: 修改后保存
- **WHEN** 管理员从“GLM 娘”新建人设，改动说话风格后保存
- **THEN** 系统保存改动后的内容，该人设修订号加一；内置预设“GLM 娘”保持原样

#### Scenario: 选用预设不增加判定调用
- **WHEN** 管理员从任一预设新建人设、不做修改并设为使用中，随后一条消息命中其中的关键词规则
- **THEN** 该规则正文进入提醒区，本条消息只有一次回复生成请求

#### Scenario: 被问是不是官方
- **WHEN** 使用从“Claude 娘”新建且未修改的人设时，用户问“你是 Anthropic 官方的吗”
- **THEN** 互动边界和身份设定中的条款要求回复说明自己是网友二创的非官方角色、与 Anthropic 无关

#### Scenario: 询问做法
- **WHEN** 使用从任一预设新建且未修改的人设，测试用户在试聊中问“番茄炒蛋怎么做”
- **THEN** “不给步骤”规则命中，其正文进入提醒区，试聊本轮详情显示命中关键词“怎么做”

#### Scenario: 比较两个预设的说话风格
- **WHEN** 管理员先后查看内置预设“大肥鱼”和“Claude 娘”的说话风格分区
- **THEN** 两者开头的通用写法完全相同，之后的口吻不同，且各自写明公开回复的常用长度

#### Scenario: 被夸
- **WHEN** 使用从任一预设新建且未修改的人设，用户说“你好可爱”
- **THEN** “被夸”规则命中，其正文进入提醒区；用户说“我不喜欢你”时该规则不命中

#### Scenario: 被问到才用的分区
- **WHEN** 管理员查看任一角色预设
- **THEN** 她自己、外貌、认识的 AI 娘、身份设定四个分区的第一行都是触发条件说明

### Requirement: 角色预设的账号披露提醒

查看角色预设，或查看从角色预设新建的人设时，人设页 MUST 显示该预设的建议简介，并可一键复制；建议简介 MUST 包含“非官方”和“AI”。把从角色预设新建的人设设为使用中后，人设页 MUST 在当前页面显示提醒，直到管理员关闭或离开页面，提示管理员在恢复业务前修改 X 账号名称和简介，并建议把“非官方”加入合规检查的披露词。系统 MUST NOT 自动修改 X 账号资料或合规检查设置。

#### Scenario: 启用从大肥鱼新建的人设
- **WHEN** 管理员把从“大肥鱼”新建的人设设为使用中
- **THEN** 人设页显示提醒，内容包含建议简介、修改名称和简介的说明，以及到设置页的链接；提醒在管理员关闭或离开页面前一直显示；账号资料和披露词设置保持不变

#### Scenario: 启用从通用默认新建的人设
- **WHEN** 管理员把从“通用（默认）”新建的人设设为使用中
- **THEN** 人设页只提示今日日程不会自动改变，不显示非官方披露提醒

#### Scenario: 只保存不启用
- **WHEN** 管理员保存一个从角色预设新建、但未使用的人设
- **THEN** 页面不显示账号披露提醒，配置页中仍可查看和复制建议简介

### Requirement: 统一的生效人设

人设库中的使用中人设 MUST 是唯一的生效人设。回复生成、早安帖、晚安帖和虚构日程生成 MUST 读取同一份使用中人设；试聊默认使用它，也可以按试聊规则选用其他已保存人设。人设库从未保存过时，使用中人设 MUST 按升级前的规则得出：面板从未保存过人设、且配置文件人格属于随版本发布的示例文本时，使用通用默认人设；面板保存过人设时使用该人设；配置文件中的自定义人格原样保留在角色定义中。

#### Scenario: 未定制时生成日程
- **WHEN** 面板从未保存过人设和人设库，配置文件人格为旧版示例文本，系统生成当日虚构日程
- **THEN** 传给模型的人格内容来自通用默认人设，而不是旧的一句话

#### Scenario: 切换后各处一致
- **WHEN** 管理员把“GLM 娘”设为使用中
- **THEN** 下一轮回复、之后的早晚安帖、次日日程生成和试聊默认选项都使用“GLM 娘”，配置文件中的人格不参与

### Requirement: 隔离多轮试聊

系统 MUST 保留用未保存人格在公开或私信场景进行多轮试聊的接口，供批量验收工具使用：默认使用模拟记忆，不向 X 发送、不修改真实记忆，并返回本轮全部调用费用。面板 MUST NOT 再提供该入口；面板中的试聊按“正常流程试聊”规则进行。

#### Scenario: 未保存人格试聊
- **WHEN** 批量验收工具用一份未保存的人格调用该接口发起多轮试聊
- **THEN** 系统使用该人格生成，人设库、生产记忆、试聊测试数据和真实出站记录保持不变

#### Scenario: 面板没有旧入口
- **WHEN** 管理员打开人设页的任一模式
- **THEN** 页面没有填写模拟记忆或模拟日程的旧试聊表单

### Requirement: 提示词与命中结果预览

系统 MUST 在人设页试聊模式的本轮详情和提示词标签中展示每一轮的回复或跳过结果、触发命中原因、实际提示词分段及耗时，且不得展示密钥。

#### Scenario: 检查一次试聊
- **WHEN** 管理员查看一轮完成的试聊
- **THEN** 能分别检查静态分区、命中的触发卡、日程、召回的记忆与当次上下文，且无密钥内容

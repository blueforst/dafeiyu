## 2. 人设库

## 4. 试聊服务

- [ ] 4.1 独立存储（第 4.1 节）。验收：
  - 首次使用时在 `DATA_DIR/chat-test/` 创建库和表；账本文件位于该目录；
  - 试聊库损坏时接口返回 503，生产启动和一轮主循环不受影响。
- [ ] 4.2 事件构造与来源划分（第 4.2、4.3 节）。验收：测试断言：
  - 试聊库账号为 `chat_test`，测试消息都能成功入库；
  - 公开与私信事件的字段形状与生产采集结果一致；同一测试用户的公开和私信是两个身份，记忆互不召回；
  - 账号层来源只读生产，用户层来源只读试聊库；
  - 试聊使用绑定试聊库的人设服务实例，语义判定失败的日志写入试聊库；
  - 日程只调用 `describe`，不调用 `ensure`，也没有日程费用；
  - 账号未确认时依赖账号的来源为空，字数按普通规则；
  - 对话上下文结构与 `transport.context` 返回结构一致；
  - 模型会话 id 不与生产重叠。
- [ ] 4.3 一轮处理（第 4.4 节）。验收：mock 模型测试覆盖：
  - 结果：回复视为已发出并进入下一轮近期往来；超长回复不算已发出；跳过记录骚扰计数，第三次进入二十四小时冷却；冷却期间该渠道新消息不调用模型；广告过滤不调用模型；
  - 合并：先攒两条私信再处理时只有最后一条是本轮消息、前一条进入上文；十分钟内两条公开消息按生产规则合并为一轮；
  - 记忆：第五条触发整理，结果只写试聊库，调用用途为 `chat-test`；生产整理仍记为 `memory-summary`；手动整理；
  - 人设：处理中保存或切换人设不影响本轮；所选人设已删除返回 409。
- [ ] 4.4 中止、重试与并发（第 4.4 节）。验收：
  - 取消后消息回到待处理且已落账用量保留；重试产生新轮次；
  - 同一用户第二个处理请求被拒绝；全局第三个返回 429。
- [ ] 4.5 试聊接口（第 4.5 节）。验收：
  - 接口测试覆盖全部路由、鉴权、控制请求标记和请求体上限；响应不含 Key；
  - 核对生产 Nginx 对长请求的超时；如果不足 360 秒，改为轮询，并在实施记录中写明。
- [ ] 4.6 隔离与豁免回归（规格“隔离存储与只读生产来源”“额度与时段豁免”）。验收：
  - 在临时数据目录完成一组覆盖回复、跳过、过滤、合并、整理、重置和删除的试聊后，断言生产库除 `llm_calls` 新增 `chat-test` 记录外，相关表及两份生产账本都不变；
  - transport 调用次数为零；
  - 额度已满、暂停、接管、草稿模式、未收束出站和退避状态下试聊仍可处理，且这些状态与计数不变；
  - 动态、记忆、健康、日报、回放样本和质量统计接口都不出现测试用户。

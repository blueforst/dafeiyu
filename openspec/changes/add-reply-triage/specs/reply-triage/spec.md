# 消息分级与调度增量规格

## Purpose

规定待回复消息如何分级、过滤、合并、排序和分配发送名额，使限速条件下优先回复重点账号和有内容的消息，广告、刷量与反复骚扰不消耗模型费用，并且一个通道受限时不会阻塞另一个通道的处理。

## ADDED Requirements

### Requirement: 入队分级与原因

系统 MUST 在消息入队时用确定性规则把消息分为优先、普通或跳过，并保存级别与原因，不得为分级发起模型请求。优先包括重点账号、老朋友有内容的消息、首次来访和较长或明确提问；普通包括闲聊、新人只发招呼和同一用户其他会话的后续消息；跳过包括老面孔没有内容的招呼。

#### Scenario: 重点账号的普通招呼
- **WHEN** 重点名单中的公开账号只发来“在吗”
- **THEN** 消息分为优先，原因为重点账号

#### Scenario: 新人只发招呼
- **WHEN** 从未互动过的用户只发来“hi”
- **THEN** 消息分为普通，原因为新人招呼

#### Scenario: 老面孔没有内容的招呼
- **WHEN** 已有多次互动的非重点用户只发来“在吗”
- **THEN** 消息分为跳过，不进入生成，原因可在面板查看

### Requirement: 出队顺序与分级时效

系统 MUST 按级别优先、同级内平台时间较新者优先的顺序出队；普通消息超过普通时效（默认三小时）、优先消息超过现有处理时效（默认六小时）时记录为超时跳过，不再生成。

#### Scenario: 优先与普通同时排队
- **WHEN** 队列中有一条较早的优先消息和一条较新的普通消息
- **THEN** 系统先处理优先消息

#### Scenario: 普通闲聊等待过久
- **WHEN** 一条普通消息已等待三个半小时
- **THEN** 系统记录超时跳过；同样等待时长的优先消息仍会处理

### Requirement: 通道名额不被阻塞

系统 MUST 在每轮挑选消息前确定各通道是否可发送；处于退避、小时或每日额度已满、存在待回查 unknown 的通道，其消息不得占用本轮处理名额。

#### Scenario: 公开额度已满且有私信等待
- **WHEN** 公开小时额度已满，队列最新的两条是公开消息，另有一条较早的私信
- **THEN** 本轮处理该私信，公开消息保持排队

#### Scenario: 两个通道都不可发送
- **WHEN** 公开处于退避且私信存在待回查 unknown
- **THEN** 本轮不生成任何回复，也不把排队消息标记为失败

### Requirement: 同一用户多条公开消息合并

系统 MUST 将同一用户在同一会话三十分钟内的多条待处理公开消息合并处理：只回复其中最新一条，较早的标记为已合并并作为该次生成的上下文；同一用户在其他会话的后续消息降为普通。

#### Scenario: 连续三条提及
- **WHEN** 同一用户在同一帖子串十分钟内连续提及三次
- **THEN** 系统只生成并发送一条回复，另外两条显示已合并且指向该回复

#### Scenario: 不同帖子串
- **WHEN** 同一用户在两个不同帖子串各提及一次
- **THEN** 两条都保留，后到的一条降为普通

### Requirement: 广告与批量刷量过滤

系统 MUST 在入队时过滤广告与批量刷量并记录原因，不得为被过滤的消息发起模型请求。批量刷量指三个及以上不同账号在一小时内发送规范化后相同的正文；广告按可配置关键词与链接组合识别。

#### Scenario: 多个账号发送相同正文
- **WHEN** 第三个不同账号在一小时内发来相同正文
- **THEN** 该消息和仍在排队的同文消息均标记为已过滤，原因为批量刷量

#### Scenario: 普通消息含链接
- **WHEN** 一条消息只包含链接而没有广告关键词
- **THEN** 系统不仅凭链接过滤它

### Requirement: 跳过类别与骚扰冷却

模型跳过结果 MUST 可以携带骚扰、广告、无需回复或其他类别，类别缺失或无效时按其他处理且不使输出失败。同一用户在同一渠道二十四小时内三次被判为骚扰后，系统 MUST 暂时忽略该用户二十四小时：其新消息记录为已忽略、不进入生成。忽略状态不得写入记忆或长期摘要。

#### Scenario: 第三次骚扰
- **WHEN** 某用户第三次在二十四小时内被判为骚扰
- **THEN** 系统开始二十四小时忽略，并在面板显示原因与结束时间

#### Scenario: 忽略期满
- **WHEN** 忽略结束后该用户发来新消息
- **THEN** 消息按正常分级处理

#### Scenario: 记忆整理
- **WHEN** 系统整理该用户的长期记忆
- **THEN** 摘要不包含骚扰、被忽略等标签

### Requirement: 公开每日额度

系统 MUST 按北京时间自然日统计公开回复与早晚安帖的提交数量（已确认、发送中与 unknown），达到每日额度（默认 180）后当天不再提交新的公开内容；达到每日额度不得触发平台拒绝的四小时退避，次日零点恢复。

#### Scenario: 晚间达到每日额度
- **WHEN** 当天公开提交数在 21:00 达到 180
- **THEN** 公开通道当天停止提交，私信不受影响，次日 00:00 起恢复

#### Scenario: 早安帖计入额度
- **WHEN** 早安任务在 08:00 发布一篇帖子
- **THEN** 当天公开每日计数增加一

### Requirement: 重点账号名单

管理员 MUST 能在面板维护重点账号名单，条目为公开账号 handle 或私信会话标识，不做模糊匹配，也不据此合并公开账号与私信会话；名单变化后，新入队消息及仍在排队的消息在下一轮按新名单重新分级。

#### Scenario: 公开账号加入名单
- **WHEN** 管理员把某个公开 handle 加入名单
- **THEN** 该账号仍在排队的公开消息在下一轮变为优先，同名私信会话不受影响

### Requirement: 手动重新排队与解除忽略

管理员 MUST 能把已过滤、已合并、超时或分级跳过的消息手动重新排队，并能解除某用户的骚扰忽略；重新排队不得用于 unknown 出站，也不得绕过额度、退避或草稿审核规则。

#### Scenario: 误过滤的消息
- **WHEN** 管理员把一条被误判为广告的消息重新排队
- **THEN** 该消息按正常流程生成，额度与退避规则照常生效

#### Scenario: 尝试重新排队 unknown
- **WHEN** 管理员对结果未知的出站消息请求重新排队
- **THEN** 系统拒绝并提示先回查

### Requirement: 分级状态可见

面板 MUST 展示各通道各级别的排队数量、最长等待时间、今日公开提交数与每日额度、过滤与忽略的数量和原因；常规日志只记录级别与原因类别，不包含消息正文。

#### Scenario: 查看主程序队列
- **WHEN** 管理员打开队列信息
- **THEN** 能看到优先、普通的排队数和最长等待，以及当天已过滤、已合并、已忽略的数量

# 消息分级、过滤与公平调度提案

## Why

当前待处理队列按入库时间倒序，每轮只取前 `maxPerRound` 条；如果这几条所在通道正在退避、小时额度用尽或有待回查的 unknown，本轮就跳过它们，另一个通道的消息也拿不到名额，私信可能被持续涌入的公开提及饿死。所有消息共用六小时时效，没有优先级、广告过滤或同一用户多条消息的处理规则；模型判为骚扰的账号会反复进入生成并产生费用。参考帖子在限速之后用“先回谁”代替“每条都回”，并记录了一天回满 200 条后被平台拦住的问题。需要在七页提案的额度与退避之上补齐分级、过滤和公平调度。

## What Changes

- 入队时用确定性规则给消息分级并保存原因：优先（重点账号、老朋友有内容的消息、首次来访、较长或明确提问）、普通（闲聊、新人只发招呼、同一用户其他会话的后续消息）、跳过（老面孔没有内容的招呼）；广告与批量刷量单独标记为已过滤。分级不调用模型。
- 出队按级别优先、同级新消息优先；普通消息时效默认三小时，优先消息沿用现有六小时，超时记录为跳过。
- 每轮只从当前可发送的通道挑选消息；退避、小时或每日额度用尽、存在待回查 unknown 的通道不占用本轮名额。
- 同一用户在同一会话三十分钟内的多条待处理公开消息只回复最新一条，较早的标记为已合并并作为上下文；私信沿用“只处理会话最后一条入站”。
- 广告与批量刷量在入队时过滤，不调用模型；过滤、合并与跳过的消息可在面板或 CLI 手动重新排队。
- 模型跳过结果可带类别；同一用户二十四小时内三次被判为骚扰后暂时忽略二十四小时，可手动解除。忽略状态不写入记忆。
- 新增公开通道每日额度（北京时间自然日，默认 180，公开回复与早晚安帖共享），与小时额度并存；达到每日额度不触发四小时平台拒绝退避。
- 新增重点账号名单，条目为公开账号 handle 或私信会话标识，在面板维护。
- 面板展示各级排队数量、最长等待、过滤与忽略原因；常规日志不含正文。

## Capabilities

### New Capabilities

- `reply-triage`：待回复消息的分级、过滤、合并、出队顺序、通道名额分配、骚扰冷却与公开每日额度。

### Modified Capabilities

无。现有主规格不变。本能力补充未归档 `add-seven-page-production-bot` 的 `x-message-workflow`：每轮两条、公开每小时十条、私信每小时三十条、平台拒绝四小时退避与 unknown 只回查均保持不变，本提案增加分级顺序、通道名额分配和每日额度。实施时同步该提案的交叉引用，不提前写入主规格。

## Impact

- 影响 `src/store.ts`（消息分级列、出队查询）、`src/workflow.ts`（按通道可用性选取、合并、忽略检查、每日额度）、新增 `src/triage.ts`（分级与过滤规则）、`src/model.ts` 的 `parseDraft`（可选跳过类别）、`src/cli.ts`（重新排队范围）、面板设置（分级参数、重点名单）和主程序／动态页展示。
- 数据库迁移新增消息分级字段、骚扰忽略表；新增消息状态 `filtered`、`merged`、`ignored`。`deploy/rollback-schema.py` 的降级门禁需要覆盖这些新状态。
- 不新增模型请求；不使用模型分级；不在 X 上屏蔽、静音或举报任何账号；不合并公开账号与私信会话身份；不改变草稿审核、出站回执和 unknown 只回查语义。
- 本次只创建规划文件；构建、测试在服务器隔离环境执行，不改变线上运行状态。

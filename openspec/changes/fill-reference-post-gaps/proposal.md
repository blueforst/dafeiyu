# 参考帖子第三轮遗漏补齐提案

## Why

第三轮把参考帖子与当前代码逐条对照（已包含六项后续提案候选的实现），发现几处帖子已经做了、本项目的规划和代码都还没有的行为。其中“读取引用帖和链接卡片”在上一轮对照中被误标为已覆盖：

- **公开消息读不到引用帖和链接卡片。** 采集时会特意排除这两部分。对话上下文直接取帖子详情页的前 12 条，没有以目标帖为中心：长对话串会丢掉离目标最近的上文，短对话串又会混进目标帖之后其他人的回复。
- **条件规则只能靠模型判断。** 只要启用了任意一张触发卡片，每条消息都要多调一次模型。帖子里“不给步骤”这类规则是用零成本的关键词判断来补强的。
- **角色经历被普通回复淹没。** 每条确认发出的回复都会记成一条互动经历，召回时取的是全账号公开经历里最近 10 条。结果早晚安帖很快被挤出去，回复甲的内容还会作为“经历”出现在给乙的提示词里。经历段每发一条回复就变一次，也破坏了提示词前缀的稳定。另外，运营者手动发的重要帖子没有办法登记为经历。
- **置顶帖占名额。** 扫自己帖子下的回复时只看主页最前面两条，置顶帖会一直占掉其中一个。
- **漏掉的 @ 补不回来。** 没有补录入口，只能等它再次出现在采集来源里。
- **人设回放比不了模型。** 回放只能比较人设文本，做不到帖子里那种“同一批消息比较开、关思考或不同模型”。
- **固定约束少一条。** 固定系统约束只写了图片和视频不可见，没有写看不到对方主页、历史帖子和链接网页。
- **“全部”栏没人跟进。** 通知页“全部”栏是不带 @ 的引用转发唯一出现的地方。上一轮只在对照文档里建议评估，没有写进任何任务。

## What Changes

- **引用与卡片**：读取公开消息及其上下文时，把引用帖（作者、平台 ID、正文、是否含媒体）和链接卡片（域名、标题）作为独立的不可信字段，各自限长。结构不可读时明确告诉模型“对方引用了内容但当前看不到”，不静默丢弃，也不打开卡片指向的网页。
- **以目标帖为中心的上下文**：在详情页定位目标帖，取目标帖和它前面最近的上文，合计最多 12 条。目标帖之后其他人的回复不进入上下文；更早的上文被截掉时加以标注。无法唯一定位目标帖时标注“上下文不完整”，不再拿页面前几条凑数。
- **关键词触发卡片**：触发卡片新增“关键词”方式。当前消息包含任一关键词即命中，不调用模型。语义判定只覆盖语义卡片；如果启用的都是关键词卡片，就不再产生判定请求。关键词卡片和语义卡片共用顺序、开关、提醒区位置和试聊预览。
- **角色经历召回**：提示词里的角色经历只包含已确认的角色发帖和管理员登记的经历，按发生时间取最近 10 条。与其他用户的普通回复不再作为经历召回；和当前用户的往来仍由近期互动上下文提供。互动记录本身照常保存。
- **人工登记经历**：记忆页新增“角色经历”区，可以查看、登记、编辑、隐藏经历。登记时可以附上当前账号的帖子链接，系统在下一轮浏览器空闲时只读核对；带链接的经历要核对通过后才会用于回复。
- **置顶跳过**：扫自己帖子下的回复时跳过置顶帖，按可靠发布时间取最近两条。
- **按链接补录**：管理员可以提交一条帖子链接。主程序在下一轮的浏览器互斥操作里只读打开该帖，核对作者、是否和当前账号相关、时效，并按平台 ID 去重。通过后按“管理员重新排队”的同等优先级入队，仍受时效、额度、退避、草稿模式和发送前复核约束。暂停、人工接管和排空期间，补录请求只保留，不处理。
- **模型设置对比回放**：回放新增“比较模型设置”方式。两侧用同一份已保存人设，基线用使用中的模型，候选用从模型库选出的模型和推理档位。语义判定每条只做一次，两侧共用。预估和结果分别列出两侧的耗时、token、缓存读取和费用。不改变使用中的模型，也不提供一键采用。
- **不可见资料说明**：固定系统约束补充一句：看不到对方主页、历史帖子、关注关系和链接网页，被要求查看或分析时如实说明。
- **“全部”栏引用来源**：先采集真实页面的脱敏样本确认结构。确认之后，才把“全部”栏作为第四个公开来源，且只采集引用当前账号帖子的引用帖。确认之前保持不采集，并在采集说明里标注“未启用”。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `x-message-workflow`：新增引用与卡片摘要、以目标帖为中心的上下文、置顶跳过、按链接补录、“全部”栏引用来源。
- `persona-management`：修改语义触发判定和判定失败回退（只覆盖语义卡片），新增关键词触发规则。
- `reply-prompt-context`：新增不可见资料说明。
- `conversation-memory`：新增角色经历召回范围和人工登记经历。
- `persona-replay`：新增模型设置对比。

上面除 `conversation-memory` 外，其余能力目前只存在于未归档的提案中（`add-seven-page-production-bot`、`improve-reply-prompt-context`、`add-persona-replay`）。因此本提案归档前，那几项提案要先归档；`simplify-panel-activity-feed` 也有同样的顺序约束。实施可以直接基于当前代码开始。

## Impact

- **代码**：`src/browser.ts`（引用与卡片读取、目标定位、置顶识别、补录与经历核对的只读接口、“全部”栏适配器）、`src/types.ts` 与传输层（事件新增可选字段）、`src/persona.ts`（关键词卡片、判定范围）、`src/reply-prompt.ts`（固定约束与提示词版本）、`src/memory.ts` 与 `src/memory-routes.ts`（经历召回、人工经历）、`src/workflow.ts`（补录与核对请求在轮次中执行）、`src/persona-replay.ts`（模型对比）。面板会改到人设页、记忆页、动态页和设置页。
- **数据**：迁移 13 只做加法，新增“经历附加信息”和“补录请求”两张表，不改动已有表的列；事件正文 JSON 新增可选字段，人设 JSON 中的触发卡片新增可选字段。
- **模型请求**：只用关键词卡片时，每条消息少一次请求；回放的模型对比会按预估产生两侧请求，需要管理员确认。生产回复的请求次数不会增加。
- **浏览器**：补录和经历核对都在主程序轮次内、共用同一个浏览器互斥锁执行，不额外开浏览器，也不点击任何发送或设置。
- **提示词前缀**：固定约束改动会让 system 前缀失效一次。经历召回改为只含发帖后，user 开头的经历段在两次发帖之间保持不变，有利于前缀缓存。
- **不包含**：表情包（贴图或动图）清单和发送。帖子的 system 里有“表情包清单”，本项目目前把它当作 emoji 处理；接入贴图需要通过浏览器上传图片，风险更高，等用户决定。打开卡片网页、图片理解、扩大私信采集、新的原创发帖入口、外部推送也都不在本提案范围内。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行，不改变线上运行状态。

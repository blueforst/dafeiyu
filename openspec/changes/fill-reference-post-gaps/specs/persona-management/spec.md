# 人设管理增量规格（关键词触发）

## MODIFIED Requirements

### Requirement: LLM 语义触发判定

系统 MUST 使用当前模型，根据当前消息和同渠道可见上下文，一次判定全部启用的语义触发规则，并展示有效命中及原因；关键词触发规则不参与语义判定。没有启用的语义触发规则时，不得增加判定请求。

#### Scenario: 存在启用的语义规则
- **WHEN** 当前消息准备生成回复，且至少有一条语义规则启用
- **THEN** 系统执行一次统一语义判定，按配置顺序注入有效命中的规则并记录费用

#### Scenario: 没有启用的语义规则
- **WHEN** 当前没有启用的触发规则，或启用的全部是关键词规则
- **THEN** 系统不产生语义判定请求和费用

### Requirement: 语义判定失败回退

系统 MUST 校验语义判定结果，忽略未知规则和重复命中。判定失败时，不注入任何语义规则，继续使用静态规则和已命中的关键词规则，并让管理员看到警告和实际已返回的用量。

#### Scenario: 判定结果不可用
- **WHEN** 判定请求失败，或结果不符合约定
- **THEN** 回复不注入语义触发模块，系统记录回退原因，且不重复请求造成计费循环

#### Scenario: 判定失败但关键词规则命中
- **WHEN** 判定失败，且当前消息命中一条启用的关键词规则
- **THEN** 该关键词规则正文仍按顺序进入提醒区

## ADDED Requirements

### Requirement: 关键词触发规则

触发规则 MUST 支持“关键词”触发方式：管理员为规则配置一组关键词，只要当前消息正文包含其中任一个就算命中（匹配时忽略大小写、全半角差异和被提及的账号名），命中原因显示匹配到的关键词。判定不调用模型，也不读取对话里的其他消息。关键词规则与语义规则共用顺序、开关、提醒区位置和试聊预览。保存时，关键词为空或超出数量、长度上限 MUST 被拒绝。

#### Scenario: 询问做法命中“不给步骤”
- **WHEN** 管理员启用一条关键词为“怎么做、教程、步骤”的规则，用户问“番茄炒蛋怎么做”
- **THEN** 该规则正文进入提醒区，试聊和消息详情显示命中关键词“怎么做”，本次没有因该规则产生模型请求

#### Scenario: 只用关键词规则
- **WHEN** 启用的触发规则全部是关键词规则
- **THEN** 每条消息只有一次回复生成请求

#### Scenario: 关键词为空
- **WHEN** 管理员保存一条没有关键词的关键词规则
- **THEN** 保存被拒绝，并提示补充关键词

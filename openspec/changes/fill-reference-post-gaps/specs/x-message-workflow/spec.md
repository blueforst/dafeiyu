# X 生产消息工作流增量规格（第三轮遗漏）

## ADDED Requirements

### Requirement: 引用帖与链接卡片摘要

系统 MUST 在读取公开消息及其对话上下文时，把帖子内嵌的引用帖（作者、平台 ID、正文、是否含媒体）和链接卡片（域名、标题）作为独立字段读取，标为不可信资料，并且正文、引用、卡片各自限长。引用或卡片存在、但结构无法可靠解析时，系统 MUST 明确标注“内容不可读”，不得静默丢弃，也不得把引用正文并入作者本人的正文。系统不得为读取卡片而打开外部链接。

#### Scenario: 用户引用一条帖子并提问
- **WHEN** 一条提及当前账号的公开消息引用了另一条帖子，并问“你怎么看”
- **THEN** 提示词中的本次消息包含被引用帖的作者与正文，作者正文仍只有其本人写的文字

#### Scenario: 消息带链接卡片
- **WHEN** 消息包含一张显示域名与标题的链接卡片
- **THEN** 提示词包含该域名与标题，系统不访问卡片指向的网页

#### Scenario: 引用结构无法识别
- **WHEN** 页面存在引用容器，但无法可靠取得其作者或正文
- **THEN** 提示词说明对方引用了内容但当前不可读，并要求不要猜测

### Requirement: 以目标帖为中心的公开上下文

系统 MUST 在帖子详情页定位目标帖，以目标帖及其之前最近的上文（合计最多十二条）作为公开对话上下文，不得包含目标帖之后其他账号的回复。上文超过上限时，保留最接近目标的部分，并标注更早内容已省略。无法在页面中唯一定位目标帖时，系统 MUST 标注上下文不完整，不得用页面前若干条代替。

#### Scenario: 长对话串中的回复
- **WHEN** 目标帖之前有二十条上文
- **THEN** 上下文包含目标帖及紧邻其前的十一条，并注明更早内容已省略

#### Scenario: 目标帖下已有其他人的回复
- **WHEN** 帖子详情页在目标帖之后显示了其他账号的回复
- **THEN** 这些回复不进入本次生成的对话上下文

#### Scenario: 页面无法定位目标帖
- **WHEN** 详情页中找不到与目标 ID 匹配的帖子，或找到不止一条
- **THEN** 本次上下文标注为不完整，消息正文仍按已采集内容提供

### Requirement: 自己帖子回复扫描跳过置顶

扫描自己帖子下的回复时，系统 MUST 跳过页面标记为置顶的帖子，按可靠发布时间选择最近两条自己的帖子。无法识别置顶标记时，按原有顺序处理，并记录需要适配的提示。

#### Scenario: 账号有置顶的旧帖
- **WHEN** 当前账号主页顶部是一条置顶旧帖，下面依次是今天的晚安帖和早安帖
- **THEN** 本次扫描今天的晚安帖和早安帖下的回复，不扫描置顶帖

#### Scenario: 置顶标记结构变化
- **WHEN** 主页存在帖子，但无法确认哪一条是置顶
- **THEN** 系统按页面顺序选择最近两条自己的帖子，并在采集提示中说明置顶识别需要适配

### Requirement: 按链接补录公开消息

管理员 MUST 能提交一条 X 帖子链接请求补录。系统在主程序下一轮的浏览器互斥操作中只读打开该帖，并逐项核对：作者不是当前账号；内容提及当前账号，或位于当前账号帖子的对话中；时间可靠且未超过消息时效；平台 ID 没有重复。核对通过后，该帖按管理员重新排队的同等优先级进入正常队列，仍受时效、额度、退避、草稿模式和发送前复核约束。补录请求和结果 MUST 可在面板查看。暂停、人工接管或排空期间，请求只保留，不打开浏览器。

#### Scenario: 补录漏掉的提及
- **WHEN** 管理员提交一条一小时前提及当前账号、尚未入队的帖子链接
- **THEN** 下一轮该帖以优先级入队，按当前运行模式生成回复或草稿

#### Scenario: 链接已在队列或已处理
- **WHEN** 提交的帖子平台 ID 已有处理记录
- **THEN** 系统不新建消息，补录结果显示已有记录的状态

#### Scenario: 与当前账号无关或已过时效
- **WHEN** 帖子既没有提及当前账号，也不在其帖子的对话中，或者已超过消息时效
- **THEN** 补录被拒绝并显示原因，不进入队列

#### Scenario: 暂停时提交
- **WHEN** 管理员在系统暂停时提交补录
- **THEN** 请求保持待处理，恢复后的第一轮才读取页面

### Requirement: 通知全部栏的引用来源

系统 MUST 在真实页面脱敏样本确认解析规则之后，才把通知页“全部”栏作为公开来源。启用后只采集引用当前账号帖子的引用帖；点赞、关注、转发等通知不得成为待回复消息。结构无法确认时，系统 MUST 记录需要适配的提示，而不是报告没有消息。

#### Scenario: 尚未取得样本
- **WHEN** “全部”栏的解析规则尚未经过样本确认
- **THEN** 系统不从该栏采集，采集来源说明中标注未启用

#### Scenario: 有人不带 @ 引用了角色的帖子
- **WHEN** 解析规则已经确认，且“全部”栏出现一条引用当前账号帖子的引用帖
- **THEN** 该引用帖作为公开消息入队，并与其他来源按平台 ID 去重

#### Scenario: 点赞和关注通知
- **WHEN** “全部”栏出现点赞、关注或纯转发通知
- **THEN** 这些通知不进入消息队列

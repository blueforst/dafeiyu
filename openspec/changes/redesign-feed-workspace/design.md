# 动态页改版设计

## 背景

前两份提案已经提供了统一外壳（`shell.js`、`--ws-` 变量、`docs/设计规范.md`）和试聊的对话组件。本提案把动态页改为三栏工作区，组织方式为“用户即会话”：

- **左栏**：会话列表；
- **主区**：与这个身份的往来；
- **右栏**：选中那一条的详情。

草稿审核、出站、补录、告警的**规则全部不变**，变的只是展示方式，另外新增两个只读查询。

管理员确认的版式见 [panel-redesign-mockup.html](../add-persona-workspace/panel-redesign-mockup.html) 的动态页。决定来源分两类：没有特别标注的是讨论中确认的；标注“（实施者决定）”或“（规划时决定）”的，管理员可以在审阅时推翻。

## 1. 会话的定义

- **身份会话**：当前工作账号下 `messages.user_id` 相同的全部消息。公开身份是 `x:<handle>`，私信身份是 `dm:<会话>`。同一个人的公开和私信是两个会话，与生产记忆的身份划分一致（规划时决定：生产无法可靠关联两者）。
- **角色帖会话**：固定键为 `posts`，包含两类记录：
  - 当前工作账号下 `outbox.kind='post'` 的帖子；
  - 早安和晚安任务中没有产生出站记录的执行记录 `task_runs`，即停用、错过、取消、模型跳过或失败。这类记录只显示，不计入待处理。
- **排序时间**：消息取入库时间 `ingested_at`，旧数据的 `ingested_at` 为 0 时回退到 `created_at`。不用 `created_at` 作主排序的原因是：拿不到可靠平台时间的私信和公开消息，`created_at` 为 0；晚到的旧消息也会插进已加载的往来中间。帖子取出站记录的创建时间，任务记录取执行开始时间。
- **会话时间**：取会话中最新一条的排序时间。列表按会话时间倒序排列；状态变化（`updated_at` 变化）只更新状态标签，不改变顺序（规划时决定：避免批改时列表跳动）。
- **往来中的时间显示**：平台时间可靠时显示平台时间，否则显示入库时间，并标注“采集时间”。
- **会话状态标签**：按以下优先级取会话中第一个存在的状态，都不存在时取最新一条的状态：
  1. 待回查；
  2. 未过时效的发送失败；
  3. 未过期草稿或重写中；
  4. 已批准等待发送；
  5. 仍在处理时效内排队等待处理或生成中。
- **待处理**：复用现有 `ActivityFeed.pendingSql` 的判定，不重新定义。生产启用分级时，这个判定已经包含时效内排队的普通消息。会话的待处理数是其中满足该判定的条目数；角色帖的待处理是 `unknown` 状态的帖子。
- **待处理总数**：与现有 `ActivityFeed.summary` 和导航上的数字一致，因此也包含待核对的补录请求。补录请求不属于任何会话；“待处理”筛选有待核对的补录时，在列表顶部显示一个“按链接补录 · N 条待核对”入口，打开补录视图。
- **私信会话名称**：私信事件没有对方名字，`handle` 为空。名称显示为“私信 · ”加会话 id 的末四位（规划时决定）。草图中的“小雨”只是示例。以后采集能取得可靠名字时再改用，不在本提案范围内。

## 2. 接口

两个接口都只读，沿用管理鉴权：

| 接口 | 行为 |
| --- | --- |
| `GET /api/feed/conversations?filter&cursor&limit` | 会话列表 |
| `GET /api/feed/conversations/:key/items?before&limit` | 一个会话的往来，`:key` 为 URL 编码的身份 id 或 `posts` |

**会话列表**

- `filter` 取 `all`、`pending`、`public`、`private`、`posts`。
- 返回 `items[]`，每项为 `{key, channel, title, handle, latestAt, status, pending, preview, avatar}`，另有 `nextCursor` 和总 `pending`。
- 游标是 `(latestAt, key)` 的键集分页，`latestAt` 是第 1 节的会话时间，保证翻页过程中有新消息时不重复也不遗漏。
- `changedSince`：可选参数。传入后只返回其中任一条目的 `updated_at` 或排序时间晚于该值的会话，忽略游标，用于实时刷新时原位更新已加载的会话。
- `preview` 是最后一条消息或回复的前若干字，按纯文本截断。

**会话往来**

- 按排序时间倒序取最近 `limit` 条（默认 30，最多 100），返回时按正序排列。
- `before` 是 `(排序时间, id)` 游标，用于加载更早的往来；`changedSince` 返回该会话中 `updated_at` 或排序时间晚于该值的条目，用于实时刷新。
- 每条包含现有 `/api/feed` 条目的全部字段，包括 `status`、`expired`、`draft`、`receipt`、`error`、`revision`、`memory`，所以前端可以继续使用现有的状态文案、草稿操作和格式提示。另外新增只读字段 `tier`、`tierReason`（分级档位与原因，消息气泡要显示）和 `sortAt`。

**查询与索引**

- 会话列表需要按 `(account_id, user_id)` 分组，并求每组的最新时间和待处理数。现有索引有 `messages_account_created(account_id, created_at, id)` 和 `messages_user(user_id, channel, created_at)`。实施者在服务器上用生产规模的副本核对查询计划：
  - 如果会话列表在合理时间内返回（建议目标是一万条消息下 100 毫秒以内），就不加索引；
  - 否则新增一个只加索引的迁移 `(account_id, user_id, created_at)`，回退流程按 `docs/迁移与恢复.md` 处理。
- 两个接口都不触发模型调用、浏览器读取或任何写入。

**保留与扩展的接口**

- 现有 `GET /api/feed`、草稿操作接口和重新入队接口 `POST /api/messages/:id/requeue` 保持不变；导航上的待处理数量继续来自现有汇总。
- `GET /api/messages/:id` 只追加只读字段，原有字段不变：
  - 分级档位与原因；
  - 生成快照中的人设 id、名称与修订号。`add-persona-workspace` 让生成快照记录人设 id 与名称；更早的快照只有修订号，名称显示“未记录”。

## 3. 前端

### 3.1 结构

- 用 `mountWorkspace(root, {page:'feed', left, main, right})` 生成三栏。
- 主区有四个视图：会话、需要关注、按链接补录、角色帖。
- 地址：

  | 地址 | 打开 |
  | --- | --- |
  | `#/feed` | 最近的会话 |
  | `#/feed/c/<key>` | 某个会话 |
  | `#/feed/attention` | 需要关注 |
  | `#/feed/import` | 按链接补录 |

  不带具体会话时，打开会话列表的第一项；列表为空时显示空状态。
- 对话流复用试聊的组件：用户气泡、角色正文、一行摘要、虚线说明框、系统提示。草稿编辑框和操作按钮沿用现有 `feed.js` 的 `renderState` 逻辑，只改外观。

### 3.2 左栏

- 页头：“动态”、按链接补录图标、收起按钮。
- 筛选：五个筛选，“待处理”带总数。
- “需要关注 · N 项”入口：没有需要关注的项时隐藏；有错误级别的项时用错误色。
- 会话列表：滚动到底部时加载下一页。
- 底部运行状态：模式、模型、登录账号、回复字数上限、本小时公开和私信额度使用。数据来自全局状态流和现有队列与额度接口。

### 3.3 主区

- **会话页头**：身份名称、渠道、往来条数和首次时间；“在 X 上查看”（公开身份）、“记忆 →”（打开 `#/settings/memory?...` 并选中该身份）、收起右栏按钮。
- **往来**：
  - 日期分隔；
  - 对方消息气泡左侧标出渠道、分级档位和时间；
  - 角色回复上方一行摘要：状态、发送时间、回执可靠性；
  - 草稿以编辑框出现，带发送、重写（计费）、取消、状态说明和格式提示；
  - 已过滤、骚扰冷却、已合并、发送失败、已跳过的条目，在虚线说明框中保留现有的“重新入队”按钮，可用条件与现在相同。这是分级规格要求的手动重新排队入口，不能丢；
  - 滚动到顶部时加载更早的往来，并保持当前可见消息的位置。
- **需要关注**：每项一张卡片，写明原因，并带指向对应设置项或会话的按钮。来源与现有告警相同：
  - 健康的活跃告警（含历史采集告警）；
  - 账号检查；
  - 配置错误；
  - 浏览器需要人工处理；
  - 公开或私信退避；
  - 待回查数量。
- **按链接补录**：原 `manual-import-panel.js` 的表单和请求列表，行为不变。

### 3.4 右栏

- 选中一条往来后显示其详情，数据来自现有 `GET /api/messages/:id`，在选中时读取：状态、分级、人设与修订、命中、生成与校验、出站与回执、错误、关联调用。
- 下方是该身份的只读记忆，来自现有的只读召回预览接口，并带“在设置 → 记忆中管理”的链接。
- 角色帖会话的右栏显示帖子的任务、出站和调用。
- 右栏可以收起，收起状态记在 `ws:feed:right`；收起后选中往来不会自动展开（规划时决定）。

### 3.5 实时刷新

- 全局 `feed` 事件只带 `{latest, pending}`。收到后如果 `latest` 变了，就用上次刷新的时间作为 `changedSince`，分别读取会话列表和当前会话的变化：
  - 已加载的会话原位更新状态标签、摘要和待处理数；
  - 有新消息的会话移到顶部；
  - 当前会话追加新条目或更新已有条目。
  - 不重读已加载的全部分页。
- 正在编辑的草稿不覆盖：沿用现有“输入框未改动才替换”的规则。
- 主区不在底部时，新消息到达不自动滚动，而是在底部显示“有新消息”的提示。

### 3.6 窄屏

- 左栏是抽屉，右栏是浮层。窄屏下选中一条往来时，打开右栏浮层。
- 草稿编辑和发送在 375px 下可以完整操作。

## 4. 兼容与回退

- 新增的只有两个只读接口和 `GET /api/messages/:id` 的几个只读字段，可能还有一个只加索引的迁移。前端回退即恢复卡片流；旧版本不使用新接口和新字段。
- 浏览器里的 `ws:feed:*` 键对旧版本无影响。

## 5. 验证

构建、测试和界面验收只在服务器隔离环境执行，不使用生产数据目录。

- **会话查询**：单元与接口测试覆盖：
  - 身份划分：同一用户的公开和私信是两个会话；
  - 角色帖会话；状态标签优先级；过期草稿不计入；
  - 五种筛选；键集分页在翻页过程中插入新消息时不重复不遗漏；
  - 只返回当前账号；外部文本原样返回；
  - 接口不产生写入、模型调用和浏览器请求。
- **性能**：在服务器用一万条消息的隔离数据核对会话列表的查询计划和耗时，结果写入实施记录，并说明是否加了索引。
- **草稿审核回归**：批准、重写、取消、过期、修订冲突、等待原因的现有测试全部通过；界面上在会话中完成这些操作，结果与改版前一致。
- **实时刷新**：编辑草稿时同一会话和其他会话收到新消息，草稿文字和光标不变，阅读位置不跳动。
- **界面**：1440、1280、860、375 四种宽度，浅色和深色；四个主区视图、右栏收起、窄屏抽屉和浮层；截图存入证据目录，无整体横向滚动。现有动态页界面验收改写后通过。

## 6. 留给实施者的决定

- 是否需要索引，依据查询计划。
- `preview` 截断长度、会话页大小，以及头像字和颜色的生成方式。
- “有新消息”提示的样式。

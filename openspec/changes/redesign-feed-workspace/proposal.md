# 动态页改版：用户即会话提案

## Why

面板改版的第三份，也是最后一份提案。前两份已经把人设页（[`add-persona-workspace`](../add-persona-workspace/proposal.md)）和设置页（[`redesign-settings-workspace`](../redesign-settings-workspace/proposal.md)）改为统一设计，本提案把动态页也迁移过去，完成整个前端的统一。

动态页的组织方式改为**用户即会话**，和人设页的试聊用同一套对话组件：左栏每一项是一个 X 用户（一个身份），主区是和这个人的完整往来，草稿就在对话里编辑和发送。这样批改草稿时能直接看到这个人之前说过什么、角色怎么回的。这个版式已经由管理员看过草图确认。

**现状（2026-10-28 核对本机提交 `6e20f56`）：**

- 动态页从上到下依次是：
  - 标题行与“按链接补录”；
  - 概况行：运行模式、模型、登录账号、字数上限、设置链接；
  - 告警：健康、账号检查、浏览器需要人工处理、通道退避、配置错误；
  - 全部／待处理／回复／私信／发帖五个筛选；
  - 按时间倒序的卡片流，每张卡片一条互动：对方原话、回复或草稿、状态、操作和默认收起的详情。
- 接口：
  - `GET /api/feed?filter&cursor&limit` 按时间分页，返回消息和角色帖两类条目，以及待处理数量；
  - 草稿操作走 `POST /api/messages/:id/approve|cancel|regenerate`；
  - 详情读取 `GET /api/messages/:id`；
  - 实时刷新依靠全局事件流。
- 生产里同一个人的公开和私信是两个身份：公开身份是 `x:<handle>`，私信身份是 `dm:<会话>`。

## What Changes

- **左栏是会话列表**：
  - 每一项是当前工作账号下的一个身份（公开身份或私信会话），另有一个固定的“角色帖”条目，汇集早安帖和晚安帖；
  - 每项显示头像字、名称、最近时间、状态标签和最后一条的摘要，按最新一条消息的时间倒序排列；状态变化不改变顺序，免得批改时列表跳动；
  - 状态标签取这个会话里最需要处理的那条：待回查优先，其次是发送失败、草稿、等待发送，没有待处理时显示最近一条的状态；
  - 顶部是筛选：全部、待处理（带数量）、公开、私信、角色帖；
  - 筛选下方固定一个“需要关注 · N 项”入口；
  - 左栏底部是运行状态摘要：模式、模型、账号、字数上限和本小时额度使用；
  - 页头有“按链接补录”入口和收起按钮。
- **主区是与这个人的往来**，按时间正序排列：
  - 对方消息用气泡显示，并标出渠道、分级和时间；
  - 角色的回复用无气泡的正文显示，上方一行摘要写明状态、发送时间和回执；
  - 草稿以编辑框出现在对应消息之后，旁边是发送、重写（计费）、取消，行为与现有草稿审核完全相同；
  - 跳过、过滤、合并、冷却、发送失败以虚线框写明原因，保留现有的“重新入队”按钮；
  - 往上滚动到顶部时加载更早的往来；
  - 页头有身份名称、往来条数、“在 X 上查看”和“记忆 →”（打开设置页记忆项并选中该身份）。
- **右栏是选中那一条的详情**：状态、分级、所用人设、命中、生成、校验、出站与回执、关联调用的耗时、token 和费用，以及这个身份的记忆（只读）。不显示提示词正文和密钥。右栏可以收起。
- **需要关注**：原来页面顶部的告警（待回查、账号检查、浏览器需要人工处理、通道退避、历史采集告警、配置错误）改为在主区以卡片列出，每张卡片链接到对应的设置项或会话。
- **按链接补录**：原补录表单和请求列表改为在主区显示，行为不变。
- **角色帖**：主区按时间列出早安帖和晚安帖，包括发送结果，以及停用、错过、取消等没有发帖的任务记录。
- **排序与命名**：会话按入库时间排序，因为私信常拿不到可靠的平台时间；私信没有对方名字，以“私信 · 会话尾号”显示。
- **接口**：
  - 新增两个按会话读取的只读接口：会话列表，以及单个会话的往来记录与分页；两者都支持按变化时间增量读取，用于实时刷新；
  - `GET /api/messages/:id` 补充分级与人设快照两个只读字段；
  - 现有 `GET /api/feed`、草稿操作和重新入队接口保留不变。
- **导航**：“动态”入口上的待处理数量不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `activity-feed`：修改以下需求，来自未归档的 `simplify-panel-activity-feed` 与 `separate-run-control-from-takeover`：
  - 动态时间线内容
  - 时间线筛选与待处理计数
  - 时间线分页
  - 条目细节默认收起
  - 跳转到用户记忆
  - 时间线实时刷新
  - 首页概况行

本提案排在 `simplify-panel-activity-feed`、`separate-run-control-from-takeover`、`add-persona-workspace`、`redesign-settings-workspace` 之后归档。

## Impact

- **后端**：
  - `src/activity-feed.ts` 新增会话列表与会话往来两个只读查询，复用现有的待处理判定、过期判定和条目映射；
  - `src/feed-routes.ts` 新增两个路由；
  - `src/program.ts` 的消息详情追加分级与人设快照字段；
  - 可能为会话查询补一个只读索引（实施者核对查询计划后决定，见 design.md）。
- **前端**：
  - `public/js/views/feed.js` 重写为动态工作区，草稿操作、状态文案和格式提示沿用现有逻辑；
  - `manual-import-panel.js` 改为挂在主区；
  - 对话组件与试聊共用 `shell.js` 中的组件。
- **测试**：
  - 新增会话查询的单元与接口测试；
  - 改写动态页界面验收；
  - 草稿审核、出站和补录的现有测试保持通过。
- **文档**：`docs/前端接口.md`、README 动态页说明、`docs/设计规范.md`。
- **不涉及**：
  - 不改草稿批准、重写、取消、过期和出站规则；
  - 不改待处理的判定口径；
  - 不改补录规则；
  - 不改人设页和设置页。
- **回退**：前端回退即恢复卡片流；新增的会话接口只读，旧版本不使用；如果新增了索引，它对旧版本无影响。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行；生产发布需要另行授权。

## Out of Scope

- 把同一个人的公开和私信身份合并为一个会话：生产无法可靠关联两者，因此仍按身份分开。
- 在动态页编辑记忆；管理仍在设置页记忆项。
- 改变草稿审核、出站和告警的规则。

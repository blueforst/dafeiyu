# 动态增量规格（用户即会话）

## MODIFIED Requirements

### Requirement: 动态时间线内容

面板首页 MUST 以“动态”工作区展示当前工作账号的互动：

- **左栏**按会话列出：每个会话是一个身份（公开身份或私信会话），另有一个固定的“角色帖”会话汇集早安帖和晚安帖。会话按其中最新一条记录的入库时间倒序排列，状态变化不改变顺序；私信会话没有对方名字时，以“私信”加会话标识末四位命名；每项显示名称、最近时间、状态标签和最后一条摘要。状态标签取该会话中最需要处理的一条：待回查优先，其次是发送失败、草稿、等待发送，没有待处理时显示最近一条的状态。
- **主区**选中会话后按时间正序显示往来：
  - 对方消息显示原话、渠道、分级和时间；
  - 角色的回复与私信显示正文、状态，已发送的带在 X 上查看的链接；
  - 草稿显示为可编辑的正文和草稿操作；
  - 跳过、过滤、合并、冷却和发送失败显示原因，并在规则允许时提供“重新入队”；
  - 角色帖会话显示帖子正文、任务名称和出站状态，以及停用、错过、取消等没有发帖的任务记录。

所有外部文本 MUST 按纯文本显示。动态 MUST NOT 显示其他工作账号的数据，也 MUST NOT 把同一个人的公开身份和私信会话合并为一个会话。

动态页 MUST 在首个可见帧拥有完整工作区样式，跨页返回不得短暂显示未加样式的侧栏。

#### Scenario: 慢网络下进入或返回动态
- **WHEN** 管理员首次进入动态或从其他页返回，动态样式下载尚未完成
- **THEN** 页面不呈现裸露的侧栏内容，完整样式就绪后显示动态，后续切页保留已加载样式

#### Scenario: 查看已发送回复
- **WHEN** 一条公开回复已确认发送且回执带有平台链接
- **THEN** 该身份的会话中依次显示对方原话和回复正文，回复标为“已发送”并带在 X 上查看的链接

#### Scenario: 模型选择跳过
- **WHEN** 模型对一条入站消息选择跳过
- **THEN** 会话中该消息之后显示“已跳过”和跳过原因，不显示空白回复

#### Scenario: 查看早安帖
- **WHEN** 早安任务已提交一条公开帖子
- **THEN** “角色帖”会话显示任务名称、帖子正文和出站状态，左栏该会话移到最近活动的位置

#### Scenario: 数据库含其他账号记录
- **WHEN** 数据库中存在其他工作账号或未知归属的消息
- **THEN** 会话列表和往来只包含当前工作账号的记录

#### Scenario: 原话含 HTML 片段
- **WHEN** 对方原话包含 HTML 标签或脚本片段
- **THEN** 页面按原样文本显示，不执行或解析其中内容

#### Scenario: 同一个人的公开与私信
- **WHEN** 同一个 X 用户既在公开回复中提及角色，又发来私信
- **THEN** 左栏分别出现该用户的公开身份会话和私信会话，两者的往来互不混合

### Requirement: 时间线筛选与待处理计数

会话列表 MUST 提供全部、待处理、公开、私信、角色帖五种筛选。待处理条目的判定 MUST 与改版前的待处理数量口径一致：未过期的草稿、重写中和已批准待发送的条目，未超过普通消息时效的发送失败条目，发送结果待回查的条目，仍在处理时效内排队等待处理的消息，以及待核对的补录请求；已过期的条目不计入。“待处理”筛选只列出含待处理条目的会话，并在每个会话上显示其待处理数；有待核对的补录请求时，列表顶部另显示补录入口及数量。总数 MUST 显示在筛选项上，并在其他页面的导航“动态”入口上显示，两处数字相同。

#### Scenario: 筛选待处理
- **WHEN** 存在两条草稿（分属两个身份）、一条发送失败（属于第三个身份）和若干已发送回复，没有排队消息和补录请求
- **THEN** 选择“待处理”只显示这三个会话，筛选项和导航上显示数量 3

#### Scenario: 有待核对的补录
- **WHEN** 除上述三条外还有一条待核对的补录请求
- **THEN** 筛选项和导航上显示数量 4，“待处理”列表顶部显示“按链接补录 · 1 条待核对”

#### Scenario: 旧草稿已过期
- **WHEN** 一条草稿已超过普通消息时效
- **THEN** 它仍在其会话中显示为已过期，但不计入待处理数量，该会话不因它出现在“待处理”筛选中

#### Scenario: 没有待处理
- **WHEN** 当前没有草稿、失败或待回查条目
- **THEN** 不显示数量标记，“待处理”筛选显示空状态说明

### Requirement: 时间线分页

会话列表 MUST 首次只加载有限个会话，滚动到底部时继续加载；单个会话的往来 MUST 首次只加载最近有限条，滚动到顶部时加载更早的往来。翻页过程中有新条目到达时，已加载内容不得重复或遗漏，加载更早往来时 MUST 保持当前阅读位置不跳动。

#### Scenario: 浏览时有新消息到达
- **WHEN** 管理员已加载两页会话后有新消息入库，再继续向下加载
- **THEN** 收到新消息的会话移到顶部，第三页紧接第二页最后一个会话，没有重复会话

#### Scenario: 加载更早往来
- **WHEN** 管理员在一个有一百条往来的会话中滚动到顶部
- **THEN** 系统加载更早的一页往来，原来可见的那条消息仍停在原位置

### Requirement: 条目细节默认收起

主区的每条往来 MUST 默认只显示正文、状态和一行摘要；管理员选中一条后，右栏显示该条的状态、分级、所用人设与修订、触发命中、生成与校验结果、出站与平台回执、错误原因，以及关联的模型调用（用途、模型、耗时、token、费用估算或未定价）。右栏可以收起。细节 MUST NOT 显示提示词正文或密钥。

侧栏展开／收起入口 MUST 以明确的图形和可访问名称表示当前动作，窄屏关闭入口使用关闭图形；键盘切换后焦点 MUST 留在可见的对应控件。

#### Scenario: 查看一条回复的详情
- **WHEN** 管理员选中一条已发送回复
- **THEN** 右栏显示该回复关联的调用耗时、token 和估算费用以及平台回执，费用与设置页计费项的同一流水一致

#### Scenario: 发送失败
- **WHEN** 平台明确拒绝一条回复
- **THEN** 该条显示“发送失败”，选中后右栏显示拒绝原因

#### Scenario: 收起右栏
- **WHEN** 管理员收起右栏后刷新页面
- **THEN** 右栏保持收起，主区占满宽度；再次选中一条往来时不自动展开

#### Scenario: 键盘切换侧栏
- **WHEN** 管理员用回车或空格收起、展开侧栏
- **THEN** 图形、可访问名称及展开状态同步更新，隐藏原按钮后焦点转到可见的对应入口，窄屏 Escape 仍归还入口焦点

### Requirement: 跳转到用户记忆

身份会话 MUST 在主区页头提供“记忆 →”入口，打开设置页“记忆”项并直接选中该会话所属的工作账号、身份和渠道；右栏 MUST 以只读方式显示该身份当前可召回的记忆。“角色帖”会话不提供该入口。

#### Scenario: 从私信会话跳到记忆
- **WHEN** 管理员在一个私信会话中点击“记忆 →”
- **THEN** 设置页“记忆”项打开并显示该私信身份的记忆，不显示同一用户公开身份的记忆

#### Scenario: 记忆项有未保存修改
- **WHEN** 管理员已在记忆项修改条目但未保存，再从动态点击另一身份的“记忆 →”
- **THEN** 页面提示保留编辑或放弃，不静默丢失修改

### Requirement: 时间线实时刷新

动态页打开期间，新入库消息、状态变化和新帖子 MUST 在不手动刷新的情况下更新到会话列表（顺序、状态标签、摘要、待处理数）和当前打开的会话中；刷新 MUST NOT 覆盖管理员正在编辑的草稿文字，也 MUST NOT 让正在阅读的往来位置跳动。

#### Scenario: 草稿发送成功
- **WHEN** 管理员批准的草稿在后台发送成功
- **THEN** 会话中该条状态变为“已发送”，左栏该会话的状态标签同步更新但位置不变，无需重新加载页面

#### Scenario: 编辑草稿时后台刷新
- **WHEN** 管理员正在修改一条草稿，期间同一会话收到新消息
- **THEN** 输入框中的文字和光标位置保持不变，新消息出现在会话末尾

#### Scenario: 其他会话有新消息
- **WHEN** 管理员正在看会话 A，会话 B 收到新消息
- **THEN** 左栏会话 B 移到顶部并更新摘要，主区仍停留在会话 A

### Requirement: 首页概况行

动态页左栏底部 MUST 显示运行模式、当前模型、登录账号、字数上限和本小时额度使用；运行状态和启动／暂停由全局顶部栏提供，这里不再重复。配置错误、浏览器需要人工处理、通道退避、待回查数量、账号检查和历史采集告警 MUST 汇总为左栏筛选下方的“需要关注 · N 项”入口，没有时不显示该入口；点击后主区以卡片列出每一项及原因，并链接到对应的设置项或会话。

#### Scenario: 草稿模式运行中
- **WHEN** 系统处于运行中且运行模式为草稿
- **THEN** 顶部栏显示“运行中”和“暂停”按钮，左栏底部显示“草稿模式”、模型名称和登录账号

#### Scenario: 公开通道退避
- **WHEN** 公开通道处于平台拒绝后的退避期
- **THEN** “需要关注”入口计入这一项，打开后显示退避结束时间

#### Scenario: 浏览器需要人工登录
- **WHEN** 浏览器状态显示需要人工处理验证码或登录
- **THEN** “需要关注”入口以错误色显示，打开后的卡片链接到设置页浏览器接管项

# 回复提示词结构增量规格（回复文风）

## MODIFIED Requirements

### Requirement: 稳定前缀分层顺序

系统 MUST 按固定顺序组装回复提示词：system 只包含固定系统约束、已保存静态人格和按渠道固定的规则；user 依次为角色经历、当日日程与当前时段、对此人的允许范围记忆、与对方的近期往来、当前对话、提醒区、本次消息，最后为当前时间。同账号、同渠道、同一人设修订、同一北京日期内，system MUST 逐字节一致。

#### Scenario: 两条消息命中不同触发规则
- **WHEN** 同一天同渠道的两条消息分别命中不同的触发规则
- **THEN** 两次请求的 system 完全相同，差异只出现在 user 的提醒区及之后

#### Scenario: 管理员保存新人设
- **WHEN** 人设修订号变化后开始下一轮生成
- **THEN** system 使用新人设，同一修订内的后续请求再次保持一致

#### Scenario: 近期往来的位置
- **WHEN** 为一位有近期往来的用户生成回复
- **THEN** user 中“与对方的近期往来”位于记忆之后、当前对话之前，记忆部分不再重复这些往来

### Requirement: 提醒可见与记录

试聊与生产 MUST 使用同一组装逻辑；试聊预览按实际请求顺序展示分段，并列出本轮加入的动态提醒及原因；生产消息详情记录提醒类别并关联该次调用的缓存读取 token。常规日志不得包含提醒或近期往来中的消息正文和回复原文。

#### Scenario: 查看一次试聊
- **WHEN** 管理员完成一轮试聊
- **THEN** 页面按实际请求顺序显示 system 与 user 各分段，并列出实际加入的迟到、语言或表情提醒

#### Scenario: 查看常规日志
- **WHEN** 一条回复的提示词包含与对方的近期往来
- **THEN** 常规日志只记录提醒类别，不包含近期往来中的消息或回复原文

## ADDED Requirements

### Requirement: 与对方的近期往来

系统 MUST 把与当前对方的近期互动放在独立的“与对方的近期往来”部分，说明其中的回复是角色已经发出的原话，并要求本条不再使用其中出现过的梗、口癖、开头、收尾和说法。该部分的条数、时间窗口、渠道范围和遗忘规则 MUST 与近期互动上下文相同，只包含与当前对方的往来，不得包含角色给其他用户的回复；未确认发送的回复不得作为已发出的原话出现。没有近期往来时，该部分注明暂无。

#### Scenario: 前一天对同一个人用过口癖
- **WHEN** 角色前一天在一条已确认发送的回复里对用户甲自称“本鲸”，今天用户甲又发来消息
- **THEN** 用户甲的提示词在“与对方的近期往来”中包含那条回复，并说明这次不再使用其中出现过的梗、口癖、开头和收尾

#### Scenario: 刚回复过其他用户
- **WHEN** 角色刚给用户甲发出公开回复，随后为用户乙生成回复
- **THEN** 用户乙的提示词中没有给用户甲的回复

#### Scenario: 第一次互动
- **WHEN** 用户第一次和账号互动
- **THEN** “与对方的近期往来”注明暂无，其他部分照常组装

#### Scenario: 上一次只生成了草稿
- **WHEN** 与对方的上一次互动只生成了草稿、没有发出
- **THEN** 该次往来只显示对方的消息，不显示为已发出的回复

## REMOVED Requirements

### Requirement: 开头去重提醒

**Reason**: 该提醒列出的是同账号最近给所有人的回复开头。每个人一般只看到给自己的回复，跨人重复不需要控制；而且片段只有开头几个字，看不出梗、收尾和句式的重复。对同一个人的重复改由“与对方的近期往来”处理。

**Migration**: 动态提醒设置中的“避免开头重复”开关和条数不再显示、不再生效；已保存的旧字段仍可读取和保存。历史消息记录中的开头提醒类别照常显示。

# 回复文风：近期往来、帖子去重与格式标记提案

## Why

**现状（2026-10-28 核对本机工作副本与生产服务器）：**

- **文风基本只靠提示词约束。** 代码只硬性拦截字数、链接和 @（`src/posting-policy.ts`）。回复写成编号列表、分步教程或 Markdown，消息上也没有任何标记：草稿模式下审批的人得自己看出来，自动模式下发出后更难发现。检测步骤的函数 `hasSteps` 已经有了（`src/reply-style.ts`），但只在人设回放的统计里用。
- **开头去重看的是给别人的回复。** 动态提醒里的“开头去重”（`src/reply-hints.ts`）把同账号最近最多 12 条回复的开头片段列给模型，这些回复大多是给别人的。管理员确认：每个人一般只看到给自己的回复，跨人重复不需要控制。而且片段只取第一个标点前最多 8 个字，看不出梗、口癖、收尾和句式有没有重复。
- **和当前这个人的近期往来没有标明用途。** 默认 7 天内最近 3 次往来（包括已发出的回复原文）已经在提示词里，但混在“关于对方的记忆”这段 JSON 里，模型不知道这些是自己说过的话、应该避免重复。
- **早晚安帖看不到以前的帖子。** 早晚安帖（`src/production-tasks.ts`）生成时不带角色经历；开头去重也只取回复，不取帖子。所以模型看不到自己前几天发了什么。关注者每天都会看到这些帖子，前后雷同最容易被发现。其实确认发出的帖子已经记进角色经历，回复生成时也在用。
- **生产状态**：当前暂停；面板没有保存过人设和动态提醒设置，都用默认值。

## What Changes

- **近期往来单独成段**：把记忆里的近期往来移到独立的“与对方的近期往来”段，放在记忆之后、当前对话之前。段内说明：这些是你之前和对方的往来，回复是你已经发出的原话；这次不要再用其中出现过的梗、口癖、开头、收尾和说法。条数、时间窗口、可见范围和遗忘规则都沿用现有的近期互动规则，不加入给其他人的回复。试聊和人设回放使用同一组装逻辑。
- **去掉跨人的开头去重提醒**：不再把最近给所有人的回复开头列给模型。动态提醒设置里“避免开头重复”的开关和条数从界面移除；已保存的旧字段仍能读取和保存，只是不再生效。表情节制提醒保留：它只统计数量、不含任何人的内容，控制的是整体表情用量，不是重复。
- **早晚安帖带上以前的帖子**：生成早晚安帖时带上角色经历，其中包括最近已确认的帖子和人工登记的经历；提醒区要求这条帖子不重复其中帖子的开头、句式和切入点。不新增查询，也不新增数据。
- **格式标记**：正文含编号或项目符号列表、分步说明、Markdown 标题或加粗时，在消息上标记原因，不改变发送流程。
  - **自动模式**：照常自动发送，事后可以在动态页的消息详情里看到标记。
  - **草稿模式**：标记显示在草稿上，供审批时参考，是否发送仍由管理员决定。
  - **早晚安帖**：照常提交，在任务记录里标记。
  - **检查方式**：只用确定性规则，不发起模型请求，不改写正文，不拦截发送。试聊也显示检查结果。
- **提示词版本**：在实施时的当前版本上加一。

**不在本提案范围内：**

- 各人设的口吻和角色梗的写法属于人设内容，在 `add-persona-presets` 中调整。
- 不控制跨人重复。
- 不拦截客服腔、禁用开头、表情超额等问题。代码判断这些不准，靠人设约束和回放发现。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `reply-prompt-context`：
  - 修改“稳定前缀分层顺序”：在记忆之后加入“与对方的近期往来”；
  - 新增“与对方的近期往来”；
  - 删除“开头去重提醒”；
  - 修改“提醒可见与记录”：去掉开头提醒的说法，并规定近期往来原文不进常规日志。

  以上需求来自未归档的 `improve-reply-prompt-context`。
- `task-scheduling`：修改“早晚安任务默认与内容”（来自未归档的 `add-seven-page-production-bot`），加入角色经历、帖子去重提醒和格式标记。
- `x-message-workflow`：新增“回复格式标记”。该能力来自未归档的 `add-seven-page-production-bot`。

归档需排在 `add-seven-page-production-bot` 和 `improve-reply-prompt-context` 之后。

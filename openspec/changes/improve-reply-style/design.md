# 回复文风：近期往来、帖子去重与格式标记技术设计

## Context

动机见 [proposal.md](proposal.md)。行为契约见以下三份增量规格：

- [reply-prompt-context](specs/reply-prompt-context/spec.md)
- [task-scheduling](specs/task-scheduling/spec.md)
- [x-message-workflow](specs/x-message-workflow/spec.md)

以下现状来自 2026-10-28 本机工作副本（提交 `b607c3d` 加未提交改动）和生产服务器只读核对。

**提示词组装**

`assembleReplyPrompt`（`src/reply-prompt.ts`）把 memory 对象中的 `experiences` 取出来，单独放进“角色经历”段；其余内容整体放进“关于对方的记忆”段，包括 `memories`、`recent` 和 `recallOmitted`。user 各段依次为：

- 角色经历
- 今日日程
- 关于对方的记忆
- 当前对话
- 提醒
- 本次消息
- 现在

**近期往来**

`MemoryService.context()`（`src/memory.ts`）返回的 `recent` 规则如下：

- **条数和时间窗口**：按记忆策略取 `recentDays` 天内最近 `recentCount` 次已处理互动，默认 7 天、3 次，记忆页可调。
- **字段**：每项含 `id`、`channel`、`message`、`timestamp`；只有已确认发送的互动才带 `reply`。
- **可见范围**：公开回复只看公开往来；私信看公开往来和本人的私信往来。
- **遗忘**：已遗忘用户返回空。

**动态提醒**（`src/reply-hints.ts`）

- **样本**：`recentReplySamples` 取同账号最近 20 条回复样本，包括已确认、草稿、发送中和未知状态。公开回复只取公开回复样本；私信取公开回复样本和同一私信会话的样本。
- **开头提醒**：取前 `openingCount`（默认 12）条样本的开头片段（第一个标点前最多 8 个字）。
- **表情提醒**：统计同渠道最近 10 条。
- **设置校验**：设置字段 `openingEnabled`、`openingCount` 由 `validatePromptHints` 校验，未知字段返回 400。

**早晚安帖**（`src/production-tasks.ts`）

- **生成**：调用 `persona.assemble` 时不传 memory 和 experiences，所以角色经历为空；传入的 `recentReplies` 是公开回复样本。
- **记入角色经历**：帖子确认发出后，`postSideEffects` 把它记为 `role_experiences` 中 `kind='post'` 的经历。`recallRoleExperiences` 返回最近 10 条已确认帖子和可用的人工经历，被隐藏的不返回。
- **校验失败**：先建立候选出站再立即取消，任务结果记为 skipped，并写明原因。

**自动发送**（`src/workflow.ts`）

- **生成后**：`generateDraft` 依次执行 `parseDraft` 和 `validatePostingText`，再把结果保存为草稿。
- **自动提交条件**：只有自动模式、正文校验通过且不在重写流程中，才进入 `sendDraft`。校验不通过的消息保持 `draft` 状态，`error` 写明原因，动态页详情会显示。
- **管理员批准**：`src/activity-feed.ts` 的批准只复核字数、链接和提及。

**文风检测**

`src/reply-style.ts` 的 `opening`、`expressions` 和 `hasSteps` 由提示词和人设回放统计共用。`hasSteps` 的规则如下：

- 行首编号：`\d{1,2}` 后跟 `.、)）`；
- 行首中文序号；
- 行首 `-` 或 `*` 加空格；
- “第 N 步”；
- “首先……然后……最后”。

只要出现一行就算命中，所以以“3.5 分”开头的句子也会被误判。

**试聊与回放**

试聊和人设回放走同一组装逻辑；回放用保存的生成快照重新组装，快照里的 memory 含 `recent`。

**生产**

生产当前暂停，面板没有保存过 `persona` 和 `promptHints`，提示词版本由代码决定。

## Goals / Non-Goals

**Goals：**

- 模型能看出自己对同一个人说过什么，避免对同一个人重复梗、口癖、开头和收尾。
- 早晚安帖能看到前几天发过的帖子，避免天天一个样。
- 回复里出现列表、步骤或 Markdown 时，审批的人和事后查看的人都能直接看到标记。

**Non-Goals：**

- 不因格式检查改变发送流程：自动模式照常自动发送，草稿模式照常由管理员审批。
- 不控制跨人的重复；不把给其他人的回复原文放进提示词。
- 不改近期互动的条数、时间窗口和可见范围的默认值。
- 不为文风发起额外模型请求，不自动重写，不由代码改写正文。
- 不拦截客服腔、禁用开头、动作描写、表情超额。
- 不改人设内容。口吻和梗的写法在 `add-persona-presets` 中调整。
- 不改表情节制提醒。

## Decisions

### 1. 近期往来单独成段

- `assembleReplyPrompt` 像现在取出 `experiences` 一样，从 memory 对象里取出 `recent`。“关于对方的记忆”段不再包含 `recent`。
- 新增分段 `{kind:'recent', title:'与对方的近期往来', role:'user', stable:false}`，位于记忆段之后、当前对话之前。
- 段内容为 JSON：`{note, items}`。
  - `items` 沿用 `recent` 的字段，不重新查询。
  - `note` 是固定文本：“以下是你和对方最近的往来，按时间先后排列；reply 是你已经发出的原话，没有 reply 表示那次没有发出回复。用来接上话题、避免重复：这次不要再用其中出现过的梗、口癖、开头、收尾和说法。”
- 没有近期往来时（新用户、超出时间窗口、已遗忘），内容为“暂无”，分段结构保持固定。
- 数据来源、条数、时间窗口、渠道范围和遗忘规则全部沿用 `MemoryService.context()`，因此不会出现给其他人的回复，私信的可见范围也与现在一致。
- 试聊时，管理员传入的 memory 如果包含 `recent`，同样单独成段。回放用的旧快照不需要迁移，重新组装时自动采用新结构。
- `REPLY_PROMPT_VERSION` 在实施时的当前值上加一。`remove-message-forget-command` 的实现已把它改为 `reply-context-v3`，本提案以实施时的实际值为准。

**为什么不直接把最近回复原文放进去：** 给其他人的回复里可能有对方的私事，模型可能把它当成当前这个人的事。管理员也确认跨人重复不需要控制。所以只用和当前这个人的往来。

### 2. 去掉跨人的开头去重提醒

- `buildReplyHints` 不再生成 `opening` 提醒。`ReplyHintKind` 去掉 `opening`；历史消息记录里的 `opening` 类别照常显示。
- `openingEnabled` 和 `openingCount` 保留在设置结构和校验里，旧数据和旧请求都不会返回 400；生成时忽略它们。人设页“动态提醒”卡片不再显示这两项。
- 表情节制提醒不变：仍然使用账号级的最近回复样本，只统计数量。
- `replyOpening` 继续供人设回放的“开头重复”统计使用。该统计保留，作为观察指标。

### 3. 早晚安帖带上以前的帖子

- 早晚安帖调用 `persona.assemble` 时传入 `experiences: recallRoleExperiences(store, accountId)`，和回复使用同一个召回函数。
- 提醒区追加一条只用于早晚安帖的提醒，新增类别 `post-variety`，文本为：“角色经历里有你最近发过的帖子。这条帖子不要重复它们的开头、句式和切入点；今天的内容以今日日程为准，不要把以前帖子里的事当成今天又发生一次。”
- 不新增查询，不读取出站表。管理员隐藏的帖子不再参与，这与角色经历的现有规则一致。
- `recentReplies` 照旧传入，供表情节制统计。
- 角色经历最多 10 条。早晚各发一条时大约覆盖 5 天，用来避免前后雷同已经够用。

### 4. 格式标记

格式检查只做标记，不改变发送流程：自动模式照常自动发送，草稿模式照常由管理员审批。检查不发起模型请求，不改写正文。

**检测**

`src/reply-style.ts` 新增 `formatIssues(text)`，返回命中的类别。

- **`list-or-steps`**：在 `hasSteps` 基础上收紧，减少误判：
  - 行首编号后面紧跟数字时不算，例如“3.5 分”；
  - 行首编号或项目符号要至少两行才算列表；
  - “第 N 步”和“首先……然后……最后”保持不变。

  `hasSteps` 同步改用这套规则，人设回放的步骤统计也随之更准。
- **`markdown`**：以下任一情况算命中：
  - 行首 1—6 个 `#` 加空格的标题；
  - `**文字**` 或 `__文字__`；
  - 三个反引号的代码块。

**回复和私信**

- `generateDraft` 在正文校验之后计算 `draft.format = {issues}`，随草稿一起保存。没有命中时 `issues` 为空数组。
- 自动提交条件不变，`error` 也不写格式问题，避免和正文校验失败混淆。
- 动态页：
  - 草稿卡片在正文下方显示一行提示，例如“格式提示：含列表或步骤”，供审批时参考；
  - 已发送消息的详情里显示同样的提示，方便事后查看。
- 管理员改写草稿后，按改写后的正文重新计算标记。重写草稿生成新正文时同样重新计算。

**早晚安帖**

在正文校验之后检查格式，照常提交。命中时把 `format` 写进任务记录，任务执行历史里显示同样的提示。

**试聊**

结果里增加 `format` 字段，试聊区显示“格式检查：通过”或命中的类别。

**不加告警**

不新增健康告警，也不新增统计页。人设回放的生产回复质量统计已经统计步骤，检测规则共用后结果一致。

## Risks / Trade-offs

- **近期往来默认只有 3 次**：更早的重复看不到。可以在记忆页调大，每多一次往来约多几十到几百 token，这部分在每次都会变的段落里。
- **常聊的人很少再见到梗**：对经常来聊的人，“用过的不再用”会让梗很久不出现。这是可以接受的代价，用验收结果观察。
- **账号回复页可能出现雷同开头**：去掉跨人开头提醒后可能出现这种情况。管理员已确认可以接受。人设回放的开头重复统计仍在，必要时可以撤回本项。
- **标记不拦截**：自动模式下，含列表或步骤的回复仍会发出。减少这类回复靠人设里的“不给步骤”卡和通用写法；标记用来事后发现问题，再回头改人设。
- **格式误判**：叙述里写“首先……然后……最后”也会被标记。因为只是提示、不影响发送，误判的代价只是多一行提示。
- **并行修改**：`public/js/views/persona.js`、`src/persona.ts` 和 `src/reply-prompt.ts` 上都有其他提案未提交的改动。实施前先核对这些改动，只做本提案需要的修改，提交前确认没有覆盖。

## Migration / Rollback

- 不改数据库，不迁移数据。旧的生成快照可以照常回放，旧的动态提醒设置可以照常读取。
- 回退时恢复原来的组装、提醒和任务即可。草稿里多出的 `format` 字段旧版本不读取，不影响使用。
- 提示词版本变化只影响生成记录里的版本字段，不影响已有数据。

## Verification

**服务器单元测试**

- **分段顺序**：顺序为记忆 → 与对方的近期往来 → 当前对话；记忆段不再包含 `recent`；没有近期往来时显示“暂无”。
- **范围**：
  - 为用户乙生成时，不包含刚发给用户甲的回复；
  - 公开回复不包含私信往来；
  - 已遗忘用户的近期往来为空；
  - 只生成了草稿、没有发出的那次往来不带 `reply`。
- **提醒**：
  - 不再出现开头提醒；
  - 包含 `openingEnabled`、`openingCount` 的旧设置能读取和保存；
  - 表情节制结果与改动前相同。
- **早晚安帖**：
  - 提示词的角色经历包含最近确认的帖子，提醒区有帖子去重提醒；
  - 被隐藏的帖子不出现；
  - 回复的提示词里没有这条帖子提醒。
- **格式检测**：
  - **应该命中**：两行以上的编号列表、两行以上的“- ”列表、“第一步……第二步”、“首先……然后……最后”、“## 标题”、“**加粗**”、代码块。
  - **不应命中**：“3.5 分也太低了吧”、只有一行“1、我觉得可以”、破折号、句中单个星号、颜文字中的符号、“哈哈哈”。

**服务器工作流测试**（模拟模型）

- **自动模式**：含列表的回复照常自动提交，消息记录带格式标记；模型调用次数与改动前相同。
- **草稿模式**：含列表的回复保存为草稿并带格式标记；不批准就不发送，与改动前相同。
- **改写**：管理员改写草稿、去掉列表后，标记随之消失。
- **早晚安帖**：含 Markdown 的帖子照常提交，任务记录带格式标记。

**服务器隔离界面验收**（Camoufox，1440px 与 375px）

- 人设页“动态提醒”不再显示开头相关项。
- 试聊分段里出现“与对方的近期往来”，并显示格式检查结果。
- 动态页的草稿卡片和已发送消息详情显示格式提示；任务执行历史显示帖子的格式提示。

**真实模型验收**（计费调用，需要另行授权）

- 用试聊模拟同一个人连续聊五轮，把前几轮作为近期往来传入，比较改动前后梗、口癖、开头和收尾的重复。
- 结果写入实施记录。可以和 `add-persona-presets` 的批量验收（任务 4.3）合并进行，避免重复花费。

**发布后只读观察**（需要发布授权）

- 早晚安任务启用后，看连续几天帖子的开头和句式。
- 看被标记的回复和帖子有多少，据此决定要不要调整人设。

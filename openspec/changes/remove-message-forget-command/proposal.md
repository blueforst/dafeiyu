# 取消消息里的遗忘指令提案

## Why

**现状（2026-10-28 核对本机提交 `b607c3d` 与生产服务器）：**

- 主循环在入队阶段检查每条消息的正文：整条消息是“忘了我吧”（也认“忘记我吧”“忘我吧”，末尾可带句号、感叹号）时，系统遗忘这个用户、停止记录，并直接跳过这条消息，不生成回复；整条是“重新记住我”时恢复记录。这两条指令照搬自参考帖，代码在 `src/workflow.ts` 入队阶段，没有测试覆盖，`docs/记忆策略.md` 也没有写。
- 这条指令弊大于利：
  - **容易误触**：随口一句玩笑或情绪话“忘了我吧”，系统就会永久停止记录这个人。人设预设上线后，粉丝和 AI 娘玩梗时更容易说出这句话。
  - **没有反馈**：这条消息被直接跳过，对方收不到任何回应，也不知道怎么恢复。
  - **识别不一致**：新发一条“@账号 忘了我吧”时正文带 @，整条匹配可能认不出来（未实测）。
- 记忆页已经支持管理员遗忘和恢复。真有人要求删除记录，管理员在记忆页处理即可。
- 生产数据目录里没有遗忘账本文件，说明从来没有人被遗忘过，取消指令不影响任何现有用户。

## What Changes

- **删除两条消息指令**：“忘了我吧”“重新记住我”这类消息和其他消息一样进入分级、生成和发送流程，不改变遗忘状态。
- **遗忘和恢复只在记忆页操作**：管理员通过记忆页（及其现有接口）遗忘或恢复用户，接口不变。
- **回复不假装忘了**：取消指令后，模型可能顺口回复“好，我已经忘了”，这是做不到的承诺。固定系统约束增加一句：被要求忘掉对方或删除聊天记录时，不说已经忘了或删了，如实说明自己做不到，记录由运营者管理。回复提示词版本升为 `reply-context-v3`。
- **文档**：`docs/记忆策略.md` 写明遗忘只在记忆页操作，消息内容不触发遗忘；`docs/参考帖子对照.md` 的对应行改为“明确不做”。

这句约束放在固定系统约束而不是人设里，因为它对任何人设都成立：自定义人设不用自己写，也不需要改动正在实施的 `add-persona-presets`。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `conversation-memory`：修改“遗忘与恢复记录”，去掉用户消息指令入口，并规定被要求遗忘时的回复约束。

“遗忘与恢复记录”的现行写法来自未归档的 `add-seven-page-production-bot`（其中写有“已有用户指令入口”），本提案需要排在它之后归档。

## Impact

- **代码**：`src/workflow.ts` 删除入队阶段的两条判断；`src/reply-prompt.ts` 的固定系统约束增加一句，`REPLY_PROMPT_VERSION` 改为 `reply-context-v3`。
- **测试**：`test/draft-workflow.test.ts` 新增回归用例；`test/reference-prompt.test.ts` 更新版本号并断言新句。
- **提示词缓存**：固定系统约束属于稳定前缀，发布后第一轮会重新建立缓存，之后恢复命中。
- **与其他提案**：不改 `add-persona-presets` 正在修改的文件，也不依赖它。
- **不涉及**：数据库结构、记忆页接口、遗忘账本与恢复流程均不改。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行，生产发布需要另行授权。

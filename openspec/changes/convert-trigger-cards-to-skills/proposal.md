# 触发卡改为按需读取提案

## Why

管理员 2026-10-29 反馈：关键词触发很容易识别不到，也很容易被绕过，应该改用模型语义识别，并像 skill 一样渐进式加载。以下对照本机源码 `746ba7e` 核对。

- **关键词卡误判和漏判。** 关键词只做子串匹配。0.1.20 真实试聊中，骚扰消息“别装可爱”命中了“被夸”卡（见 [2026-10-29 真实试聊](../../../docs/实施记录/2026-10-29-dsv4.1f真实试聊.md)）；换个说法就漏判，比如“怎么才能做好番茄炒蛋”不含“怎么做”。六个内置预设的触发卡全部是关键词卡。
- **语义卡要多发一次请求。** 现有语义卡由一个单独的路由请求判断命中，它只看得到卡片条件。只要启用了任意一张语义卡，每条消息都要先多请求一次，哪怕最后一张卡也用不上。
- **“被问到才用”的内容每次都整段放进提示词。** 角色预设的“她自己”“外貌”“认识的 AI 娘”“身份设定”四个分区是静态分区，每次回复都整段放在 system 里，只靠第一行文字提醒模型“被问到才用”。不相关的内容常驻提示词，模型容易顺手提起，也占用每次请求的输入。
- **以后会加别的工具。** 管理员计划之后给回复加入其他工具调用，需要一套通用的工具调用流程，而不是只为触发卡做的专用判断步骤。

## What Changes

- **触发卡只有一种。**
  - 每张卡只填标题、“什么时候用”（一句话）和内容，另有启用开关和顺序。
  - 取消“关键词”触发方式及其字段，也不再有“触发方式”选项。
  - 页面上始终叫“触发卡”，不出现 skill、工具调用等概念。
- **“被问到才用”的分区并入触发卡。** 人设编辑页只分“始终生效”和“触发卡”两组。
- **底层按 skill 的方式读取。**
  - 回复模型的 system 里常驻一份触发卡目录，每张启用的卡一行，写标题和“什么时候用”。
  - 模型判断本条消息用得上哪张卡，就通过工具调用读取这张卡的内容，读完再写回复。读完一张还可以再读别的。
  - 用不上卡片时直接回复，只发一次请求。原来单独的语义路由请求取消。
  - 读取用各服务商原生的工具调用，由 Pi 统一适配，不做不支持工具调用时的退回方案。
- **工具调用上限。**
  - 一次回复最多调用 20 次工具。读取触发卡算工具调用，以后新增的工具也计入这 20 次。
  - 用满后不再执行工具，模型必须用已有内容写出最终回复。
- **没有对话的生成带上全部卡片。** 虚构日程和早晚安帖没有对方消息可供判断，直接带上全部启用触发卡的内容，不调用工具。
- **诊断与计费。**
  - 试聊、动态详情和回放显示本条回复读取了哪些卡、模型给出的读取理由，以及工具调用次数。
  - 每一轮请求照常写入统一调用流水，用途与所在流程相同，比如生产为“回复”、试聊为“试聊”。
  - 不再产生“语义触发”用途，历史记录照常显示。
- **回放。**
  - 两侧各自决定读哪些卡。模型对比不再“两侧共用一次语义判定”。
  - 预估请求数按近期每条回复的平均请求轮数估算，并说明读取卡片会增加请求。
- **连接测试。** 模型库的单模型测试改为发送一次带工具的请求，模型返回工具调用才算通过。这样不兼容工具调用的接口在测试阶段就会暴露。
- **已有人设一次性升级。**
  - 关键词卡转成普通触发卡，原来的关键词写进“什么时候用”。
  - 标题含“被问到才用”的分区转成触发卡。
  - 从预设新建且未改动过的卡片和分区，换成新版预设的写法。
  - 每个有变化的人设修订号加一，升级前的设置先备份。
- **内置预设升级到第 3 版。**
  - 四个“被问到才用”的分区改为触发卡。
  - 全部关键词卡改写为“什么时候用”的说明，例如“被夸”卡写明反话、嘲讽和骚扰不算夸。
- **人设文件。** 导出升级为第 2 版格式；导入第 1 版文件时按上面的升级规则转换。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `persona-management`：触发卡结构与编辑；移除语义路由判定、判定失败回退和关键词触发；新增按需读取、工具调用上限、读取异常、无对话场景使用全部卡片、旧人设升级；预设与试聊预览随之修改。
- `reply-prompt-context`：system 增加触发卡目录；卡片内容改为在本次消息之后以工具结果出现。
- `chat-test`：正常流程、本轮诊断和计量改为按需读取的口径。
- `persona-replay`：费用预估和模型对比改为两侧各自读取。
- `persona-library`：人设文件第 2 版及旧文件转换。
- `workflow-observability`：取消语义判定阶段，生成阶段显示请求轮数与读取卡片数。
- `llm-usage-billing`：全用途计量去掉语义触发用途，每轮读取后的请求单独记录。
- `model-configuration`：单模型测试包含工具调用。

上述能力除 `model-configuration` 的主规格外，目前都只存在于未归档的提案中：`add-seven-page-production-bot`、`fill-reference-post-gaps`、`add-persona-presets`、`add-persona-workspace`、`improve-reply-prompt-context`、`improve-reply-style`、`refine-settings-memory-timezone`、`add-persona-replay`、`add-persona-file-transfer`、`simplify-panel-activity-feed`。本提案应在这些提案之后归档；实施可以直接基于当前代码开始。本提案与 `simplify-model-params` 互不依赖，二者修改 `model-configuration` 中不同的需求。

## Impact

- **代码**
  - 核心：`src/persona.ts`（卡片结构、目录、升级规则）、`src/persona-presets.ts`（第 3 版预设）、`src/persona-library.ts`（升级迁移、文件版本）、`src/reply-prompt.ts`（目录分段、版本 `reply-context-v6`）、`src/model.ts` 与 `src/llm-store.ts`（多轮请求与工具）。
  - 新增 `src/reply-tools.ts`：工具调用循环，生产、试聊、回放和批量预览共用。
  - 同步修改：`src/reply-pipeline.ts`、`src/chat-test.ts`、`src/persona-replay.ts`、`src/daily-state.ts`、`src/production-tasks.ts`、`src/model-library.ts`、`src/model-routes.ts`。
  - 前端：`persona-editor.js`、试聊详情、动态右栏、回放预估和模型测试结果。
- **数据**：不新增数据库迁移。人设 JSON 去掉 `match`、`keywords` 字段；升级只改面板设置中的人设与人设库，并先写备份。
- **模型请求**
  - 用不上卡片的消息只请求一次；有语义卡的人设因此比现在少一次路由请求。
  - 读取卡片的消息每多一轮读取就多一次请求，后续请求与前一次共用前缀，可命中缓存。
  - 原来只用关键词卡的人设（包括全部内置预设）在需要卡片时会比现在多请求。另一方面，四个“被问到才用”的分区不再常驻 system，每次请求的输入变短。
  - 一次回复最多 21 次请求：20 次工具调用各占一轮，再加最终回复一轮。
- **提示词前缀**：system 新增目录、去掉四个分区，前缀会失效一次；之后在同一人设修订内保持逐字节一致。
- **不包含**：除读取触发卡以外的其他工具；导入导出标准 skill 文件夹；子资料（卡片下再挂文件）；按用途分别选择模型；修改输出上限和超时（见 `simplify-model-params`）。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行；真实模型验收是计费调用，生产发布另需授权。


## 管理员追加：终态草稿工具

最终草稿也通过原生 `submit_draft` 工具给出，读取与输出在同一通用循环中完成；终态输出不占20次读取额度。不读卡仍只需一次请求。早晚安只带终态工具，日程和记忆整理保持原 JSON。无自动格式修复重试，无平台发送副作用。

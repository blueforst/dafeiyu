# 触发卡按需读取实施任务

当前完成 20/20 项。规格见 [persona-management](specs/persona-management/spec.md)、[reply-prompt-context](specs/reply-prompt-context/spec.md)、[chat-test](specs/chat-test/spec.md)、[persona-replay](specs/persona-replay/spec.md)、[persona-library](specs/persona-library/spec.md)、[workflow-observability](specs/workflow-observability/spec.md)、[llm-usage-billing](specs/llm-usage-billing/spec.md) 和 [model-configuration](specs/model-configuration/spec.md)，实现边界见 [design.md](design.md)。

执行边界：

- 构建和测试只在服务器隔离环境 `/srv/role-workflow-proposals` 执行，不使用生产 profile。
- 真实模型调用是计费调用，需要另行授权；生产发布也需要授权。提案创建不视为任何授权。
- 实施前确认本机工作副本中 `persona.ts`、`persona-presets.ts`、`persona-library.ts`、`reply-prompt.ts`、`reply-pipeline.ts`、`model.ts`、`persona-replay.ts`、`chat-test.ts`、`persona-editor.js`、`feed.js` 没有其他人的未提交改动。

## 1. 前置验证

- [x] 1.1 用使用中的模型在服务器隔离环境验证一次会话先调用 read_card、再调用 submit_draft 生成草稿，不附加 JSON mode（计费，需授权，不超过 5 次请求）。验收：实施记录写明请求次数、费用和结论；不兼容时按 design.md 第 3 节“输出格式”的处理执行，并在记录中注明。

## 2. 模型调用层

- [x] 2.1 `runCompletion` 接受 Pi `Context`，新增 `Generator.converse`；`complete` 改为包装调用（design.md 第 4 节）。验收：现有模型、计量、会话路由测试全部通过；新增用例覆盖 `toolUse` 正常返回、其他异常状态失败、每轮单独落账并带 `round`；测试替身实现 `converse`。
- [x] 2.2 `src/reply-tools.ts`：工具接口、`read_card` 与 `runReplyLoop`（第 3 节）。验收：单元测试覆盖无读取一次请求、读一张、连续读两张、不存在、重复、同轮并发超限（19 次后请求 3 张只执行 1 张）、满 20 后再调用以 `tool-limit` 失败且共 21 次请求、中止、第二轮失败时错误带完整 `callIds`；满额后只接受终态工具并保留原定义；补终态参数、普通文本与并行提交拒绝用例。

## 3. 人设结构、提示词与预设

- [x] 3.1 `PersonaTrigger` 去掉 `match`、`keywords`，校验拒绝关键词字段，删除关键词匹配代码（第 1 节）。验收：接口测试断言带关键词字段的保存返回 400 及说明；带 `match:'semantic'` 的保存成功且不保存该字段；分级广告关键词测试不受影响。
- [x] 3.2 触发卡目录分段、提醒区不再含卡片、`reply-context-v6`（第 2 节）。验收：提示词测试断言目录位于静态人格与渠道规则之间、只含启用卡且按顺序、换行被替换；同一修订内不同消息的 system 与工具定义逐字节一致；没有启用卡时无目录、只带终态工具；原 `reply-prompt-context` 测试中依赖旧提醒区的断言按新规格更新，其余不变。
- [x] 3.3 第 3 版内置预设及 `PERSONA_PRESETS_V2` 比对常量（第 9 节）。验收：预设测试断言六个预设的四个始终生效分区与第 2 版逐字相同、卡片顺序与标识、五个角色预设有四张原分区卡且“始终生效”只有四个分区、“被夸”说明含反话、嘲讽与骚扰、每个预设有“不给步骤”与“被夸”；原预设测试中的关键词断言删除并说明原因。

## 4. 升级与人设文件

- [x] 4.1 `upgradePersona` 纯函数（第 10 节）。验收：单元测试逐条覆盖分区转换（预设未改、预设改过、自建）、关键词卡转换（预设未改、自动条件、自写条件）、语义卡、重复执行 `changed=false`、超长人设可读不可存。
- [x] 4.2 启动时升级、备份与修订号（第 10 节）。验收：测试用 0.1.20 结构的面板设置夹具（含从大肥鱼新建并改过外貌的人设、自建关键词卡、通用默认），断言备份文件存在且权限 0600、变化项修订号加一、镜像与使用中一致、运行控制不变、二次启动无变化；无旧结构时不写备份。
- [x] 4.3 人设文件第 2 版与第 1 版导入转换。验收：文件往返测试覆盖第 2 版往返一致、第 1 版含关键词卡与“外貌（被问到才用）”的转换、未知版本拒绝且人设库不变。

## 5. 接入各流程

- [x] 5.1 生产与试聊流水线改用循环，取消 `semantic-trigger` 阶段，阶段记录 `rounds`、`cardsRead`（第 5、6 节）。验收：工作流测试断言读取一张卡时有一个生成阶段、两次调用都计入本轮、草稿 `meta` 含 `triggerHits`、`toolCalls`、`callIds`；失败时两轮用量都在流水中；试聊测试断言读取摘要、详情与计量。
- [x] 5.2 批量预览接口改用循环。验收：预览测试断言 `calls`、`fees` 汇总全部轮次，`warning` 不再出现语义回退文案。
- [x] 5.3 回放两侧各自读取、模型对比取消共享路由、预估按平均轮数（第 5 节）。验收：回放测试断言两侧读取互不影响、`shared` 统计为 0、有记录时用平均轮数、无记录时按 2、预估说明文字；旧回放记录仍可读取。
- [x] 5.4 虚构日程与早晚安帖带全部卡片（第 8 节）。验收：日程与发帖测试断言请求包含全部启用卡片内容、不带读取工具，早晚安只带终态工具、日程不带工具，只有一次请求、关闭的卡片不包含。
- [x] 5.5 连接测试改为工具调用（第 7 节）。验收：模型库测试覆盖调用了工具即通过、只返回文字失败并显示“未完成工具调用”、接口拒绝时显示原因；CLI `model-check` 使用同一逻辑。

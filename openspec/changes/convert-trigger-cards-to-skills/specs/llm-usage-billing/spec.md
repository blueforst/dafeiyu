# 模型计量增量规格（触发卡按需读取）

## MODIFIED Requirements

### Requirement: 全用途请求计量

系统 MUST 为回复、日程、记忆、连接测试、CLI 测试、试聊、回放、早安及晚安的每次实际模型请求记录唯一调用、用途、来源、模型、状态和耗时；一条回复读取触发卡后的每一轮后续请求 MUST 作为独立调用记录，并与该回复关联；重试必须保留新的实际请求。系统 MUST NOT 再产生用途为“语义触发”的新调用，历史调用照常统计和显示。

#### Scenario: 一轮试聊包含语义判断与生成
- **WHEN** 管理员发起一轮试聊，模型读取一张触发卡后写出回复
- **THEN** 系统记录两次独立调用，并在试聊显示两者合计费用

#### Scenario: 同一消息重新请求模型
- **WHEN** 第一次生成失败后发起新的真实请求
- **THEN** 系统保留两次调用，不能按消息 ID 覆盖首次消耗

#### Scenario: 升级后按用途查看
- **WHEN** 管理员在升级后按用途查看包含升级前日期的范围
- **THEN** 历史的“语义触发”调用仍单独列出，升级后的读取请求计入各自流程的用途

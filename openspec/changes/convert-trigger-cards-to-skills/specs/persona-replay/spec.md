# 人设回放增量规格（触发卡按需读取）

## MODIFIED Requirements

### Requirement: 费用预估与确认

系统 MUST 在开始回放前显示预计模型请求数和按 Pi 内置价格估算的费用。每条样本每侧的请求数 MUST 按近期同用途回复的平均请求轮数估算（没有记录时按每条两次），并说明读取触发卡会增加请求、每侧每条最多 21 次；存在未定价模型时如实提示。只有管理员确认后才开始。回放可随时中止，已完成条目保留，未开始条目不再请求；全部调用以回放用途计量。

#### Scenario: 中途中止
- **WHEN** 管理员在 50 条中完成 20 条时中止
- **THEN** 已完成的 20 条结果保留，其余条目不再发起请求，计费页可按回放用途查到实际调用

#### Scenario: 模型未定价
- **WHEN** 当前模型没有可靠的 Pi 价格
- **THEN** 预估显示请求数与“未定价”，不显示为免费

#### Scenario: 预估说明读取卡片
- **WHEN** 管理员对带触发卡的人设打开回放预估
- **THEN** 预估显示按平均轮数估算的请求数，并说明每读取一张卡多一次请求、每侧每条最多 21 次

### Requirement: 模型设置对比

回放 MUST 支持以模型设置为比较对象：两侧使用同一份已保存人设和提醒设置；基线用使用中的模型重新生成，候选用管理员从模型库选择的模型与推理档位。两侧 MUST 从相同的首轮提示词出发，各自决定读取哪些触发卡，读取次数和请求轮数分别计算。预估 MUST 按两侧各自模型的 Pi 价格分别计算，未定价的一侧如实显示。结果 MUST 分别展示两侧的平均耗时、请求次数、读取卡片数、输入和输出 token、缓存读取与实际费用。模型对比不改变使用中的模型，也不提供一键采用。

#### Scenario: 比较开启思考前后
- **WHEN** 管理员选择同一模型、候选推理档位设为 low，对 16 条公开样本运行回放
- **THEN** 结果并排展示两侧回复，并列出两侧的平均耗时、输出 token 与费用差异

#### Scenario: 候选模型未定价
- **WHEN** 候选模型没有可靠的 Pi 价格
- **THEN** 预估显示候选侧未定价、基线侧按价格估算，确认前不会显示为免费

#### Scenario: 语义规则只判定一次
- **WHEN** 人设带触发卡，某条样本中基线模型读取了“她自己”，候选模型没有读取
- **THEN** 每条样本不再有单独的语义判定请求，两侧各自判断；该条基线显示读取了“她自己”和两次请求，候选显示未读取和一次请求

#### Scenario: 对比结束后
- **WHEN** 模型对比回放完成
- **THEN** 使用中的模型保持不变，结果页只提供前往模型设置的入口

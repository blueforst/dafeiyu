# 试聊增量规格（触发卡按需读取）

## MODIFIED Requirements

### Requirement: 按正常流程处理

每条试聊消息 MUST 按生产中相同渠道的真实消息处理，使用与生产相同的规则和代码：分级（广告与刷量过滤、首次来访、提问、老面孔招呼等）、同一用户连发合并、骚扰冷却、记忆召回（长期记忆、近期往来、角色经历）、当天虚构日程的当前时段、人设分区与触发卡目录、按需读取触发卡及工具调用上限、提示词提醒、使用中的模型和参数、模型跳过判断、公开或私信的字数校验、格式标记与私信内容重合检查。记忆召回 MUST 与生产中已关联身份的规则相同：私信这一轮召回私信记忆与近期往来，以及同一测试用户的公开记忆与公开近期往来；公开这一轮召回公开记忆与近期往来，以及该用户的私信长期记忆作为只作背景的“私信中得知”。被过滤的消息 MUST NOT 调用模型。

#### Scenario: 记得上一轮
- **WHEN** 测试用户先说“项目下周上线”，角色回复后，再问“还记得我在忙什么吗”
- **THEN** 第二轮的近期往来包含第一轮的消息和回复，本轮详情列出这条召回

#### Scenario: 广告被过滤
- **WHEN** 测试用户发送带链接的广告关键词消息
- **THEN** 本轮显示被分级过滤及原因，没有模型调用和费用

#### Scenario: 公开往来在私信中可召回
- **WHEN** 测试用户在公开回复中说“你好呀”并得到回复，之后在私信里问“你还记得我吗?”
- **THEN** 私信这一轮的近期往来包含那次公开往来并标明来自公开，本轮详情列出这条召回

#### Scenario: 私信记忆在公开中只作背景
- **WHEN** 测试用户在私信中提到养猫并已整理成长期记忆，之后在公开回复里聊天
- **THEN** 公开这一轮的提示词在“私信中得知”区包含这条记忆，不包含私信原文；本轮详情显示召回了私信背景，回复如与之重合八个字符以上则显示“正常流程不会发出：可能提及私信内容”

#### Scenario: 关键词卡命中
- **WHEN** 使用中的人设带由关键词卡升级而来的“被夸”卡，测试用户说“你好可爱”，模型读取了“被夸”卡
- **THEN** 本轮详情显示读取了“被夸”及模型给出的理由，而不是命中的关键词；工具调用 1 次，本轮共两次回复生成请求

### Requirement: 本轮诊断

每一轮 MUST 在对话中显示一行摘要（所用人设、分级结果、召回条数、读取的卡片、耗时），回复下方显示模型、输入和输出 token 以及费用。点击某一轮后，右栏“本轮详情” MUST 显示：人设名称与修订号、分级档位与原因、合并条数、日程时段、读取的触发卡及理由、工具调用次数与上限、提示词提醒、模型与调用次数、耗时、字数校验和格式标记、本轮实际召回的记忆；“提示词”标签 MUST 按实际请求顺序显示各提示词分段及其属于稳定前缀还是动态内容，并显示每次读取返回的卡片内容。“记忆”标签 MUST 分公开身份和私信身份显示该测试用户当前的长期记忆、近期往来、距下次整理的进度和骚扰计数，以及只读的角色经历。任何展示都 MUST NOT 包含密钥。

#### Scenario: 查看某一轮的提示词
- **WHEN** 管理员点击第三轮回复并切换到提示词标签
- **THEN** 右栏按顺序显示该轮的系统层和消息层分段，包括触发卡目录、当时召回的记忆和日程，以及读取返回的卡片内容，不含任何 Key

#### Scenario: 没有读取卡片
- **WHEN** 一轮回复没有读取任何卡片
- **THEN** 摘要和详情显示“未读取触发卡”，工具调用 0 次

### Requirement: 试聊计量

试聊产生的每次实际模型请求，包括回复生成的每一轮（含读取卡片后的后续请求）和记忆整理，MUST 写入统一调用流水，用途记为“试聊”，并能区分是哪一步；计费页 MUST 把“试聊”作为单独用途统计。主区页头 MUST 显示当前测试用户的累计估算费用。生成失败、输出不合格或中止后已经落账的用量 MUST 仍计入；没有可靠价格时显示未定价或未知，不视为免费。

#### Scenario: 计费页按用途查看
- **WHEN** 管理员进行了若干轮试聊后在计费页按用途查看
- **THEN** “试聊”单独成为一个用途，其请求数和费用与试聊页显示的累计一致

#### Scenario: 读取卡片后的计量
- **WHEN** 一轮试聊读取了两张卡片，共三次回复生成请求
- **THEN** 调用流水中有三条用途为“试聊”的回复请求，本轮费用为三者合计

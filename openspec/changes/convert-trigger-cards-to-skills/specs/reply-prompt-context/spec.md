# 回复提示词结构增量规格（触发卡目录）

## MODIFIED Requirements

### Requirement: 稳定前缀分层顺序

系统 MUST 按固定顺序组装回复提示词：system 依次包含固定系统约束、已保存静态人格（始终生效分区）、触发卡目录和按渠道固定的规则；user 依次为角色经历、当日日程与当前时段、对此人的允许范围记忆、与对方的近期往来、当前对话、提醒区、本次消息，最后为当前时间。读取的触发卡内容 MUST 以工具结果的形式出现在 user 之后。同账号、同渠道、同一人设修订、同一北京日期内，system 和工具定义 MUST 逐字节一致。

#### Scenario: 两条消息命中不同触发规则
- **WHEN** 同一天同渠道的两条消息分别读取了不同的触发卡
- **THEN** 两次首轮请求的 system 和工具定义完全相同，卡片内容只出现在各自后续轮次的工具结果中

#### Scenario: 管理员保存新人设
- **WHEN** 人设修订号变化后开始下一轮生成
- **THEN** system 使用新人设和新目录，同一修订内的后续请求再次保持一致

#### Scenario: 近期往来的位置
- **WHEN** 为一位有近期往来的用户生成回复
- **THEN** user 中“与对方的近期往来”位于记忆之后、当前对话之前，记忆部分不再重复这些往来

#### Scenario: 读取卡片后的下一轮
- **WHEN** 模型在首轮请求读取一张卡片
- **THEN** 第二轮请求依次包含与首轮相同的 system 和 user、首轮的工具调用、该卡的工具结果，前缀与首轮一致

### Requirement: 命中模块靠近生成位置

本轮读取的触发卡内容 MUST 只以工具结果的形式出现在本次消息和当前时间之后，紧邻模型写出回复的位置；system 中只有目录，不得包含任何卡片内容；提醒区 MUST NOT 再包含触发卡内容。

#### Scenario: 命中管理员配置的“不给步骤”规则
- **WHEN** 消息询问做法，模型读取“不给步骤”卡
- **THEN** 该卡内容出现在本次消息之后的工具结果中，而不在 system 或提醒区中

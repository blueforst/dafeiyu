# 并发运行控制

## Purpose

保证多个管理页面和慢浏览器请求并发时，后发出的暂停、人工接管与安全暂停仍能成为有效控制结果，避免已经失效的启动或失败收束再次恢复自动处理，保持管理员可判断的运行状态。

## ADDED Requirements

### Requirement: 新控制使旧启动失效

系统 MUST 在后发暂停、接管、安全暂停或关闭工作流后使尚未完成的旧启动失效；旧请求不能恢复运行、覆盖账号或撤销新的控制结果。

#### Scenario: 身份检查期间暂停
- **WHEN** 启动等待身份检查，后发暂停已完成，随后身份检查成功
- **THEN** 旧启动返回已被替代的结果，业务与浏览器保持暂停

#### Scenario: 身份检查期间接管
- **WHEN** 启动等待身份检查，后发人工接管已完成，随后身份检查成功
- **THEN** 旧启动不能恢复自动模式，人工接管保持有效

### Requirement: 控制提交与失败收束有序

系统 MUST 保证浏览器控制提交互斥；旧请求等待浏览器期间发生新控制后，旧请求的成功或失败均不能覆盖新状态。释放接管仍保持暂停，普通配置保存不产生运行控制。

#### Scenario: 浏览器启动控制尚未返回
- **WHEN** 浏览器启动控制正在执行，管理员请求暂停
- **THEN** 业务立即停止进入新工作，暂停等待旧控制退出后完成，最终应用和浏览器均暂停

#### Scenario: 旧暂停失败
- **WHEN** 旧暂停请求失败但已有更新的接管请求
- **THEN** 旧请求不补写暂停覆盖新接管，最新请求按正常规则收束

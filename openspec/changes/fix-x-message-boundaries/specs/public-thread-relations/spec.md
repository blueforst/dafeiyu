# 公开线程可信关系

## Purpose

为公开采集、目标上下文、人工补录与连续消息合并提供一致的关系证据边界，区分帖子本身、被回复的目标和所属线程，避免把推荐、广告或页面顺序误认为用户正在与运营账号互动。

## ADDED Requirements

### Requirement: 公开关系必须有可靠来源

系统 MUST 仅从页面自身取得且能绑定消息 ID、作者、可靠时间的原生资料确认回复关系及线程；缺失、冲突、跨导航过期的资料不得变成可信关系。系统不得主动构造、重放私有接口请求来补证。

#### Scenario: 原生资料与可见文章吻合
- **WHEN** 当前导航的原生资料给出明确父帖和线程，文章的 ID、作者与时间一致
- **THEN** 消息携带可信线程与父帖信息，独立平台 ID 和实际发送目标不改变

#### Scenario: 关系缺失或冲突
- **WHEN** 关系资料缺失、字段冲突、作者／时间不符或来自旧导航
- **THEN** 消息不声明可信关系，不根据页面位置或同文猜测线程

### Requirement: 自动采集和提交前确认相关性

系统 MUST 只自动处理作者正文明确提及工作账号，或有可信回复关系归属工作账号的公开消息。自己帖子页面上的推荐、广告和其他线程文章不得成为回复候选。提交前 MUST 重新核对目标与相关性，旧队列也不能绕过。

#### Scenario: 自己帖子和推荐同时出现
- **WHEN** 自己帖子详情页包含真实回复和无关推荐文章
- **THEN** 只收集已确认属于目标的回复，推荐不触发模型或发送

#### Scenario: 旧队列条目缺少相关性
- **WHEN** 旧队列的目标可定位但既无当前账号提及也无可信关系
- **THEN** 浏览器在提交意图之前拒绝发送，保存明确未提交原因

### Requirement: 上文只包含可信祖先

系统 MUST 按已确认父子关系读取目标的最近上文，合计最多十二条；目标之后的回复、兄弟分支和仅在 DOM 中排在前面的文章均不得进入上文或祖先作者名单。链路缺失时显式标记不完整，已验证的目标正文仍可提供。

#### Scenario: 前置文章不是父帖
- **WHEN** 目标前有工作账号文章，但不存在可靠父子关系
- **THEN** 该文章不进入上文或祖先名单，不能让无提及的补录通过

#### Scenario: 长链及分支
- **WHEN** 目标有二十条可信上文，页面另含兄弟回复
- **THEN** 仅返回最近十一条祖先和目标，并注明早文省略，不返回兄弟回复

### Requirement: 同线程合并保持独立目标

新采集的公开消息 MUST 仅使用可信线程信息参与同用户三十分钟合并，回复目标仍为最新消息自身的唯一平台 ID；无法确认线程时不得跨消息合并。历史记录和冻结出站不得自动改写。

#### Scenario: 同主帖下同用户两条回复
- **WHEN** 两条新消息有相同可信线程且在三十分钟内
- **THEN** 只生成最新一条回复，早消息标记合并并保留为上下文

#### Scenario: 不同线程或关系未知
- **WHEN** 同用户的消息属于不同线程，或新消息的线程未确认
- **THEN** 分别保留，不能因同页出现而合并

# X 消息链路边界修复

## Why

2026-10-29 隔离扫描复现了旧启动请求覆盖暂停／接管、无关公开文章进入回复链路，以及同线程合并失效三个问题。管理员已要求修复，实施范围限定为这些现有契约内的缺口。

## What Changes

- 运行控制增加请求修订和浏览器控制互斥，后发暂停／接管使旧启动失效。
- 从页面自身产生的原生响应读取有界回复关系，绑定可见消息的 ID、作者和时间；未知或冲突关系不推断。
- 公开采集、目标上下文、补录及提交前校验共用可信关系，不再依赖同页出现或 DOM 顺序。
- 新采集消息区分平台消息、发送目标和可信线程 ID，同线程连续消息可以合并；缺关系消息不跨线程合并。
- 在服务器隔离环境验证，无真实模型、真实发送、数据迁移、生产部署或恢复业务。

## Capabilities

### New Capabilities

- `run-control-ordering`：并发运行控制的失效、提交和失败收束语义。
- `public-thread-relations`：公开消息的可信关系、来源资格、上文读取与同线程合并。

### Modified Capabilities

无独立主规格修改。新增要求补强现有七页、运行控制分离、参考补齐和分级提案，已存在的暂停、unknown、额度与审核规则继续生效。

## Impact

涉及 `workflow.ts`、公开采集与目标模块、浏览器边界、消息类型和分级合并；不新增依赖或数据库 schema。现有工作区的设置与模型修改保留；本轮不处理历史出站状态，也不扩大原生 Chat 自动收发范围。

# X 链路修复设计

## Context

依据扫描报告及 proposal.md 实施。当前工作区另有设置和模型修改，修复只改 X 边界，服务器复现以固定 0.1.23 镜像为基线；不迁移历史消息或 unknown。

## Goals / Non-Goals

目标是实现并发控制失效与公开可信关系两份规格。不更改人设、模型、回复时段、额度、私信契约或 unknown 门禁；本轮不发布、不恢复、不发起真实付费和平台收发。

## Decisions

1. **运行控制**：请求同步取得单调修订；异步身份／空闲检查和浏览器控制前后核验修订。浏览器控制使用应用层独立串行尾队列，仅锁实际控制 RPC，不锁等待工作轮次，避免与安全暂停死锁。旧成功及旧失败均不回写新状态。
2. **关系证据**：新建有界公开关系读取模块，读取页面已产生的原生响应内的平台 ID、作者、时间、conversation ID 和 in-reply-to ID／作者。按导航重置，等待解析完成，冲突标记不可用；不使用 DOM 自定义属性或页面顺序冒充平台关系。以消息 ID、作者、时间绑定实际文章。
3. **传递与边界**：Event 增加可选可信线程标记及父帖信息。新 DOM 读取默认不可信，原生证据验证后才写可信线程；未确认时保留消息 ID 作为展示回退，但不得用于合并。原有消息没有新字段时保留原处理边界，不自动回填。
4. **来源和上文**：正文提及可独立成立；回复资格通过已验证父子链或原生线程根证明。自己帖扫描只取该帖后代。上文只跟随父链，最多十二条，缺链标不完整；补录祖先名单不再来自 DOM 顺序。发送前再次验证当前账号与相关性，拦截历史误入队目标。
5. **测试和交付**：新增并发、原生解析、导航隔离、推荐排除、补录与合并端到端测试。原有合成夹具补齐明确的合法关系，保留原断言并新增缺证反例；在服务器构建／回归和隔离 Camoufox 网络拦截环境验证，不用生产 profile。

## Risks / Trade-offs

- 原生字段缺失或变更会保守减少自动采集 → 记录固定关系诊断，不伪报可靠空集，正文明确提及仍可处理。
- 长链部分上文不可见 → 只提供可验证片段并标记不完整，不补造父帖。
- 并发控制旧错误可能晚到 → 修订保护成功与异常分支；新暂停即时阻止新工作，控制 RPC 最终串行完成。
- 既有设置并行修改可能影响整库构建 → 单独保存修复文件清单，以提交基线加修复生成独立候选；保留工作区改动。

## Migration Plan

无 schema、凭据或历史状态迁移。只新增可选事件字段与内存导航证据。测试通过后交付可审阅代码和证据；部署须后续明确授权。代码回退采用原成对 app／browser，数据库、冻结正文及 journal 保持不变；回退会重新暴露已记录缺陷，因此继续暂停。

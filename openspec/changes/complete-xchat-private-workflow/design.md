## Context

0.1.26 的原生 Chat 为只读观察契约，私信正文虽然可见，但时间为 0、入站归属未确认，不能进入业务队列。主收件箱的空态也不能证明请求列表为空。用户已授权立即实施正常一对一新用户的自动处理。控制状态须每次实时读取，历史暂停记录不覆盖后续管理员操作。

## Goals / Non-Goals

**Goals:** 完成请求发现、现有规则过滤、安全接受、可靠入站、原队列生成、原出站发送和持久回查；各阶段可诊断且可分别验证。

**Non-Goals:** 不扩展群聊，不自动删除／屏蔽联系人，不更改公开通道行为、跨渠道身份自动关联、模型或人设，不为不可确认的时间和回执生成替代值。

## Decisions

1. **实际平台证据先行。** 在受控人工接管窗口只读取得原生结构和机器元数据，私有原样本保存在服务器限制权限目录，仓库只存脱敏结构。新契约必须绑定原生消息 UUID、正文、发送者、会话和时间来源；旧观察契约仍可解释不完整结构。替代方案仅点 Accept 会让无法可靠读取的请求丢失在收件箱，故不采用。
2. **请求发现和接收分离。** 浏览器只读发现实际入口及候选，工作流复用配置的广告关键词、骚扰冷却、遗忘和运行限制决策。接受前浏览器重新核对账号、会话、请求来源、消息版本和唯一接受控件；正文伪造的按钮不能成为控件。接受后重新读取有效事件，不能把列表摘要当消息。
3. **副作用有持久意图。** 每个账号／会话／请求版本保存接受意图及确认或未知结果；落盘失败不点击。未知结果先检查平台状态，不能重试点击。现有发送 journal／outbox 保留，只增加原生版本证据；缺原意图、同文冲突或平台确认不足保持 unknown。
4. **共用现有控制链。** 暂停、接管、草稿模式在接受之前检查。关闭回复时段、私信限额、回复时效和通道 unknown 只限制生成／提交，不阻止可靠收件和入库。应用控制修订使未提交动作失效，浏览器控制与业务 RPC 共用串行队列。旧公开 unknown 与缺 journal 的记录不被修复程序自动清空。
5. **有界并可见。** 原有轮次截止、来源名额、资源限制继续生效。来源未检查、请求被规则保留、结构不足、接受未知与正常空收件箱用不同固定诊断码；普通日志不写私信正文、显示名或认证材料。

## Risks / Trade-offs

- 平台更新原生结构 → 版本化校验，不符合契约时保留观察与待人工原因。
- 仅有分钟显示时间或无法绑定原生发送者 → 保持不可靠；若采用时间精度区间，必须同时覆盖年龄、遗忘及回执边界并更新本设计与测试，不能直接填当前时间。
- 点击后断线、进程重启或其他客户端并发 → 提交前意图持久化，重启只核对，不重复接受或发送；歧义保持 unknown。
- 用户在验收期间改变接管状态 → 按最新控制与 epoch 停止动作，结束时不恢复过时状态。
- 已接受请求无法通过版本回滚撤销 → 发布说明列明平台副作用；拒绝或过滤不执行 Delete／Block。

## Migration Plan

优先复用 schema 14 的版本化 runtime 状态及 browser journal；若实际证据需要新字段，使用可兼容可保留的扩展。服务器独立候选执行定向、全套单元及隔离 DOM／工作流验收。真实接收、实际回复、双方回执和生产部署分别记录。发布保留 0.1.26 app／browser 成对镜像，回退不删除新增意图或 unknown 记录。

## Open Questions

已取得入站公开 getter、请求入口和接受控件的实际证据；平台 SDK 区分 Received／Pending／Sent 及服务器序号。0.1.28.1 已确认真实接受后的空 composer、五条入站和实际上下文，真实模型回复、实际出站及双方回执仍须正常生产路径验收，不能以 SDK 和合成 DOM 代替。实现与隔离测试见 docs/新Chat私信处理.md。

## 2026-10-30 收件与回复分离

实际运行日志显示请求已可靠读取，但 reply-hours-closed 使其一直停在接受和入库前。按管理员要求，接收正常请求不再受回复时段、额度或回复时效限制，既有生成／发送闸门继续保留。原生解析返回最新出站／未知边界之后的连续可靠入站，最多二十条；每会话仍只生成一个最新请求候选，接受后重读全部事件。旧条目标记 privateHistoryOf 并以 merged 状态入库，最新条目保留 queued；重复原生 ID 不改写已有状态。平台上下文仍读取同会话全部可见可靠消息，测试核对实际模型参数包含前文而本次消息只有最新正文。schema 和 journal 格式不变，app／browser 必须成对发布。

实际接受后空编辑器显示语音入口，Send 只在正文非空时出现。接受回查使用正确会话、请求提示消失、唯一可编辑输入和可靠原生消息的正面组合，发送则在填入后重新要求唯一 Send；不重新接受未知意图。原生同会话的排队条目每轮仅保留最新普通候选，较早普通候选归为 merged 并保留正文及关联，人工重排／重写不被覆盖。

## 真实链路资源门禁修复

现网在80%左右浏览器内存下因旧公开unknown进入pending-recovery，prepare-round据此全局businessBlocked，导致不同通道的新私信不能进入模型。未收束出站仍禁止关闭会话和重发；非临界轮换只延后恢复，不阻止其他通道。达到95%、无法测量或已有明确资源故障时仍只回查。工作流保留按通道unknown、额度、时段、时效和身份门禁。

小补丁基于正式a0dba43，仅改BrowserResourceGuard并补实际guard与Workflow的组合回归。app正常构建，browser在原0.1.28.1镜像上只替换同源编译产物，保留旧内核、运行依赖、profile和journal，避免混入尚未发布的安全候选。构建经过共享锁、640MiB、无额外swap、单CPU，测试串行。回退保留0.1.28.1成对镜像，不恢复旧业务库或清除unknown；控制以管理员实时操作为准。

真实验收按授权只补处理昨天最新私信，前文进入上下文；临时扩大时效后恢复3小时，不修改其他发送限制。通过模型流水监控和保守峰价预留控制本次验证在一美元内。生产运行与公开出站未知分别记录，不能将私信成功当作所有X渠道均已验证。

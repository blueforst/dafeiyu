## Why

新用户的 X Chat 私信仍停留在消息请求中，普通收件箱为空时程序没有检查隐藏的请求入口。现有新 Chat 适配只观察正文和显示标签，不具备可靠的入站时间、发送者归属及发送回执，因此未进入回复队列。用户要求立即补齐正常新用户从请求到回复的处理闭环。

## What Changes

- 从平台实际提供的入口检查普通、请求及隐藏收件来源，分别记录是否检查成功；普通收件箱为空不代表没有请求。
- 根据实际平台样本建立版本化消息契约，绑定账号、会话、发送者、稳定消息 ID、完整正文和可靠时间。证据不足时明确待处理原因。
- 在自动运行时，沿用现有广告过滤、骚扰冷却和遗忘保护，自动接受正常的一对一请求并入库；回复时段、额度及回复时效只限制生成和发送。前文进入动态和模型上下文，仅由最新一条触发回复。过滤、群聊或归属不明的请求保留，不删除或屏蔽。
- 请求接受使用持久意图和结果核对，暂停、接管、重复轮次及重启不重复操作；接受后重新读取，再进入原有队列与记忆流程。
- 补齐新 Chat 正常发送和原意图回查；只有与本次意图绑定的平台确认才确认成功，结果不明保持 unknown。
- 在现有动态、采集来源、日志及健康状态中准确区分未检查、被过滤、待人工、已接受、已入队及发送待回查。

## Capabilities

### New Capabilities

- `xchat-private-workflow`：新 Chat 请求发现、规则过滤、接受、可靠入站读取与持久发送回执闭环。

### Modified Capabilities

无。保留现有公开消息、限额、时段、身份关联、记忆及 unknown 语义。

## Impact

涉及 `chat-dom`、浏览器 RPC／传输、工作流、消息分级及采集诊断，按证据需要增加私信请求持久状态。高负载构建和测试在服务器隔离目录执行。真实平台接受请求、发送、模型费用与生产发布分别保留证据；旧公开 unknown 不因本次变更被清空或重发。回退使用现有 0.1.26 成对镜像，已经接受的联系人属于平台状态，不能通过镜像回退撤销。

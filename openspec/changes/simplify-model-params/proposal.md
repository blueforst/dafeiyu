# 模型参数精简提案

## Why

管理员 2026-10-29 反馈：模型配置页的“回复长度上限”和“超时”没有意义，输出上限应该只受账号限制。以下对照本机源码 `746ba7e` 核对。

- **回复长度上限与账号字数限制重复。**
  - 每个模型都有一项“回复长度上限”，默认 4096 token、范围 64–8192，作为每次正式请求的 `max_tokens`。
  - 回复实际能发多长，已经由 X 账号的发帖权限决定：普通账号 280 加权字符，Premium 长帖另有上限。这条限制写在提示词的渠道规则里，发送前还会校验（见 `add-account-aware-post-limits`）。
  - token 上限只会在模型写到一半时截断。截断的回复以“返回不完整”失败，并不能让回复变短。
- **超时不需要用户设置。**
  - 每个模型的“超时”默认 60 秒、范围 1–180 秒。它只是防止接口卡死的保护措施，用户很难判断该填多少。
  - 填小了会让开启推理的请求无故失败；整轮处理另有无人值守健康的软、硬超时兜底。

## What Changes

- **模型参数只剩推理强度。** 模型库的“编辑模型参数”窗口删除“回复长度上限”和“超时”两项；无法识别的模型仍需填写上下文长度和是否支持推理。
- **输出上限取模型自身最大值。**
  - 正式请求的输出上限取该模型自身允许的最大输出，不再人为截短。目录中识别不到的模型按 8192 token。
  - 回复长度只由 X 账号的发帖限制约束，现有提示词与发送前校验不变。
  - 如果“输入加最大输出”可能超过上下文长度，按上下文长度自动收小，避免接口拒绝。
- **内部固定保护时限。** 每次模型请求固定最长等待 180 秒，不在页面显示，也不可配置；整轮处理仍受无人值守健康的软、硬超时约束。
- **内部任务保留各自的小上限。** 连接测试、虚构日程等内部请求原本就有自己的输出上限，不受本提案影响。
- **旧配置兼容。**
  - 已保存的模型参数和配置文件中的 `maxTokens`、`timeoutMs` 照常读取，但不再生效；下次保存时去掉这两个字段。
  - 接口收到这两个字段时忽略，不报错。
- **项目约定更新。** `openspec/config.yaml` 中“默认 4096 token”的约定改为“回复请求输出上限取模型自身最大值”。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `model-configuration`：修改主规格的“请求额度与未知价格”；修改 `simplify-panel-activity-feed` 中的“服务商模型列表”和“既有模型配置迁移”；新增“模型请求保护时限”。

本提案应在 `simplify-panel-activity-feed` 之后归档。它与 `convert-trigger-cards-to-skills` 互不依赖，二者修改 `model-configuration` 中不同的需求。

## Impact

- **代码**
  - 参数与校验：`src/settings.ts`（`PanelModel`、`toConfigModel`）、`src/model-library.ts`（`LibraryParams`、默认值、校验、比较）、`src/model-routes.ts`、`src/config.ts`（配置文件校验）、`src/types.ts`。
  - 请求：`src/model.ts`（输出上限与固定时限）、`src/persona-replay.ts`（模型快照字段）。
  - 前端：`public/js/views/model.js`、`public/js/views/model-form.js`。
- **数据**：不新增数据库迁移；面板设置中的旧字段在下次保存时移除。
- **模型请求**
  - 回复不再因 4096 token 被截断。开启推理时，思考也不再挤占输出上限。
  - 每次请求的计费只按实际生成的 token，`max_tokens` 变大本身不增加费用。
  - 模型失控、写出超长内容时，单次花费的上限变为模型自身的最大输出，而不是 4096 token；超长回复仍会被现有字数校验拦下，不会发出。
- **超时**：原来设成 60 秒的模型，现在最多等 180 秒才判定超时。
- **不包含**：按用途分别设置输出上限或时限、修改连接测试的判定方式（见 `convert-trigger-cards-to-skills`）。
- 本次只创建规划文件。构建和测试在服务器隔离环境执行，生产发布另需授权。

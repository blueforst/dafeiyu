# 正常流程试聊规格（对话排版改版增量）

## MODIFIED Requirements

### Requirement: 本轮诊断

每一轮 MUST 在对话中显示所用人设和读取的卡片；分级结果、召回条数、耗时和费用 MUST 在该轮被鼠标悬停、获得键盘焦点或被选中时显示在回复下方；模型、输入和输出 token MUST 显示在右栏“本轮详情”中，MUST NOT 在对话中常驻。点击某一轮或它的“详情”后，右栏“本轮详情” MUST 显示：人设名称与修订号、分级档位与原因、合并条数、日程时段、读取的触发卡及理由、工具调用次数与上限、提示词提醒、模型与调用次数、耗时、字数校验和格式标记、本轮实际召回的记忆。“提示词”标签 MUST 按实际请求顺序显示各提示词分段及其属于稳定前缀还是动态内容，并显示每次读取返回的卡片内容。“记忆”标签 MUST 分公开身份和私信身份显示该测试用户当前的长期记忆、近期往来、距下次整理的进度和骚扰计数，以及只读的角色经历。任何展示都 MUST NOT 包含密钥。

#### Scenario: 查看某一轮的提示词
- **WHEN** 管理员点击第三轮回复并切换到提示词标签
- **THEN** 右栏按顺序显示该轮的系统层和消息层分段，包括触发卡目录、当时召回的记忆和日程，以及读取返回的卡片内容，不含任何 Key

#### Scenario: 没有读取卡片
- **WHEN** 一轮回复没有读取任何卡片
- **THEN** 对话中该轮的人设名旁没有卡片标签；右栏详情显示“未读取触发卡”，工具调用 0 次

#### Scenario: 悬停查看本轮数据
- **WHEN** 管理员把鼠标移到一轮已完成的回复上
- **THEN** 回复下方出现分级、召回条数、耗时和估算费用；移开后这行隐藏，对话中始终不显示模型名和 token 数

## ADDED Requirements

### Requirement: 试聊对话细节

试聊对话 MUST 在统一对话流排版之上满足以下规则。消息渠道与上一条不同时，MUST 显示一条分隔线并注明切换到的渠道；对话的第一个时间分隔同时注明渠道。只有被合并、作为上文、仍待处理或所在轮次失败、取消的消息，才在气泡下方显示对应的简短标记；已完成轮次中的本轮消息 MUST NOT 显示“待处理”。读取了卡片时，MUST 在人设名旁显示卡片标签。没有回复、被过滤、骚扰冷却、正常流程不会发出、格式标记、可能提及私信内容、失败或取消的原因 MUST 直接显示在该轮中。有回复正文时，操作行 MUST 提供“复制”；失败或取消的轮次提供“重试（会再次计费）”。记忆整理结果 MUST 以居中的简短提示显示。

#### Scenario: 已回复的消息
- **WHEN** 测试用户发出一条公开消息，角色回复成功
- **THEN** 这条消息的气泡下方没有“待处理”，回复下方有“详情”和“复制”，对话中没有模型名和 token 数

#### Scenario: 切换到私信
- **WHEN** 测试用户先在公开聊了两轮，再发一条私信
- **THEN** 这条私信前出现一条分隔线，注明时间和“切换到私信”；之后连续的私信之间不再出现分隔线

#### Scenario: 角色选择不回复
- **WHEN** 模型以连续催促为由对一轮私信选择跳过
- **THEN** 该轮在人设名下方直接显示“没有回复”及原因，不需要悬停或打开详情

#### Scenario: 回复不会发出
- **WHEN** 一轮公开回复超过账号允许的字数
- **THEN** 该轮显示回复正文，并直接在正文下方显示“正常流程不会发出”及原因

#### Scenario: 失败的一轮
- **WHEN** 一轮因模型服务错误失败
- **THEN** 该轮直接显示错误原因和“重试（会再次计费）”，本轮消息的气泡下方标记“待处理”

#### Scenario: 复制回复
- **WHEN** 管理员点击一轮回复下方的“复制”
- **THEN** 回复正文进入剪贴板并提示已复制；浏览器不允许写入剪贴板时提示无法复制，正文保持可选中

### Requirement: 试聊输入区

试聊输入区 MUST 是主区底部的一个圆角输入框：文字输入随内容增高，到上限后在框内滚动，MUST NOT 提供拖拽调整大小。人设选择、“公开｜私信”切换、“先攒几条再回”开关和发送按钮 MUST 位于输入框内底部一行；有待处理消息时，同一行 MUST 出现“让角色回复”（公开为“回复下一条”）并显示待处理条数。本轮处理期间，发送按钮 MUST 变为停止按钮，点击即取消本轮，其他控件按原规则禁用。“正常流程 · 当前模型 · 不发到 X · 不占额度 · 会计费”的说明 MUST 显示在输入框下方。按回车 MUST 发送，Shift 加回车换行，输入法组字期间按回车 MUST NOT 发送。所有控件 MUST 有可读名称并可用键盘操作；窄屏下控件可以换行，但 MUST 完整可用。

#### Scenario: 回车与换行
- **WHEN** 管理员输入一行文字后按 Shift 加回车，再输入一行并按回车
- **THEN** 两行文字作为一条消息发出，输入框清空

#### Scenario: 输入长文字
- **WHEN** 管理员粘贴二十行文字
- **THEN** 输入框长高到上限后在框内滚动，主区对话仍然可见，输入框没有拖拽角

#### Scenario: 先攒两条私信
- **WHEN** 管理员打开“先攒几条再回”，切换到私信，连发两条消息
- **THEN** 输入框底部一行出现“让角色回复 · 2 条”，两条消息在对话中标记“待处理”

#### Scenario: 处理中停止
- **WHEN** 一轮正在处理，管理员点击停止按钮
- **THEN** 本轮被取消并显示原因，消息回到待处理，停止按钮恢复为发送按钮

#### Scenario: 手机宽度
- **WHEN** 管理员在 375px 宽的浏览器中打开试聊
- **THEN** 输入框内的控件可以换行但全部可操作，页面没有整体横向滚动

# 动态增量规格（对话排版改版）

## MODIFIED Requirements

### Requirement: 动态时间线内容

面板首页 MUST 以“动态”工作区展示当前工作账号的互动：

- **左栏**按会话列出：每个会话是一个身份（公开身份或私信会话），另有一个固定的“角色帖”会话汇集早安帖和晚安帖。会话按其中最新一条记录的入库时间倒序排列，状态变化不改变顺序；私信会话没有对方名字时，以“私信”加会话标识末四位命名；每项显示头像、名称、最近时间、状态和最后一条摘要。状态取该会话中最需要处理的一条：待回查优先，其次是发送失败、草稿、等待发送，没有待处理时显示最近一条的状态。
- **主区**选中会话后按时间正序显示往来，并按统一对话流排版：
  - 对方消息显示原话；渠道在主区页头注明，分级和时间在悬停、聚焦或选中时显示，完整信息在右栏；
  - 角色的回复与私信显示正文、状态，已发送的带在 X 上查看的链接；
  - 草稿显示为可编辑的正文和草稿操作；
  - 跳过、过滤、合并、冷却和发送失败显示原因，并在规则允许时提供“重新入队”；
  - 角色帖会话显示帖子正文、任务名称和出站状态，以及停用、错过、取消等没有发帖的任务记录。

所有外部文本 MUST 按纯文本显示。动态 MUST NOT 显示其他工作账号的数据，也 MUST NOT 把同一个人的公开身份和私信会话合并为一个会话。

#### Scenario: 查看已发送回复
- **WHEN** 一条公开回复已确认发送且回执带有平台链接
- **THEN** 该身份的会话中依次显示对方原话和回复正文，回复标为“已发送”并带在 X 上查看的链接

#### Scenario: 模型选择跳过
- **WHEN** 模型对一条入站消息选择跳过
- **THEN** 会话中该消息之后显示“已跳过”和跳过原因，不显示空白回复

#### Scenario: 查看早安帖
- **WHEN** 早安任务已提交一条公开帖子
- **THEN** “角色帖”会话显示任务名称、帖子正文和出站状态，左栏该会话移到最近活动的位置

#### Scenario: 数据库含其他账号记录
- **WHEN** 数据库中存在其他工作账号或未知归属的消息
- **THEN** 会话列表和往来只包含当前工作账号的记录

#### Scenario: 原话含 HTML 片段
- **WHEN** 对方原话包含 HTML 标签或脚本片段
- **THEN** 页面按原样文本显示，不执行或解析其中内容

#### Scenario: 同一个人的公开与私信
- **WHEN** 同一个 X 用户既在公开回复中提及角色，又发来私信
- **THEN** 左栏分别出现该用户的公开身份会话和私信会话，两者的往来互不混合

#### Scenario: 对方消息不逐条显示渠道
- **WHEN** 管理员打开一个公开身份会话
- **THEN** 主区页头注明“公开”，每条对方消息只有原话气泡，悬停后才显示分级和时间

### Requirement: 条目细节默认收起

主区的每条往来 MUST 默认只显示正文、状态，以及需要关注时的原因和可用操作；时间、分级、提交与回执等摘要 MUST 在该条被悬停、获得键盘焦点或被选中时显示。管理员选中一条后，右栏显示该条的状态、分级、所用人设与修订、触发命中、生成与校验结果、出站与平台回执、错误原因，以及关联的模型调用（用途、模型、耗时、token、费用估算或未定价）。右栏可以收起。细节 MUST NOT 显示提示词正文或密钥。

#### Scenario: 查看一条回复的详情
- **WHEN** 管理员选中一条已发送回复
- **THEN** 右栏显示该回复关联的调用耗时、token 和估算费用以及平台回执，费用与设置页计费项的同一流水一致

#### Scenario: 发送失败
- **WHEN** 平台明确拒绝一条回复
- **THEN** 该条显示“发送失败”，选中后右栏显示拒绝原因

#### Scenario: 收起右栏
- **WHEN** 管理员收起右栏后刷新页面
- **THEN** 右栏保持收起，主区占满宽度；再次选中一条往来时不自动展开

#### Scenario: 悬停查看提交与回执
- **WHEN** 管理员把鼠标移到一条已发送回复上
- **THEN** 回复下方出现分级、提交时间和回执状态；移开后隐藏

## ADDED Requirements

### Requirement: 动态往来排版

角色回复或私信的状态 MUST 显示在人设名旁，状态名称沿用现有名称。“已发送” MUST 以不加底色的弱化样式显示；草稿、等待处理、生成中、等待发送、发送中、待回查、发送失败等需要关注的状态 MUST 以对应颜色显示，并在正文下方直接说明原因，例如回复时段已关闭、等待回执核对。草稿 MUST 显示在一个可直接编辑的圆角框中，“重写”（标明计费）和“发送”按钮及发送说明位于框内底部；编辑框随内容增高，MUST NOT 提供拖拽调整大小。“取消发送”“重新入队”“在 X 上查看”“查看原文”等操作 MUST 位于该条下方的操作行，按原规则出现。人设名取该条记录的人设，没有记录时显示当前账号 handle。左栏会话状态 MUST 以颜色文字显示，需要处理的状态与普通状态颜色不同。

#### Scenario: 审核草稿
- **WHEN** 管理员在草稿框中改了一处文字后点击框内的“发送”
- **THEN** 按原规则以修改后的文字批准，提示已批准等待发送，该条状态变为“等待发送”

#### Scenario: 已发送的回复
- **WHEN** 一条回复已确认发送
- **THEN** 人设名旁显示不带底色的“已发送”和小勾，操作行有“在 X 上查看”

#### Scenario: 等待发送说明原因
- **WHEN** 一条已批准的回复因回复时段关闭而等待
- **THEN** 人设名旁显示带颜色的“等待发送”，正文下方写明回复时段已关闭，操作行有“取消发送”

#### Scenario: 待回查
- **WHEN** 一条回复提交后没有拿到回执
- **THEN** 人设名旁显示告警色的“待回查”，正文下方直接说明需要核对回执，没有“发送”或“重新入队”按钮

#### Scenario: 草稿框长文字
- **WHEN** 草稿正文有十行
- **THEN** 草稿框随内容长高，框内底部仍是“重写”和“发送”，框没有拖拽角

#### Scenario: 旧记录没有人设
- **WHEN** 一条早期回复没有记录所用人设
- **THEN** 该条头像与名称显示当前账号 handle，不显示其他人设的名称

# 试聊与动态对话排版改版提案

## Why

管理员 2026-10-29 反馈：人设页的试聊对话界面“太丑了”，主要是排版问题，希望参考 DeepSeek Harness 的聊天页美化；选定试聊方案后又要求“动态页也优化一下”。对照 0.1.19.1 验收截图（`部署记录/2026-10-29-0.1.19.1/green/` 下的 `persona-workspace-ui-acceptance/persona-chat-u1-light-1440.png` 与 `feed-workspace-ui-acceptance/feed-feed-c-x-anna-light-1440.png`）和本机源码，两页的问题相同：

1. **每条消息上下都挂一整行灰字。**
   - 试聊：用户消息上方是“公开 · 时间 · 状态”。回复上方是“人设 · 状态 · 分级 · 召回 · 卡片 · 毫秒”，下方是“模型 · token · 费用”。
   - 动态：对方消息上方是“公开 · 普通 · 正常消息 · 时间”。回复上方是“已发送 · 确认于… · 历史回执未记录 · 查看详情”。
   - 两页都是正文不突出，一屏只放得下三四轮。
2. **选中时整块刷成品牌浅蓝。** 试聊把用户消息和回复都套上 `.ws-turn.selected`；动态给选中回复加 `--ws-brand-soft`，宽度铺满对话列。
3. **输入和审核区拼凑感强。**
   - 试聊：上方是两个大号原生下拉框和一个复选框，中间是带拖拽角的方框。这与 2026-10-28 批准的草图不一致，草图里输入区是一个圆角框，控件都在框内。
   - 动态：草稿是带拖拽角的方框，下面接黑色通栏“发送”和白色通栏“重写”。
4. **头像看不清。** 动态左栏头像和试聊会话列表图标用 `--ws-brand-soft` 底配 `--ws-brand` 字；动态截图里是深蓝底上的蓝色字母，几乎不可读。
5. **右栏名称和数值上下错位。** 通用样式 `.row` 用 flex 加 `align-items:start`，数值列另带 `.pre-wrap`，两列没有对齐，数值看起来比名称低半行。
6. 试聊截图中已回复的消息仍显示“待处理”。这张截图用的是模拟接口；真实后端处理后会把消息改为已处理、上文或合并，生产不一定出现。但界面只看消息自身状态，没有结合所在轮次，模拟数据一不完整就会误导。

管理员先在两种试聊草图中选择 B“对话优先”：正文为主，统计数据收进“详情”和右栏，输入区改为大圆角框。之后确认了按同一思路改的动态页草图。两份草图合在 [design-mockup.html](design-mockup.html)。

## What Changes

- **两页共用的对话排版**
  - 对方或测试用户的消息只保留右侧气泡，不再挂渠道、分级、时间、状态行。
  - 时间改为分隔显示：第一条消息前、相隔五分钟以上或跨日时，在对话中间显示一次。
  - 角色一侧每条以人设名首字的圆形头像和人设名开头，正文行距加大。
  - 每条下方一排操作，至少有“详情”。时间、分级、耗时、费用、回执等摘要只在悬停、键盘聚焦或选中时显示，触屏只在选中时显示。
  - 需要关注的结果和原因始终直接显示。
  - 选中只给角色一侧加浅灰底，不再整行刷强调色。
  - 头像改用一组固定配色，按条目稳定取色，浅色和深色下文字都清楚。左栏会话头像同样修正。
  - 右栏凡是“名称—数值”成对显示的，名称与数值同一行对齐。
- **试聊**
  - 公开和私信来回切换时插入分隔线。读取了触发卡时，人设名旁显示卡片标签。
  - 回复下方：有正文时可“复制”，失败或取消时“重试（会再次计费）”。
  - 模型和 token 只在右栏显示。
  - 输入区改为灰色大圆角框，控件在框内，处理中发送变停止，说明文字移到框下。
- **动态**
  - 回复状态显示在人设名旁：常见的“已发送”只是灰色小勾；草稿、等待处理、等待发送、发送中、待回查、发送失败等上色，并在正文下方直接说明原因。
  - 草稿改为可直接编辑的圆角框，“重写（计费）”“发送”和发送说明都在框内。
  - 取消发送、重新入队、在 X 上查看、查看原文放进下方操作行。
  - 左栏会话状态改为彩色文字。
- **不改**：两页的处理流程、接口、数据、计费、筛选、分页和实时刷新；草稿批准、重写、取消、重新入队的规则；页头、右栏和记忆的内容；状态名称；人设模式、日程模式和设置页的外观。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `panel-design-system`：新增“对话流排版”“头像配色”“详情名称与数值对齐”三项要求，试聊和动态共用。
- `chat-test`：本轮诊断在对话中改为按需显示，模型与 token 只在右栏；新增“试聊对话细节”“试聊输入区”两项要求。
- `activity-feed`：“动态时间线内容”中对方消息不再逐条显示渠道、分级和时间；“条目细节默认收起”的摘要改为悬停或选中时显示；新增“动态往来排版”，规定状态、草稿框和操作行的呈现。

## Impact

- 前端共用：
  - `public/style.css`：新增对话流、头像配色、圆角输入框、右栏对齐的共用样式和变量，浅色、深色各一套。
  - `public/js/shell.js`：新增 `avatar()`、`divider()`、`reply()` 三个组件。`turn()`、`composer()`、`sideItem()` 的参数不变；`sideItem` 的 `icon` 改用头像配色。
- 试聊：`public/js/views/chat-test.js`。
- 动态：`public/js/views/feed.js`、`public/js/views/feed-workspace.css`。
- 测试：试聊相关五个界面套件中操作渠道下拉框的步骤改为点击切换按钮；动态相关套件中断言旧摘要行的步骤改为断言悬停摘要或右栏；新增两页的排版断言。保留原有业务断言。
- 文档：`docs/设计规范.md`（对话流、头像、圆角输入框、右栏对齐），`docs/人设与日程.md` 的试聊一节，`docs/后续提案实施.md` 的“三页面板与草稿”一节。
- 后端、数据库、接口、模型请求：无变化，也不需要真实模型调用。动态的人设名取自现有返回中草稿记录的人设，没有时显示账号 handle。
- 依赖与归档顺序：
  - `activity-feed` 的两项修改以 `redesign-feed-workspace` 的文字为基础，`panel-design-system` 的新增在 `add-persona-workspace` 之上，`chat-test` 的“本轮诊断”以 `convert-trigger-cards-to-skills` 修改后的文字为基础。本提案应在这三份之后归档。
  - `convert-trigger-cards-to-skills` 正在实施，它对 `chat-test.js` 和 `feed.js` 的前端改动尚未提交；本提案实施时在其之上进行，不得回退读取卡片和工具调用的展示。

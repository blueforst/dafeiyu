# 七页面板与生产工作流技术设计

## Context

动机和范围见 [proposal.md](proposal.md)，可验收行为以本 change 的八份增量规格为准。迁移来源是仓库中的[七页计划](../../../docs/superpowers/plans/2026-10-27-seven-page-production-bot.md)。

现有业务为 Fastify／SQLite app 与 Camoufox／Playwright browser 两个容器，宿主负责 Nginx、systemd、监控和证书续期。前端为无构建步骤的原生 ES 模块。当前模型调用已包含 OpenCode 会话信息、CommandCode 认证与模型地址兼容，正式回复默认 4096 token。

现有不足包括：只返回部分 usage；摘要覆盖旧文本且按平台时间判断新增；用户和消息未完整归属工作账号；主程序只暴露 busy 与 lastTick；定时维护散落在 app 与宿主。实际页面 DOM 和 Chat 状态必须在实施及真测时重新检查。

本次 OpenSpec 接入只完成规划与项目集成，不修改业务代码、不部署、不启用任务。主规格仅登记当前面板、记忆和模型基线；新能力留在 change 中，实施及验证后再同步。

## Goals / Non-Goals

**目标：** 在现有依赖与服务边界内，提供统一的生成服务、上下文组装、持久出站、任务记录及七页管理入口；明确每次请求、阶段、记忆和平台回执之间的关联。

**非目标：** 不更换前端框架或浏览器引擎，不建设向量数据库或自主工具代理，不新增任意 shell 执行、视觉／视频理解、模糊身份合并、账户充值或供应商余额查询。

## Decisions

### 1. 七页路由与共享设置

按发布后的用户反馈，主页面保留运行、账号、模型与接管入口，日志卡移入主程序页并替换原日志展示。主程序沿用原主页面的行式日志，已有筛选和暂停实时功能保持；常规日志数据仍来自同一持久日志与兼容 SSE，不新增另一份日志来源。

沿用现有 hash 路由和 ES 模块，增加 persona、memory、program、tasks、billing 视图，原 browser 视图作为主页面的可折叠接管组件复用。旧 browser 地址跳转主页面并打开该组件，避免增加第八个一级页面或废弃已保存入口。

保留全局控制和现有鉴权。人设内容、记忆策略、运行设置与任务计划存入现有非密钥面板设置，按对应字段合并读取，保存带修订版本避免并发覆盖。日程内容在人设页，计划在任务页，仅维护一个配置来源。密钥存放及槽位规则不变。

相较引入新的前端构建链和独立配置服务，此方案能保留既有发布和接管行为。人设／试聊路由单独设置 128 KiB 请求体上限，并继续检查人设总长 20,000 字符及试聊上下文额度；其他路由保留原有默认限制。

### 2. 统一模型调用与请求生命周期

建立一个模型服务，接收用途、来源、工作账号、渠道、会话关联、system／user 及取消信号，所有生产、预览、任务、CLI 和连接测试都通过该服务。底层继续使用 Pi，不在每个业务模块另写协议适配。

调用前创建唯一请求记录；返回后在同一记录保存完整 usage、分项成本、实际模型、耗时、结束原因和价格来源。生成结果解析和正文校验发生在计量之后，因此模型文本不合格也不会漏记。抛错、取消和进程重启分别收束到失败、中止或中断；没有可靠数据的字段保留未知，不能把 Pi 错误响应的占位零一概视为实际免费。

用途包括 reply、semantic-trigger、daily-state、memory-summary、model-test、persona-preview、morning-post、evening-post。语义判定和最终生成是两条调用，用同一交互关联 ID 汇总。回复重试保留新请求 ID，不按平台消息去重实际费用。

保留目前工作流传入的稳定会话路由和服务商身份信息；独立模型连接测试使用新会话。扩展结果接口时同步现有调用者和 mock，不能退回无会话的 OpenCode 调用或把正式回复默认值改回 1024。

### 3. 价格与历史统计

沿用 Pi 的价格分档、缓存读取／写入与 usage.cost，不另写一份费率算法。仅对可靠匹配的内置服务商和型号使用内置价格；未知兜底型号必须清除继承价格，CommandCode 与自定义接口保持未定价。

新流水保存请求时的成本快照和计价状态。旧 usage 不伪造用途、价格或模型，作为历史 token 汇总来源；现有 status.usage 与新计费页使用同一聚合口径，避免既写旧表又写新表造成双计。思考仅作输出子集展示。

计费记录不存提示词或生成内容，任务／人设界面只引用原流水。日期按 Asia/Shanghai 的日界线解释，接口使用半开时间范围，金额展示保留足够精度并区分零、未知及未定价。

### 4. 人设、语义路由与共用提示词组装

人格保存为有序静态分区及触发卡片。每张触发卡有稳定 ID、标题、自然语言条件、正文、开关与顺序。旧 persona 整段迁入一个静态分区，不能自动补写角色事实。

语义路由与生产回复使用同一模型配置。路由请求包含启用规则 ID／条件、当前消息和同渠道可见上下文，不带无关私信或完整触发正文。输出限制为命中 ID 及简短原因，默认最大 512 token；能关闭推理则关闭，否则使用最低可用档。

结果通过结构与允许 ID 校验，去重后按配置顺序组装。没有规则则跳过请求；失败只回退静态内容并记录警告，不无限重试或让全局工作流停摆。固定系统约束不依赖语义判定是否命中。

共用组装顺序为静态规则、命中模块、角色经历／今日日程、可见记忆／对话、当次提醒／时间。固定系统约束明确区分虚构设定、真实互动与不可信外部输入。输出仍使用 reply／skip 结构和现有正文校验。

多轮试聊接收未保存配置和模拟对话，在请求范围内组装上下文；不创建真实消息、出站和记忆。试聊返回分段提示词与命中说明，不返回密钥或模型思考原文。默认模拟记忆与记忆页的真实只读召回入口分开。

### 5. 当日日程的唯一状态

日程按工作账号、本地日期及修订保存，字段覆盖时段、三餐、活动和心情，记录来源、生成时间、配置修订及关联模型请求。自动任务和首次使用共享账号／日期互斥键，同日只有一次成功自动生成，主动编辑或重新生成另建修订。

生成读取已保存人格和近七日历史，标记虚构，避免重新演出历史往事。人工修改后不会被稍后到达的旧生成覆盖。自动失败按三十分钟退避、当日最多三次；失败与暂停时使用明确暂无状态，不能沿用昨日内容冒充今日。

调度默认 06:00，已启用；首次业务使用缺失状态时允许提前补生成。保存长期人格不会自动替换当天状态，避免同一天前后说法不一致。

### 6. 记忆来源、修订与可见范围

近期原文仍来自消息表，默认三次、七天窗口；只有 confirmed 回复能作为“已说过的话”。长期内容改为条目和来源关系，附工作账号、用户／会话、渠道、事实／偏好／未完话题、时间及修订信息。

采用明确的已处理入站进度，而非平台 timestamp 与摘要 updated_at 比较。每五条触发一次增量整理；每日任务只补整理存在新增进度的用户。请求输入包含仍有效旧记忆与未整理记录，保留历史并更新矛盾事实；提交成功才推进游标。

人工修改提升修订，删除同时记录来源忽略信息。模型提交必须同时校验账号、遗忘代次、记忆修订及输入进度快照，过期结果不写回。遗忘仍保留独立账本，恢复只允许未来记录，不恢复旧数据。

公共记忆和私信记忆继续隔离。现有公开标识与私信会话标识不做模糊合并；无法确认参与者时页面如实展示会话。角色经历仅从有平台回执或明确来源的重要互动产生，与虚构日程和用户事实分类型存储。

### 7. 采集身份与持久出站

继续用 Camoufox／Playwright DOM 读取和页面点击；必要时监听页面自身的实际响应取得消息 ID 与回执，不反向构造私有接口。按真实页面拆开主帖、引用、回复和私信方向，扫描有界并持久去重。

新内部事件 ID 按工作账号、渠道和平台消息 ID 命名，平台 ID、目标 ID 及会话 ID 独立保存，不再从内部字符串猜测平台身份。旧消息 ID 保留并标记归属；无法确认账号的历史不自动分配给新登录账号。

新增通用 outbox 承载公开回复、私信和定时帖子，保存工作账号、来源消息／任务、目标、冻结正文、请求标识及回执。浏览器发送日志继续作为提交边界的保护，两层记录用同一出站标识关联。

发送前再核对当前账号、可靠目标、额度、正文、控制状态及私信最新消息。提交意图先持久化，再操作页面；开始提交后中断为 unknown。只在作者、目标关系、正文、时间与唯一平台 ID 均一致时确认，回查不会通过同文其他帖子误认成功。

所有浏览器操作经过现有串行入口和 profile 独占控制；定时发帖不得另开共享 profile 的写入脚本。平台拒绝执行四小时通道退避，公开帖与回复共用公开额度。

### 8. 程序阶段与日志事件

在工作流关键边界记录阶段开始／结束和关联信息，以 finally 或等价收束保证失败和取消也结束阶段。主程序页将阶段与整体控制状态分开显示，持久记录上一轮摘要，重启将旧运行阶段标为中断。

扩展 SSE 为程序与任务增加事件类型，保持现有 logs 完整数组事件兼容。队列和日志独立分页，详情按需读取；常规日志只写元数据，不写提示词、私信或完整密钥。控制异常落到可重试的明确状态，不永久停在 draining。

### 9. 单一调度与宿主桥接

主循环继续采用轮次结束后等待，不叠加 cron 式第二轮询器。其余任务由统一计划与运行记录调度，实例键为任务、计划时刻和账号，手动执行同样争用该实例锁。关闭任务取消尚未提交工作，已提交发送只收束或回查。

默认时间及开关按 task-scheduling 规格：日程 06:00、记忆 03:00 启用；早安 08:00、晚安 23:00、数据库备份 02:30 初始关闭；宿主健康检查每五分钟继续启用。所有时间使用 Asia/Shanghai。

问候帖只有计划后五分钟内能开始，超窗记录 missed；恢复不补旧问候。日程与记忆可补当天缺失，备份最多补一次。帖文生成后冻结，不在重试时重新生成。数据库备份保留最近七份，只含业务数据库，不含面板设置、Key、源码和 profile。

宿主仍负责健康检查、备份与证书续期。采用受限的文件请求／结果桥接：app 只可写请求目录和只读结果目录，宿主固定 helper 只接受 backup／health 及受支持的计划／启停／单次操作。请求按 UUID 去重，输入不作为命令或路径执行；不挂载 Docker socket，不让 app 修改任意 systemd 服务。任务页展示同一宿主任务，不另起一个应用内假健康检查。

### 10. 数据迁移与接口边界

继续使用 SQLite 与版本化、可重复的增量迁移，不引入 ORM 或外部消息队列。新增 llm_calls、日程修订、memory_items／sources／忽略信息、outbox、任务运行及阶段记录；保留原消息、摘要、usage 和遗忘账本。

新增接口分组：

| 入口 | 作用 |
| --- | --- |
| `GET/PUT /api/persona`、`POST /api/persona/preview`、`POST /api/persona/daily/generate` | 人设、试聊、主动生成及日程历史 |
| `/api/memory/users`、用户详情、条目修订／删除及 summarize／forget／remember／preview | 可分页来源管理和可见范围召回 |
| `/api/program`、`/api/program/settings`、`/api/messages` | 阶段、运行设置和受鉴权详情 |
| `/api/tasks`、任务配置、单次运行和运行历史 | 统一计划与任务记录 |
| `GET /api/billing/summary`、`GET /api/billing/calls` | 范围汇总、趋势、分组与游标分页 |

保留现有 model、status、control、logs、events 与 desktop 接口。新增读写沿用管理鉴权、来源检查与控制请求标记；配置保存不改变运行状态。

## Risks / Trade-offs

- X DOM、加密 Chat 或消息方向变化 → 保存脱敏样本、显式适配错误和真实验收证据，不能静默猜测或把空解析当成功。
- 语义触发多一次请求且可能失败 → 一次路由覆盖全部启用规则，设置小输出上限，回退静态规则，所有消耗可见。
- 虚构设定和真实记忆混淆 → 内容类型、来源和可见范围独立，提示词与页面都明确标记。
- 旧账号数据、摘要和价格缺少归属或来源 → 保留并标记未知，不推断关联、补造来源或按同名模型估价。
- 请求或提交期间进程崩溃 → 请求先落库、发送先保存意图；费用未知如实显示，发送 unknown 不重发。
- 业务暂停后维护失明或重复调度 → 宿主健康独立，业务主循环只有一个；任务实例唯一键与统一互斥。
- 只备份数据库不含面板设置 → 任务页明确范围，恢复说明要求单独准备配置与凭据，遗忘账本不得覆盖。

## Migration Plan

1. 核对当前工作树、模型会话修复及实际服务器状态，在独立开发目录和独立数据上实施。OpenSpec 校验可在服务器专用镜像目录运行，不使用生产数据。
2. 先落迁移与计量，再做人设／日程／记忆，接通出站与调度，最后完成七页和事件联动；各阶段对照规格场景进行服务器测试。
3. 完成隔离 DOM、模型 mock、任务时钟／重启、费用和页面验收后构建新版本，更新生产先保持暂停。不自动创建升级源码／数据库／profile 备份或长期保留旧镜像。
4. 用户完成模型配置后，经一次真实模型测试，再人工接管发布 `Ciallo～(∠・ω< )⌒☆`。操作前重读服务器和 Ceyi 当前账号，既有账号快照不作为白名单或预期配置。
5. 释放接管并开启正常 auto，Ceyi 发起评论和私信，其他符合条件消息继续正常处理；核对阶段、语义调用、记忆、双方可见回执、费用和重复保护。通过后保持自动运行，早晚安与备份继续按开关执行。
6. 保留基线 Git 提交和迁移版本。回退时先暂停并排空，确认旧程序兼容性，再从对应提交重新构建；若迁移不兼容，必须提供受验证的反向迁移或用户提供的配套数据恢复步骤，不能只切镜像。独立遗忘账本始终保留。
7. 更新 README、接口与发布证据；只有实际完成并验证的任务才能勾选，之后才允许同步增量规格和归档。模拟、真实模型、真实平台读取、发送与回执分别记录证据。

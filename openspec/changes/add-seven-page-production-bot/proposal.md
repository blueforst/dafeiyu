# 七页面板与生产角色工作流提案

## Why

当前面板只有概览、模型和浏览器入口，LLM 仅记录部分 token，人设与记忆缺少可视化管理，生产收发和后台任务也缺少统一的阶段、回执与成本追踪。需要把已确认的七页设计整理为可验收的功能契约，在现有服务商兼容和账号控制基础上完成生产闭环。

## What Changes

- 扩展为主页面、模型、人设、记忆、主程序、定时任务、计费七页，浏览器接管并入主页面，保留旧入口兼容。
- 新增静态提示词、LLM 语义触发、多轮模拟试聊与 LLM 虚构日程，展示命中规则、提示词、日程历史和调用费用。
- 改进近期及长期记忆，提供来源、修订、删除、遗忘、角色经历与只读召回预览，防止私信泄露和旧数据复活。
- 完善 Playwright 评论、私信和消息请求的采集、身份与目标校验、持久出站及唯一平台回执；真实验收不增加账号白名单。
- 展示主程序各处理阶段、耗时、队列、退避和日志，统一主循环、早晚安帖、日程、记忆、数据库备份和健康检查的管理与执行记录。
- 日志集中放在主程序页，沿用原主页面的时间／事件／说明行式展示，替换原主程序日志列表；主页面不再重复显示日志。
- 所有 LLM 用途统一计量，只采用 Pi 内置价格；未知价格显示未定价，保留失败和中止时实际返回的用量。
- 采用兼容性新增和分阶段验证，不把本次 OpenSpec 接入当成业务实现或生产发布。

## Capabilities

### New Capabilities

- `persona-management`：静态与语义触发提示词、热更新、多轮试聊及运行预览。
- `role-daily-state`：LLM 虚构角色日程、同日一致性、历史和失败恢复。
- `x-message-workflow`：正常生产消息采集、账号归属、互斥发送和可靠回执。
- `workflow-observability`：主程序阶段、队列、结构化日志及状态恢复。
- `task-scheduling`：周期任务、早晚安发帖、补执行策略及宿主维护任务管理。
- `llm-usage-billing`：全部 LLM 用途、完整 token、历史估算和计费页。

### Modified Capabilities

- `panel-navigation`：由三页扩展为七页，接管移入主页面并保留旧浏览器地址兼容。
- `conversation-memory`：增加近期时间窗口、可靠增量整理、带来源的长期记忆和可视化管理，保留并加强遗忘约束。

`model-configuration` 是本轮不改变的基线能力，现有服务商、OpenCode 会话路由和 4096 token 默认值必须保留。

## Impact

- 影响原生前端路由与视图、Fastify 管理接口、模型服务、工作流、浏览器 transport、SQLite 数据与宿主任务桥接。
- 新增人设、记忆、程序、任务及计费接口；既有控制、鉴权、SSE 和模型接口保持兼容。所有构建及自动化验收在服务器隔离环境执行。
- 原七页计划保留为来源；OpenSpec 增量规格与设计成为后续变更入口。主规格仅记录已有行为，待实现并验证后才同步新能力。
- 不接入视觉／视频、LLM 自主操作浏览器、跨渠道模糊身份合并、手工单价、充值收款或任意 shell 执行。
- 生产真测沿用用户授权的 Ciallo 测试帖及本机 Ceyi 互动，通过后保持正常自动运行；本次仅整理提案，不发送消息或改变运行状态。

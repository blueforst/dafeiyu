# 主程序可观测性增量规格

## Purpose

让管理员在主程序页看到当前工作流的真实处理阶段、持续时间、排队情况与关联日志，区分正常等待、限速退避、正在发送和异常中断，能够从一条消息追踪到其生成调用和平台回执。

## ADDED Requirements

### Requirement: 实时阶段与关联信息

系统 MUST 展示等待、身份检查、公开／私信采集、排队、上下文、记忆召回、语义判定、生成、发送、回查、整理、退避及错误阶段，包含开始时间、持续时间、轮次和可用关联 ID。

#### Scenario: 一条消息进入语义判定
- **WHEN** 工作流开始该消息的触发规则判定
- **THEN** 主程序页显示语义判定阶段、耗时和该消息的关联信息

### Requirement: 队列和运行设置

主程序页 MUST 显示队列状态、最近完成轮次、下次循环、通道额度与退避，并允许配置正常运行模式和额度；轮询间隔只在任务页维护。

#### Scenario: 通道正在退避
- **WHEN** 某通道在退避时段内
- **THEN** 页面显示该通道的退避原因与结束时间，不把等待显示成无故卡住

### Requirement: 日志筛选与详情

系统 MUST 支持按级别、渠道、时间和关联 ID 查看有限分页日志，允许暂停滚动及展开错误，并将日志与相应消息、调用或任务结果关联。

#### Scenario: 查看一次失败生成
- **WHEN** 管理员按关联 ID 筛选日志
- **THEN** 页面显示本次错误与关联调用，不混入其他请求的正文

### Requirement: 日志隐私与鉴权

常规日志 MUST 不包含消息正文、私信内容或完整密钥；消息详情与记忆原文必须沿用管理鉴权，仅在对应详情入口读取。

#### Scenario: 查看常规运行日志
- **WHEN** 系统采集或回复了一条私信
- **THEN** 常规日志仅展示处理元数据，私信正文不会出现在日志列表

### Requirement: 阶段与控制状态收束

系统 MUST 在成功、失败、中止和重启时结束或标明旧阶段；排空或控制失败后不得永久显示不可操作的 busy 或 draining 状态。

#### Scenario: 人工接管控制失败
- **WHEN** 排空后浏览器控制接口失败
- **THEN** 系统记录错误，页面提供可重试或明确暂停状态，不永久禁用控制

#### Scenario: 进程在生成期间重启
- **WHEN** 服务重新启动
- **THEN** 上一阶段显示为中断，系统保持启动暂停语义，未完成发送按未知结果处理

### Requirement: 状态事件向后兼容

系统 MUST 实时更新程序与任务状态，并保持现有状态、控制与日志事件消费者的兼容性。

#### Scenario: 旧日志订阅继续连接
- **WHEN** 已有客户端只订阅原日志事件
- **THEN** 新增阶段和任务事件不破坏其日志读取

# 对话记忆增量规格

## MODIFIED Requirements

### Requirement: 近期互动上下文

系统 MUST 默认向回复生成提供七天以内最近三次已处理互动中的入站原文，只把已确认发送的回复作为已经说过的话；近期数量和原文保留策略可在记忆页配置，原文默认保留三十天。

#### Scenario: 存在未发送草稿
- **WHEN** 用户的近期记录包含一条草稿和一条已确认回复
- **THEN** 上下文可包含收到的原文，但只有已确认回复被标识为角色已发送内容

#### Scenario: 近期记录超过时间窗口
- **WHEN** 某条原始互动已超过七天且仍存在数据库中
- **THEN** 默认近期上下文不包含它，符合来源约束的长期记忆可按规则继续使用

### Requirement: 长期摘要整理

系统 MUST 按用户与渠道在新增五条已处理真实入站记录后安排 LLM 整理，合并旧记忆与新增事实和未完话题；使用处理进度判断新增，不得因只覆盖最近原文而丢失仍有效历史。

#### Scenario: 达到摘要阈值
- **WHEN** 某用户某渠道累计达到五条新处理的真实入站记录
- **THEN** 系统安排该范围的整理，不将角色自己的发言写成用户事实

#### Scenario: 新处理消息的平台时间较早
- **WHEN** 消息被新处理但其平台时间早于上次摘要写入时间
- **THEN** 系统仍把它计入新增进度，不因时间比较漏掉整理

#### Scenario: 旧记忆仍有依据
- **WHEN** 最近一批原文没有再次提到一个仍有效的既有事实
- **THEN** 整理结果保留该事实，不因它未出现在最近记录中而直接覆盖删除

### Requirement: 记忆可见范围

公开回复 MUST 只使用同工作账号归属下的公开原文与记忆，私信按允许范围使用；无可靠身份映射时不得自动合并公开账号和私信会话，无法确认归属的历史数据不得自动迁给新账号。

#### Scenario: 公开与私信都有记录
- **WHEN** 系统为公开消息获取记忆
- **THEN** 返回的上下文不包含私信原文或私信摘要

#### Scenario: 浏览器切换工作账号
- **WHEN** 新账号开始处理消息
- **THEN** 系统不把旧工作账号的私信或无法确认归属的历史记忆交给新账号

### Requirement: 遗忘与恢复记录

系统 MUST 在记忆页及已有用户指令入口支持遗忘并停止记录、恢复后续记录，以及使遗忘前正在生成的旧摘要失效；独立遗忘记录在恢复旧数据库后仍必须生效。

#### Scenario: 遗忘时仍有摘要在生成
- **WHEN** 用户被遗忘后旧摘要请求才返回
- **THEN** 系统拒绝写回该摘要并继续阻止记录

#### Scenario: 恢复记录
- **WHEN** 已遗忘用户重新允许记录
- **THEN** 系统可以记录之后的新消息，不自动恢复此前已删除的内容

#### Scenario: 恢复旧数据库
- **WHEN** 旧数据库包含已经遗忘的用户内容
- **THEN** 系统在继续处理前重放独立遗忘记录并移除对应内容

## ADDED Requirements

### Requirement: 用户和会话可视化列表

记忆页 MUST 提供用户／会话搜索、渠道筛选、最近互动、记忆数量、整理时间及遗忘状态；无法可靠识别私信对方时必须展示会话标识，不伪造账号关联。

#### Scenario: 私信只有会话标识
- **WHEN** 管理员查看尚无可靠用户映射的私信记忆
- **THEN** 页面按会话展示并说明身份未确认，不强行关联同名公开账号

### Requirement: 长期条目来源与内容边界

长期记忆 MUST 记录明确自述的事实、偏好和未完话题的来源、时间及可见范围，不推断身份或敏感标签；旧摘要来源不完整时必须如实标记。

#### Scenario: 迁入旧版自由文本摘要
- **WHEN** 系统不能确认其对应来源消息
- **THEN** 页面保留旧摘要并标记来源不完整，不生成虚假的来源链接

### Requirement: 人工修订和删除防回写

管理员 MUST 能编辑或删除长期条目、手动重新整理；修订和删除后旧后台结果或基于旧来源的再次整理不得复活被删除内容。

#### Scenario: 删除时整理请求未结束
- **WHEN** 管理员删除一个条目后旧整理结果才返回
- **THEN** 系统拒绝过期结果，不重新写回已删除条目

### Requirement: 角色经历与虚构内容分层

系统 MUST 单独记录有来源或平台回执的角色重要发帖与互动，并与人格背景、虚构日程及用户自述事实分开展示和使用。

#### Scenario: 当日虚构日程包含外出
- **WHEN** 该日程被用于角色回复
- **THEN** 系统不会把外出自动记为已确认现实事件或某用户的经历

### Requirement: 只读召回预览与整理计费

记忆页 MUST 展示选定账号、用户和渠道实际可召回的内容及来源，预览不得写回生产记忆；LLM 整理必须纳入同一计费系统，无新增记录时不自动整理。

#### Scenario: 查看公开召回
- **WHEN** 管理员预览某用户的公开回复上下文
- **THEN** 页面只展示公开允许内容，不创建真实互动或新的长期条目

#### Scenario: 手动重新整理
- **WHEN** 管理员明确发起一次有可用原文的记忆整理
- **THEN** 系统记录该 LLM 请求费用，结果遵守来源、可见范围和修订保护

# 定时任务增量规格

## Purpose

统一展示和管理角色工作流的业务循环、定时内容与维护任务，让管理员明确任务是否启用、何时执行及执行结果，并保证并发、暂停、重启和未知发送不会造成重复帖子、额外模型请求或失去独立健康监控。

## ADDED Requirements

### Requirement: 可视化任务计划与历史

系统 MUST 以北京时间展示任务开关、周期、上次／下次执行、状态、耗时、错误和费用，支持修改计划、手动执行与查看有限分页历史；保存计划不得隐式恢复生产。

#### Scenario: 暂停时修改任务
- **WHEN** 管理员在暂停状态保存新执行时间
- **THEN** 页面更新计划，系统继续暂停且不立即发送或调用模型

### Requirement: 单一主循环

系统 MUST 使用一个主循环，默认在一轮结束后等待六十秒，可设置三十至三千六百秒；任务页的主循环启停必须与全局运行控制一致。

#### Scenario: 本轮执行耗时较长
- **WHEN** 某轮处理超过配置等待间隔
- **THEN** 系统等待该轮结束后再计时，不叠加启动第二轮

### Requirement: 暂停与人工接管语义

系统 MUST 在业务暂停或接管期间停止自动业务采集、发送及日程／记忆的自动 LLM 调用，保留计划；已提交的出站结果仍需受控回查，宿主维护任务按独立开关运行。

#### Scenario: 暂停时到达日程时间
- **WHEN** 已启用的日程任务到期但业务暂停
- **THEN** 系统不自动调用模型，保留恢复时补处理的状态

### Requirement: 早晚安任务默认与内容

系统 MUST 提供默认北京时间 08:00 的早安和 23:00 的晚安任务，初始关闭；启用后用当前人设与当日日程经 LLM 生成，采用正常正文校验、额度和平台回执。

#### Scenario: 刚完成系统升级
- **WHEN** 管理员尚未启用新早晚安任务
- **THEN** 系统不会因升级或回复验收自动发布问候帖

#### Scenario: 启用的早安任务执行
- **WHEN** 任务到期且业务正常运行、额度可用
- **THEN** 系统保存生成正文后提交，并记录模型费用和平台回执

### Requirement: 每日问候错过窗口

早晚安任务 MUST 只在计划时刻后五分钟以内开始，超出窗口标记错过；重启或恢复时不得补发已过时问候。

#### Scenario: 晚间恢复早安任务
- **WHEN** 服务直到当晚才恢复，早安任务未执行
- **THEN** 系统记录错过，不发布早安帖

### Requirement: 日程与记忆维护默认

系统 MUST 默认启用每日 06:00 日程生成和每日 03:00 记忆补整理；日程支持当天缺失补生成，记忆只整理有新增且未被整理的记录。

#### Scenario: 没有新增用户互动
- **WHEN** 记忆补整理任务执行
- **THEN** 系统不对没有新增数据的用户发起摘要请求

### Requirement: 任务实例互斥

同一任务、计划时刻和账号 MUST 只有一个执行实例，手动与定时执行共享互斥；unknown 出站只能回查，不能通过再次执行重发或重写已提交正文。

#### Scenario: 手动执行与定时器同时到达
- **WHEN** 同一任务的两种触发并发到达
- **THEN** 只执行一个实例，不重复调用模型或发送

#### Scenario: 帖子提交后结果未知
- **WHEN** 管理员再次执行关联任务
- **THEN** 系统回查原提交，不生成另一篇正文或再次发布

### Requirement: 关闭任务和重启恢复

系统 MUST 在关闭任务后取消未开始的后续执行，并持久保存历史；恢复时日程和记忆可补处理当天工作，备份最多补一次，不能回放所有遗漏日期。

#### Scenario: 关闭已生成但未提交的问候
- **WHEN** 管理员关闭任务且该实例尚未提交
- **THEN** 系统停止该实例的后续发送

### Requirement: 数据库备份范围与默认

系统 MUST 提供默认每日 02:30、初始关闭、保留最近七份的业务数据库备份；页面必须说明不包含面板配置、密钥、源码或浏览器 profile，恢复不得覆盖独立遗忘记录。

#### Scenario: 未启用自动备份
- **WHEN** 到达默认备份时间
- **THEN** 系统保持现有关闭状态，不自动创建备份

#### Scenario: 执行数据库备份
- **WHEN** 管理员已启用任务或明确单次执行
- **THEN** 系统创建可校验的业务数据库备份并按保留策略处理，不包含上述排除内容

### Requirement: 独立健康检查与受限维护

宿主健康检查 MUST 保持每五分钟运行且独立于 app 及业务暂停，结果可在任务页查看；维护入口只接受限定任务，不能执行任意命令或削弱容器隔离。

#### Scenario: 应用不可用
- **WHEN** app 故障而宿主仍运行
- **THEN** 独立检查记录应用不可达，不因 app 内调度失效而停止检测

#### Scenario: 请求任意命令
- **WHEN** 管理接口收到不属于支持任务的执行请求
- **THEN** 系统拒绝请求，不把输入交给 shell 执行

### Requirement: 证书续期连续性

任务页改造 MUST 保留宿主现有证书续期机制，并展示相关健康结果，不因维护任务整合而关闭续期。

#### Scenario: 业务暂停期间证书将到期
- **WHEN** 宿主续期检查到达
- **THEN** 续期机制继续按原规则工作，结果可供健康状态读取

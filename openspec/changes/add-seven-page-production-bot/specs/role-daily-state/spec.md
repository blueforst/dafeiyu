# 虚构角色日程增量规格

## Purpose

让角色按已保存人格获得每天一致且明确标记为虚构的生活日程，并在人设页查看和修改。自动触发与首次使用必须共享同一份当天状态，避免重复调用、跨日误用以及把角色设定混入真实用户记忆。

## ADDED Requirements

### Requirement: LLM 生成虚构日程

系统 MUST 根据已保存人格和近七日日程调用 LLM 生成日期、时段、三餐、活动与心情，并明确标记虚构性质，不把历史往事重新描述成当天真实事件。

#### Scenario: 自动生成新一天日程
- **WHEN** 当日状态需要生成且模型可用
- **THEN** 系统生成符合人格的新日程并记录 LLM 用量，内容可供当天回复复用

### Requirement: 自动生成按账号和日期去重

系统 MUST 默认在北京时间每日 06:00 生成日程，当天首次处理缺少日程时提前补生成；同账号同日期的自动生成不得因多个触发入口重复执行。

#### Scenario: 定时器和首次使用同时触发
- **WHEN** 两个入口同时请求同账号同一天的日程
- **THEN** 只发起一次实际生成请求，两个入口使用同一结果

#### Scenario: 首次处理早于默认生成时间
- **WHEN** 当天 06:00 前开始处理且没有当日日程
- **THEN** 系统补生成一份，06:00 不再自动替换它

### Requirement: 当日日程保持一致

系统 MUST 复用当天已生效日程，只有管理员主动编辑或重新生成才替换内容；保存长期人格不自动重写当天日程。

#### Scenario: 当天修改长期人格
- **WHEN** 管理员保存新人格而没有重新生成日程
- **THEN** 后续回复使用新人格和原当日日程

### Requirement: 人设页日程展示与编辑

系统 MUST 在人设页展示当天时间轴、当前时段、生成来源、更新时间、近七日历史和生成状态，并提供编辑及重新生成操作；调度时间引用任务页的同一设置。

#### Scenario: 手动重新生成
- **WHEN** 管理员主动请求重新生成且没有同日生成任务正在执行
- **THEN** 页面展示进行状态，新结果生效并记录本次费用

### Requirement: 暂停及恢复时生成语义

系统 MUST 在业务暂停或人工接管期间停止自动日程模型调用，恢复处理时补当天缺失状态；管理员明确发起的生成不受自动调度暂停限制。

#### Scenario: 暂停时经过生成时间
- **WHEN** 系统暂停且到达日程生成时间
- **THEN** 系统不自动调用模型，恢复时再补当天缺失状态

### Requirement: 日程失败退避与跨日边界

系统 MUST 在自动生成失败后间隔三十分钟重试，当日最多自动尝试三次；无有效当日日程时使用明确的暂无状态，不得把昨日内容标为今日。

#### Scenario: 多次自动生成失败
- **WHEN** 同账号当天已自动尝试三次且均失败
- **THEN** 系统停止当天自动重试，展示失败，后续回复使用暂无当日日程状态

#### Scenario: 跨日后只有昨天日程
- **WHEN** 当前日期已变化且新日程尚未成功生成
- **THEN** 系统不把昨日时间轴作为今天的角色活动

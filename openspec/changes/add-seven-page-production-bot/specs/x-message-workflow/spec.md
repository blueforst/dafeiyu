# X 生产消息工作流增量规格

## Purpose

规定真实公开消息与一对一私信从读取、排队到回复确认的可验证行为，使浏览器操作具备可靠目标、账号归属和重复保护。该能力承接现有工作流并补齐生产验收条件，不能把模拟解析或点击成功当作真实发送证据。

## ADDED Requirements

### Requirement: 多来源有界采集

系统 MUST 采集通知提及、搜索、自己帖子下的回复、一对一私信与消息请求，有界扫描并持久去重；页面结构不可识别时必须记录异常而不是报告没有消息。

#### Scenario: 相同消息出现在多个来源
- **WHEN** 同一平台消息被通知与搜索重复采集
- **THEN** 系统只保留一个正常处理项，不重复生成或发送

#### Scenario: 私信页面改版
- **WHEN** 当前页面无法可靠识别会话或消息
- **THEN** 系统记录需要适配的异常，停止该项操作

### Requirement: 可靠消息身份和时效

系统 MUST 区分主帖、引用、评论、会话及消息方向，并在真实自动发送前取得可靠消息 ID、目标关系和时间；不得用正文哈希或当前时间伪装缺失证据。

#### Scenario: 缺少可靠时间或消息 ID
- **WHEN** 读取的入站消息无法满足身份或时效校验
- **THEN** 系统可以记录待核对状态，但不自动发送回复

#### Scenario: 私信最新消息是自己发送的
- **WHEN** 会话的最后消息明确为出站
- **THEN** 系统不把该消息作为新的待回复入站消息

### Requirement: 正常生产范围

系统 MUST 按正常来源、过滤、时效、额度和退避规则处理所有符合条件的消息，不增加仅供本轮验收账号使用的白名单，也不要求配置预期账号。

#### Scenario: 测试期间其他账号发来合格消息
- **WHEN** 另一个账号的消息符合正常生产处理规则
- **THEN** 系统按同一工作流处理，不因不是 Ceyi 测试账号而排除

### Requirement: 工作账号数据归属

系统 MUST 使用浏览器当前登录账号工作，并隔离队列、记忆、任务和出站记录的账号归属；登录身份变化时暂停，不把旧账号消息交给新账号发送。

#### Scenario: 生成中切换账号
- **WHEN** 当前登录账号在回复生成后发生变化
- **THEN** 系统暂停，当前回复不发送，也不迁给新账号

### Requirement: 上下文和媒体可见性

系统 MUST 在生成前读取可确认的对话上下文及允许范围内的记忆，并明确说明当前不可见媒体；不得猜测图片或视频内容。

#### Scenario: 消息含尚未接入理解的媒体
- **WHEN** 某条消息包含图片或视频但没有可验证内容
- **THEN** 模型收到媒体不可见说明，回复不以猜测的媒体细节为依据

### Requirement: 互斥操作与发送前复核

回复、私信、定时帖子和人工接管 MUST 共用互斥的浏览器控制，提交前重新核对身份、目标与私信最新上下文。

#### Scenario: 读取后私信已有新消息
- **WHEN** 准备发送时会话最新入站消息已变化
- **THEN** 系统停止旧上下文下的发送并重新处理，不直接提交旧回复

#### Scenario: 人工接管请求到达
- **WHEN** 管理员发起接管且浏览器正在操作
- **THEN** 系统排空操作后移交，不与人工操作同时写入浏览器

### Requirement: 可验证的平台回执

系统 MUST 在提交前保存发送意图，并仅在核对唯一平台 ID、作者、目标关系、正文及时间后确认成功；点击成功或出现任意提示不得单独视作确认。

#### Scenario: 相同正文出现在另一个帖子
- **WHEN** 回查发现同文回复但不能确认其属于目标帖子
- **THEN** 系统不把它当成本次发送的成功回执

### Requirement: 未知发送只回查

结果不明确的出站 MUST 进入 unknown 并只允许回查，不得自动重发；服务重启、手动执行或任务重试不能绕过这一限制。

#### Scenario: 提交后连接中断
- **WHEN** 提交已开始但未取得明确回执
- **THEN** 系统记录 unknown，恢复后回查而不重新提交

### Requirement: 额度退避与正文校验

系统 MUST 默认每轮最多处理两条、公开每小时十条、私信每小时三十条，早晚安帖共享公开额度；平台明确拒绝后对应通道退避四小时。公开正文 MUST 使用[账号发帖限制提案](../../../add-account-aware-post-limits/specs/x-posting-limits/spec.md)的同一账号与操作类型策略：普通账号或能力未知／过期／冲突时按 280 加权字符完整校验；只有长帖资格、数字上限及计数适配均已确认时才使用对应长帖规则。该上限不改变模型 token、小时额度或私信 4,000 字符规则，不能把资源保护上限当作平台权限。

#### Scenario: 公开通道额度用尽
- **WHEN** 公开回复和定时帖子合计已达小时额度
- **THEN** 系统不通过定时任务入口绕过额度继续发送

#### Scenario: 平台明确拒绝
- **WHEN** 页面确认平台拒绝了本次发送
- **THEN** 系统记录拒绝并使对应通道退避四小时，不连续重复提交

#### Scenario: 长帖规则尚未确认
- **WHEN** 账号显示订阅或认证标记，但缺少该操作类型已确认的长帖资格、上限或计数适配
- **THEN** 系统仍按 280 加权字符校验，不因为标记或自报上限放开长帖

#### Scenario: 已确认的操作类型长度策略
- **WHEN** 当前账号的原创或回复资格、上限及计数适配均已确认且未失效
- **THEN** 对应操作按同一长帖策略生成与校验，其他未确认操作继续短帖回退，提交前仍独立复核

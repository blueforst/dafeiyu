# 人设管理增量规格

## Purpose

允许管理员在人设页维护始终生效的人格规则与按语义触发的内容，并用隔离的多轮对话检查实际提示词和生成效果，确保配置可理解、可验证且不会因试聊影响真实用户或生产发送。

## ADDED Requirements

### Requirement: 静态提示词可视化编辑

系统 MUST 提供角色定义、说话风格、记忆与承诺、互动边界等静态分区，每次回复始终使用已生效内容，并原样保留导入的旧人格文本。

#### Scenario: 导入既有人格
- **WHEN** 系统首次读取旧版完整人格配置
- **THEN** 人设页保留原文，不编写新的角色身份或经历

### Requirement: 触发规则可视化管理

系统 MUST 允许编辑触发规则的名称、自然语言条件、正文、启用状态及顺序，并只把本次命中的启用规则正文加入回复上下文。

#### Scenario: 规则未命中或被关闭
- **WHEN** 某规则没有命中或已被管理员关闭
- **THEN** 本次回复提示词不包含其正文

### Requirement: LLM 语义触发判定

系统 MUST 使用当前模型根据当前消息和同渠道可见上下文，一次判定全部启用规则，展示有效命中及原因；无启用规则时不得增加判定请求。

#### Scenario: 存在启用规则
- **WHEN** 当前消息准备生成回复
- **THEN** 系统执行一次统一语义判定，按配置顺序注入有效命中的规则并记录费用

#### Scenario: 没有启用规则
- **WHEN** 当前没有启用的触发规则
- **THEN** 系统直接使用静态提示词生成，不产生语义判定费用

### Requirement: 语义判定失败回退

系统 MUST 校验语义判定结果，忽略未知规则和重复命中；判定失败时继续使用静态规则，并使管理员可见警告和实际已返回用量。

#### Scenario: 判定结果不可用
- **WHEN** 判定请求失败或结果不符合约定
- **THEN** 回复不注入任何触发模块，系统记录回退原因且不重复请求造成计费循环

### Requirement: 人格生效与固定系统规则

人格保存 MUST 从下一轮处理生效，不改变正在执行的生成或隐式恢复业务；页面必须只读展示固定系统约束，允许明确的虚构设定但不得伪造真实互动记忆。

#### Scenario: 生成中保存人格
- **WHEN** 管理员在一轮生成中保存新人格
- **THEN** 当前生成继续使用原快照，下一轮使用新人格

#### Scenario: 暂停时保存人格
- **WHEN** 系统暂停且管理员保存人格
- **THEN** 系统继续暂停，不自动发送或开始业务处理

### Requirement: 隔离多轮试聊

系统 MUST 允许用未保存的人格在公开或私信场景进行多轮试聊，默认使用模拟记忆，不向 X 发送、不修改真实记忆，并展示本轮全部调用费用。

#### Scenario: 未保存人格试聊
- **WHEN** 管理员修改人格后发起多轮试聊
- **THEN** 系统使用该草稿生成，保存的人格、生产记忆和真实出站记录保持不变

### Requirement: 提示词与命中结果预览

系统 MUST 在人设页展示试聊的回复或跳过结果、语义命中原因、实际提示词分段及耗时，且不得展示密钥。

#### Scenario: 检查一次试聊
- **WHEN** 管理员查看一轮完成的试聊
- **THEN** 能分别检查静态规则、命中模块、日程、模拟记忆与当次上下文，且无密钥内容

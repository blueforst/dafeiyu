# 顶部运行状态与浏览器接管分离提案

## Why

**现状（2026-10-28 核对本机提交 `b607c3d` 与生产 0.1.17.1，两者顶部栏相同）：**

- 顶部栏右侧有一个状态标签和一个主按钮，混用了四种控制状态：
  - 处理中：显示“处理中”和“暂停”；
  - 已暂停：显示“已暂停”和“恢复处理”；
  - 排空中：显示“等待当前操作结束”，按钮不可用；
  - 人工接管：显示“人工接管中”和“释放接管”。
- 发起接管的“接管并连接”在设置页“浏览器接管”分区，释放接管却要回到顶部栏点主按钮（`public/js/views/browser.js` 开头注释写明“释放接管统一使用右上角的主按钮”）。同一件事的开始和结束分在两个地方。
- 顶部栏的按钮在接管时变成“释放接管”，平时又是暂停／恢复，同一个按钮的意思随状态变化，容易点错。

管理员希望顶部栏只管运行：一眼看出现在是否在运行，并能直接启动或暂停；接管浏览器的按钮和状态放到接管分区里。

## What Changes

- **顶部栏只显示运行状态和启停**：
  - 状态标识只有“运行中”“已暂停”“正在暂停…”三种（读取失败时显示“连接失败”）。
  - 按钮只有“启动”和“暂停”。
- **接管期间顶部只做提示**：显示“已暂停”，旁边一个“浏览器接管中 →”链接，点击打开设置页并展开浏览器接管分区。“启动”按钮变灰，悬停说明需要先释放接管。系统在接管期间本来就拒绝启动，这样管理员能看到原因。
- **接管全部放到“浏览器接管”分区**：
  - 分区里新增“释放接管”按钮，接管未连接桌面和已连接桌面时都能看到。
  - 分区标题行的摘要随状态显示“人工接管中”或“按需连接”。
- **文案**：
  - 顶部按钮由“恢复处理”改为“启动”，状态由“处理中”改为“运行中”。
  - 释放接管后的提示改为“已释放接管，处理保持暂停，可在顶部启动”。
  - 定时任务提示里的“右上角”改为“顶部”。
- **不改后端**：控制接口、排空、接管和释放的语义都不变。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `panel-navigation`：
  - 修改“全局控制与配置保存”：规定顶部栏的运行状态标识和启停，接管期间只提示、不提供接管操作。
  - 修改“浏览器人工接管”：发起和释放接管都在接管区。
- `activity-feed`：修改“首页概况行”。运行状态和启停改由全局顶部栏提供，概况行只显示运行模式、模型和账号，与现有实现一致。

“全局控制与配置保存”的现行写法来自未归档的 `add-seven-page-production-bot`，“浏览器人工接管”和“首页概况行”来自未归档的 `simplify-panel-activity-feed`。本提案需要排在这两项之后归档。

## Impact

- **前端**：
  - `public/index.html`、`public/js/app.js`：顶部栏状态与按钮；
  - `public/js/views/browser.js`：释放接管按钮；
  - `public/js/views/settings.js`：分区摘要；
  - `public/js/state.js`、`public/js/views/tasks.js`：提示文案；
  - `public/style.css`：少量样式。
- **验收脚本**：`test/panel-e2e.mjs`、`test/ui-acceptance.mjs`、`test/production-five-pages.mjs` 中依赖“恢复处理”“释放接管”文案和顶部按钮的步骤需要同步。
- **文档**：`docs/Camoufox浏览器.md` 中“右上角‘释放接管’”的说法。
- **不涉及**：后端、控制接口、数据库、运行模式切换。
- **与其他提案**：`add-persona-presets` 正在修改 `public/style.css`，实施时注意不要覆盖对方的未提交改动。
- 本次只创建规划文件。界面验收在服务器隔离环境执行，生产发布需要另行授权。

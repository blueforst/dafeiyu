# 顶部运行状态与浏览器接管分离技术设计

## Context

动机见 [proposal.md](proposal.md)，行为契约见 [panel-navigation](specs/panel-navigation/spec.md) 与 [activity-feed](specs/activity-feed/spec.md) 增量规格。以下现状来自 2026-10-28 本机提交 `b607c3d` 和生产 0.1.17.1 只读核对：

- **顶部栏**：`public/index.html` 的 `.top-actions` 内有 `#conn`（连接提示）、`#status-pill`（状态标签）和 `#primary-action`（主按钮）。`public/js/app.js` 用两张表映射控制状态：
  - `LABEL`：`paused` 已暂停、`running` 处理中、`draining` 等待当前操作结束、`manual` 人工接管中；
  - `PRIMARY`：`paused` 恢复处理、`running` 暂停、`draining` 不可用、`manual` 释放接管。
  - 排空中且当前没有操作、也没有进行中的请求时，按钮显示“重试暂停”。
- **接管分区**：设置页“排查问题”组里的“浏览器接管”分区（`#/settings/browser`，摘要固定为“按需连接”）加载 `public/js/views/browser.js`。
  - 只有“接管并连接”（未接管时）或“连接桌面”（已接管时）按钮，没有释放按钮。
  - 状态离开 `manual` 时，分区自动卸载桌面画面。
- **设置页**：`settings.js` 已支持按地址展开分区（`route()`），并在 `onStatus` 回调里更新各分区摘要。
- **提示文案**：`public/js/state.js` 的 `DONE` 在操作完成后显示：
  - 恢复：“已恢复处理”，草稿模式下附加说明；
  - 释放：“处理保持暂停，可在右上角恢复”。
  - `tasks.js` 主循环提示写有“启停与右上角全局控制一致”。
- **后端**：`/api/control/{pause,resume,takeover,release}` 不变。
  - 接管先排空（`draining`）再进入 `manual`；
  - 接管期间恢复会被拒绝（“请先释放人工接管”）；
  - 释放后回到 `paused`，桌面入口返回 423。
- **生产**：当前为 `paused`、自动模式，顶部栏与本机相同。

## Goals / Non-Goals

**Goals：**

- 顶部栏只表达“是否在运行”，并提供启动和暂停。
- 接管的发起、状态、桌面连接和释放都在浏览器接管分区完成。
- 接管期间，任何页面的顶部都能看出处理为什么停着，并一键到达接管分区。

**Non-Goals：**

- 不改控制接口和状态机，不新增“启动时自动释放接管”。
- 不改运行模式的切换位置（仍在设置页标题行）。
- 不统一其他位置的“恢复处理”说法，例如草稿“等待发送（恢复处理后发送）”和后端错误“请先恢复处理”。它们仍然看得懂，需要时另行处理。

## Decisions

### 1. 顶部栏状态表

保留 `#status-pill` 和 `#primary-action` 两个元素标识，新增 `#takeover-link`（`<a href="#/settings/browser">`），只在接管期间显示。

| 控制状态 | 状态标识 | 按钮 | 接管链接 |
| --- | --- | --- | --- |
| `running` | 运行中（绿色） | 暂停 | 隐藏 |
| `paused` | 已暂停（黄色） | 启动 | 隐藏 |
| `draining` | 正在暂停…（黄色） | 不可用；沿用现有逻辑，满足条件时显示“重试暂停” | 隐藏 |
| `manual` | 已暂停（黄色） | 启动（不可用） | “浏览器接管中 →” |
| 状态读取失败 | 连接失败（红色） | 不可用 | 隐藏 |

接管期间“启动”不可用，`title` 和 `aria-describedby` 说明“请先在浏览器接管分区释放接管”。不做“点启动自动释放接管”：桌面可能正在另一个标签页里登录或过验证码，自动释放会直接切断它。

`draining` 既可能来自暂停，也可能来自接管，顶部统一显示“正在暂停…”。如果是接管，浏览器分区会另外显示“正在等待当前操作结束”。

### 2. 浏览器接管分区

- 已接管但未连接桌面时：在“连接桌面”“新标签页打开”旁边加“释放接管”。
- 已连接桌面时：在桌面上方状态条的“新标签页打开”旁边加“释放接管”。
- 点击后调用 `runControl('release')`。请求期间所有控制按钮不可用（沿用 `isPending()`）；成功后状态变为 `paused`，现有逻辑会卸载桌面画面。
- 分区标题行摘要：`manual` 时显示“人工接管中”，`draining` 时显示“等待当前操作结束”，其他状态显示“按需连接”。由 `settings.js` 现有的 `onStatus` 回调更新。
- `browser.js` 开头的注释改为“接管与释放都在本分区完成”。

### 3. 文案

| 位置 | 原文 | 新文 |
| --- | --- | --- |
| 顶部按钮（暂停时） | 恢复处理 | 启动 |
| 顶部状态（运行时） | 处理中 | 运行中 |
| 顶部状态（排空时） | 等待当前操作结束 | 正在暂停… |
| 启动完成提示 | 已恢复处理（草稿模式时附说明） | 已启动（草稿模式时附同样的说明） |
| 释放完成提示 | 处理保持暂停，可在右上角恢复 | 已释放接管，处理保持暂停，可在顶部启动 |
| 定时任务主循环提示 | 启停与右上角全局控制一致 | 启停与顶部的启动／暂停一致 |

### 4. 窄屏

375px 下 `.top-actions` 已经单独占一行。接管期间的状态、链接和按钮必须在这一行内显示完整，不产生整体横向滚动；放不下时链接文字可以换到状态下方，但不能被截断或隐藏。

## Risks / Trade-offs

- **习惯改变**：管理员习惯在右上角释放接管。缓解：接管期间每个页面的顶部都有“浏览器接管中 →”链接，一步就能到释放按钮。
- **忘记释放**：接管后离开设置页，可能忘了还在接管。缓解：接管链接在所有页面的顶部持续显示，直到释放。
- **并行修改**：`add-persona-presets` 正在修改 `public/style.css`。实施时只追加本提案需要的样式，提交前核对没有覆盖对方改动。

## Migration / Rollback

纯前端改动，无数据迁移。回退时恢复原 `app.js` 映射表、`browser.js`、`settings.js`、文案和样式即可，后端状态不受影响。

## Verification

- **服务器隔离界面验收**（Camoufox，1440px 与 375px，浅色与深色，使用隔离环境和夹具，不使用生产 profile）：
  - 运行中、已暂停、正在暂停…、接管中、状态读取失败五种情况下，顶部的状态、按钮和接管链接与第 1 节的表一致。
  - 顶部“暂停”和“启动”能正常切换，运行模式不变。
  - 接管期间顶部“启动”不可用并有说明，点击“浏览器接管中 →”打开设置页并展开浏览器接管分区。
  - 在分区里接管、连接桌面、释放接管；释放后处于已暂停，桌面入口返回 423，顶部的“启动”恢复可用。
  - 分区标题行摘要随状态变化。
  - 375px 下没有整体横向滚动，接管期间顶部内容完整可见。
- **验收脚本同步**：更新 `test/panel-e2e.mjs`、`test/ui-acceptance.mjs`、`test/production-five-pages.mjs` 中依赖顶部“恢复处理”“释放接管”的步骤，改为在分区里释放，并在服务器隔离环境跑通。
- **生产发布**（需要另行授权）：发布后只读打开面板，确认顶部显示“已暂停”和“启动”。验收期间不点击启动，也不接管。

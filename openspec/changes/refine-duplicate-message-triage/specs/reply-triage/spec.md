# 消息分级增量规格（同文降优先）

## MODIFIED Requirements

### Requirement: 广告与批量刷量过滤

系统 MUST 在入队时过滤广告并记录原因，不得为被过滤的消息发起模型请求。广告按可配置关键词与链接组合及纯广告关键词识别。规范化后相同正文达到可配置的不同用户阈值时，系统 MUST 只将同一工作账号、同一渠道内的普通消息及仍排队同文项降为普通优先级，原因明确为同文重复，不得仅因重复标记为已过滤。统计窗口仍为一小时，默认阈值三人；明确重点名单、管理员重新排队、重写及人工补录 MUST 保留优先。已发送、已过滤、unknown 和出站状态 MUST NOT 自动改写。

#### Scenario: 多个账号发送相同正文
- **WHEN** 第三个不同用户在一小时内同一渠道发来相同普通提问
- **THEN** 该消息和仍排队的普通同文消息归普通优先级，仍可进入生成而非已过滤

#### Scenario: 普通消息含链接
- **WHEN** 一条消息只包含链接而没有广告关键词
- **THEN** 系统不仅凭链接过滤它

#### Scenario: 公开与私信不混算
- **WHEN** 两位用户公开提问，另一位私信提出同一问题
- **THEN** 两个渠道均未达到三人阈值，私信不使公开消息降级

#### Scenario: 明确优先与历史状态
- **WHEN** 同文组含重点名单或管理员明确操作，且另有已发送或已过滤项
- **THEN** 明确优先的待处理项保留优先，历史终态和冻结出站不改变

#### Scenario: 广告仍过滤
- **WHEN** 消息含广告关键词与链接，或正文仅为广告关键词
- **THEN** 消息仍标记已过滤，不因新重复策略放行

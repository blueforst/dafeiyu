# 设置页紧凑排版与高级设置收起提案

## Why

管理员 2026-10-29 先说"设置模型页布局也可以再优化一下"，问题是"屏幕的使用率太低了"，随后补充"其他设置页也有一样的问题"：有的页"都有大片的空白区域"，有的"文字太密，让人眼花缭乱"；"这些高级参数直接放在主页面很容易让人头大"。

当天在管理员自己的浏览器（窗口 1439×868）里只读量了生产面板的十一个设置项：

| 设置项 | 内容高度 / 可视高度 | 问题 |
| --- | --- | --- |
| 模型 | 3061 / 767，约 4 屏 | 一个模型占 4 行，一屏只看到 3 个；服务商侧栏列出全部 40 个目录服务商；地址、协议、Key 三个整行输入框压在模型列表上方；页头按钮与页内重复 |
| 运行与发送 | 1.4 屏 | 7 个输入框都超过 300px 宽，只填两三位数；勾选框单独占一行 |
| 定时任务 | 1.4 屏 | 每个任务三行小字，开关在最左、时间和按钮在最右 |
| 消息分级与过滤 | 1 屏 | 四个大统计卡、四个大文本框、通栏"刷新分级概况"按钮 |
| 记忆 | 0.4 屏 | 未选用户时右侧全空；用户卡片每人四行；"策略"标签页只有三个数字参数 |
| 计费 | 1.9 屏 | 金额显示到八位小数（$0.04840811）；趋势图约 350px 高；页尾重复刷新按钮和说明 |
| 浏览器接管 | 0.5 屏 | 未接管时只有一行账号和一句"浏览器未连接" |
| 采集来源 | 0.5 屏 | 4 行，下方全空 |
| 健康与日报 | 1.3 屏 | 每个指标都写"正常 · xx 正常"，需要处理的 3 项不显眼 |
| 日志阶段与队列 | 约 2.8 屏 | 每行直接显示原始 JSON；跨天没有日期；5 个筛选框加单独"筛选日志"按钮 |
| 任务执行历史 | 2 屏 | 每 5 分钟一条"宿主健康检查"，其他任务被淹没 |

另外发现"运行与发送"的"普通消息时效（6 小时）"和"消息分级"的"普通消息时效（3 小时）"名称相同、含义不同：前者实际是所有消息的最长时效（优先消息按它算），后者才是普通消息时效。管理员认为"也让人困惑"，选择合并成一个。

各页草图逐页给管理员看过并确认，汇总在 [mockups/](mockups/)。

## What Changes

- **共用排版规则（全部设置项）**
  - 输入框按内容定宽，短数字不再拉满整行；内容用两列卡片铺满宽度，能一屏放下的页面不滚动。
  - 平时不用改的参数收进每页底部的"高级设置"，默认收起，展开状态按页记住。
  - 列表一行一项；行内操作只在悬停、键盘聚焦或选中时出现，触屏在选中后出现。
  - 空的列表或统计合成一行说明；金额最多保留两位有效小数，悬停显示精确值。
- **模型**
  - 服务商侧栏只列已添加的服务商；悬停出现 ✎，点开弹窗才显示并修改名称、地址、Key，删除服务商也在弹窗里。页面上不再显示地址、协议和 Key。
  - **接口协议改为模型的属性**：目录模型协议只读显示在模型编辑窗口；自定义接口在模型编辑窗口逐个选择协议，拉取模型列表时自动识别。既有自定义服务商的协议迁移到它的每个模型上。
  - 模型表分三块：**星标**（管理员点星标记，可拖动排序）→ **最近使用**（最近 30 天有调用）→ **其他模型**。
  - 每行只有：星、模型名（推理、看图用灰色小图标，不支持不显示）、上下文、价格（输入 / 输出，悬停显示缓存读取 / 写入价）、测试结果，以及悬停才出现的"设为使用中 / 测试 / 编辑"。
  - 表格上方只剩一行：服务商名、模型数、搜索、刷新列表、手动添加模型。去掉页头"测试使用中模型"和"全部 / 已测试 / 未定价"筛选。价格只用 pi 目录，不做峰谷价。
- **运行与发送**：运行模式两张小卡；发送上限改为 2×2 小表（公开 / 私信 × 每小时 / 每天，带已用）；回复时段大字显示关闭区间并带"跟随早晚安"开关；高级设置为每轮最多处理、晚安后关闭延迟、账号字数上限。
- **消息时效合并**：只保留一个"消息时效"，放在"消息分级与过滤"的高级设置，默认 3 小时，优先和普通消息都按它判断；升级时取原普通消息时效作为新值。
- **定时任务**：顶部加"今天的安排"时间轴（任务时间、不回复时段、现在）；任务按执行时间排序，每个一行（开关、名称、时间、上次执行）；早晚安帖带"会发到 X"；主循环间隔和宿主健康检查间隔进高级设置。
- **消息分级与过滤**：统计压成一条；关键词和名单改为小标签，点"＋"添加；排队、过滤、冷却为空时合成一行；高级设置为消息时效与同文重复降优先阈值。
- **记忆**：进入时自动选中第一个用户；用户列表一人两行；详情主栏用"长期记忆 / 互动记录 / 近期可见"标签切换，侧栏放身份关联和整理；"遗忘并停止记录"进 ··· 菜单；原"策略"视图改为页头"高级设置"；"角色经历"改为一条一行的列表，"＋ 登记经历"弹窗。
- **计费**：汇总一条 → 每日用量柱状图与用量占比并排 → 活动热力图压成一条 → 调用流水（保持默认收起）；范围切换和刷新移到页头，去掉页尾重复。
- **浏览器接管 / 采集来源**（管理员选择保持两页）：接管页的空白改为远程桌面占位，"接管并连接"居中；采集来源改为紧凑表格。
- **健康与日报**：需要处理的项单独置顶并带"去处理"；正常指标只显示"绿点 + 名称"，说明放到悬停；日报金额精简；健康与披露配置进高级设置。
- **日志阶段与队列**：每行先显示中文摘要，原始内容放行尾、变浅、可展开；按天分隔；筛选压成一行，修改即生效。
- **任务执行历史**：连续重复的同一任务合并为一行（例如"宿主健康检查 ×85"），可展开；顶部按任务筛选并显示次数，另有"只看失败"；改为表格。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `panel-design-system`：新增设置页紧凑排版、高级设置收起、行内操作显隐三项共用规则。
- `panel-navigation`：修改"并入页面与分区的称呼对应"（记忆策略改称高级设置）和"健康与日报分组排版"；新增运行与发送、定时任务、消息分级、记忆、浏览器接管与采集来源、日志、任务执行历史的排版要求。
- `model-configuration`：修改模型分区布局、服务商详情与连接、添加后拉取、服务商模型列表；新增模型星标与最近使用、模型接口协议。
- `reply-triage`：修改"出队顺序与分级时效"，两档时效合并为一个消息时效。
- `llm-usage-billing`：修改计费页结构、按模型每日趋势（改柱状图）和计费数字精度。

## Impact

- 前端：`public/js/views/model.js`、`model-form.js`、`settings/run.js`、`task-settings.js`、`triage-settings.js`、`memory.js`、`billing.js`、`charts/usage.js`、`browser.js`、`settings/sources.js`、`settings/health.js`、`program.js`，以及 `settings.js`、`shell.js`、`view-utils.js`、`style.css`、`settings-workspace.css`。
- 后端：模型库新增星标与按模型协议（`model-library.ts`、`model-catalog.ts`、`model-routes.ts`），返回最近使用时间与缓存价；分级与配置合并消息时效（`reply-triage.ts`、`config.ts`、`program.ts`、`app.ts`）；任务历史接口增加按任务计数。
- 数据：模型库与面板设置为 JSON 设置文件内的字段迁移，不新增 SQLite schema。
- 不改：模型调用、计费口径、发送与额度规则、记忆召回、健康判定、任务计划含义；不调用真实模型，不恢复业务。
- 依赖：排在 `redesign-settings-workspace`、`refine-settings-memory-timezone`、`simplify-panel-activity-feed`、`simplify-model-params`、`add-billing-chart-interaction`、`add-reply-triage`、`add-reply-hours`、`redesign-conversation-layout` 之后实施与归档。

# 模型配置增量规格（模型页紧凑排版）

## MODIFIED Requirements

### Requirement: 模型分区两栏布局

设置页模型分区 MUST 采用左右两栏：左栏只列出已添加的服务商，每项显示名称和就绪状态圆点，并标出使用中模型所在的服务商；左栏 MUST NOT 列出未添加的目录服务商，添加新服务商只通过左栏底部的“添加服务商”打开选择窗口。指针悬停、键盘聚焦或选中一个服务商时，该项右侧 MUST 显示编辑按钮（✎），点开服务商编辑窗口。右栏显示所选服务商的模型。就绪表示已设置 Key 且至少一个模型测试通过。窄屏下左栏 MUST 收为右栏顶部的服务商选择器（含添加与编辑入口），页面不得横向溢出。

#### Scenario: 打开模型分区
- **WHEN** 管理员只添加了 opencode-go，目录中另有四十个服务商
- **THEN** 左栏只显示 opencode-go 并带“使用中”标记和“添加服务商”入口，不列出其余四十个目录服务商

#### Scenario: 编辑服务商入口
- **WHEN** 管理员把指针移到左栏 opencode-go 上
- **THEN** 该项右侧出现 ✎，点击后打开服务商编辑窗口

#### Scenario: 窄屏查看
- **WHEN** 管理员在 375px 宽度下展开模型分区
- **THEN** 服务商以顶部选择器切换，添加与编辑入口可用，模型表可完整操作，没有整体横向溢出

### Requirement: 服务商详情与连接

服务商的名称、Base URL 和 API Key MUST 只在服务商编辑窗口中显示和修改，模型分区的页面上 MUST NOT 显示地址、协议或 Key。编辑窗口中 Base URL 目录服务商带预设值且可修改，Key 只显示掩码，留空表示不修改；修改 Base URL 的主机后 MUST 要求重新填写 Key；删除服务商的操作也在该窗口中，使用中模型所在的服务商 MUST NOT 可删除，删除按钮置灰并说明原因。服务商编辑窗口 MUST NOT 提供接口协议选项。

#### Scenario: 修改地址主机
- **WHEN** 管理员在编辑窗口把已设置 Key 的服务商 Base URL 改到另一主机
- **THEN** 窗口提示需要重新填写 Key，旧 Key 不会发送到新主机

#### Scenario: 删除使用中的服务商
- **WHEN** 管理员打开使用中模型所在服务商的编辑窗口
- **THEN** “删除服务商”不可用，并说明需先切换使用中的模型

#### Scenario: 页面不显示连接信息
- **WHEN** 管理员打开模型分区但没有打开编辑窗口
- **THEN** 页面上看不到 Base URL、接口协议和 Key 掩码

### Requirement: 添加服务商后自动拉取模型

添加服务商并保存 Key（自定义接口还需地址）后，系统 MUST 自动用该 Key 拉取模型列表并保存为该服务商的模型列表，之后管理员只需从列表中选择模型。自定义接口拉取列表时 MUST 依次尝试 OpenAI 兼容与 Anthropic 兼容两种列表请求，使用第一种成功的结果，并把该协议作为拉取到的模型的默认协议；添加自定义接口时 MUST NOT 要求先选择协议。模型分区 MUST 提供“刷新列表”重新拉取；拉取失败时 MUST 显示原因，目录服务商回退为目录中的模型，并允许手动添加模型 ID。

#### Scenario: 添加目录服务商
- **WHEN** 管理员从目录添加 DeepSeek 并保存 Key
- **THEN** 系统自动拉取模型列表，右栏直接显示可选模型，无需逐个添加

#### Scenario: 添加自定义接口
- **WHEN** 管理员添加一个只提供 OpenAI 兼容 `/models` 的中转站并保存地址和 Key
- **THEN** 添加窗口没有协议选项，系统拉取到模型列表，这些模型的协议默认为 OpenAI 兼容

#### Scenario: 拉取失败
- **WHEN** 自定义接口两种列表请求都失败或 Key 无效
- **THEN** 页面显示失败原因，允许刷新重试或手动添加模型 ID

#### Scenario: 刷新后模型下线
- **WHEN** 刷新列表后，接口不再返回使用中的模型
- **THEN** 该模型仍保留并标注“接口未返回”，不自动切换使用中的模型

### Requirement: 服务商模型列表

右栏 MUST 以表格显示所选服务商的模型，从上到下分为“星标”“最近使用”“其他模型”三块，每块标题带数量；一个模型只出现在其中一块，星标优先于最近使用。表格上方 MUST 只有一行工具栏：服务商名称、模型数、搜索框、“刷新列表”、“手动添加模型”；搜索同时过滤三块。每行 MUST 只显示：星标开关、模型名称（支持推理、支持看图分别以灰色小图标紧跟名称，不支持时不显示图标，悬停图标显示文字说明）、使用中标记、上下文长度、价格（输入 / 输出，每百万 token 美元）和最近一次测试结果；“设为使用中”“测试（计费）”“编辑”按行内操作显隐规则显示。推理、看图和最近使用时间 MUST NOT 作为独立列。指针悬停或聚焦价格时 MUST 显示输入、输出、缓存读取、缓存写入四项单价及来源“pi 目录”；目录没有缓存价时只显示已有项；未定价模型显示“未定价”。价格只采用 pi 目录，MUST NOT 提供峰谷价。编辑窗口 MUST 显示该模型的接口协议、上下文、价格与能力，可编辑项只有推理强度（以及按“模型接口协议”要求的协议选择）；无法识别的模型另需填写上下文长度和是否支持推理。编辑窗口 MUST NOT 提供回复长度上限或超时。

#### Scenario: 一屏能看到的模型
- **WHEN** 管理员在 1440×868 窗口打开有 30 个模型的服务商
- **THEN** 不滚动即可看到至少 14 行模型，每个模型只占一行

#### Scenario: 三块分组
- **WHEN** 管理员星标了 3 个模型，另有 3 个模型最近 30 天有调用、其中 1 个已星标
- **THEN** 星标块显示 3 个，最近使用块显示其余 2 个，其他模型块显示剩下的模型

#### Scenario: 查看缓存价
- **WHEN** 管理员把指针移到 claude-haiku-5-5 的价格上
- **THEN** 提示框显示输入 $0.10、输出 $0.50、缓存读取与缓存写入单价，并注明来自 pi 目录

#### Scenario: 选择未识别的模型
- **WHEN** 管理员把一个目录无法识别参数的模型设为使用中或打开编辑
- **THEN** 编辑窗口要求填写上下文长度和是否支持推理后才能保存

#### Scenario: 编辑已识别的模型
- **WHEN** 管理员打开一个目录中已识别模型的编辑窗口
- **THEN** 窗口只读显示协议、上下文、价格与能力，可改的只有推理强度，没有回复长度上限和超时

## ADDED Requirements

### Requirement: 模型星标与最近使用

管理员 MUST 能在模型表任一行点星把模型加入或移出该服务商的星标；星标按服务商分别保存，并按管理员拖动后的顺序显示，拖动 MUST 同时支持键盘（选中后用上下方向键移动）。星标保存后 MUST 在刷新、重启和升级后保留；刷新列表时接口不再返回的星标模型仍保留在星标中并标注“接口未返回”。“最近使用”MUST 由统一计费流水计算：该服务商的该模型最近 30 天内有调用（包括正式回复、试聊、任务和连接测试），按最后调用时间从新到旧排列。星标与最近使用只影响模型表的显示顺序，MUST NOT 改变使用中的模型或任何调用行为。

#### Scenario: 拖动排序
- **WHEN** 管理员把星标中的第三个模型拖到第一个
- **THEN** 星标块按新顺序显示，刷新页面和重启服务后顺序不变

#### Scenario: 取消星标
- **WHEN** 管理员点亮着的星取消星标，该模型昨天有过调用
- **THEN** 该模型移到最近使用块

#### Scenario: 最近使用不含很久以前的调用
- **WHEN** 某模型最后一次调用在 40 天前
- **THEN** 它出现在其他模型块

### Requirement: 模型接口协议

接口协议 MUST 是模型的属性。目录模型的协议来自 pi 目录，只读显示在模型编辑窗口；自定义接口的每个模型 MUST 在编辑窗口或“手动添加模型”窗口中单独选择协议，拉取到的模型默认采用拉取列表时成功的协议。正式请求、连接测试和试聊 MUST 按所用模型的协议发送。升级时既有自定义服务商上保存的协议 MUST 迁移到它的每个模型上，迁移后实际请求与升级前一致；接口仍收到服务商级协议字段时 MUST 忽略而不报错。

#### Scenario: 同一中转站的两种协议
- **WHEN** 一个自定义中转站下，模型 A 选 OpenAI 兼容、模型 B 选 Anthropic 兼容
- **THEN** 把 A 或 B 设为使用中后，正式请求分别按各自协议发送

#### Scenario: 升级保留原协议
- **WHEN** 升级前自定义服务商保存的协议为 OpenAI Responses，下有两个模型
- **THEN** 升级后两个模型的协议都是 OpenAI Responses，服务商编辑窗口不再有协议项，正式请求与升级前一致

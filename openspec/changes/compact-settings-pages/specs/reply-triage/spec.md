# 消息分级增量规格（合并消息时效）

## MODIFIED Requirements

### Requirement: 出队顺序与分级时效

系统 MUST 按级别优先、同级内平台时间较新者优先的顺序出队。系统 MUST 只有一个“消息时效”，默认三小时，管理员可设 1–48 小时；优先与普通消息等待超过消息时效时 MUST 记录为超时跳过，不再生成。等待时长 MUST 扣除回复时段关闭的时长。手动补录、动态页过期判断与队列计算 MUST 使用同一个消息时效。升级时系统 MUST 一次性把原“普通消息时效”的值作为新的消息时效（未设置时取原处理时效与三小时中较小者），此后原两档设置不再生效，也不再在页面上出现；接口收到原普通消息时效字段时 MUST 忽略而不报错。

#### Scenario: 优先与普通同时排队
- **WHEN** 队列中有一条较早的优先消息和一条较新的普通消息
- **THEN** 系统先处理优先消息

#### Scenario: 等待超过消息时效
- **WHEN** 消息时效为三小时，一条普通消息和一条优先消息都已等待三个半小时
- **THEN** 两条都记录为超时跳过

#### Scenario: 跨夜等待
- **WHEN** 一条普通消息 23:10 入队，回复在 23:30 至 08:00 关闭，现在是 08:30
- **THEN** 等待时长计为 50 分钟，消息仍会处理

#### Scenario: 升级合并两档时效
- **WHEN** 升级前处理时效为 6 小时、普通消息时效为 3 小时
- **THEN** 升级后只有一个消息时效，值为 3 小时；设置页只在“消息分级与过滤”的高级设置中显示它

# 面板导航增量规格（设置页紧凑排版）

## MODIFIED Requirements

### Requirement: 并入页面与分区的称呼对应

原记忆页、计费页的功能 MUST 原样作为设置页“记忆”“计费”项提供，数据、接口和交互规则不变。既有规格中的称呼按下表理解，各规格的行为要求不因页面位置改变而改变：

| 既有称呼 | 现在指 |
| --- | --- |
| “记忆页” | 设置页“记忆”项 |
| “计费页” | 设置页“计费”项 |
| “设置页某分区” | 设置页左栏中的同名设置项；“记忆策略”分区指“记忆”项页头“高级设置”窗口，“发送限制”与“运行模式”指“运行与发送”项 |
| “排查问题区” | 排查分组中的设置项 |
| “展开某分区” | 打开对应设置项 |
| “处理时效”“普通消息时效” | “消息分级与过滤”项高级设置中的“消息时效” |

#### Scenario: 从动态跳到记忆
- **WHEN** 管理员点击一条私信条目的“记忆”入口
- **THEN** 设置页“记忆”项打开，并选中该条所属账号、用户的私信身份，不显示其公开身份的记忆

#### Scenario: 计费费用一致
- **WHEN** 管理员在动态条目详情中查看一条回复的费用，再打开设置页“计费”项的调用流水
- **THEN** 两处显示的是同一条原调用流水，金额一致

#### Scenario: 记忆策略的位置
- **WHEN** 管理员要修改近期互动数量
- **THEN** 在设置页“记忆”项点页头“高级设置”，在打开的窗口中修改并保存，保存后下一轮生效，不恢复业务

### Requirement: 健康与日报分组排版

设置页“健康与日报”项 MUST 把非正常指标集中在顶部一块：标题显示“需关注 N 项”或“异常 N 项”与采样时间，每项一行显示中文名称、完整说明和“去处理”入口；全部正常时这一块改为一行“全部正常”与采样时间。其下 MUST 按运行、采集、发送、浏览器、账号、基础设施分组展示全部指标，每组标题注明“全部正常”或“N 项需关注”；正常指标只显示状态圆点与中文名称，说明在悬停或聚焦时显示，非正常指标在组内以告警色突出。宽度大于 1100px 时各组三列排列。账号检查结果 MUST 并入“账号”组，显示检查时间和“检查计划”入口，同一检查不得在页面上出现两次。每个已知指标 MUST 有中文名称；未知指标归入“其他”组并显示其标识，不得使用同一个通用名称代替多个指标。每日日报 MUST 以表格展示，每天一行，直接显示调用次数、token、估算费用、公开与私信的入站／回复／失败、响应时间中位数与 P90、告警数，金额按紧凑精度、未知值显示“—”。告警历史默认收起；健康与披露配置放在高级设置中；刷新位于页头。本要求只改变展示，指标判定、告警、日报内容与配置含义不变。宽度不超过 860px 时，指标改为单列，日报表格在自身容器内横向滚动，页面整体不得横向溢出。

#### Scenario: 多数指标正常
- **WHEN** 健康接口返回 20 项指标，其中 3 项账号指标需关注
- **THEN** 顶部一块列出这 3 项的名称、说明和“去处理”；分组区“账号”组标注“3 项需关注”，其余组标注“全部正常”且只显示圆点与名称；在 1440×868 窗口内不滚动即可看到全部 20 项

#### Scenario: 查看正常指标的说明
- **WHEN** 管理员把指针移到“发送进度”上
- **THEN** 显示其状态和说明“发送进展正常”

#### Scenario: 账号检查不重复
- **WHEN** 健康接口同时返回三项账号合规指标和账号检查结果
- **THEN** 三项检查在顶部需关注块与“账号”组中按上述规则各出现一次，组内显示检查时间和“检查计划”入口

#### Scenario: 指标缺少名称映射
- **WHEN** 健康接口返回一个页面未登记的指标标识
- **THEN** 该指标出现在“其他”组，名称显示其标识，状态与说明照常显示

#### Scenario: 查看日报
- **WHEN** 已归档三天日报
- **THEN** 日报表格显示三行，每行直接显示当天的调用、token、费用、两个渠道的入站／回复／失败、响应时间和告警数，无需逐行展开

#### Scenario: 窄屏查看健康页
- **WHEN** 管理员在 375px 宽度下打开“健康与日报”
- **THEN** 指标单列显示，日报表格只在表格区域内横向滚动，页面没有整体横向溢出

## ADDED Requirements

### Requirement: 运行与发送排版

“运行与发送”项 MUST 依次显示：运行模式（草稿、自动两张并排小卡，选中即保存）；发送上限与回复时段两张并排卡片；高级设置。发送上限 MUST 是一张小表，公开回复与私信各一行，列为每小时上限、每天上限（私信为近 24 小时）和已用（本小时、今天或近 24 小时，带用量条）。回复时段 MUST 用大字显示不回复的时间区间、当前是否可以回复，并提供“跟随早晚安”开关。高级设置包含每轮最多处理、晚安后关闭延迟和账号字数上限（原创与公开回复的上限、计数方式、检查时间和“重新读取”）。消息时效 MUST NOT 出现在本项。各设置的取值范围与保存规则不变。

#### Scenario: 打开运行与发送
- **WHEN** 管理员在 1440×868 窗口打开“运行与发送”
- **THEN** 不滚动即可看到运行模式、发送上限表、回复时段和高级设置标题行；页面上没有消息时效输入框

#### Scenario: 账号字数在高级设置中
- **WHEN** 管理员要查看公开回复的字数上限
- **THEN** 展开高级设置即可看到上限、计数方式与检查时间，并可点“重新读取”

### Requirement: 定时任务排版

“定时任务”项 MUST 在顶部显示“今天的安排”时间轴（北京时间 00:00–24:00）：每个任务在计划时间显示一个点和名称，未启用的任务为空心浅色；回复时段关闭的区间以斜线底纹标出；当前时间以竖线标出。时间轴下方 MUST 以表格按计划时间从早到晚列出任务，每个任务一行：启用开关、名称、计划时间、上次执行（时间与结果，从未执行显示“从未执行”）；会向 X 发帖的任务名称旁 MUST 始终显示“会发到 X”；“单次执行”按行内操作显隐规则显示，计费任务带“计费”标记。主循环间隔与宿主健康检查间隔（只读）放在高级设置中；页尾提供“查看任务执行历史”入口。任务计划含义与保存规则不变。

#### Scenario: 打开定时任务
- **WHEN** 管理员打开“定时任务”，早安帖与晚安帖未启用
- **THEN** 时间轴上早安帖、晚安帖为空心点，23:30–08:00 显示为不回复区间；表格中两者名称旁显示“会发到 X”，开关为关闭

#### Scenario: 修改任务时间
- **WHEN** 管理员把记忆补整理的时间从 03:00 改为 04:00 并保存
- **THEN** 表格顺序与时间轴位置随之更新，保存不恢复业务

### Requirement: 消息分级与过滤排版

“消息分级与过滤”项 MUST 在顶部用一条统计显示今日公开（已用 / 上限）、近 24 小时私信（已用 / 上限）、排队数、今日过滤数和骚扰冷却人数，刷新为统计条末端的图标按钮。其下两张并排卡片：“优先处理”（优先公开账号、优先私信会话）和“过滤”（广告关键词、纯问候词）；名单与关键词 MUST 以小标签显示，每项可删除，通过输入后回车或“＋ 添加”增加，保存时与原换行列表等价。排队明细、过滤原因与骚扰冷却名单 MUST 在为空时合并为一行说明，有内容时展开为表格，冷却名单每行提供“解除冷却”。高级设置包含消息时效与同文重复降优先阈值及其说明。

#### Scenario: 都为空
- **WHEN** 当前没有排队消息、今天没有过滤、没有骚扰冷却用户
- **THEN** 三者合为一行说明，不显示空表格

#### Scenario: 添加关键词
- **WHEN** 管理员在广告关键词输入“返现”后回车并保存
- **THEN** 关键词标签中出现“返现”，保存后的设置与在原文本框中新增一行“返现”相同

### Requirement: 记忆项排版

设置页“记忆”项页头 MUST 只有“用户记忆”“角色经历”两个视图切换和“高级设置”按钮；高级设置窗口包含近期互动数量、近期窗口（天）和原文保留（天）。“用户记忆”视图打开时如果没有选中身份，MUST 自动选中列表中的第一个身份，不显示空白详情。身份列表每项两行：名称与渠道标签；记忆条数与最近互动时间；搜索框回车即搜索，不另设“搜索”按钮。详情页头显示名称、渠道、记录状态与最近互动，以及“召回预览”“重新整理（计费）”和 ··· 菜单，“遗忘并停止记录”在 ··· 菜单中并保留原有确认。详情主栏以“长期记忆 / 互动记录 / 近期可见”标签切换，每条一行、来源与日期靠右；侧栏显示身份关联与整理进度。“角色经历”视图 MUST 以一条一行的列表显示经历，“＋ 登记经历”打开窗口填写，不再使用折叠表单；没有经历时只显示一行提示。

#### Scenario: 打开记忆项
- **WHEN** 管理员打开“记忆”项，列表中有一个身份 x:cn4bie
- **THEN** 自动选中 x:cn4bie，右侧显示其详情，不出现“选择用户或会话”的空白提示

#### Scenario: 遗忘仍需确认
- **WHEN** 管理员在 ··· 菜单中选择“遗忘并停止记录”
- **THEN** 系统先请求确认，确认后才执行，行为与原按钮相同

### Requirement: 浏览器接管与采集来源排版

“浏览器接管”与“采集来源”MUST 保持为两个设置项。浏览器接管顶部一行显示账号、登录状态、接管状态与账号检查入口；未接管时主区 MUST 显示与远程桌面同等大小的占位区，中央是说明与“接管并连接”，接管后远程桌面显示在同一区域。采集来源 MUST 以紧凑表格列出各来源，每行显示状态圆点、名称、启用状态和浅色说明；来源状态仍只在打开该项时读取，页头提供刷新。

#### Scenario: 未接管时
- **WHEN** 管理员打开“浏览器接管”且浏览器未连接
- **THEN** 主区是桌面大小的占位区，中央有“接管并连接”，页面没有大片无用途的空白

#### Scenario: 查看采集来源
- **WHEN** 管理员打开“采集来源”
- **THEN** 四个来源各占一行，名称、状态与说明在同一行，“通知全部栏引用”显示未启用

### Requirement: 日志可读排版

“日志阶段与队列”项的日志视图 MUST 每行显示时间、类别标签和中文摘要；已登记的事件类型按类型生成摘要（例如浏览器进程重启、服务启动并保持暂停、删除人设「名称」），未登记的类型显示类型标识；原始内容 MUST 以浅色截断显示在行尾，点击该行展开完整内容。日志 MUST 按北京日期插入“今天 / 昨天 / 日期”分隔行。级别、渠道、内容或关联 ID 搜索、时间范围 MUST 排成一行，修改即生效，不另设“筛选日志”按钮；“暂停实时日志”保留。日志仍只显示运行事件，不显示消息正文。“阶段”“队列”视图同样采用一行一条的表格。

#### Scenario: 浏览器重启日志
- **WHEN** 日志中有一条 browser-restart 事件
- **THEN** 该行显示“浏览器进程重启”，原始 JSON 以浅色显示在行尾，点击后展开全文

#### Scenario: 跨天日志
- **WHEN** 日志包含今天和昨天的事件
- **THEN** 两天之间有“昨天 · 10/28”分隔行

### Requirement: 任务执行历史合并重复

“任务执行历史”项 MUST 以表格显示执行记录，列为任务、结果、时间、触发方式、耗时和费用（无费用显示“—”）。同一任务连续多次结果相同的执行 MUST 合并为一行，显示次数（例如“完成 ×85”）、起止时间与平均耗时，点击展开逐次记录；失败的执行 MUST NOT 被合并进成功的行。顶部 MUST 提供按任务筛选（每项显示该范围内的次数）和“只看失败”；点击一行展开详情与关联调用。分页加载更早记录时合并规则同样适用。

#### Scenario: 健康检查不再刷屏
- **WHEN** 最近 7 小时宿主健康检查每 5 分钟成功一次，中间有一次每日日报
- **THEN** 表格显示两行合并的宿主健康检查与一行每日日报，而不是八十多行

#### Scenario: 中间有一次失败
- **WHEN** 连续 30 次宿主健康检查中第 12 次失败
- **THEN** 失败的那次单独一行显示，前后成功的分别合并

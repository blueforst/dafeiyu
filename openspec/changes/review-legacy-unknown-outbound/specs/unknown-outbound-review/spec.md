# 历史未知公开出站的精确人工封存

## Purpose

为已取得明确人工决定的历史未知公开回复提供可审阅、可撤销且永久绑定原对象的封存能力，使旧项不再单独阻塞其他新公开互动，同时保留发送结果未知这一事实、原始证据、持续回查、渠道额度和所有防重复提交规则。

## ADDED Requirements

### Requirement: 仅审核完整的历史公开未知对

系统 MUST 只允许当前工作账号下、public 渠道、公开回复类型、消息与持久出站完整关联且同时为 unknown 的一对对象被人工封存。缺少原提交时间、冻结正文或目标，归属、来源、目标、事件、消息或草稿不一致时 MUST 拒绝；独立帖子、私信、无关联出站的消息及正在提交的对象不得套用该能力。

#### Scenario: 精确旧公开回复
- **WHEN** 当前账号的一条公开回复及其唯一关联出站均为 unknown，冻结正文、目标、事件与原提交时间完整一致
- **THEN** 管理员能够取得该精确对象的可审核预览

#### Scenario: 记录缺失或正在提交
- **WHEN** 原消息缺失、关联冲突，或任一对象已进入 sending／submitting
- **THEN** 系统拒绝封存并保留通道阻塞，不自动修复或改变原记录

### Requirement: 审核需要当前修订及明确确认

系统 MUST 仅在当前账号暂停且没有在途业务时接受封存和撤销；请求必须携带当前对象修订、明确确认及对应操作。预览后的对象状态、回执或已有审核发生变化时 MUST 拒绝过时请求。审核 API MUST 沿用现有管理鉴权、控制请求标记和来源检查，不得触发模型、浏览器、暂停、接管或恢复操作。

#### Scenario: 读后对象发生变化
- **WHEN** 管理员取得预览后，原对象的回执、状态或审核已变化，再提交旧修订
- **THEN** 系统返回冲突并要求重读，不新建或覆盖审核

#### Scenario: 缺少确认或处于运行中
- **WHEN** 请求没有明确确认、使用错误动作，或当前处于 running、manual、draining 或 busy
- **THEN** 系统拒绝操作，运行状态和原对象保持不变

### Requirement: 永久精确绑定且可撤销

已确认封存 MUST 永久绑定原工作账号、public 渠道、出站、消息及冻结内容，无到期与续期。管理员 MUST 能明确撤销；撤销后旧审批请求不得重新激活该决定，重新封存须再次取得当前修订并确认。正文、目标、账号、来源、提交标识或冻结内容变化以及对象进入真实终态后，旧审核 MUST 不再适用。

#### Scenario: 重启与重复确认
- **WHEN** 已封存的精确对象没有改变，服务重启或同一审核请求被再次提交
- **THEN** 原封存继续生效，重复请求不创建新审核或修改原审核时间

#### Scenario: 撤销后重放旧请求
- **WHEN** 管理员撤销封存后重放原审批请求
- **THEN** 系统拒绝重新激活，原 unknown 再次阻塞其他公开新项

#### Scenario: 冻结内容改变
- **WHEN** 已封存对象的正文、目标、原提交时间或关联消息改变
- **THEN** 原封存失效，系统恢复阻塞，不自动更新审核指纹

### Requirement: 仅解除原项对其他新项的通道阻塞

封存 MUST 仅解除精确旧项对同渠道其他新项的阻塞，不得修改原消息或出站的 unknown 状态、原回执、冻结正文、目标、提交时间及浏览器日志；原项仍 MUST 正常回查且不能重新排队、重新生成后提交、替换正文或创建第二次发送。

#### Scenario: 新回复在已封存旧项旁执行
- **WHEN** 唯一旧阻塞项已有效封存，新的公开入站满足所有既有生成和发送条件
- **THEN** 新消息可以经过正常工作流处理，旧项仍显示 unknown 并继续回查，未发生第二次原提交

#### Scenario: 旧项终于取得真实回执
- **WHEN** 已封存旧项在正常回查中取得可靠唯一平台回执
- **THEN** 原出站依真实结果正常收束，不把封存记录当作平台回执

### Requirement: 新未知结果和异常审核继续阻塞

系统 MUST 检查全部当前阻塞项；任何其他新 unknown、未审核项、提交中项、不完整关联或损坏审核记录 MUST 继续阻塞该渠道。一个旧项的封存不得自动应用到另一条记录，不得通过扫描条数上限漏掉后续阻塞项。仅更新正常回查时间和未知原因不得使未改变冻结内容的已有封存失效。

#### Scenario: 后续回复进入未知
- **WHEN** 旧项已封存后，另一条新公开回复进入 unknown
- **THEN** 公开通道再次阻塞，系统只回查新未知项，不自动封存或继续发送

#### Scenario: 未知项超过回查批量上限
- **WHEN** 当前 unknown 数量超过回查单批上限，未审核项位于后部
- **THEN** 系统仍识别该未审核项并阻塞新的公开提交

#### Scenario: 普通回查没有新证据
- **WHEN** 原精确对象只更新回查时间或未知原因，冻结内容和状态保持不变
- **THEN** 已生效封存继续有效，原项仍继续回查

### Requirement: 所有入口共享剩余发送限制

自动回复、人工批准稿、主动帖子和健康可发送性 MUST 使用同一封存规则。封存不得清零小时或每日提交计数，不得绕过身份、时段、退避、额度、可靠目标、遗忘、临界资源或唯一回执规则，也不得解除原未知出站对浏览器会话的保护。

#### Scenario: 已封存但额度已满
- **WHEN** 旧项已封存，公开通道小时或每日额度仍已满
- **THEN** 自动回复、批准稿和主动帖子均继续等待额度，不因封存增加可提交数量

#### Scenario: 浏览器达到临界资源
- **WHEN** 旧项已封存但浏览器触发临界资源保护
- **THEN** 原会话继续受保护，系统只进行允许的回查，不启动新业务

### Requirement: 脱敏审计与可回退

系统 MUST 提供受鉴权的封存预览、状态和撤销结果，日志只记录操作及关联元数据，不复制正文、密钥或认证信息。部署不得新增数据库 schema 迁移；回退到不识别封存的旧版本时 MUST 保留原 unknown 与审核记录，并恢复旧通道阻塞行为。

#### Scenario: 管理员查看封存对象
- **WHEN** 管理员查看审核预览及常规日志
- **THEN** 可核对归属、状态、修订、冻结指纹及审核时间，原项未被显示为已发送，日志不含正文或凭据

#### Scenario: 回退原稳定版本
- **WHEN** 系统暂停排空后成对回退到不支持封存的稳定版本
- **THEN** schema14 和业务账本仍可用，旧 unknown 重新阻塞，不删除原审核或伪造回执

### Requirement: 真实公开验收与限定清理

真实验收 MUST 通过正常生产采集、任务、模型及持久出站链路，逐场景记录平台目标、生成调用、唯一发送回执和独立读回。获授权使用的对端账号 MUST 先核对当前登录身份；验收完成后只清理本轮登记新增的公开内容，保留私信、旧公开内容及业务账本。缺乏某来源真实样本时不得由其他来源成功代替其验收。

#### Scenario: 公开矩阵取得实际结果
- **WHEN** 主动发帖、提及、搜索、自帖评论及后续回复分别获得真实样本
- **THEN** 每个场景分别记录采集来源与原目标、一次提交及唯一回执，不以补录或其他场景结果冒充通过

#### Scenario: 清理本轮测试内容
- **WHEN** 公开测试完成并按各账号操作删除已登记的本轮新增帖与回复
- **THEN** 逐条核对平台删除结果，保留本地原提交账本和所有私信，未确认删除的对象明确记为待处理

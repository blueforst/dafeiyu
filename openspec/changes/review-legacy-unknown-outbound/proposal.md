## Why

生产遗留的一条公开回复持续为 unknown，原始浏览器提交意图已缺失，且测试目标已被删除；现有通道门禁因此一直阻止新的公开互动。管理员已明确确认“封存并继续测试”，需要把这次精确人工决定保存为可撤销的例外，同时保留原始未知事实与防重复保护。

## What Changes

- 新增受鉴权的历史未知出站预览、封存与撤销能力，仅接受同账号、公开回复、完整关联且均为 unknown 的 message／outbox 一对。
- 封存永久绑定原账号、渠道、出站及消息的冻结指纹，没有到期与续期；撤销或冻结内容变化后恢复阻塞，不自动重新审批。
- 只让已封存旧项不再单独阻塞同渠道其他新项；原状态、原回执、journal、提交时间、额度计数和持续回查保留，原来源仍不能重排、重写或再次提交。
- 自动回复、人工批准稿、主动帖子与健康可发送性使用相同的阻塞判断；新 unknown、提交中出站或不完整记录继续阻塞。
- 在服务器隔离验证后，经正常生产链路实测主动发帖、提及、搜索、自帖评论和后续回复；使用已授权登录的 Ceyi 账号互动，记录真实唯一回执，完成后只删除本轮新增公开内容，保留私信与业务账本。

## Capabilities

### New Capabilities

- `unknown-outbound-review`：精确历史 unknown 对的永久人工封存、撤销、失效、跨入口通道门禁及审计，保留原出站事实与回查。

### Modified Capabilities

无。本轮通道例外针对既有 change 中尚未归档的 unknown 规则，以新增独立增量规格明确覆盖范围，不提前改写主规格。跨帖同一人的公开上下文由独立 `add-cross-thread-public-context` 提案承载，本提案只记录联合真实验收依赖。

## Impact

涉及历史审核服务、管理 API 接线、工作流和健康的 unknown 阻塞判断及隔离回归；使用 schema14 已有 runtime KV，不新增迁移，不升级浏览器内核，不增加模型请求或前端审核界面。原生产分支、模型、人设、profile、记忆和未发布安全候选保持各自范围；发布、真实平台结果、计费、清理与回退证据分别记录。

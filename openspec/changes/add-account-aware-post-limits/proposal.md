# 按账号权限校验 X 发帖字数

## Why

当前公开回复和定时发帖统一使用 `twitter-text` 的默认 280 加权字符校验，账号身份只识别登录与人工验证状态。具备长帖权限的账号也被限制为短帖，模型在生成前不知道可用字数，超长结果只能在生成后失败；需要按当前账号的实际能力统一生成和发送约束。

## What Changes

- 识别当前登录账号对原创帖子、公开回复的实际长帖能力、上限及计数规则，记录账号归属、来源、检查时间与有效状态；订阅名称、蓝标和历史成功记录不能单独证明权限。
- 普通账号或能力未知／过期时沿用 280 加权字符；只有取得当前账号的可靠能力证据并验证对应计数规则后，才启用该类型的长帖上限。区分平台字数上限与模型 token 上限。
- 生产公开回复、早晚安帖子及公开试聊共用长度策略：生成前告知限制，生成后校验，浏览器提交前复核；账号切换、权限降级或缓存过期不能沿用旧权限发送。
- 移除公开正文在模型解析、出站存储及浏览器侧各自固定为 4,000 的不一致门槛，改为同一策略和有界输入保护；私信现有规则保持。
- 本地超长或权限变化明确区分为“未提交”，保留草稿和已有模型费用，不点击、不自动截断／拆帖／反复生成，也不触发平台拒绝的四小时冷却。已经开始提交的 unknown 仍只回查。
- 长帖回执读取完整正文，避免把时间线截断文本当成完整结果；主页面与主程序显示当前生效上限、计数单位、证据状态与拦截原因，试聊显示所用策略。

## Capabilities

### New Capabilities

- `x-posting-limits`：账号绑定的公开长度能力、计数策略、生成与提交校验、未提交结果及可观察状态。

### Modified Capabilities

无。现有主规格中的模型配置、导航与记忆要求不变；本能力补充尚未归档的 `add-seven-page-production-bot` 消息与任务流程，不把其增量规格提前迁入主规格。

## Impact

- 影响 `src/types.ts`、`src/model.ts`、`src/persona.ts`、`src/workflow.ts`、`src/production-tasks.ts`、`src/outbox.ts`、`src/browser.ts`、`src/transport.ts`，以及状态接口、公开试聊和主页面／主程序展示。
- 新增共用长度策略和账号能力快照；扩展内部浏览器结果和增量持久元数据。沿用当前鉴权、账号检查、互斥、冻结正文、平台回执、小时发送额度及平台拒绝退避。
- 保留现有 Pi／OpenCode 会话路由、正式回复默认 4096 token 和 CommandCode 未定价语义；不因为开通长帖就自动增大模型输出或调用次数。
- 不包含 HTTP／模型 RPM、TPM 限流或费用封顶，不扩大私信长度，不引入多账号轮换、自动订阅、文章、引用帖、媒体及新的发帖入口。
- 本次只创建规划文件。构建、自动化测试与后续平台验收在服务器执行；真实发帖另按实施阶段取得的授权执行，创建提案不改变线上运行状态。

## References

2026-10-28 核对的官方资料：

- [X 字符计数](https://docs.x.com/fundamentals/counting-characters)：普通帖子使用 280 加权字符，说明中文、emoji 与 Unicode 计数。
- [X Premium](https://help.x.com/en/using-x/x-premium)：当前列出各 Premium 档位的长帖能力及最高 25,000 字符，并包括回复；这不是当前登录账号的权限证明。
- [X 发帖帮助](https://help.x.com/en/using-x/how-to-post)：长帖步骤仍列 4,000 字符，与 Premium 页面存在差异。因此本提案以实际账号和当前网页能力验证作为放开依据，长帖计数单位及完整回执结构列入实施前置验收。

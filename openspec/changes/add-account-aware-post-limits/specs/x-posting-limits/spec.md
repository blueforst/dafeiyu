# X 账号发帖长度能力

## Purpose

规定当前登录账号的公开发帖长度能力如何被确认、展示并用于生成与发送，使普通账号、长帖账号和权限未知状态具有一致且可验证的处理行为。该能力同时约束原创帖子和公开回复，防止账号切换、权限过期或截断回执导致越权提交、重复发送和错误成功报告。

## ADDED Requirements

### Requirement: 账号与操作类型绑定的能力

系统 MUST 分别确认当前登录账号的原创帖子和公开回复能力，展示上限、计数单位、来源、检查时间及有效状态。订阅名称、认证标记、其他账号能力和历史发帖成功不能单独作为放开长帖的依据。

#### Scenario: 只有认证标记
- **WHEN** 页面能识别账号认证标记，但没有当前账号可靠的长帖能力证据
- **THEN** 系统显示长帖能力未知，沿用短帖限制，不把认证标记当作放开依据

#### Scenario: 只确认原创长帖能力
- **WHEN** 已确认原创帖子可用长帖，但不能确认公开回复的相应能力
- **THEN** 原创帖子使用确认后的上限，公开回复继续使用短帖限制

#### Scenario: 更换登录账号
- **WHEN** 当前登录账号与已保存能力所属账号不同
- **THEN** 旧能力立即失效，原工作流按既有身份变化规则暂停，旧草稿不转交新账号

### Requirement: 保守回退和准确计数

系统 MUST 对普通账号或未知、失效、证据冲突的能力使用 280 加权字符限制。只有账号能力、对应上限和计数规则均已确认时才允许超出短帖；不得把模型 token、字符串存储长度或短帖加权值直接当成长帖计数。

#### Scenario: 普通账号中文边界
- **WHEN** 普通账号提交由 140 个或 141 个普通汉字组成的公开正文
- **THEN** 前者通过长度校验，后者被拦截；通过长度校验不代表其他发送检查已通过

#### Scenario: 长帖上限明确但计数未确认
- **WHEN** 已读取长帖资格和数字上限，但当前适配器尚未验证中文、emoji 或组合字符的计数规则
- **THEN** 系统继续使用短帖限制并说明计数规则未确认

#### Scenario: 长帖长度边界
- **WHEN** 当前账号某类型的上限及计数规则已确认
- **THEN** 按该规则恰好达到上限的正文通过，超过一个计数单位的正文被拦截，不再被旧的公开正文 4,000 字符门槛提前拒绝

#### Scenario: 权限检查失败
- **WHEN** 能力检查超时、页面结构变化或来源结果相互矛盾
- **THEN** 系统显示未知与回退原因，短帖仍可按原工作流处理，不反复尝试提交长帖

### Requirement: 生成与试聊使用同一限制

系统 MUST 在生产公开回复和定时帖子生成前提供对应账号、操作类型及计数限制，并在生成后校验。公开试聊使用当前账号的同一策略；没有可靠账号时明确模拟普通账号。字数上限不得自动修改模型输出 token 配置或增加生成次数。

#### Scenario: 普通账号生成回复
- **WHEN** 模型开始为普通账号生成公开回复
- **THEN** 当次提示词包含短帖计数限制，生成结果按同一规则校验

#### Scenario: 模型返回超长正文
- **WHEN** 生成结果结构有效但长度超过当次限制
- **THEN** 系统保留有界草稿、实际计数、上限、失败原因和已发生模型费用，不发送、不截断、不拆帖，也不自动追加模型请求

#### Scenario: 未登录时公开试聊
- **WHEN** 管理员执行公开试聊但没有可靠当前账号
- **THEN** 试聊明确显示使用普通账号的模拟限制，不读取其他账号权限，不创建真实出站

### Requirement: 提交前复核与入口一致

系统 MUST 在公开回复和原创帖真正提交前重新核对当前账号、对应能力、正文、控制状态及既有发送条件；浏览器必须独立校验，不能信任调用方自报上限。读取状态或刷新能力不得自动恢复业务、抢占人工接管或触发发帖。

#### Scenario: 生成期间权限降级
- **WHEN** 草稿按长帖能力生成，但提交前只能确认普通账号能力
- **THEN** 系统按新的短帖限制复核，超长草稿停止提交并显示权限变化原因

#### Scenario: 直接调用内部发送入口
- **WHEN** 调用方跳过应用层，向浏览器发送超过当前账号限制的正文或自报更高上限
- **THEN** 浏览器按自身确认的当前能力拦截，不点击提交按钮

#### Scenario: 人工接管时读取或刷新
- **WHEN** 人工接管期间管理员读取限制或请求刷新
- **THEN** 系统只展示已有状态，明确提示刷新不可用，不操作人工页面、不改变控制模式

### Requirement: 明确未提交与平台拒绝分离

系统 MUST 将可证明尚未开始提交的长度或能力拦截报告为“未提交”，保留草稿和可回查原因，不计入发送额度、不启动平台拒绝冷却。平台真正明确拒绝仍沿用既有额度和四小时退避；无法证明未提交时继续按未知结果处理。

#### Scenario: 提交前发现超长
- **WHEN** 浏览器在保存提交意图和点击之前发现正文超长
- **THEN** 系统持久记录未提交结果，停止该出站，界面可查看原因，公开小时额度与通道冷却不变

#### Scenario: 未提交结果响应丢失
- **WHEN** 浏览器已持久确认本次被预检拦截，但应用没有收到响应
- **THEN** 应用先保留未知状态，之后可用同一出站标识回查为未提交，不新建发送或自动重试

#### Scenario: 已开始提交后断线
- **WHEN** 已保存提交意图或无法排除点击发生，随后连接中断
- **THEN** 系统记录 unknown，只允许回查，不把它重分类为安全可重发的未提交

### Requirement: 权限变化不影响既有回查

系统 MUST 允许对已提交或结果未知的历史出站继续核对原始回执，不能因为当前权限变低或原正文超过新上限而跳过回查，也不能改变已冻结正文或重新发送。

#### Scenario: 长帖提交后订阅失效
- **WHEN** 长帖已经进入 unknown，之后账号失去长帖能力
- **THEN** 系统仍按原账号、原正文、原目标及原提交时间回查，不再尝试提交，不因新上限直接判定旧发送失败

### Requirement: 完整长帖回执

系统 MUST 仅在取得完整正文并满足原有作者、目标关系、时间及唯一平台 ID 校验时确认长帖成功。截断预览、相同前缀和“显示更多”占位内容不能作为完整正文匹配证据。

#### Scenario: 时间线只返回长帖前缀
- **WHEN** 回查只读取到与发送正文前缀相同的截断内容
- **THEN** 系统保持 unknown，并继续允许读取完整详情，不把前缀相同视为确认

#### Scenario: 原创长帖取得完整证据
- **WHEN** 原创长帖取得完整正文、正确作者、非回复关系、提交时间范围及唯一平台 ID
- **THEN** 系统确认对应出站，平台 ID 和 URL 可在受鉴权详情中查看

#### Scenario: 长回复取得完整证据
- **WHEN** 长回复取得完整正文、正确作者、准确被回复目标、提交时间范围及唯一平台 ID
- **THEN** 系统确认对应回复，不把同文原创帖子或其他目标下的回复当作成功

### Requirement: 可观察状态与兼容行为

系统 MUST 在现有页面和受鉴权接口展示账号对应的生效上限、计数单位、能力有效性及长度拦截详情；常规日志仅包含关联标识和计数元数据。既有私信长度、小时额度、互斥、鉴权、暂停、模型计量及七页导航保持兼容。

#### Scenario: 查看被拦截的草稿
- **WHEN** 管理员查看某条超长草稿或对应定时任务
- **THEN** 详情显示实际计数、当次上限、操作类型及拦截原因，普通日志不复制正文或认证数据

#### Scenario: 账号拥有长帖权限
- **WHEN** 当前账号已确认能够发送长帖
- **THEN** 正式模型默认仍为 4096 token，公开小时额度和私信长度不因此提高，保存或刷新能力不恢复暂停业务

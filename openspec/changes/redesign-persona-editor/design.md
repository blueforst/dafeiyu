# 人设编辑区目录加编辑改版设计

## 背景与决定来源

范围只包括人设模式下“我的人设”和内置预设的编辑区，也就是 `persona-editor.js` 中 `editor()` 渲染的部分。以下页面不改：

- 左侧人设列表、顶栏和主区页头按钮；
- 日程、试聊、动态提醒和回放页面。

管理员逐项确认的决定：

| 决定 | 管理员原话或选择 |
| --- | --- |
| 不用卡片网格、不用等大预览卡 | “不要再折腾这种卡片式的排版了” |
| 采用“目录 + 编辑”，不用“对开两栏” | 选 B |
| 目录项不加占比条或百分比 | “还是不加了, 太丑了” |
| 目录各项之间有明确分界 | “侧边栏不同选项的分界不是很明确” |
| 触发卡各字段之间有明确分界 | “触发卡详情分界也不明确” |
| 触发卡详情和分区正文都用可直接编辑的文本框 | “触发卡详情应该是可以直接编辑的文本框 / 角色定义也是” |
| 可编辑与只读在外观上分开 | “让可编辑内容和不可编辑内容区分开” |
| 只改人设编辑区 | “我只让你改人设中的人设页, 没让你改其他页面” |

下面几项由规划时决定，标为（规划时决定）：

- 卡名提示语。草图原写“只给自己看”，但触发卡目录会把标题发给模型，因此改为“目录里显示的名称，模型也会看到”。
- 第三组名称。草图原写“系统”；这一组还要放建议简介，所以改为“只读”。
- 选中项不写进地址。
- 860–1100px 宽度时目录收窄到 260px。

[mockups/persona-editor.html](mockups/persona-editor.html) 已按上面两处措辞修正。

## 1. 版式与尺寸

- **主区布局**：`ws.main` 挂载编辑区时加 `pe-host` 类，取消主区自身的内边距和滚动，改为两列网格 `grid-template-columns: 300px minmax(0,1fr)`。卸载编辑区时去掉这个类。回放、动态提醒、预设以外的路由不加这个类，原有滚动方式不变。
- **目录**：独立纵向滚动，与编辑区之间用 `--ws-border` 分隔线隔开。
- **编辑区**：纵向 flex。页头和说明固定在上方，字段区占满剩余高度。左右内边距 40px；窄屏时 16px。
- **宽度断点**：
  - 861–1100px：目录宽 260px（规划时决定）。
  - ≤ 860px：目录隐藏，编辑区顶部出现下拉选择，左侧人设列表沿用工作区抽屉。
- **令牌**：样式只使用 `DESIGN.md` 的令牌。
  - 目录项：`--r-md`。
  - 输入框：`.input` 规格，`--ws-border-strong` 描边，`--r-md` 圆角，聚焦时用 `--ws-brand` 描边加 `--ws-brand-soft` 外圈。
  - 只读区：`--ws-fill` 底色，`--r-lg` 圆角。
  - “只读”标签：`--r-sm`。
  - 深色模式自动换成深色令牌，不写死颜色和尺寸。
- **字号**：正文 14px，行高 1.8；说明和字数 12–12.5px；目录项名称 13.5px，字重 600。

## 2. 目录

### 2.1 条目与分组

由当前人设或预设生成一个条目数组 `items`，每项形如 `{key, group, title, count, preview, readOnly}`：

| 分组 | key | 内容 |
| --- | --- | --- |
| 始终生效 | `s:<index>` | `persona.sections` 按顺序排列；标题为空时显示“未命名分区” |
| 触发卡 | `t:<id>` | `persona.triggers` 按 `order` 排列；标题为空时显示“未命名卡片” |
| 只读 | `fixed` | 固定规则（`item.fixedRules`） |
| 只读 | `bio` | 建议简介。来源与现有 `bio()` 相同，取 `item.disclosure`、来源预设或预设本身中的 `bioSuggestion`；没有时不出现 |

- **字数**：
  - 分区：`content.length`。
  - 触发卡：`condition.length + content.length`，与页头合计的算法一致。
  - 固定规则：全文长度。
  - 组标题右侧写组内合计。只读组不写合计，因为固定规则不计入人设字数。
- **预览**：
  - 换行替换为空格，用 CSS `line-clamp: 2` 截断。
  - 触发卡显示 `condition`；若以统一前缀“对方聊到下列说法或类似意思时使用：”开头，展示时去掉该前缀，数据不改。
  - 内容为空时显示浅色“（空）”。
  - 固定规则显示“只读 · 所有人设共用”，建议简介显示“只读 · 账号披露”。
- **组标题**：用 `h3` 渲染。“始终生效”“触发卡”“只读”是标题的可读名称，测试里 `getByRole('heading', {name:'始终生效'})` 继续可用。
- **分隔线**：
  - 相邻项之间：`::before` 画 1px `--ws-border`，左右各缩进 10px。选中项上方和下方的线都隐藏。
  - 组与组之间：`--ws-border-strong`。

### 2.2 选中与未保存标记

- **选中项**：`selected` 保存当前 key。打开人设时为 `s:0`。选中项与草稿一起存进 `drafts`，在同一会话里切换人设再切回来时恢复。选中项不写进地址（规划时决定）。
- **切换选中项**：只重绘编辑区和目录中两项的选中状态，不经过离开确认。草稿始终在 `persona` 对象中，切换不会丢失。
- **未保存标记**：从 `saved` 解析出已保存快照，按 key 比较分区或卡片；不同时在名称后显示 6px 的 `--ws-warning` 圆点，并带读屏文字“未保存”。删除的卡片不再显示；新加的卡片一律算作未保存。
- **随输入刷新**：输入时只更新当前目录项的字数、预览和标记，不重绘整个目录，以免打断输入焦点。

### 2.3 触发卡操作

- **开关**：用 `button role="switch"`，带 `aria-checked`。点击时阻止冒泡，只改 `enabled`，然后调用 `update()`。预设中禁用。
- **添加**：触发卡组标题旁的“＋”保留原 id `trigger-add`。点击后追加 `{id: crypto.randomUUID(), title:'', condition:'', content:'', enabled:true}`，重新编号，选中新卡并把焦点放到卡名输入框。
- **拖动排序**：触发卡目录项可以拖动，只能在本组内移动；用指针事件实现，同时兼容触屏。松手后重新编号，标记未保存。键盘可以用编辑区“⋯”菜单里的“上移”“下移”完成同样的操作。
- **删除**：在“⋯”里点“删除卡片”，沿用现在不弹确认、保存后才生效的做法。删除后选中下一张卡；没有下一张时选上一张；一张都不剩时选最后一个分区。

## 3. 编辑区

- **页头**：名称（17px，字重 600）、所属组和字数，右侧是“‹ 上一项名称”“下一项名称 ›”。到第一项或最后一项时，对应按钮置灰禁用。触发卡页头的名称前有开关，最右侧还有“⋯”。
- **说明句**：放在页头下方，浅色普通文字。
  - 四个标准分区按标题取固定说明：
    - 角色定义：“你是谁、在哪儿运营、和谁聊”
    - 说话风格：“怎么说话——语言、长度、口吻、不用哪些开头”
    - 记忆与承诺：“能记住什么、不能答应什么”
    - 互动边界：“哪些话题不接、遇到挑衅和危机怎么办”
  - 自定义标题的分区不显示说明。
  - 触发卡：“对方说到哪些话时，模型额外读一段什么说明”。
  - 固定规则：“系统规则，每次回复都会带上；这里只能看，不能改”。
  - 建议简介：沿用“修改账号名称与简介需要管理员在 X 上操作”。
- **分区**：一个 `textarea.input`，id 保持 `persona-section-<index>`，`aria-label` 写分区标题，`flex:1` 撑满剩余高度，内容超出时在框内滚动。保留 `resize: vertical`；管理员手动拉高后，编辑区改为整体滚动。
- **触发卡**：三个字段纵向排列。每个字段有标题行：加粗名称、浅色提示、右侧字数。
  - 卡名：单行 `input`，提示“目录里显示的名称，模型也会看到”。
  - 什么时候用：`textarea`，随内容增高，最多 8 行，之后在框内滚动。
  - 内容：`textarea`，撑满剩余高度。
  - 三者的 `aria-label` 分别为“卡名”“什么时候用”“内容”。
- **输入处理**：沿用 `oninput → 改 persona → update()`。页头合计、20,000 字上限和保存按钮禁用的逻辑不变。

## 4. 只读内容

- **只读区**：`div.pe-readonly`，`tabindex="0"`，文字可以选中，不出现输入光标。页头标题旁加“只读”标签，状态同时用颜色和文字表达。
- **固定规则**：保留 id `fixed-rules`，显示全文。
- **建议简介**：只读区带 `aria-label="建议简介"`，下方放“复制建议简介”按钮和状态文字。复制成功提示“已复制”；剪贴板不可用时选中文字，并提示手动复制，逻辑沿用现有 `bio()`。
- **内置预设**：
  - 目录与人设相同，开关禁用。
  - 编辑区所有分区和卡片字段都按只读区渲染，触发卡的三个字段各自是一块只读区。
  - 主区页头保持“名称 + 只读模板 + 以此新建”，预设的一句话简介以浅色文字跟在名称后，过长时省略。

## 5. 窄屏（≤ 860px）

- 目录改为编辑区顶部的一行下拉，用原生 `select`，按组用 `optgroup` 分组；选项写名称和字数，未保存的项后面加“· 未保存”。
- 选择后编辑区切换到对应项；‹ › 按钮保留。
- 拖动排序在窄屏不提供，用“⋯”里的上移、下移。
- 375px 宽度下不得出现整体横向滚动。

## 6. 数据流、状态与副作用

- 不新增接口，也不改变请求。读取仍用 `GET /api/personas/:id` 和 `GET /api/persona/presets`，保存仍用 `PUT /api/personas/:id`，请求体和修订号校验不变。
- 只增加前端状态 `selected`；草稿缓存从 `{persona, revision, saved}` 扩展为 `{persona, revision, saved, selected}`。
- 没有模型调用，不产生费用，也不写入数据库。

## 7. 兼容与迁移

- 人设数据、导入导出文件、预设目录和接口都不变，不需要迁移。
- 保留的 DOM 标识：
  - `#persona-save`、`#persona-preset-create`、`#trigger-add`、`#fixed-rules`；
  - 选中分区输入框的 `#persona-section-<index>`；
  - “复制建议简介”按钮名称；
  - `aria-label="建议简介"`。
- 界面验收脚本需要迁移的地方：
  - 操作 `#persona-section-1` 等非默认分区前，先点目录中对应项；
  - 原来点“建议简介 · 账号披露”展开折叠块的步骤，改为在目录中点“建议简介”；
  - 原来以触发卡 `details` 展开为前提的步骤，改为在目录中选中卡片。
  - 业务断言全部保留，不能用新冒烟用例代替原有覆盖。
- 试聊右栏提示词中的 `ws-rule-card` 不在本提案范围内，不改。

## 8. 验证

所有验证只在服务器隔离环境 `/srv/role-workflow-proposals` 中进行：

- 构建、单元测试和 `dev/workspace-ui-test.sh` 全部套件通过。
- 在 375、860、1100、1280、1440 五种宽度，以及浅色、深色两种主题下截图。1440×868 下对照草图检查：
  - 目录一屏放下；
  - 分区输入框撑满编辑区；
  - 只读区为灰底，标有“只读”；
  - 没有占比条。
- 键盘操作：用 Tab 在目录项、开关、‹ ›、“⋯”和输入框之间移动，焦点框可见；“⋯”里的上移、下移和删除可以用键盘完成。
- 未保存场景：
  - 改一段后切换目录项，不弹出确认，修改仍在；
  - 切换到另一个人设时，仍然弹出原来的离开确认。
- 预设场景：所有内容只读，开关不可操作，“以此新建”行为不变。
- 截图交管理员确认后，才算视觉验收通过。

## 9. 与现有要求和其他提案的衔接

- `convert-trigger-cards-to-skills` 的“触发规则可视化管理”：编辑区仍然只有标题（卡名）、什么时候用、内容三个输入项，加启用开关和顺序调整；没有触发方式、关键词等选项。
- 同一提案的“内置人设预设”：目录列出预设的全部分区和触发卡，每项都能只读查看，页头只有“以此新建”。名称和一句话简介显示在主区页头。
- `add-persona-workspace` 的“角色预设的账号披露提醒”：建议简介仍可在人设页查看和一键复制，设为使用中时的提醒条不变。
- `add-persona-workspace` 的“工作区版式”“侧栏收起”“统一状态提示”：目录在主区内部，不是右栏；收起左侧人设列表后，主区变宽，目录和编辑区跟着变宽；离开确认只在切换人设或页面时出现。
- 与 `compact-settings-pages`（0.1.24 已实现）、`redesign-conversation-layout` 没有共用改动；样式只在 `style.css` 中新增 `pe-*` 类。

## 10. 失败处理与回退

- 人设读取失败时沿用现有 `errorBox` 和重试，目录和编辑区都不显示过期内容。
- 保存失败时沿用现有提示，草稿和选中项都保留。
- 回退方法：恢复 `persona-editor.js` 和 `style.css` 中本提案的改动。数据和接口没有变化，回退不影响已保存的人设。

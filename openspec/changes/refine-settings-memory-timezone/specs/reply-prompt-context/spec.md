# 回复提示词增量规格（时区中立）

## MODIFIED Requirements

### Requirement: 北京时间与时段

提示词末尾 MUST 提供精确到分钟的北京时间、星期和时段名称，并标明这是角色所在地的时间、对方的当地时间未知；当日日程部分只提供角色自己的当前时段，不包含分钟级时间。

#### Scenario: 北京时间深夜
- **WHEN** 服务器 UTC 时间为 15:30，北京时间为 23:30
- **THEN** 提示词显示“你这边”北京时间 23:30 与深夜时段，并说明对方当地时间未知，不出现 UTC 时间

#### Scenario: 同一时段内多次请求
- **WHEN** 同一时段内相隔数分钟处理两条消息
- **THEN** 两次请求的日程与时段部分相同，只有末尾当前时间不同

### Requirement: 迟到提醒

当消息具有可靠平台时间且早于当前时间超过配置阈值（默认六十分钟）时，系统 MUST 在提醒区加入迟到提醒，说明对方大约多久前发来，要求自然致歉一次；提醒 MUST NOT 要求按角色所在时段问候对方。平台时间不可靠时不得加入迟到提醒。

#### Scenario: 早上的消息晚上处理
- **WHEN** 一条北京时间 08:10 的消息在 20:30 被处理且时间可靠
- **THEN** 提醒区说明对方约十二小时前发来并要求自然致歉一次，不包含按晚上时间问候对方的要求

#### Scenario: 时间不可靠
- **WHEN** 消息缺少可靠平台时间
- **THEN** 提示词不包含迟到提醒

## ADDED Requirements

### Requirement: 不假设对方时区

固定系统约束 MUST 说明 X 用户分布在不同时区、角色不知道对方当地时间，并要求：除非对方在本次消息或近期往来中提到自己的时间或作息，回复不得按角色所在时间推断对方处于早上、晚上或深夜，也不得使用“这么晚还不睡”“早安”“晚安”等替对方假设时段的问候或调侃；角色可以偶尔说自己这边的时间或日程。该约束对所有人设相同，位于稳定前缀中，不增加模型请求。当日日程、回复时段和早晚安帖仍按北京时间，不受本要求影响。

#### Scenario: 北京深夜收到问候
- **WHEN** 北京时间 03:53 收到公开消息“你好呀”，对方没有提到自己的时间
- **THEN** 提示词包含不假设对方时区的约束；真实模型抽查中，回复不出现“还没睡”“熬夜”“深夜了”等对对方时段的假设

#### Scenario: 对方自己提到时间
- **WHEN** 对方发来“早安，我这边刚起床”
- **THEN** 约束允许角色顺着对方的说法回应早安

#### Scenario: 角色说自己这边的时间
- **WHEN** 对方问“你在干嘛”，北京时间为深夜
- **THEN** 约束允许角色说自己这边已经很晚，但不得据此认定对方也在深夜

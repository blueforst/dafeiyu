# 正常流程试聊增量规格（测试用户跨渠道为同一人）

## MODIFIED Requirements

### Requirement: 测试用户

一个试聊会话 MUST 对应一个独立模拟用户，该会话内连续消息共享此用户的记忆、近期往来和冷却，新建会话即新建模拟用户。管理员 MUST 能新建、改名、重置、清除冷却和删除测试用户，最多五十个。每个测试用户有显示名（一至三十字）和测试用 handle（一至十五位小写字母、数字或下划线，库内唯一，新建时自动生成，可修改）。测试用户在公开和私信中各有一个身份：公开按新建时生成的固定模拟标识识别，私信按一个固定的测试私信会话识别；两个身份 MUST 在新建时自动建立来源为“试聊”的身份关联，视为同一个人。可编辑的测试 handle 仅改变显示，不改变身份、关联、记忆和冷却；新用户不得复用旧用户身份。记忆条目、冷却和整理进度仍按身份分开保存，召回按生产的身份关联规则跨渠道进行。重置 MUST 清除该测试用户两个身份的全部消息、记忆、冷却和整理进度，但保留用户本身及两个身份之间的关联；删除 MUST 一并移除其全部测试数据和关联。左栏 MUST 按最近活动时间排列测试用户，并显示相对时间。

#### Scenario: 新建测试用户
- **WHEN** 管理员点击新建并填写显示名“小林”
- **THEN** 左栏顶部出现“小林”，有一个自动生成的测试 handle，没有任何消息和记忆，公开与私信身份已关联

#### Scenario: 重置测试用户
- **WHEN** 管理员重置一个已有十轮对话和两条长期记忆的测试用户
- **THEN** 该用户的对话、长期记忆、近期往来、冷却和整理进度全部清空，显示名、handle 和两个身份的关联不变

### Requirement: 按正常流程处理

每条试聊消息 MUST 按生产中相同渠道的真实消息处理，使用与生产相同的规则和代码：分级（广告与刷量过滤、首次来访、提问、老面孔招呼等）、同一用户连发合并、骚扰冷却、记忆召回（长期记忆、近期往来、角色经历）、当天虚构日程的当前时段、人设分区与触发卡（关键词卡与语义卡）、提示词提醒、使用中的模型和参数、模型跳过判断、公开或私信的字数校验、格式标记与私信内容重合检查。记忆召回 MUST 与生产中已关联身份的规则相同：私信这一轮召回私信记忆与近期往来，以及同一测试用户的公开记忆与公开近期往来；公开这一轮召回公开记忆与近期往来，以及该用户的私信长期记忆作为只作背景的“私信中得知”。被过滤的消息 MUST NOT 调用模型。

#### Scenario: 记得上一轮
- **WHEN** 测试用户先说“项目下周上线”，角色回复后，再问“还记得我在忙什么吗”
- **THEN** 第二轮的近期往来包含第一轮的消息和回复，本轮详情列出这条召回

#### Scenario: 广告被过滤
- **WHEN** 测试用户发送带链接的广告关键词消息
- **THEN** 本轮显示被分级过滤及原因，没有模型调用和费用

#### Scenario: 公开往来在私信中可召回
- **WHEN** 测试用户在公开回复中说“你好呀”并得到回复，之后在私信里问“你还记得我吗?”
- **THEN** 私信这一轮的近期往来包含那次公开往来并标明来自公开，本轮详情列出这条召回

#### Scenario: 私信记忆在公开中只作背景
- **WHEN** 测试用户在私信中提到养猫并已整理成长期记忆，之后在公开回复里聊天
- **THEN** 公开这一轮的提示词在“私信中得知”区包含这条记忆，不包含私信原文；本轮详情显示召回了私信背景，回复如与之重合八个字符以上则显示“正常流程不会发出：可能提及私信内容”

#### Scenario: 关键词卡命中
- **WHEN** 使用中的人设带“被夸”关键词卡，测试用户说“你好可爱”
- **THEN** 本轮命中“被夸”，详情显示命中的关键词，且只有一次回复生成请求

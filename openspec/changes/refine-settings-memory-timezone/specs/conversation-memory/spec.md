# 对话记忆增量规格（公开与私信身份关联）

## MODIFIED Requirements

### Requirement: 记忆可见范围

记忆召回 MUST 只使用同工作账号归属下的数据，并按身份关联决定跨渠道范围。私信回复 MUST 召回该私信会话的私信记忆与私信近期往来，以及已关联公开身份的公开记忆与公开近期往来。公开回复 MUST 召回该公开身份的公开记忆与公开近期往来，以及已关联私信会话的长期记忆条目；私信原文、私信近期往来和私信来源详情 MUST NOT 进入公开回复。没有关联时不得跨渠道召回，也不得按同名、相似显示名或文本推测自动合并公开账号与私信会话；无法确认归属的历史数据不得自动迁给新账号。已被遗忘的身份，其内容 MUST NOT 进入任何关联身份的召回。

#### Scenario: 公开与私信都有记录
- **WHEN** 系统为一个没有任何关联的公开身份获取记忆，同名私信会话中有私信记录
- **THEN** 返回的上下文不包含私信原文、私信近期往来或私信记忆

#### Scenario: 私信回复召回关联的公开往来
- **WHEN** 公开身份 `x:alice` 与私信会话已关联，alice 先在公开回复中说“你好呀”并已确认回复，随后在私信中问“你还记得我吗”
- **THEN** 私信这一轮的近期往来包含那次公开往来，并标明来自公开渠道

#### Scenario: 公开回复只拿到私信长期记忆
- **WHEN** 已关联的私信会话有一条长期记忆“对方养了一只叫团子的猫”和三条私信近期原文，系统为该用户的公开消息获取记忆
- **THEN** 上下文在“私信中得知”区包含这条长期记忆，不包含任何私信原文或私信近期往来

#### Scenario: 关联身份之一已被遗忘
- **WHEN** 私信会话已被遗忘，其关联的公开身份收到新消息
- **THEN** 公开回复的上下文不包含该私信会话的任何内容

#### Scenario: 浏览器切换工作账号
- **WHEN** 新账号开始处理消息
- **THEN** 系统不把旧工作账号的私信、身份关联或无法确认归属的历史记忆交给新账号

### Requirement: 用户和会话可视化列表

记忆页 MUST 提供用户／会话搜索、渠道筛选、最近互动、记忆数量、整理时间、遗忘状态及关联状态；无法可靠识别私信对方时必须展示会话标识并说明身份未确认，不伪造账号关联。已关联的公开身份与私信会话 MUST 在列表和详情中互相显示对方及关联来源（试聊、平台读取或管理员），详情中分别列出各身份自己的记忆。

#### Scenario: 私信只有会话标识
- **WHEN** 管理员查看尚无关联的私信记忆
- **THEN** 页面按会话展示并说明身份未确认，不强行关联同名公开账号

#### Scenario: 查看已关联的身份
- **WHEN** 管理员在记忆页打开已与 `x:alice` 关联的私信会话
- **THEN** 详情显示“已关联 @alice · 来源：平台读取”，私信记忆与 alice 的公开记忆分开列出并各自标明渠道

## ADDED Requirements

### Requirement: 公开与私信身份关联

系统 MUST 维护同一工作账号下私信会话与公开身份的关联：一个私信会话最多关联一个公开身份，一个公开身份可以关联多个私信会话。每条关联 MUST 记录来源（试聊、平台读取、管理员）和建立时间。平台读取只有在一对一私信会话中可靠读到唯一的对方 @handle 时才可建立关联；读取失败、读到多个候选或与已有关联冲突时 MUST NOT 建立或改写关联，并记录诊断。管理员 MUST 能在记忆页手动关联或解除关联；管理员解除的同一对，平台读取 MUST NOT 自动再次关联，直到管理员重新手动关联。关联与解除 MUST NOT 合并、迁移或删除任何身份的记忆条目、整理进度、遗忘与删除账本；解除后召回立即恢复为未关联时的范围。

#### Scenario: 平台读取到唯一对方
- **WHEN** 一对一私信会话页面可靠显示唯一对方 @alice，且该会话尚无关联
- **THEN** 系统建立会话与 `x:alice` 的关联，来源为平台读取

#### Scenario: 读到多个候选
- **WHEN** 私信会话页面同时出现两个不同的 @handle 且无法确定哪一个是对方
- **THEN** 系统不建立关联，记录诊断，该会话继续按未关联处理

#### Scenario: 管理员解除后不再自动关联
- **WHEN** 管理员解除了某私信会话与 `x:alice` 的关联，之后平台读取再次读到 @alice
- **THEN** 系统不自动重新关联，记忆页仍显示未关联及“管理员已解除”

#### Scenario: 解除关联不丢记忆
- **WHEN** 管理员解除一个已有公开和私信记忆的关联
- **THEN** 两个身份各自的记忆条目、整理进度与遗忘状态都保持不变，下一次回复按未关联范围召回

### Requirement: 私信记忆在公开回复中只作背景

公开回复召回的私信长期记忆 MUST 放在独立的“私信中得知”区，并明确只作背景：回复不得提及、复述、暗示或确认任何私信内容，也不得提到双方私信过。公开回复生成后，系统 MUST 将回复正文与本轮提供的私信记忆做规范化比较（忽略空白、标点与大小写）；出现连续八个字符以上的重合时，该回复 MUST NOT 自动提交，改为草稿并标注“可能提及私信内容”及重合片段，由管理员审核；草稿模式下同样标注。私信回复不做此检查。

#### Scenario: 公开回复复述了私信记忆
- **WHEN** 自动模式下本轮私信记忆为“对方下个月要去大阪看樱花”，公开回复正文为“下个月要去大阪看樱花了吧！”
- **THEN** 重合片段“下个月要去大阪看樱花”达到十个字符，该回复不提交，状态为草稿，标注“可能提及私信内容”和该片段

#### Scenario: 没有重合
- **WHEN** 公开回复与本轮私信记忆没有连续八个字符以上的重合
- **THEN** 回复按原有规则继续校验和提交

#### Scenario: 本轮没有私信记忆
- **WHEN** 公开身份没有关联任何私信会话
- **THEN** 提示词中没有“私信中得知”区，也不做重合检查

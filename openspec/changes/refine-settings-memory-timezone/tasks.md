当前完成 16/19 项；隔离回归、真实模型有效时段样本与人工关联界面已验证，平台真实样本及发布仍保留独立任务。证据见 [本轮实施记录](../../../docs/实施记录/2026-10-29-设置记忆与人设文件.md)。规格见 [panel-navigation](specs/panel-navigation/spec.md)、[panel-design-system](specs/panel-design-system/spec.md)、[conversation-memory](specs/conversation-memory/spec.md)、[chat-test](specs/chat-test/spec.md) 和 [reply-prompt-context](specs/reply-prompt-context/spec.md)，实现边界见 [design.md](design.md)。

- 实施前确认本机工作副本中 `settings.js`、`settings/health.js`、`memory.js`、`style.css`、`memory.ts`、`reply-prompt.ts`、`reply-hints.ts`、`reply-pipeline.ts`、`workflow.ts`、`chat-test.ts`、`chat-dom.ts`、`browser.ts` 没有其他人的未提交改动。

## 1. 设置左栏

- [x] 1.1 共享样式：`.ws-shell .ws-side-item` 使用正文色，链接形式的条目悬停无下划线；新增 `.ws-dot`（design.md 第 1 节）。验收：服务器界面验收在浅色和深色下读取动态、人设、设置三页左栏条目的计算颜色，三页一致且不等于 `--ws-brand`；悬停时 `text-decoration` 为 `none`。
- [x] 1.2 设置左栏改用 `sideItem`，去掉文字摘要，按第 1 节的表格显示圆点；`refreshSummaries` 只保留健康与任务历史两个请求。验收：界面验收覆盖健康需关注、人工接管、需要登录、最近任务失败、模型未配置、配置错误、全部正常七种状态，断言圆点的有无、颜色、`aria-label` 与 `title`；打开设置页时的接口请求只有这两个，加上原有的状态推送。

## 2. 健康与日报

- [x] 2.1 指标分组表格、状态行、账号组合并、名称补全与“其他”组（第 2 节）。验收：用生产 `/api/health` 的结构做夹具（20 项、4 项需关注），断言六组的归属和顺序、非正常项在组内最前、三项账号检查各只出现一次、没有“运行观察”；加一个未登记标识，断言它出现在“其他”组。
- [x] 2.2 日报表格与告警历史表格（第 2 节）。验收：三天日报夹具渲染三行，每行有第 2 节列出的全部列；告警与配置默认收起；健康配置保存流程沿用原有断言并通过。
- [x] 2.3 版式验收。验收：1440×900 截图中 20 项名称和状态无需滚动全部可见；375px 截图无整体横向滚动，日报只在表格内滚动；浅色和深色截图存入证据目录。

## 3. 身份关联与召回

- [x] 3.1 schema 14 迁移与 `identity-links.ts`（第 3 节）。验收：迁移测试覆盖新库、已有 schema 13 库、重复执行；关联服务测试覆盖格式校验、平台来源冲突不改写、阻止记录、管理员覆盖并清除阻止、解除；关联变化时回放记忆快照作废。
- [x] 3.2 `MemoryService.context` 跨渠道召回与 `privateBackground`（第 4 节）。验收：`test/memory.test.ts` 新增用例，先在服务器上对修改前代码运行并失败，修改后通过。覆盖：
  - 私信召回关联公开条目与公开近期往来，带渠道；
  - 公开只召回私信长期条目，不含私信原文、来源 ID 或私信近期往来；
  - 私信背景限 10 条／2000 字符；
  - 无关联时两种回复的上下文与修改前逐字段相同；
  - 任一侧被遗忘时跳过该侧。
- [x] 3.3 记忆接口与详情（第 8 节）。验收：接口测试覆盖查询、管理员关联（handle 格式错误被拒、覆盖平台关联）、解除后写入阻止记录；写操作缺少控制标记时返回 403；`/api/memory/users` 返回 `linkedTo`。
- [x] 3.4 记忆页关联管理与动态右栏显示（第 8 节）。验收：界面验收覆盖未关联会话手动关联、确认文案、解除并显示“管理员已解除”、公开身份列出多个私信会话；动态右栏的只读记忆标注渠道与来源；375px 可完整操作。

## 4. 私信内容重合检查

- [x] 4.1 `privateOverlap` 与流水线接入（第 6 节）。验收：单元测试覆盖正好 8 字命中、7 字不命中、空白与标点干扰、全角半角、emoji 和无背景时不计算；私信回复不计算。
- [x] 4.2 `private-overlap` 转为草稿，以及动态页和试聊的标注（第 6 节）。验收：工作流测试断言自动模式下命中时零提交、状态为草稿、带原因与片段，管理员批准后可以提交；草稿模式同样带标注；试聊显示“正常流程不会发出：可能提及私信内容”，不计入已发出。

## 5. 试聊

- [x] 5.1 新建即关联、启动补写、重置保留、删除移除（第 9 节）。验收：试聊测试覆盖四种情况，补写可重复执行；复现“公开发‘你好呀’后私信问‘你还记得我吗?’”，私信这一轮的近期往来包含那次公开往来；试聊库与生产库互不读取关联。

## 6. 时区中立

- [x] 6.1 固定约束、“现在”段、日程说明、迟到提醒与 `reply-context-v5`（第 5 节）。验收：提示词测试断言段落顺序、各段文字和版本号；迟到提醒不含“按现在的时段问候”；同一时段内稳定前缀与日程段不变；原 `reply-prompt-context` 测试中依赖旧文案的断言按新规格更新，其余断言不变。
- [x] 6.2 真实模型抽查（计费，需授权）。用试聊在北京深夜和早晨各发问候类与普通消息，覆盖大肥鱼和另外两个预设；有关联的测试用户同时检查公开回复是否提及私信背景。验收：记录调用次数、费用和逐条结果。对方未提时间时，回复中对其时段的假设为零才算通过；有失败的如实记录，不改写结论。

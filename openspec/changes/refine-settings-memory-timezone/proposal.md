# 设置页细节、跨渠道记忆与时区中立提案

## Why

管理员 2026-10-29 试用 0.1.19 后反馈了四个问题。以下逐条对照本机源码 `f29715f` 和生产只读数据核对。

1. **设置左栏显示成蓝色，右侧摘要参差不齐。**
   - 原因：工作区通用样式 `.ws-shell a{color:var(--ws-brand)}` 的优先级高于 `.settings-nav-item{color:inherit}`，十一个设置项标题都显示成品牌蓝，悬停时还会出现旧样式的下划线。共享组件 `sideItem` 用作链接时也有同样的问题。
   - 每项右侧的摘要从空白到“deepseek / deepseek-v4…”长短不一，右对齐后截断位置也不一样。人设页、动态页左栏用正文色的 `sideItem`，三页不一致。
2. **同一个用户的私信和公开记忆不互通。**
   - 原因：公开身份是 `x:<handle>`，私信身份是 `dm:<会话 ID>`，系统里没有任何数据把两者关联起来。记忆条目、近期往来和整理进度都按身份分开。
   - 现有规格本来允许私信回复使用公开记忆，但两个身份对不上，这条规则从未真正生效。试聊规格要求“与生产一致”，也给每个测试用户分了两个身份。
   - 生产试聊记录可以复现：测试用户先在公开回复里说“你好呀”，然后在私信里问“你还记得我吗?”，角色回答不记得。
3. **大肥鱼的时间观念过重。**
   - 原因：提示词只给出北京时间和“深夜”这类时段名，没有说明这是角色所在地的时间；迟到提醒还要求“按现在的时段问候”。X 上的用户分布在各个时区，模型却按北京时间猜测对方的作息。
   - 生产试聊记录：北京时间 03:53 公开收到“你好呀”，回复是“这个点还没睡，是来陪我熬深夜的吗”。
   - 这段提示词由所有人设共用，问题不限于大肥鱼。
4. **健康页浪费空间。**
   - 生产当前返回 20 项指标，其中 16 项正常。每项占一张大卡片，排成四列五行，正常项只显示一个大号的“正常”。
   - 三项账号检查在指标卡和“账号检查”区重复出现；采集类三项缺少中文名，都显示为“运行观察”。
   - 日报按天折叠成一行，展开前看不到数字。

## What Changes

- **设置左栏**
  - 改用与人设页、动态页相同的左栏条目样式和正文色。修复通用链接色覆盖左栏条目的问题，所有页面的左栏都受益。
  - 去掉右侧的文字摘要。只在需要处理时，在标题右侧显示一个状态圆点：
    - 健康需关注或异常；
    - 浏览器人工接管中或需要登录；
    - 最近一次任务失败；
    - 模型尚未配置；
    - 运行配置有错误。
  - 圆点带可读名称和悬停说明，例如“健康：需关注 4 项”；颜色沿用现有告警色。
- **健康与日报**
  - 顶部用一行显示总状态、非正常项数和采样时间。
  - 指标按运行、采集、发送、浏览器、账号、基础设施六组排成表格，每行一项：圆点、名称、状态、说明。组内非正常项排在最前，完整显示说明；宽屏下正常项两项一行。
  - 账号检查并入“账号”组，在组内显示检查时间和“检查计划”入口，不再单独重复。
  - 已知指标都有中文名。未知指标归入“其他”组并显示其标识，不再出现多个“运行观察”。
  - 日报改为表格，每天一行，直接显示调用、token、费用，公开和私信的入站、回复、失败，响应时间和告警数。
  - 告警历史改为表格，和健康与披露配置一样默认收起。
  - 只改展示，不改指标判定、告警和日报内容。
- **公开与私信的身份关联**
  - 新增身份关联：一个私信会话最多关联一个公开身份，一个公开身份可以关联多个私信会话。每条关联记录来源：试聊、平台读取或管理员。
  - 试聊：每个测试用户的公开身份和私信会话自动关联，视为同一个人。
  - 生产：读取一对一私信会话时，只有页面能可靠读到唯一的对方 @handle 才建立关联；读不到或有冲突时不关联，继续按会话处理。这项读取需要真实私信样本验收，验收前生产只有管理员手动关联生效。
  - 管理员可以在设置页“记忆”中手动关联或解除。管理员解除的一对，平台读取不得自动再关联。
  - 不合并存储：记忆条目、整理进度、遗忘与删除账本仍按原身份保存，关联只影响召回。解除关联后立即恢复原状。
- **跨渠道召回：双向，私信内容只作背景**
  - 私信回复：同时召回已关联公开身份的公开记忆和公开近期往来，与私信记忆一起使用。这是原规格已经允许、现在才真正生效的行为。
  - 公开回复：在公开记忆之外，召回已关联私信会话的长期记忆条目，单独放在“私信中得知”区并标明只作背景。回复不得提及、复述、暗示或确认任何私信内容，也不提“私信里说过”。私信原文和私信近期往来不进入公开回复。
  - 防泄露兜底：如果公开回复与本轮提供的私信记忆有连续八个字以上的重合（规范化后比较），不自动发送，转为草稿并标“可能提及私信内容”，等管理员审核。草稿模式下同样标记。
  - 被遗忘身份的内容不进入任何关联身份的召回。
- **时区中立**
  - 提示词里的北京时间明确写成“你（角色）这边的时间”，并说明 X 用户分布在不同时区，不知道对方当地几点。
  - 固定规则新增一条：除非对方在本次消息或近期往来中提到自己的时间或作息，不得按角色的时间推断对方是早上、晚上还是深夜，也不用“这么晚还不睡”“早安”“晚安”等替对方假设时段的说法；可以偶尔顺口说自己这边的时间或日程。
  - 迟到提醒改为“自然致歉一次”，不再要求按时段问候。
  - 当日日程、回复时段、早晚安帖仍按北京时间，不受影响。
  - 提示词版本升为 `reply-context-v5`。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `panel-navigation`：设置左栏条目改为状态圆点；新增健康与日报的分组表格排版。
- `panel-design-system`：左栏条目在任何页面都使用正文色，不被通用链接色覆盖。
- `conversation-memory`：身份关联与解除、跨渠道召回范围、私信记忆在公开回复中只作背景及防泄露兜底、记忆页的关联管理。
- `chat-test`：测试用户的公开和私信为同一个人，按新的跨渠道规则召回。
- `reply-prompt-context`：当前时间标明为角色所在时间，新增不假设对方时区的规则，迟到提醒不再按时段问候。

## Impact

- 前端：`public/js/views/settings.js`、`public/js/views/settings/health.js`、`public/js/views/memory.js`、`public/settings-workspace.css`、`public/style.css`（左栏条目颜色）。动态页右栏的只读记忆随接口显示关联来源。
- 后端：`src/memory.ts`（召回与关联）、`src/memory-routes.ts`（关联接口）、`src/reply-prompt.ts`、`src/reply-hints.ts`、`src/reply-pipeline.ts` 和 `src/workflow.ts`（私信重合检查）、`src/chat-test.ts`（自动关联）、`src/chat-dom.ts` 与 `src/browser.ts`（私信对方 handle 读取）。
- 数据库：schema 14，新增身份关联表和管理员解除账本，只增不改；旧版本代码忽略新表。
- 模型请求：不增加请求次数。提示词变化需要真实模型抽查，属于计费调用，需另行授权。
- 不改：指标判定、告警与日报内容、设置项含义与接口、记忆整理的触发阈值和存储范围、回复时段、早晚安帖、额度与出站规则、动态页的会话分组。

# 运行健康增量规格：完整轮次后的自动浏览器恢复

## Purpose

使程序在确有资源恢复需要时，自动等待完整业务轮次收束后恢复同一浏览器上下文，并保留原未知发送、身份及已接受私信的实际可用性。恢复是否完成由新鲜验证证据决定，避免轮中关闭会话、把空收件箱当成解锁或因失败反复重启。

## MODIFIED Requirements

### Requirement: 浏览器资源自愈

浏览器服务 MUST 沿用内存与运行时长阈值，在操作前采样并判定准入，但 MUST 将实际上下文重启安排到完整业务轮次结束后的自动维护阶段。默认内存阈值为上限75%、运行时长二十四小时；内存压力 MUST 持续至少三十秒并有至少两次有效采样，采样计数间隔至少一秒。自动恢复 MUST 遵守最小五分钟间隔、每小时最多两次及既有故障保护，context重启不得清空这些频率记录。提交、回查、人工接管或其他在途操作中不得执行恢复；重启保留同一profile、设备及journal，重新验证同一登录账号和原已接受Chat，失败安全暂停而不自动重复restart。

#### Scenario: 空闲时内存超过阈值
- **WHEN** 轮前采样发现超过阈值，且只有本提案允许的soft保护并明确启用维护策略
- **THEN** 系统记录待轮末恢复，完整执行该轮后才重新评估并恢复，不在采集开始前关闭上下文

#### Scenario: 发送过程中超过阈值
- **WHEN** 内存在一次回复提交过程中超过阈值
- **THEN** 系统等待本轮已开始的全部业务收束；只有出站明确收束且没有hard保护时才允许轮末恢复，未知结果保持保护和只回查

#### Scenario: 重启后登录失效
- **WHEN** 重启后无法确认原工作账号已登录
- **THEN** 系统安全暂停并记录失败，不使用新身份继续处理，也不立即重复重启

#### Scenario: 单次尖峰或频率超限
- **WHEN** 压力未持续三十秒、有效采样不足，或本次恢复违反五分钟／每小时两次约束
- **THEN** 系统不执行新的context重启，按压力观察或原频率故障保护收束，不通过重置计数重试

#### Scenario: 到轮末压力已消退
- **WHEN** 完整轮次结束后重新采样已不满足任何恢复阈值
- **THEN** 系统返回无需恢复，保留原会话并按正常间隔运行下一轮

## ADDED Requirements

### Requirement: 完整轮次后的串行自动维护

系统 MUST 仅在采集、接受处理、queue、上下文／生成、发送、整理及scheduler的已开始操作全部await收束，常规业务链路完整结束，控制仍running且未abort时执行轮末维护。应用 MUST 在维护RPC实际收束前保留busy及浏览器串行互斥；因门禁、异常、取消或early return未完成的轮次不得在finally补做重启。

#### Scenario: scheduler仍在发送
- **WHEN** 入站回复已处理完，但本轮scheduler触发的提交尚未收束
- **THEN** 系统继续等待，不关闭浏览器，不启动第二轮或另一维护尝试

#### Scenario: 轮次提前结束
- **WHEN** 本轮因hard门禁、异常或abort提前返回而没有完成常规业务链路
- **THEN** 系统不执行finish-round恢复，保留保护与实际轮次结果

### Requirement: soft维护策略不豁免hard保护

系统 MUST 区分有效精确reviewed旧unknown及已解锁Chat等soft保护，与新unknown、sending／submitting、未收束私信接受、needs-human、解锁待人工、接管及在途操作等hard保护。只有明确allowSessionRecovery且仅有soft保护时，prepare才可不因临界压力提前fault／blocked，让本轮完整结束后评估恢复。实际维护前 MUST 再次核对资格；该策略不得清除真实故障、频率限制或hard保护。

#### Scenario: 仅有允许的soft保护
- **WHEN** 本轮仅存在有效精确审核旧unknown及已解锁Chat，且维护策略明确允许
- **THEN** prepare允许完整执行本轮，实际恢复仍等待轮末的新鲜资源及保护检查

#### Scenario: 新hard unknown处于临界压力
- **WHEN** 存在新的未审核unknown且内存达到原临界保护条件
- **THEN** 系统只执行允许的回查并提前结束，不开始新业务，也不执行finish-round重启

#### Scenario: 轮中新增hard状态
- **WHEN** 轮前只有soft保护，但本轮发送或私信接受产生新的未收束意图
- **THEN** 轮末维护拒绝关闭上下文，保留该意图及原保护，不自动追加审核

### Requirement: 精确审核旧unknown的有限维护例外

旧unknown只有在同账号、同原消息／出站且精确审核指纹仍有效时，才MAY不单独阻止本次获授权维护。系统 MUST 保留其unknown、冻结内容、提交信息、额度计量、原回查及禁止重发语义，不补造缺失journal，不将该例外推广到新unknown、孤立意图或私信接受。资格不得只由一个客户端允许布尔值证明。

#### Scenario: 旧审核仍有效
- **WHEN** 轮末确认唯一旧项的审核和冻结指纹有效，且其他维护条件通过
- **THEN** 系统可恢复同profile上下文，旧项继续unknown和正常回查，原source不能再次提交

#### Scenario: 审核失效或另有未知意图
- **WHEN** 原项指纹变化、审核撤销，或应用／浏览器存在另一个未覆盖的未知意图
- **THEN** 维护例外不适用，系统保留上下文并记录具体保护原因

### Requirement: 原已接受Chat的真实恢复验证

系统 MUST 在恢复前确定本次拟关闭的原已接受Chat验证对象，重启后重新确认同一账号、同一已接受会话、实际消息可读及唯一正确composer可编辑。普通收件箱empty、首页登录、缓存已解锁标记或其他会话输入框不得证明该Chat已恢复。验证不得发送消息、自动接受请求、处理PIN或调用模型；必需验证失败时安全暂停，不重复restart。

#### Scenario: 原会话确实恢复
- **WHEN** 重启后原已接受会话的身份、实际消息读取及正确composer编辑状态均通过原生契约核对
- **THEN** 系统才记录恢复成功，并在原控制仍有效时正常进入下一轮

#### Scenario: 成功后自动继续原运行状态
- **WHEN** 自动维护前应用为running、浏览器为auto，恢复验证成功且没有较新的管理员控制
- **THEN** 系统保留running／auto，按原采集间隔继续下一轮，不要求管理员再次启动

#### Scenario: 冷启动消息和编辑器尚在水合
- **WHEN** 原会话文字已可见，但可靠机器字段或正确composer仍未全部就绪
- **THEN** 系统在既有证据预算内等待完整条件连续通过，未满足前不宣布成功，出现锁定或预算耗尽时安全暂停

#### Scenario: 普通收件箱为空
- **WHEN** 重启后只能确认普通收件箱empty，未取得原会话实际可读／可编辑证据
- **THEN** 系统不判定解锁成功，不开启后续业务，保留失败原因并安全暂停

#### Scenario: 解锁或接受提示重新出现
- **WHEN** 重启后的原会话出现PIN、需要人工处理或请求接受提示
- **THEN** 系统保持暂停，不自动输入、接受、发送或再次重启尝试解锁

### Requirement: 维护结果、控制竞争与失败可观察

系统 MUST 分开记录prepare准入、待轮末／被保护延后、恢复尝试、身份／Chat验证及实际终态。暂停、接管、abort或超时不得导致第二次恢复或恢复过时控制；客户端超时不得视为服务端已退出。失败 MUST 安全暂停，保留同次操作和原意图，不自动重复restart。日志不得包含私信正文或认证材料，health缓存字段不得单独作为临界准入或维护成功证据。

#### Scenario: 关闭前发生暂停
- **WHEN** 管理员在真正关闭上下文前暂停或接管
- **THEN** 系统取消维护，服从最新控制，不启动下一轮

#### Scenario: 同次RPC重入或超时
- **WHEN** 原维护RPC结果尚未收束，调用方超时或重复提交相同轮次标识
- **THEN** 系统不第二次close／launch，不提前释放serial给新维护，并按实际终态及最新控制收束

#### Scenario: 缓存显示未阻塞
- **WHEN** health缓存businessBlocked=false，但没有本次prepare或finish的新鲜验证结果
- **THEN** 系统不据此宣称临界新业务准入或浏览器恢复成功

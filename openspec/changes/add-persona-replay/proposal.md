# 人设回放对比与回复质量统计提案

## Why

人设页目前只能手工构造对话做多轮试聊，无法用一批真实消息比较新旧人设，也看不到生产回复在开头重复、颜文字频率、长度、跳过率等方面的整体趋势。单条回复看不出模板化，人设改动是否有效也缺少批量证据。参考帖子的迭代方法是“看真实数据、归类问题、一次只改一两类、用同一批真实消息新旧两版逐条对比、上线后再观察”，本项目已有试聊隔离与统一计费，适合在此基础上补齐批量回放和质量统计。

## What Changes

- 回放样本：从当前工作账号已处理的真实消息中按日期、渠道、分级和数量（每次最多 50 条）选取；私信需单独勾选，遗忘或删除的来源不可选。
- 生成输入快照：生产生成时保存当次对话上下文、记忆召回和提醒元数据的有界快照，保留期与原文一致，受遗忘、删除和修订约束；回放优先使用快照，没有快照的旧消息如实标注“上下文不完整”。
- 双版本生成：基线可选“当时实际回复”（不产生费用）或“当前已保存人设重新生成”；候选使用未保存的人设草稿与动态提醒设置。两侧使用相同的模拟日程与时间，结果不发送、不写记忆、出站或角色经历。
- 运行前显示预计请求数与估算费用并需确认；运行可中止，已完成的条目保留；所有调用以 `persona-replay` 用途计量。
- 并排对比与人工标注：每条可标记候选更好、基线更好、差不多或都有问题，并选择问题类别（答非所问、编造、模板化开头、表情过多、列步骤、该跳过没跳过等）；汇总胜负与问题分布。
- 确定性质量指标：对两侧结果和生产回复统计跳过率、平均长度、开头重复率、颜文字／emoji／“～”频率、列步骤比例、禁用内容与公开长度违规；不使用模型评审。
- 生产回复质量统计：人设页按日期范围展示上述指标趋势，用于上线后观察。
- 采用候选：对比后可把候选草稿按正常保存流程设为当前人设，修订冲突时拒绝。

## Capabilities

### New Capabilities

- `persona-replay`：真实样本回放、生成输入快照、双版本隔离生成、费用确认、并排标注、确定性质量指标与生产回复质量统计。

### Modified Capabilities

无。现有主规格不变。未归档 `add-seven-page-production-bot` 中 `persona-management` 的“隔离多轮试聊”保持不变；`conversation-memory` 的遗忘、删除与修订约束同样适用于新增快照。

## Impact

- 新增 `src/replay.ts`（样本选择、执行队列、指标计算）及接口；`src/workflow.ts` 在生成时写入输入快照；`src/memory.ts` 与 `src/store.ts` 的遗忘、删除和保留清理覆盖快照与回放结果；计费用途新增 `persona-replay`。
- 数据库新增生成输入快照、回放运行与回放条目表；人设页新增“回放对比”与“回复质量”区域（`simplify-panel-activity-feed` 落地后为人设页标签）。
- 回放调用当前模型配置与 Key，与生产共用服务商额度但不占用浏览器互斥；不改变 OpenCode 会话路由（回放使用独立会话标识）。
- 与 `improve-reply-prompt-context` 共用开头与表情检测函数；先实施的一方建立共享模块。
- 不使用模型做自动评审；不把回放结果当作生产回复；不发送任何消息。
- 本次只创建规划文件；构建、测试在服务器隔离环境执行，不改变线上运行状态。

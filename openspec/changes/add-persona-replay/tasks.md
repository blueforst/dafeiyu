# 人设回放实施任务

当前已完成下列八项实现与服务器自动回归，回放界面专项、真实模型与生产发布仍待对应验收。规格见 [persona-replay](specs/persona-replay/spec.md)，实现边界见 [design.md](design.md)，证据见[后续提案实施记录](../../../docs/实施记录/2026-10-28-后续提案.md)。服务器全量类型检查、构建及 325/325 项回归通过，其中回放 18 项全部通过。构建、自动化测试与界面验收均在服务器隔离环境执行；使用真实模型的回放会产生费用，需取得授权后进行。

## 1. 快照与隐私约束

- [x] 1.1 新增 `generation_snapshots`、`replay_runs`、`replay_items` 迁移，`Workflow` 在生成前写入有界快照；以服务器迁移与集成测试验证重复迁移、16 KB 截断标记和常规日志不含快照内容为验收。
- [x] 1.2 把快照与回放条目纳入保留清理、遗忘、记忆删除和旧库恢复重放路径，更新 `docs/记忆策略.md`；以服务器回归验证遗忘后删除、恢复旧库后仍删除、删除的记忆不会经快照复活为验收。

## 2. 回放执行

- [x] 2.1 实现样本选择（日期、渠道、分级、数量上限、私信显式勾选、排除遗忘与删除来源）；以服务器单元测试覆盖规格中遗忘用户与未勾选私信场景为验收。
- [x] 2.2 实现 `ReplayRunner` 双版本生成、独立会话标识、固定模拟日程与时间、中止；以服务器集成测试验证回放期间生产表不变、不调用浏览器、中止后不再请求、调用以 `persona-replay` 计量为验收。
- [x] 2.3 实现费用预估与确认接口；以服务器测试覆盖已定价、未定价、无历史三种显示及实际费用汇总为验收，更新 `docs/前端接口.md`。

## 3. 指标与界面

- [x] 3.1 新增 `src/reply-style.ts`（若 `improve-reply-prompt-context` 已建立则复用）与回放／生产质量指标；以服务器样本测试验证开头重复率、表情频率、列步骤识别与违规计数为验收。
- [x] 3.2 人设页新增“回放对比”区：筛选、预估确认、进度、并排标注、汇总与采用候选（含修订冲突）；以服务器浅色／深色／375px 界面验收与外部文本纯文本渲染为验收。
- [x] 3.3 人设页新增“回复质量”区：日期范围与渠道趋势，私信示例走受鉴权详情；以服务器界面与接口验收为准。
- [x] 3.4 实现最近二十次运行保留与单次删除；以服务器测试验证第二十一次运行清理最早记录为验收。

## 4. 集成与发布

- [x] 4.1 在服务器 staging 用模拟模型完成全量类型检查与回归，覆盖规格全部场景；以测试报告关联场景为验收。
- [ ] 4.2 取得授权后用真实模型对不超过 20 条公开样本运行一次回放，记录实际请求数、费用与预估偏差；未授权时如实标注未验证。
- [ ] 4.3 取得发布授权后发布并保持原有控制状态，确认生产快照开始写入且不影响回复耗时；以发布记录为验收。

## Workflow follow-up

- 实施并验收后同步本能力到主规格并归档；与 `improve-reply-prompt-context` 的共享检测模块保持一份实现。
- OpenSpec 严格校验通过只代表规划结构可用；上方勾选依据服务器实现回归，不以规划校验代替业务验证。

本轮补充：回放筛选、显式私信、预估确认、中止、并排标注、私信展开、采用修订冲突、质量逐日趋势及375px深色均由服务器 `proposals-ui-acceptance.mjs` 通过。真实模型与生产发布仍未执行。

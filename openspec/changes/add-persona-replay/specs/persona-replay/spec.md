# 人设回放增量规格

## Purpose

让管理员用一批真实历史消息比较人设草稿与当前人设或当时实际回复的效果，并用确定性指标观察生产回复的整体质量，使人设迭代基于批量证据而不是单条试聊，同时保证回放不会发送消息、改动生产记忆或绕过隐私约束。

## ADDED Requirements

### Requirement: 回放样本选择

系统 MUST 允许管理员从当前工作账号已处理的真实消息中按日期范围、渠道、分级和数量选取回放样本，每次最多 50 条；私信消息只有在管理员明确勾选私信时才可入选；已遗忘用户、已删除来源和其他工作账号的消息不得入选。

#### Scenario: 已遗忘用户的消息
- **WHEN** 选取范围内包含已被遗忘用户的消息
- **THEN** 这些消息不出现在样本中，样本数量说明已排除的条数

#### Scenario: 未勾选私信
- **WHEN** 管理员只选择公开渠道
- **THEN** 样本不包含任何私信消息

### Requirement: 生成输入快照

生产生成 MUST 保存当次对话上下文、记忆召回结果与提醒元数据的有界快照，保留期与消息原文一致；用户被遗忘、来源被删除或记忆条目被修订删除时，相应快照必须同时删除或失效，快照内容不得出现在常规日志中。

#### Scenario: 用户被遗忘
- **WHEN** 管理员或用户指令遗忘某用户
- **THEN** 该用户消息的生成输入快照被删除，已有回放结果中的对应条目显示已移除

#### Scenario: 旧消息没有快照
- **WHEN** 回放一条在本功能上线前处理的消息
- **THEN** 系统只使用消息原文与当前允许范围的记忆生成，并标注上下文不完整

### Requirement: 双版本隔离生成

回放 MUST 对每条样本生成基线与候选两侧结果：基线为当时实际回复或用当前已保存人设重新生成，候选使用未保存的人设草稿与提醒设置；两侧使用相同的模拟日程与时间。回放不得发送消息，不得写入出站、生产记忆、角色经历或消息状态。

#### Scenario: 回放期间生产正常运行
- **WHEN** 回放与主程序同时运行
- **THEN** 生产出站、记忆和消息状态只由主程序改变，回放不占用浏览器操作

#### Scenario: 基线选择当时实际回复
- **WHEN** 管理员选择以当时实际回复为基线
- **THEN** 基线一侧不产生模型请求，被跳过的消息显示当时的跳过原因

### Requirement: 费用预估与确认

系统 MUST 在开始回放前显示预计模型请求数（含语义判定）和按 Pi 内置价格估算的费用，存在未定价模型时如实提示；只有管理员确认后才开始。回放可随时中止，已完成条目保留，未开始条目不再请求；全部调用以回放用途计量。

#### Scenario: 中途中止
- **WHEN** 管理员在 50 条中完成 20 条时中止
- **THEN** 已完成的 20 条结果保留，其余条目不再发起请求，计费页可按回放用途查到实际调用

#### Scenario: 模型未定价
- **WHEN** 当前模型没有可靠的 Pi 价格
- **THEN** 预估显示请求数与“未定价”，不显示为免费

### Requirement: 并排对比与人工标注

系统 MUST 并排展示每条样本的原消息、基线与候选结果，允许管理员标记候选更好、基线更好、差不多或都有问题，并选择一个或多个问题类别；汇总区展示各标记数量与问题类别分布。

#### Scenario: 标注完成
- **WHEN** 管理员标注了全部样本
- **THEN** 汇总区显示候选更好与基线更好的条数，以及各问题类别出现次数

### Requirement: 确定性质量指标

系统 MUST 用确定性规则为回放两侧计算跳过率、平均长度、开头重复率、颜文字／emoji／“～”使用频率、列步骤比例、禁用内容与公开长度违规数，规则与提示词提醒使用的检测一致，不得调用模型评审。

#### Scenario: 开头重复率
- **WHEN** 候选的 20 条回复中有 6 条以相同开头片段开始
- **THEN** 指标显示候选开头重复率 30%，并列出最常见的开头片段

### Requirement: 生产回复质量统计

人设页 MUST 按选定日期范围和渠道展示当前工作账号生产回复的同一组质量指标及每日趋势；汇总视图不得显示私信正文，查看具体私信示例需进入受鉴权的消息详情。

#### Scenario: 上线新人设后观察
- **WHEN** 管理员查看保存新人设前后各三天的统计
- **THEN** 页面按日显示开头重复率、颜文字频率等指标的变化

### Requirement: 采用候选人设

管理员 MUST 能把回放所用的候选草稿通过正常人设保存流程设为当前人设；若回放开始后人设已被他人修改，保存必须因修订冲突被拒绝并提示重新回放或手动合并。保存后沿用下一轮生效语义，不恢复暂停的业务。

#### Scenario: 修订冲突
- **WHEN** 回放运行期间人设已被另一次保存修改
- **THEN** 采用候选被拒绝，页面提示修订已变化

### Requirement: 回放记录保留

系统 MUST 保留最近二十次回放运行及其条目与标注，允许管理员删除单次运行；超出保留数或来源被遗忘、删除时相应结果被移除。

#### Scenario: 超出保留数量
- **WHEN** 第二十一次回放完成
- **THEN** 最早的一次回放运行及其条目被删除

# 对话记忆

## Purpose

记录当前工作流已经具备的近期原文、按渠道摘要与遗忘机制，明确原文和已发送回复的区别，以及公开回复不得使用私信内容的边界。可视化管理、来源条目和改进后的增量整理由后续变更提出。

## Requirements

### Requirement: 近期互动上下文

系统 MUST 向回复生成提供最近三次已处理互动中的入站原文，只把已确认发送的回复作为已经说过的话；草稿文本不得当成已发送记录。

#### Scenario: 存在未发送草稿
- **WHEN** 用户的近期记录包含一条草稿和一条已确认回复
- **THEN** 上下文可包含收到的原文，但只有已确认回复被标识为角色已发送内容

### Requirement: 长期摘要整理

系统 MUST 按用户与渠道维护摘要，在累计五条新记录后安排 LLM 整理，并仅记录用户明确自述的事实与未完话题。

#### Scenario: 达到摘要阈值
- **WHEN** 某用户某渠道累计达到五条新记录
- **THEN** 系统安排该范围的摘要整理，不将角色自己的发言写成用户事实

### Requirement: 记忆可见范围

公开回复 MUST 只使用公开原文与摘要；没有可靠身份映射时，系统不得自动合并公开账号和私信会话。

#### Scenario: 公开与私信都有记录
- **WHEN** 系统为公开消息获取记忆
- **THEN** 返回的上下文不包含私信原文或私信摘要

### Requirement: 遗忘与恢复记录

系统 MUST 支持忘记用户并停止后续记录、恢复后续记录，以及使遗忘前正在生成的旧摘要失效；独立遗忘记录在恢复旧数据库后仍必须生效。

#### Scenario: 遗忘时仍有摘要在生成
- **WHEN** 用户被遗忘后旧摘要请求才返回
- **THEN** 系统拒绝写回该摘要并继续阻止记录

#### Scenario: 恢复记录
- **WHEN** 已遗忘用户重新允许记录
- **THEN** 系统可以记录之后的新消息，不自动恢复此前已删除的内容

#### Scenario: 恢复旧数据库
- **WHEN** 旧数据库包含已经遗忘的用户内容
- **THEN** 系统在继续处理前重放独立遗忘记录并移除对应内容
